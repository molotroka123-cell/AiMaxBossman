# START_TOMORROW_RU — владельческий прогон Bossman 1.0-RC

> Шипованный протокол с восемью шагами, привязанный к лаунчерам архива (Owner-Run.cmd, Media-Setup.cmd, Coaching.cmd, Collect-Diagnostics.cmd), лежит в корне репозитория и в архиве: `START_TOMORROW_RU.md`. Этот файл — заметки канонической линии; при расхождении главный — корневой.

Задача владельца завтра — ЗАПУСТИТЬ прогон и снять улики, а не чинить зависимости.
Каждый шаг: вход → ожидаемый эффект → куда смотреть, если не так.

## 0. Установка и целостность
- Проверить SHA-256 присланного архива против значения в релиз-заметке RC.
- Распаковать РЯДОМ со старой установкой (не поверх). Запуск — `Start-Bossman.cmd`.
- Убедиться: ffmpeg/ffprobe лежат в `<app>\media` (в PATH их класть не нужно — лаунчер
  добавляет их сам); модель-каталог и `MANIFEST.json` — в `BOSSMAN_MEDIA_MODELS`.
  Отсутствующая media-модель НЕ должна ломать старт остального Bossman.

## 1. Обнаружение моделей и первая задача
- Дашборд → должны подняться MAIN и FAST (llama-server :8081/:8082).
- Дать реальную инструментальную задачу через Bossman (не «скажи done») и убедиться,
  что путь агента реально выполнил инструмент, а не отрапортовал завершение.

## 2. Браузер и загрузка (B4 — починено)
- Скачать файл через браузер-инструмент: ожидается корректный файл (имя, размер, sha),
  а не HTTP 500; исполняемый — в карантин; агентская загрузка идёт через подтверждение.

## 3. Computer Use — рабочий стол (CU — усилено)
- Открыть окно, ввести текст, проверить STOP/Resume (эндпоинты
  /api/computer/stop|resume; кнопку в UI ещё предстоит добавить — пока стоп по эндпоинту).
- ВАЖНО (усилено сегодня): последствийное действие (оплата/перевод/удаление/деплой)
  теперь ВСЕГДА поднимает подтверждение владельцу — даже если модель назвала действие
  безобидно. Проверить, что подтверждение появляется на кнопке вроде «Удалить аккаунт».
- verify: пустое/неизвестное ожидание больше НЕ считается «проверено».

## 4. Файлы, память, сайт, код, мультиагент
- Прогнать файловые операции, потерю ответа после перемещения, восстановление stale-lock,
  реальные coding/terminal миссии. Улики — в артефактах прогона.

## 5. Медиа: картинка → видео (sd.cpp, усилено)
- Сгенерировать изображение (Z-Image-Turbo), затем видео (Wan2.2 TI2V-5B) ≥3 c,
  I2V из результата, отмену и ошибку. Проверить: воспроизведение/экспорт, отмена НЕ
  оставляет живого процесса (убивается всё дерево), повреждённая (того же размера)
  модель-файл теперь ОТВЕРГАЕТСЯ по sha (не только по размеру).
- Пресет: 832×480 / 20 шагов даёт осмысленный ролик; низкий профиль давал шум —
  прогнать A/B с одним изменяемым параметром при фиксированном seed.

## 6. Обучение (coaching) + holdout
- Прогнать coaching-раннер: ≥5 задач + отдельный holdout, зафиксированные
  model/runtime/tool-permissions, unassisted/coached/teacher-patch раздельно.
  Сохранить: pass@1, попытки, ошибки инструментов, вмешательства, время.
- Урок должен пережить restart и примениться повторно. teacher-patch НЕ засчитывать
  как успех ученика. Веса не менять.

## 7. Восстановление и итоговая атака
- Задача с неопределённым исходом → восстановление; затем независимая красная команда.

## Что честно НЕ измеряется в CI (owner-only)
- Удержание интеллекта: файл бенчмарка создаётся только на железе владельца.
- «Человеческая скорость»: на Windows часы квантованы (15.625 мс) — меряется у владельца.
Эти две оси красны в CI ПО РЕШЕНИЮ, а не из-за дефекта, и не входят в обязательную
матрицу сертификации.
