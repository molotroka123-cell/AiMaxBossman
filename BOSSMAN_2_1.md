# Bossman 2.1 — canonical design pointer

The current cross-branch design for the next autonomous-computer stage is:

[`docs/autonomy/BOSSMAN_2_1_AUTONOMOUS_COMPUTER_OPERATOR.md`](docs/autonomy/BOSSMAN_2_1_AUTONOMOUS_COMPUTER_OPERATOR.md)

Read that document before planning or implementing Bossman 2.1. It defines:

- one-command autonomous computer missions with verified completion;
- recovery and learning from every failed attempt;
- Jev/Kev-class owner-Windows control and OpenBot isolated computers;
- OpenDots adoption as a bounded UX/AG-UI sidecar, not as Bossman authority;
- trusted Internet research and Codex escalation through Bossman CMD;
- restart/resume, receipts, rollback, shadow/canary promotion and the 24-hour gate;
- per-model Token Auditor totals, including Codex, in the Telegram owner console.

This is a target architecture, not proof that LIVE owner-hardware acceptance has
passed. Repository code, CI, REAL_SANDBOX, owner-hardware and unattended LIVE
evidence must remain separate claims.
