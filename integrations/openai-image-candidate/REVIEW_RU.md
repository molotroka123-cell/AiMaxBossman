## Почему нельзя автоматически активировать в финальном V8

1. OpenAIImageProvider.render отправляет POST /images/generations напрямую после
   наличия API key. Привязки к каноническому approval, authoritative tariff,
   reservation/egress revocation перед POST в этом адаптере нет. Наличие ключа
   не является согласием потратить деньги или отправить конкретный prompt.
2. _bounded_size разрешает 256x256 (65536 pixels), а прочитанная официальная
   текущая GPT Image документация требует минимум 655360 pixels, максимум
   8294400, кратность 16 и другие ограничения. Синтетический тест 256x256
   поэтому не доказывает принимаемый provider запрос. Размер молча округляется.
3. Ограничение 64 MiB применяется после загрузки JSON/base64: исходное тело
   ответа не читается ограниченным потоком. base_url можно переопределить;
   отправка Authorization требует отдельного доверенного endpoint-контракта.
4. image_chat.js использует JavaScript ASCII word-boundary для кириллицы:
   русские слова нельзя считать проверенными только по наличию RU_GENERATE.
   Автоматический выбор cloud-модели не заменяет подтверждение стоимости.

Модели gpt-image-2.5-flare и gpt-image-2.5-sunburst подтверждены официальной
публикацией, их существование НЕ является найденной ошибкой.
Источники: https://openai.com/index/introducing-chatgpt-images-2-5/ и
https://developers.openai.com/api/docs/guides/image-generation .

## Безопасное завершение

Внести адаптер в существующую Studio governance/queue, а не создавать обход.
До generation POST: exact model/параметры, проверенная цена/бюджет, подтверждение
точных данных, повторная проверка отзыва разрешения. Исправить размеры, потоковый
лимит, endpoint и Unicode intent; добавить различающие отрицательные тесты.
Затем заново собрать и принять exact application ZIP. Ключи и платные вызовы
для этих отрицательных тестов не нужны. До этого active=FALSE, статус
PRESERVED_NOT_ACTIVATED, а НЕ PASS/готовая генерация.
