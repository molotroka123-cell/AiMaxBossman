## Что подключено

Двенадцать механизмов и их точные границы описаны в [README](README.md). Выполняются явно переданные локальные миссии: транзакционный журнал/CAS, ресурсы, DAG, полномочия, реальный V3 executor, независимое чтение результата, подписанные квитанции, память Core, контекст с зависимостями, локальный модельный маршрут, recovery и неизменяемая оценка. Консоль работает через существующую авторизацию BCC.

Расширение использует штатное обнаружение Feature через opt-in wrapper. Основной работающий Bossman не перезапускался. Состояние, ключ доказательств и артефакты разделены.

## Исправленные ошибки интеграции

1. Перенос квитанции между двумя миссиями с одинаковым контрактом: Store теперь требует `mission_id` вместе с contract/step/actor/fence.
2. Запуск зависимого действия по историческому verified после изменения файла: runtime повторно проверяет подписи и фактические зависимости перед продолжением.
3. Специальные имена Windows (`NUL`, `CON`, `COM1` и варианты), traversal и неоднозначные хвосты пути: отклоняются до IO.
4. Повторное исполнение после неопределённого результата: unknown сохраняет резерв; recovery только наблюдает уже существующий эффект.
5. Инференс без общего резерва: локальный запрос теперь захватывает ресурсы до вызова adapter; timeout/cancellation не освобождают недоказанно завершившийся запрос.
6. Статическая консоль перекрывалась существующим UI mount `/`: исправлен порядок только нового маршрута wrapper; авторизация API сохранена.

Это ошибки, найденные при сборке новой надстройки. Отчёт не выдаёт их за новые уязвимости неизменённого Core.

## Как повторить и откатить

`tools/live_probe.py` проверяет работающий loopback HTTP, файлы и необязательную модель. Запуск с `--resume` проверяет состояние после перезапуска без создания/перезаписи результата. `tools/console_probe.py` выполняет браузерный сценарий. Оба принимают `--data-dir` и `--output`; токен читается локально, не печатается и не передаётся аргументом командной строки.

В GitHub добавлена `.github/workflows/executive-os.yml`: Windows/Python 3.11+3.12, проверка неизменности Core, тесты установленного пакета и wheel. Локальные результаты выше подтверждены; наличие workflow само по себе не означает успешный удалённый CI.

Для отката остановить только `bossman_os.bcc_app` на 8812. Его data-dir сохранить. В основном экземпляре Bossman ничего откатывать не требуется. Автозапуск после перезагрузки Windows не устанавливался.

## Границы доказательства

Это действующая надстройка для ограниченных локальных миссий, а не распределённый supervisor всех существующих задач. Нет физических квот ОС, контейнеров, облачных расходов, удалённого Fleet и автопродвижения кода. Gate сравнивает заданные миссии и не доказывает улучшение версии ПО/модели; откат относится к отдельному процессу надстройки. Модель получила протокол выполнения через prompt, её веса не обучались. Качество рассуждений не измерялось успешной доставкой текста.

Общая оценка ОС 8500/10000 не заявляется: зафиксированного независимого benchmark всей ОС для такого вывода нет. Успешная одна миссия из одной также не означает надёжность 100%.
