# Core, Memory, Context — проверка и улучшения

Дата: 2026-09-05. База: `c5a73976a152199312fa2d0543fc2fe9dd4d8c03`.
Изменения выполнялись в изолированной ветке `codex/reality-compiler-v010`;
основной checkout с параллельной работой пользователя не изменялся.

## Что означают 7200 и 8500

Источник оценки 7200/10000 в исполняемой системе оценивания не найден.
До изменений зафиксированы существующие scorer, manifest и golden corpus.
Их правила и ожидаемые ответы не менялись для увеличения балла.

Имеются три разные шкалы, смешивать которые нельзя:

- Ручная категория зрелости **Memory / Context** в этой ветке — 6.2/10,
  в более новом общем checkout — 6.5/10.
- Существующий offline nightly **SystemIQ** уже даёт 1.0 на базовом коде;
  Memory и Context также 1.0. Это ограниченная, уже насыщенная выборка:
  36 REAL_SANDBOX, 21 REGRESSION, **LIVE=0**.
- Все 25 прежних context golden cases уже сохраняют 100% обязательных якорей.
  Они проверяют сохранность фактов на заданных примерах, а не общий интеллект.

Поэтому результат **«всё приложение стало 8500/10000» не подтверждён**.
Вместо ручного изменения оценки устранены воспроизводимые дефекты, сохранена
старая матрица и добавлены отрицательные проверки найденных границ.
[Baseline с командами и хешами](docs/reality/evidence/core-memory-context-eval.json).

## Исправления

| Область | Дефект до изменения | Поведение после |
|---|---|---|
| История решений | `current_only=False` игнорировал `scope` и `subject`; будущие записи выдавались как текущие. | Обе ветки SQL сохраняют фильтры; current требует наступивший `valid_from`. Три воспроизведения падали, затем прошли вместе с восемью прежними contract tests. |
| История контекста | Лимит не ограничивал число добавляемых сообщений; старые сообщения занимали место свежих. | Упаковка от новых к старым, строгий оценочный лимит и сохранение последнего результата инструмента. Полный журнал не удаляется ради одного запроса. |
| Политика и текущая задача | Процентная квота могла молча отрезать конец системной политики; tool schemas не учитывались в финальной проверке вместимости. | Политика и задача сохраняются целиком; при невозможности поместить обязательный контекст — явная ошибка до обращения к модели. |
| Сжатие | Прежняя сводка не подавалась в оба следующих пути compaction. | Предыдущая сводка передаётся как данные; повторяющийся точный текст не дублируется без необходимости. Пустой compact не стирает историю. |
| Граница памяти | Собственные заметки агента `memory.md` становились системными инструкциями. | Заметки сохраняются в явно помеченном блоке данных; утверждённый `prompt.md` остаётся политикой. Память не выдаёт approvals. |
| Индекс проектов | Идентификатор документа не включал проект. | Одинаковый путь и текст в разных проектах создают отдельные записи; результаты перепроверяются по scope. |
| Свежесть источника | Новая версия файла оставляла старые chunks в обычном поиске. | Атомарно переключается текущая версия источника. Старые raw documents/chunk refs остаются адресуемыми для аудита. |
| Классификация | Fast path неизменного текста пропускал изменения sensitivity и metadata. | Классификация обновляется без повторного embedding; источник не остаётся публичным из-за кеша старой метки. |
| Качество recall | После plugin retrieval релевантность терялась при сортировке только по importance/confidence. | При объединении сохраняется приоритет соответствия текущему запросу; проверяются project и статус записи. |
| Доверие к memory ID | Новый текст под прежним ID мог унаследовать ACTIVE и прежнее доказательство. | Подмена text/project/kind отвергается до изменения проверенной записи. |
| Экспорт памяти | JSON plugin превращал superseded-записи в ACTIVE. | Статусы и проект фильтруются; отменённая память не возвращается как действующая. |
| Отказы embeddings | Сбой embedder или повреждённый vector мог уничтожить и доступные результаты lexical search. | Лексические доказательства сохраняются; некорректные векторы изолируются. |

## Доказательства и ограничения

Новые регрессии воспроизводят реальные операции сборщика и локальной SQLite:
запись/повторное открытие индекса, переключение версии, rollback прерванной
публикации, проверку классификации, ранжирование, ошибку embedding и формирование
реального payload Core. SQL decision memory проверен исполнением запросов на
контролируемых строках; это не выдаётся за live PostgreSQL.

Сохраняются существующие Reality gates, approvals, grants, completion evidence
и глобальные бюджеты. Системные инструкции не копируются из retrieved content.
Токены оцениваются эвристикой проекта, а не точным tokenizer каждой модели:
это ограничение явно сохраняется, даже когда оценочный лимит соблюдён.

Настоящие PostgreSQL-проверки требуют `BOSSMAN_TEST_PG_DSN`; отсутствие сервера
не считается PASS. Нет новой облачной оценки, обучения весов либо доказательства
роста качества всех локальных моделей. Работающий старый процесс Bossman не
перечитывает опубликованный код автоматически.

## Результаты финального прогона

Финальный код: `c8a8506d7c9b6eb26f62a5af0b6b74bb43695777`.
[Команды и результаты](docs/reality/evidence/core-memory-context-final.json):
82 существующих теста, 40 новых регрессий и 26 дополнительных проверок защит —
**148 passed, 9 PostgreSQL skips**. Nightly — **READY**, 36 REAL_SANDBOX и
21 REGRESSION, LIVE=0. Scorer, manifest и golden corpus совпадают с базовыми.

Два старых теста и один sandbox case ожидали помещение memory.md в system.
Их актуальные проверки перенесены на реальный payload: память сохранена в data,
в system её нет. Неизменённые старые тесты также запущены против нового кода:
**80 passed, 2 failed, 9 skipped**; два падения соответствуют этой намеренной
смене границы доверия. Они не скрыты и не используются для заявления роста балла.

[Установленный wheel](docs/reality/evidence/core-memory-installed-checks.json)
проверен через `python -I` на Python 3.11 и 3.12: хеши девяти модулей совпали с
исходниками; фактический payload сохраняет memory как данные, реальная SQLite
выбирает текущий источник. Синтаксис 15 изменённых Python-файлов и secret scan
прошли. Рабочая установка пользователя не заменялась.

Следующий достоверный шаг к общей цели 8500 — контрольная выборка реальных задач
владельца с неизменной шкалой, независимой проверкой артефактов и учётом отказов,
утечек, повторных эффектов, времени и стоимости. Текущий насыщенный offline
benchmark не различает уже обнаруженные здесь ошибки, поэтому одного его балла
недостаточно для такой оценки.
