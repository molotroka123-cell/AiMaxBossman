# Установка Bossman

Рабочая ветка: `claude/bossman-final-convergence-hu2702`.
Старые инструкции Stage 12 перенесены в [архив](docs/archive/root-history/INSTALL_STAGE12.md).

## Windows — готовое приложение для тестирования 21 сентября

Основной вариант — готовая сборка. Отдельно устанавливать Python, Chromium
и FFmpeg для неё не нужно: они входят в архив. **Клон репозитория для
приёмки архива не нужен**: доктор, проверка установленного продукта,
развёртка кнопок, проверка живой модели и приёмка на целевом железе
поставляются внутри ZIP в папке `app-support` и запускаются встроенным
интерпретатором (OA-04 аудита 17 сентября).

1. Откройте [Windows-сборки в GitHub Actions](https://github.com/molotroka123-cell/AiMaxBossman/actions/workflows/windows-bundle.yml).
   Выберите прогон ветки `claude/bossman-final-convergence-hu2702`.
2. В шаге **Accept the archive as a product on a clean machine** должна быть
   строка `BOSSMAN_BUNDLE_ACCEPTANCE=PASS`, а в задании **freeze** — строки
   `BOSSMAN_ASTRA6_FREEZE=` и `BOSSMAN_ASTRA6_RELEASE_READY=`. Один зелёный
   значок без этих строк не подтверждает полную проверку архива;
   `RELEASE_READY=NO` означает, что архив пригоден для теста, но не для
   выпуска (например, нет ключа живой модели или входы сборки ещё не
   закреплены замком `tools/windows_bundle_lock.json`).
3. Внизу страницы, в **Artifacts**, скачайте `bossman-windows-<SHA>`.
   Для скачивания нужен вход в GitHub. Распакуйте скачанный архив, затем
   находящийся внутри `BOSSMAN-Windows-x64-<SHA>.zip`. Прямой ссылки на один
   ZIP приложения (GitHub Release) пока нет: публикация — отдельное
   действие владельца после `RELEASE_READY=YES`; хэш публикуемого ZIP
   считается по внутреннему `BOSSMAN-Windows-x64-<SHA>.zip`, а не по
   обёртке Actions.
4. Поместите папку приложения, например, в `C:\Bossman`.
   Открывайте программу из распакованной папки.
5. Дважды нажмите **Start-Bossman.cmd**. Вариант для обычного браузера:
   `Start-Bossman.cmd --web`.
6. Подключите свою модель в настройках панели и включите агента для задач.
   Веса модели и ключи провайдера в архив не входят.
7. Для диагностики запустите **Evening-Test.cmd** из PowerShell.
   Скрипт печатает сборку, доктора, приёмку установленного продукта, все
   причины и один вердикт: `PASS` (код 0), `OWNER_REQUIRED` (2, не хватает
   только действия владельца — занятый порт, ключ), `PARTIAL` (3, запуск с
   `--skip-doctor`, полной приёмкой не считается), `FAIL` (1). Каждый запуск
   пишет в новую папку `%LOCALAPPDATA%\Bossman\evening\<SHA>\<run_id>`;
   старый результат нынешний запуск удовлетворить не может.

### Что ещё умеет архив без клона

| команда из папки архива | что делает |
|---|---|
| `.\Evening-Test.cmd` | доктор + установленный продукт (боевой сценарий: запуск, вход, история, перезапуск) |
| `.\Evening-Test.cmd --full` | то же плюс развёртка видимых кнопок и проверка живой бесплатной модели через установленный UI; без `BOSSMAN_OPENROUTER_API_KEY` в окружении стадия модели — `OWNER_REQUIRED`, а не PASS |
| `.\Machine-Report.cmd` | семь стадий о вашей машине (ниже) |
| `.\runtime\python.exe -I .\app-support\target_hardware_acceptance.py --json target.json` | приёмка на целевом железе: на Ryzen AI Max+ 395 / Radeon 8060S / 128 ГБ выполняет три проверки **этого архива** (установленный продукт по SHA манифеста, доктор, вечерняя приёмка); на другой машине честно печатает `SOFTWARE_READY_FOR_TARGET_HARDWARE_RUN` и никогда не объявляет готовность железа |
| `.\runtime\python.exe -I -m bcc.owner_acceptance --data-dir "$env:LOCALAPPDATA\Bossman\CommandCenter" --output owner-acceptance.json` | настоящая ИИ-задача через вашу настроенную модель (см. «Первая проверка») |

Идентичность во всех этих проверках — `MANIFEST.json` архива (точный SHA
источника и хэш каждого файла), а не Git-чекаут: скрипты проверяют, что
запущены из `app-support` рядом с манифестом, и не зависят от текущего
каталога. Ключи в архив не кладутся; ключ живой модели задаётся в окружении
на время запуска и в улики не пишется.

Проверка архива подтверждает запуск, поставку библиотек, браузера и медиасредств,
авторизацию и сохранение после перезапуска. Она не подтверждает работу настоящей
модели без ключа, управление вашим рабочим столом или скорость Radeon 8060S.

### Восемь open-source направлений: что в архиве, а что нет

`MANIFEST.json` → `oss_directions` перечисляет для каждого направления
отдельно: `BUNDLED` (пакет действительно установлен в runtime архива),
`CONFIGURED` (всегда действие владельца после распаковки), `MODEL_REQUIRED`
(нужны веса), `EXTERNAL_SERVICE_REQUIRED` (нужен отдельный сервис) и
`VERIFIED` — в манифесте всегда `false`: проверка направления — отдельное
действие на вашей машине, и её способ назван в поле `verify_by`.
Таблица — в [docs/oss/README.md](docs/oss/README.md). Локальные
inference-серверы (llama-server, ComfyUI, SearXNG) и веса в архив не
входят и на старте приложения не запускаются; без них соответствующие
карточки честно отвечают `MODEL_REQUIRED` / «сервис не подключён».

### Семь ответов о вашем компьютере, а не один

Дважды нажмите **Machine-Report.cmd** (или `.\Machine-Report.cmd --json owner-machine.json`).
Отчёт печатает семь стадий отдельно, потому что путать их дорого: запущенное
приложение не означает загруженную модель, загруженная модель не означает
работающее ускорение, а работающее ускорение не означает откалиброванную камеру.

| стадия | на что отвечает | если не готово |
|---|---|---|
| `app` | приложению есть куда писать ваше состояние | освободите место или задайте `BCC_DATA_DIR` |
| `hardware` | ваша ли это машина целевого класса | ничего: приложение работает и на другой |
| `model_server` | отвечает ли локальный сервер модели | запустите Ollama либо укажите `OLLAMA_HOST` |
| `model_loaded` | загружены ли в него веса | `ollama pull <модель>` |
| `acceleration` | какая доля весов лежит в видеопамяти | счёт идёт на процессоре: обычно это сборка сервера или драйвер |
| `camera` | отвечает ли сервис камеры | запустите приложение камеры из Command Center |
| `speed_memory` | сколько памяти и сколько токенов в секунду | нет модели — нечего мерить |

Про пятую стадию отдельно: ускорением считается не наличие Radeon в списке
устройств, а доля весов в видеопамяти. Ноль означает счёт на процессоре, каким
бы мощным ни был ускоритель, и отчёт скажет это прямо.

Отчёт **не объявляет аппаратную приёмку** ни при каких зелёных стадиях: такого
значения в нём нет. Приёмку на целевом железе выдаёт только
`target_hardware_acceptance.py`, запущенный НА самой машине — из архива
(команда в таблице выше) или из клона. Камеру отчёт не открывает: читается
только объявленная готовность сервиса.

### Сохранение интеллекта локальной модели — что для этого нужно

Проверка `Intelligence Preservation` в CI красная, и это честный ответ, а не
поломка: канонический файл `docs/benchmark/intelligence-preservation-current.json`
никто не производил. Произвести его можно только настоящим парным измерением на
машине с локальной моделью. **Это единственное измерение, которое по-прежнему
требует клона репозитория**: его runner привязывает результат к дереву Git
(`git ls-tree` каждого файла), а не к манифесту архива, и по OA-05 нужен
независимо отрецензированный корпус большего размера — до него измерение
даёт `INSUFFICIENT_EVIDENCE` при любом способе запуска. Из клона репозитория:

```powershell
python tools/intelligence_preservation_run.py --model <точный id модели> --preflight-only
```

Предварительная проверка не делает НИ ОДНОГО обращения к модели и сразу говорит,
хватает ли набора задач. На поставляемом наборе она отвечает так:

```
INTELLIGENCE_PRESERVATION=INSUFFICIENT_EVIDENCE
corpus has only 20 items in its smallest metric ... even perfect core metrics need 189 each
```

Значит, **недостающих условий два, а не одно**: локальная модель И набор не
меньше 189 задач на каждую основную метрику. Сейчас в
`docs/benchmark/intelligence_tasks.json` 220 задач — по 20 на каждую из
одиннадцати метрик. Одной только покупкой или загрузкой модели эта проверка не
закрывается; нужен независимо отрецензированный набор большего размера.
Дописывать его собой и собой же оценивать нельзя — это самозаверение.

Когда оба условия выполнены, полное измерение запускается так:

```powershell
python tools/intelligence_preservation_run.py `
  --model <точный id модели> --tasks <ваш набор>.json `
  --quantization <фактическая квантизация> `
  --hardware "Ryzen AI Max+ 395 / Radeon 8060S / 128 GB"
```

Флаг `--allow-insufficient-samples` существует только для диагностики: он не
меняет гейт и не превращает недостаточную выборку в PASS.

### Первая проверка на новом компьютере

- Создайте тестовый сайт, измените заголовок в «Конструкторе блоков»,
  сохраните, закройте приложение и откройте проект снова.
- Импортируйте короткое собственное видео, сделайте обрезку и экспорт;
  откройте получившийся файл в видеоплеере.
- Для работы с файлами используйте отдельную папку с копиями документов.
  Сначала проверьте предпросмотр действий.
- После настройки модели выполните отдельную проверку настоящей ИИ-задачи.
  В PowerShell из папки приложения, если используется стандартный каталог данных:

```powershell
.\runtime\python.exe -I -m bcc.owner_acceptance   --data-dir "$env:LOCALAPPDATA\Bossman\CommandCenter" `
  --output owner-acceptance.json
```

Если меняли `BCC_DATA_DIR`, укажите свой каталог. Проверка делает
настоящий запрос к выбранной модели в отдельном тестовом состоянии; это не
команда на выполнение всех пользовательских задач. Результат `OWNER_REQUIRED`
означает, что настройка ещё не завершена, а не успешное выполнение.

При ошибке сохраните вывод Evening-Test и `owner-acceptance.json`.
Ключи провайдеров и файлы токенов никому не отправляйте. Если окно запуска
сразу закрывается, выполните `.\Start-Bossman.cmd` из уже открытого
PowerShell — сообщение об ошибке останется на экране.

При обновлении распаковывайте новую сборку отдельно. Пользовательские данные
готового приложения находятся в `%LOCALAPPDATA%\Bossman\CommandCenter`;
сохраняйте этот каталог. Старую рабочую сборку оставьте до проверки новой.

## Windows — запуск из исходников

Установите Python 3.11+ и FFmpeg. Для Python рекомендуется 3.12.
Скачайте указанную ветку или переключитесь на неё в своём клоне.
В PowerShell из папки репозитория выполните:

```powershell
.\start-bossman.ps1
```

Скрипт создаёт `.venv`, устанавливает три пакета Bossman, приложения из `apps/`,
MCP, OpenTimelineIO, PDF-парсер, библиотеки управления Windows и Chromium.
После проверки откроется Command Center.

Повторный запуск без переустановки: `.\start-bossman.ps1 -SkipInstall`.
Открыть в обычном браузере: добавьте `-Web`.
Проверить установку: добавьте `-DoctorOnly`. Другой порт: `-Port 8810`.

## Linux / macOS

Установите Python 3.11+ и FFmpeg средствами своей системы, затем:

```bash
bash start-bossman.sh
```

Повторный запуск: `bash start-bossman.sh --skip-install`.
Обычный браузер: `--web`; диагностика: `--doctor-only`; другой порт: `--port=8810`.
На минимальной Linux-системе Chromium может потребовать системные библиотеки;
их устанавливает команда `.venv/bin/python -m playwright install-deps chromium`.

## Первый вход

Панель доступна по <http://127.0.0.1:8800>. Используйте токен входа из файла,
путь к которому показывает приложение. Подключите модель в настройках:
локальный сервер или свой облачный провайдер. Без модели можно редактировать
сайт вручную и работать с доступными локальными инструментами, но ИИ-задачи
выполняться не будут.

GrapesJS открывается кнопкой **«Конструктор блоков»** в Веб-дизайне.
Он работает со статическим HTML/CSS. Если импорт может потерять программируемые
или неподдерживаемые элементы, приложение предлагает редактировать исходный код.
Сохранение использует те же проекты и историю версий. При конфликте с другой
вкладкой черновик остаётся открыт и доступен для скачивания.

MCP-серверы и OpenHands требуют настройки. Установка библиотек сама по себе
не подключает внешние сервисы и не запускает модели.

## Установка для разработки

Для облегчённого сервера по-прежнему можно ставить пакеты без `[runtime]`.
Для полного приложения в активированном окружении:

```bash
python -m pip install -e . -e "command-center[runtime,dev]" -e "bossman-core[runtime,dev]"
```

`start-bossman` дополнительно ставит все объявленные приложения из `apps/`.
Профиль `[runtime]` также используется Windows-сборкой и установщиком локального
архива. Для обновления состава зависимостей повторите запуск без `SkipInstall`.

## Данные

Запуск из исходников по умолчанию хранит данные в `command-center/data`;
установленный пакет — в пользовательском каталоге данных платформы.
`BCC_DATA_DIR` задаёт другой каталог. При обновлении не удаляйте каталог данных,
файлы токенов, Vault или ключи подтверждения: это состояние владельца.
