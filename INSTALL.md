# Установка Bossman для первого прогона

**Единственный кандидат: `release/bossman-owner`, PR #67.** Планируемая владельческая приёмка — 21 сентября 2026. Эта инструкция не объявляет текущую ветку сертифицированной.

## 1. Какой архив брать

Интегратор передаёт один комплект: `TESTED_SHA`, URL Windows-архива, SHA-256 именно скачиваемого ZIP, ссылки на выполненные обязательные проверки и честные ограничения. Пока комплект не готов, нельзя считать произвольный последний архив финальной сборкой.

Источник готовых Windows-архивов: [One-download Windows application](https://github.com/molotroka123-cell/AiMaxBossman/actions/workflows/windows-bundle.yml). Выбирать нужно **`release/bossman-owner` и ровно TESTED_SHA**. Зелёный Linux Local bundle или старый Windows-архив не подменяют этот прогон.

В существующем workflow предусмотрены `BOSSMAN_BUNDLE_ACCEPTANCE=PASS` и статусы freeze/release-ready. Проверять нужно также реальные jobs, ограничения отчёта и идентичность архива. `OWNER_REQUIRED` может обозначать честно отсутствующий ключ или действие человека; он не означает, что все функции прошли тест. `BLOCKED`/ошибка сборки не являются разрешением на установку с рабочими данными.

## 2. Скачать и сверить

В Artifacts нужного прогона найти `bossman-windows-<SHA>` и распаковать обёртку Actions. Внутри ожидается `BOSSMAN-Windows-x64-<SHA>.zip`; фактическое имя сверять с отчётом сборки. Если интегратор дал проверенный Release asset, использовать его прямую ссылку.

Хэш внутреннего ZIP и digest обёртки Actions — **разные значения**. В PowerShell из папки со скачанным ZIP:

```powershell
Get-FileHash .\BOSSMAN-Windows-x64-<SHA>.zip -Algorithm SHA256
```

Заменить `<SHA>` фактической частью имени. Сравнить результат с хэшем, который относится именно к этому ZIP. Несовпадение — остановка, не предупреждение, которое можно игнорировать.

## 3. Запустить без инженерной установки

Распаковать приложение в отдельную тестовую папку, например `C:\Bossman-Test`. Не запускать из ZIP, не ставить поверх рабочей папки и не копировать туда рабочую базу данных.

Дважды нажать **`Start-Bossman.cmd`**. Для обычного браузера предусмотрен `Start-Bossman.cmd --web`.

Полный Windows bundle проектируется с собственными Python, Chromium, FFmpeg и `app-support`; их наличие проверяется приёмкой архива. Если файл или зависимость отсутствует, фиксируем дефект упаковки, а не превращаем владельца в сборщика программы. Git-клон для основной проверки архива не нужен.

Веса моделей, внешние inference-сервисы и приватные ключи отдельно. Сначала настроить **одну** проверенную модель в панели. Ключи вводить локально; не прикладывать к GitHub, скриншотам или журналам. Не отключать Defender/SmartScreen ради запуска.

## 4. Первый тест

Из PowerShell в распакованной папке приложения:

```powershell
.\Evening-Test.cmd
```

Это базовая диагностика и проверка установленного продукта, **не автоматический PASS всех HW-01…HW-13**. Владелец затем проходит [OWNER_ACCEPTANCE](OWNER_ACCEPTANCE.md).

`Evening-Test.cmd --full` включает дополнительные проверки, в том числе путь живой модели; выполнять только с разрешённым тестовым провайдером/данными и согласованным бюджетом. Недостающий ключ должен отображаться как требуемое действие, а не как успешный ответ ИИ.

Для отчёта о машине предусмотрен `Machine-Report.cmd`. Более узкий harness можно запускать встроенным Python, задав реальную настроенную папку данных:

```powershell
.\runtime\python.exe -I -m bcc.owner_acceptance --data-dir "<configured-test-data-dir>" --output "owner-acceptance.json"
```

Не использовать случайный глобальный `python` вместо runtime архива. Тестовый отчёт принимать только от текущего успешного запуска и с правильной идентичностью сборки; старый оставшийся JSON не является результатом нового прогона. Этот harness не сертифицирует все локальные модели, desktop и Telegram за один вызов.

## 5. Что передать при сбое

Достаточно: HW-кейс, точная команда обычным языком, ожидаемый и фактический результат, TESTED_SHA, хэш архива, обезличенный лог/скриншот. При подозрении на внешнюю отправку не повторять действие, пока не проверен результат первой попытки.

Оплата, торговые ордера и отправка реального заявления MVČR не входят в безопасный первый прогон. Для MVČR готовим пакет до `WAIT_APPROVAL`.

## Для инженера

Оставить один проверенный архив и один короткий отчёт передачи. Доказательства CI, установленного Windows-продукта, реальной модели и владельческого железа хранить раздельно. После любого исправления перепроверять затронутые сценарии; окончательная сертификация относится к одному SHA и конкретным байтам архива.

Подробные прежние команды и история упаковки сохранены в [архиве](docs/archive/owner-preflight-05a1bb02/README.md). Историческая ветка из старой инструкции не является текущим кандидатом.
