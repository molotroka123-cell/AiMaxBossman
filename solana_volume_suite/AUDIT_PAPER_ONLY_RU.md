# Аудит Solana/Pump.fun: бумажный режим

Дата: 2026-10-10
Область: `solana_volume_suite` в ветке `claude/bossman-final-convergence-hu2702`.

## Что было найдено

- `setup_mainnet.py` проверял доступность mainnet RPC/Jito, создавал или загружал приватные ключи и записывал пароль хранилища открытым текстом в `.env`.
- `start_prototype.py --mainnet` печатал `MAINNET_READY`; запуск без флага импортировал dashboard, который мог инициализировать пул ключей.
- `orchestrator_loop.py` загружал кошелёк с диска, при ошибке расшифровки удалял файл, а после симуляции присваивал сделке `confirmed_onchain=True` и выдуманную подпись.
- API dashboard выдавал фиктивный успешный ответ на создание кошельков и «свип» балансов, меняя локальное состояние.
- AI fallback генерировал `KOTH_PULSE` при тишине и `FLOOR_DEFENSE` после крупной продажи. Эти действия предназначены для искусственного объёма и поддержки цены.

## Что изменено

- Launcher отклоняет `--mainnet` и `--setup` до импорта dashboard. Он запускает только локальную бумажную симуляцию.
- Mainnet setup стал fail-closed заглушкой: без RPC-запросов, создания ключей и записи файлов.
- Цикл использует фиксированный синтетический пул и виртуальные `SIM-WALLET-*`. Он не читает, не создаёт и не удаляет хранилище, не загружает ключи и не обращается к сети за данными.
- `BUY`/`SELL` сохраняются только как бумажные записи. `confirmed_onchain` всегда `false`, подпись транзакции отсутствует. Искусственный объём и автоматическая поддержка цены блокируются.
- API генерации ключей и свипа отвечает `BLOCKED`; существующие файлы и балансы не изменяются. Dashboard явно подписывает метрики как оценки симуляции.

## Pump.fun и границы аудита

В исходниках `solana_volume_suite` не обнаружены код создания SPL mint/Pump.fun-токена и endpoint запуска токена. `stages/pumpfun_engine.py` строит инструкции покупки/продажи для уже существующего mint. Отправка bundle через `core/jito_client.py` намеренно завершает вызов исключением `LIVE_EXECUTION_DISABLED`; вызовов стандартного RPC `sendTransaction` в проверенных Python-файлах не найдено.

Отдельная утилита `scripts/generate_vault.py` по-прежнему предназначена для ручного создания зашифрованных локальных ключей; dashboard и paper-runner её не вызывают. Вспомогательные модули умеют строить инструкции/планы, но этот audit не является утверждением о безопасности каждого экспериментального файла репозитория. Три доказанных workflow дохода в этой области не обнаружены — paper-метрики не означают доход или исполненные сделки.

## Проверка

Новые и обновлённые тесты проверяют отсутствие доступа к vault в runner, блокировку искусственного объёма/поддержки цены, отсутствие on-chain-подтверждений, блокировку mainnet запуска, и отсутствие побочных эффектов у API генерации ключей/свипа. Команда:

```powershell
python -m pytest solana_volume_suite/tests tests/test_solana_safety.py
```
