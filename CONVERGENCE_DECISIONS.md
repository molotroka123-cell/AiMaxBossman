# CONVERGENCE_DECISIONS

Происхождение каждой критической части Bossman. Не эссе — след.

Канон: **`release/bossman-owner`**. Победитель — всегда он, а не историческая
заявка. Порядок улик: владельческое железо > установленный продукт Windows >
установленный продукт вообще > сквозной сценарий > перезапуск/восстановление >
отказы/безопасность > интеграционные > контрактные > модульные > чтение кода >
документация > имя/возраст/автор ветки.

## CI-001 — покрытие канонической ветки заданиями Windows

**Подсистема:** конвейер выпуска.
**Кандидаты:** A — фильтр `claude/**`+`night/**` (как было); B — добавить `release/**`.
**Победитель:** B.
**Почему:** измерение, не мнение. На `release/bossman-owner` было 44 прогона и
12 заданий, из них `windows-bundle` и `windows-owner-tasks` — **ноль**.
Каноническая ветка не собирала продукт владельца ни разу.
**Улики:** GitHub API по ветке; после правки `windows-owner-tasks` №16 реально
пошёл на канонической ветке (in_progress, 02:28).
**Отклонено:** A — отсутствие прогона не окрашено никак и читается как
«замечаний нет».
**Риск регресса:** очередь раннеров глубже. Группа `concurrency` привязана к
`github.ref`, поэтому соседние ветки не отменяются — проверено.
**Откат:** `fa8588d6^`.
**Сторож:** `tests/test_windows_workflows_cover_owner_branches.py` (42 теста).

## CI-002 — обязательные задания должны СУЩЕСТВОВАТЬ для точного SHA

**Подсистема:** гейт выпуска.
**Кандидаты:** A — смотреть на красное/зелёное; B — считать отсутствие отказом.
**Победитель:** B (`tools/release_workflow_gate.py`).
**Почему:** прямое требование владельца после BL-089. Отсутствует — ОТКАЗ;
в очереди — НЕИЗВЕСТНО; отменён — НЕИЗВЕСТНО; ПРОЙДЕНО только завершённый успех.
**Улики:** 22 теста на чистых функциях + прогон на НАСТОЯЩИХ данных API.
**Что гейт нашёл сразу:** на `295b4d73` оба задания Windows — `MISSING`.
Причина не в поломке: последние коммиты трогали `bossman-core/tests/`,
`README.md` и `docs/`, которых нет в фильтре путей `windows-bundle`.
**Следствие, важное для выпуска:** кандидатом может быть только SHA, на котором
задания Windows реально поднялись, либо их надо поднять для кандидата вручную
(`workflow_dispatch` есть у обоих). «Зелено на соседнем коммите» уликой не
является и гейтом не принимается.
**Откат:** удалить `tools/mandatory_release_workflows.json`.

## REALITY-001 — наблюдения для выбора маршрута

**Кандидаты:** A — `features/reality.py::memory_reading` (канон);
B — `media_routing.py` из PR #59.
**Победитель:** A.
**Почему:** A — функциональное НАДмножество. Тот же ключ `process.host`, та же
проверка FRESH, тот же довод дословно; плюс `memory_requirement()`, который
отвергает NaN/±inf/отрицательные на ручке (422). У B этой проверки нет.
Перенос заменил бы более строгую проверку менее строгой.
**Отклонено:** B — дублирующая архитектура, второй экземпляр тех же правил.
**Не потеряно:** сводка здоровья провайдера четырьмя состояниями — факт
`provider.models` публикуется `reality/observers.py:171`, разбирается в
`reality/strategy.py`. Отдельного модуля не требует.

## SOCIALFARM-001 — PR #59 — ПЕРЕОТКРЫТО

**Статус: РЕШЕНИЕ ОТОЗВАНО, идёт разбор по подсистемам.**

Сначала я отклонил все 39 файлов, сославшись на правило «Higgsfield — только
официальный MCP и аккаунт владельца». Владелец поправил: существо PR #59 —
**свой форк Higgsfield ВНУТРИ Bossman**, а не пользование чужим сервисом.
Правило было не про это, и моё отклонение опиралось на неприменимое основание.

Признано ошибкой отклонения, а не «уточнением формулировки».

Решения REALITY-001 и APPRENTICE-001 остаются в силе: они приняты по замеру
дублирования, а не по правилу про Higgsfield.

Остальные 28 файлов (`apps/social-farm/src/social_farm/generation` и тесты)
разбираются матрицей PRESENT_BETTER_IN_OWNER / PORT_REQUIRED / OBSOLETE /
OWNER_HARDWARE_ONLY. Запись будет дополнена.
