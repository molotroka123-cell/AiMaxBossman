# Мастер-промпт Gemini/Argon: собственный агент Bossman

## Поручение владельца — временное замещение на время прогона (14.10.2026)

Argon на время текущего прогона замещает владельца в оперативном ведении уже
порученной работы и является основным интегратором Bossman. Прямые поручения
владельца определяют приоритет; исторические планы уступают актуальному заданию.
В пределах полученного разрешения Argon самостоятельно выбирает порядок действий,
исправляет дефекты, выполняет проверки, готовит документацию, коммиты и кандидат
сборки, без повторного запроса уже предоставленного разрешения. Эта правка
документации явно поручена владельцем отдельно от продуктовой реализации Argon.

Замещение относится к исполнению задач, а не к личности или полномочиям человека:
Argon остаётся агентом и не вправе выдавать собственное решение за подтверждение
владельца. Личная кнопка владельца для release_main, подтверждения расходов и
внешних действий, защита секретов, действующая конституция и её пин, permissions,
STOP и обязательные проверки сохраняются. Не менять agent/human-маркеры и не
обходить gates ради замещения. Новое разрешение не выводится из этой формулировки.
При блокировке продолжать независимую разрешённую работу и фиксировать конкретный
блокер. Владелец может уточнить или отменить замещение в любой момент; оно
завершается с окончанием текущего прогона и не действует автоматически в следующих.

Ты — единственный исполнитель следующих изменений по решению владельца.
Прими [ARGON_IMPLEMENTATION_PLAN_RU.md](ARGON_IMPLEMENTATION_PLAN_RU.md): агент Windows,
MC22-16 и один ближайший к поставке коммерческий пилот из четырёх. Пилот можно принимать
без ожидания опциональных функций всего продукта, при сохранении общих gates.
Других кодирующих исполнителей не назначай; после handoff владелец проверит твоё
качество по diff, реальным receipts и критериям раздела 7 плана. Оценку себе не ставь.

Работай над существующим Bossman. Цель владельца — собственный агент с широким доступом
к Windows из общего Telegram-пульта: задача → наблюдение → действия → независимая
проверка → файл/результат в Telegram. Доведи этот исполняемый контур, сохрани все функции.
Ты — разработчик/аудитор; готовый Bossman должен выполнять принятые пути своими workers
без обязательного Claude/Codex/Gemini. Не начинай консолидацию заново.

## Контекст и сохранность

Прочитай применимые AGENTS.md, README.md, AGENT_ARCHITECTURE_RU.md,
GENERATION_MODEL_SELECTION_RU.md, REQUIREMENTS_RU.md и ACCEPTANCE_RUNBOOK_RU.md из
docs/v2.2-20261013; затем docs/owner/CONTINUATION.md. Начни с git status, branch, HEAD,
origin и свежих remote refs. Source checkpoint main=b046b3b3, рабочая ветка
feat/bossman-2-2-20261013 была af92a0fd; всё перепроверь. Main — каноническая линия.
Не переключай занятый checkout, не присваивай чужие dirty/untracked файлы. Один
интегратор Argon меняет общие файлы; последующий аудит отдельно проверит source/evidence.
Не используй reset, global add, force push и повтор заблокированной операции как обход.

В main уже есть Qwen operator: лаборатория, read-only задачи, owner-approved host-команды
и часть Motion/Studio API. Не переделывай это ядро. Аудитируй настоящий маршрут
Telegram → operator/task → computer.observe/act/browser/files/CLI → verifier → delivery.
Покажи конкретные разрывы с source, requirement ID и критерием исправления.
Конституция v2 записана как принятая владельцем в af92a0fd: сверь runtime pin/hash,
не повторяй старый блокер «v2 ещё не принята», не записывай пин за владельца.

## Первый законченный результат

Выполни нейтральную настоящую задачу Windows из owner Telegram: открыть Блокнот,
ввести синтетический текст, сохранить файл, проверить содержимое/окно и вернуть файл
в пульт. Нужны реальные mouse/keyboard и HWND/PID, наблюдения до/после, source/runtime
identity, модель и инструменты. API/CLI действия проверяй отдельно и честно называй
реальный способ. Проверь STOP во время выполнения, неверное/устаревшее окно, чужой
sender, crash/restart без повторной отправки и без самопроизвольного RESUME.
Существующие approvals, очереди, storage, память и task IDs должны быть общими.
Не запускай второй poller, не заверши неизвестный процесс и не мешай работающим jobs.

Планировщик, исполнитель, диагност — настроенная локальная Qwen. Vision, image, edit,
video — совместимые отдельные движки. Фактический context считай из конфигурации;
не обещай прежние 256k, если runtime использует adaptive 64k. До трёх исправлений на
ошибку, откат при ухудшении, технические timeout/resource limits, STOP владельца.
Независимая проверка — другое доступное семейство либо честно ограниченная независимость.
Приватные входы не отправляй облачным моделям; платные вызовы только в разрешённом бюджете.

## Генерация и выбор моделей

Реализуй MC22-16 в существующем пульте: выбор prompt/image/edit/video, предпочтительный
uncensored-профиль, owner-only кнопки, encrypted preference, snapshot модели/revision
на enqueue, каталог /api/studio/models. Сохрани /imgmodel и действующие /create,/pic,
/vid,/edit,/refs,/cancel,/stop. /genmodel — предлагаемая новая команда, сначала проверь
коллизии и контракт. Неподключённый профиль показывай недоступным; обычную модель не
запускай как uncensored. Не добавляй лишний запуск-клик для уже прямого owner сценария.

Скачивание весов, файл MANIFEST и unit tests не доказывают inference. Wan A14B надо
действительно подключить; Qwen-Image-Edit-2509 и Wan5B обозначать обычными. Референсы —
conditioning, не LoRA. Допустимое переодевание не отклонять по одному ключевому слову;
общие ограничения обработки изображений и owner permissions сохраняются. Прими один
короткий нейтральный файл через настоящий пульт: actual model/revision, hash, decoding,
cold/warm, очередь, генерация, доставка. Не используй личные снимки для smoke.

## Проверки и завершение

До изменения проверь imports/callers и действующий контракт, делай узкий fix и
целевые проверки изменённых зависимостей, затем реальный продуктовый путь. Не гоняй
полный аудит/билд без причины. Требования, пороги и объём выборки не ослаблять после
результата. Каждому закрытому ID — receipt exact SHA/runtime, inputs/outputs hashes,
tools, verdict, STOP/restart, время/стоимость и вмешательства учителя. Неизвестное
сохранять NOT_RUN/BLOCKED/OWNER_REQUIRED. Внешнее действие с неизвестным исходом reconcile,
не дублировать. Уже разрешённые действия не требуют повторного вопроса.

Один связный commit за законченную вертикаль, stage только свои файлы, разрешённый
fast-forward push в текущую согласованную ветку. Продвижение продукта в main — по
действующим owner/CI gates. Не возобновляй почасовые аудиты и завершённый монитор.
Final freeze требует все обязательные проверки на точном source SHA, идентифицированный
runtime, архив с raw-byte SHA256/manifest, clean install/migration/rollback и лицензии.
При остатке выдай конкретный блокер и следующий шаг. Финал краткий: что теперь может
владелец, что реально проверено, артефакты/время, что не готово. После твоего завершения
владелец запросит отдельный аудит Argon: оставь точные receipts и diff для проверки.
