# Bossman 2.2 — единая спецификация и карта работ

Дата: 13 октября 2026. Аудитная база: `ea7c9a3d9a46d8339a8917b6f4163cba0d9fb27c`. Статус: **SPECIFICATION / NOT FROZEN**.

## Что означает 2.2

Цель — один Bossman, которым владелец управляет из интерфейса, терминала и Telegram:
задача проходит от входа до проверенного результата, переживает перезапуск, соблюдает
STOP и бюджет. Локальные модели выполняют выбранные рабочие пути без обязательного
Claude/Codex. Обучение подтверждается сравнением на новых задачах, а коммерческие
пилоты — реальными результатами и учётом затрат.

Сведение исходников в main выполнено на аудитной базе. Полная автономность 2.1 ещё
не доказана: её документ имеет статус DESIGN / NOT YET PROVEN LIVE. Поэтому пакет
разделяет **остатки обязательств 2.1** и **новые возможности 2.2**. Исторические
документы V2_1/V2_2 другой линии разработки сохраняются как история, без нового freeze.

## Полная инвентаризация

В [inventory/](inventory/) сохранены все **901 узел дерева**, включая
883 конечных узла, 109 модулей features,
660 статически объявленных маршрутов этих модулей,
57 записей leaf-manifest и 54 JS-файла страниц.
Это реестр источников; наличие строки не означает успешного запуска.

Каждый узел получает собственную строку с исходным ID, родителем, статусом карты,
путями и результатом проверки их наличия. Поле `audit_state` специально не повышает
доказанность функции. Все 1745 выбранных исходных файлов
есть в source-crosswalk.csv; 1181 не имеют
точной ссылки из seed. Это задачи сверки, а не такое количество потерянных функций.

## Ближайший законченный результат

Один настоящий owner-сценарий пульта: фото + подпись → локальная Qwen → подтверждаемый
черновик → очередь → готовый файл → измеренное время → отмена/перезапуск без дубля.
Входные данные остаются локальными. Параллельно можно готовить независимый корпус
Jeff и сверку Reports. Один интегратор меняет общие файлы; аудиторы работают отдельно.

## Где приватный отчёт по ключам

Фактические балансы, лимиты и состояние конкретных учётных записей сохранены владельцу
в локальном `creative-runs/FULL-TREE-AUDIT-20261013/KEYS_AND_BALANCES_RU.md`.
Они не входят в этот публикуемый пакет. Здесь есть только процедура проверки.

## Управление изменениями

Новый запрос связывается с ID требования и узлом дерева либо добавляется отдельной
строкой. Удаление функции требует миграции и явного решения владельца. При смене
исходного SHA прежнее доказательство остаётся историческим; применимость проверяется
по изменённым зависимостям. Время, номер версии, число строк и зелёный CI сами по себе
не закрывают требование. Пакет не включает новые разрешения на расходы, публикации
или внешние действия и не возобновляет отменённые периодические аудиты.
