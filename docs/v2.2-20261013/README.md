# Bossman 2.2 — собственный агент Windows через Telegram

## Поручение владельца — временное замещение на время прогона (14.10.2026)

Argon на время текущего прогона замещает владельца в оперативном ведении уже
порученной работы и является основным интегратором Bossman. Прямые поручения
владельца определяют приоритет; исторические планы уступают актуальному заданию.
В пределах полученного разрешения Argon самостоятельно выбирает порядок действий,
исправляет дефекты, выполняет проверки, готовит документацию, коммиты и кандидат
сборки, без повторного запроса уже предоставленного разрешения. Эта правка
документации явно поручена владельцем отдельно от продуктовой реализации Argon.

Замещение относится к исполнению задач, а не к личности или полномочиям человека:
Argon остаётся агентом и не вправе выдавать собственное решение за подтверждение
владельца. Личная кнопка владельца для release_main, подтверждения расходов и
внешних действий, защита секретов, действующая конституция и её пин, permissions,
STOP и обязательные проверки сохраняются. Не менять agent/human-маркеры и не
обходить gates ради замещения. Новое разрешение не выводится из этой формулировки.
При блокировке продолжать независимую разрешённую работу и фиксировать конкретный
блокер. Владелец может уточнить или отменить замещение в любой момент; оно
завершается с окончанием текущего прогона и не действует автоматически в следующих.

Статус: **спецификация; полный агент и final freeze не приняты**. Актуализация 13.10.2026:
checkout `feat/bossman-2-2-20261013` на `af92a0fd`, проверенный remote `main` на `b046b3b3`.
Это идентичности исходников, не идентичность установленного продукта.

Последняя сверка remote: `main cd71cddc9423d9781dff7eb24ba5b09fb24a990d`.
Дельта от b046b3b3 добавляет только три owner-документа с ночным checkpoint и PC-Agent
промптом; продуктовый код тот же. Эти документы сохранены в main. Активный план
Argon ниже уточняет их коммерческий scope и проверку качества.

## Главный результат

Владелец пишет задачу в общий Telegram-пульт. Bossman понимает цель, наблюдает Windows,
управляет приложениями, браузером, файлами и разрешёнными командами, проверяет результат
и возвращает файл или отчёт в тот же пульт. Длинная работа переживает сбой и не мешает
STOP. Рабочие пути исполняются собственными локальными workers без обязательного
Claude/Codex. Gemini/Argon помогает разработке и аудиту, а не становится обязательным
компонентом установленного агента.

Канонический контракт: [агентная архитектура](AGENT_ARCHITECTURE_RU.md).
Для генерации: [выбор моделей](GENERATION_MODEL_SELECTION_RU.md), предпочтительный
профиль — uncensored отдельно для текста, image, edit и video. Отсутствующий или
неподключённый движок явно недоступен; обычная модель не подменяет его молча.
Этот документ не активирует новый селектор в работающем пульте.

**Поручение владельца: дальше изменения выполняет только Argon.** Полный
[план и ТЗ с монетизацией](ARGON_IMPLEMENTATION_PLAN_RU.md) задаёт его работу и
последующий независимый аудит качества. Других параллельных исполнителей не назначать.

## Проверенное и неизвестное

В коде есть общий backend, Telegram-пульт, Computer Use tools, оператор Qwen с
лабораторией, разрешёнными host-командами и частью Motion/Studio API. Это компоненты
будущего единого агента. Наличие маршрутов не доказывает сквозное выполнение произвольной
задачи Windows. Общий выбор text/image/edit/video с неизменной моделью в очереди пока
является новым требованием MC22-16, а не пройденной функцией.

Коммит `af92a0fd` фиксирует принятую владельцем конституцию v2. Старое указание
«владелец ещё не принял v2» устарело. Действительность runtime-пина и разрешения
конкретной операции всё равно сверяются по текущей установке; агент пин не записывает.

[Аудит ea7c9a3d](AUDIT_RU.md), [уточнение 38f4aec3](UPDATE_20261013_1350_RU.md) и
инвентаризация [inventory/](inventory/) сохранены как датированные срезы. Их числа,
PID, балансы, статусы и следующие шаги нельзя переносить на новый HEAD автоматически.
Инвентаризация сохраняет все 901 узел исходного дерева и связи с кодом; новая архитектура
не удаляет предыдущие функции и не перекрашивает их в PASS.

## Первый законченный шаг

Telegram-задача → настоящее наблюдение Windows → действия в Блокноте → сохранённый
тестовый файл → независимая проверка → доставка владельцу. Проверить STOP посреди
задачи, восстановление после сбоя и отсутствие повторного внешнего действия. Затем
принять выбор моделей на одном коротком нейтральном сценарии генерации.

Четыре коммерческих направления остаются: Jeff Stars, Motion, Operations, Reports.
Техническая готовность, спрос, платёж и прибыль учитываются отдельно. North Star:
строгое самоисправление → три цикла → перенос навыка → 24/48 часов → недельный режим
→ коммерчески пригодный пилот. Часовые аудиты и завершённый монитор готовности не возобновлять.
