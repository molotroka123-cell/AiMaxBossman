- Идентифицировать единственный poller, backend, модель и место хранения.
- Сверить update → inbox → lane → draft → generation job → output → delivery.
  Не читать личный prompt ради диагностики: достаточно ID, типов, времени и кодов.

Готовность для теста владельцем: один текущий Telegram roundtrip с подтверждёнными

## 2. Закрыть готовые коммерческие вертикали

Четыре направления, каждое с отдельной карточкой: кому полезно, вход, результат,
предельные затраты, ручные шаги, канал, цена-гипотеза, критерий качества и доказательства.

| Пилот | Минимальный проверяемый путь | Что нужно для коммерческого статуса |
|---|---|---|
| Jeff Stars | Документ → ответ с подтверждающей цитатой → лимит → счёт → событие платежа → доступ → restart → refund | Официальная тестовая среда, цена/terms/support; отдельное разрешение на публичный запуск |
| Motion | Разрешённые исходники → план → короткий preview → коррекция → монтаж/субтитры/музыка/обложка → editable project/export | Реальный результат, качество, сроки, лицензии всех assets/weights |
| Operations | Разрешённые заявки → проверенные поля → дедупликация → ручная очередь/CRM → отчёт → restart/retry | Проверенная выборка, отсутствие дублей/потерь, согласованный режим внешних действий |
| Reports | Telegram JSON/CSV → месяц 21–20 Europe/Prague → спорные строки → сверяемый отчёт | Независимая контрольная книга, полнота данных, отдельный учёт оборота и прибыли |

Технически готовый путь можно запускать как ограниченный пилот после его применимых
gates, не дожидаясь опциональных функций всей 2.2. Статусы коммерции: hypothesis →
technical demo → customer interest → accepted order → delivered → paid → withdrawn →
profit. Для каждого перехода — фактическое подтверждение; автоматической выручки не обещать.

## 4. Обучение, Poker и North Star

Сначала dataset provenance и независимый holdout; разделение по исходной записи,
пользователю/семейству задач, а не соседним кадрам. До обучения сохранить baseline.
После обучения тот же evaluator/корпус/лимиты; плохой candidate отклонять. Проверить
retention после restart и перенос на unseen задачи. Минимальный размер выборки
вычислять действующим статистическим gate; 20 примеров не подменяют требуемые 189.
Не снижать порог после неудачи.

Soup — возможный адаптер, не уже интегрированный runtime: проверить текущий main,
upstream commit/лицензию, отдельную PR/реализацию и совместимость. Text-SFT не учит
diffusion/видеодвижок; для Genjutsu нужен его собственный training backend.

Порядок North Star: infrastructure → строгий single repair → 3 различных repair →
измеренный transfer → 24h soak → 48h soak → week readiness → revenue-capable pilot.
Memory hit, teacher patch, повтор известного задания и mock не повышают ступень.
Poker: запись и OCR-кандидат → независимые метки → калибровка → held-out accuracy →
офлайн-разбор; coaching в собственном разрешённом симуляторе проверять отдельно.

Коммерческий pipeline исключает несовместимые noncommercial компоненты.

## 7. Покрытие дерева и единый freeze

1. Каждый обязательный ID связан с capability ID, кодом, тестом и actual receipt.
2. Висячая ссылка получает решение archive/remap/restore; новые функции получают листья.
3. Статусы применяются через штатные tree_apply_evidence/tree_registry_sync, без ручного зелёного.
4. Проверить public site source, seed, registry, installed build и accepted source.
5. На принятом SHA выполнить обязательные CI и реальные сценарии нужной среды.
6. Собрать архив из чистого принятого source; verifier, hash, manifest и обратная сверка.
7. Чистая установка/миграция на копии данных, проверенный rollback, второй ноутбук для
   обещанного multi-device режима; приватные данные/ключи/веса по лицензии не попадают в ZIP/Git.
8. Release содержит AGPL, third-party notices, ограничения, instructions и SHA256.
   Публикация/переустановка — по действующему разрешению владельца.

Незакрытый обязательный gate означает NOT_FROZEN с конкретным остатком и следующим
действием. Отчёт о завершении не заменяет архив и реальные доказательства.

## Формат доказательства и экономия лимитов

Использовать evidence.schema.json: exact source SHA, dirty, installed identity, hashes
входа/модели/результата, среда, команды/worker, фактический verdict, заранее фиксированные
пороги, negative control, STOP/restart, время/стоимость, вмешательства учителя.
Schema проверяет структуру, а не истинность результата. Частные входы и prompts вне Git.

Один интегратор, до трёх независимых read-only аудиторов. Сначала локальные инструменты
и существующие результаты; облако — только при разрешённом scope/budget. Повторять
целевые проверки изменённых зависимостей; полный audit/build только с конкретной причиной.
Один связный commit за вертикаль, stage только свои файлы, push fast-forward в общую
ветку. Отменённые часовые аудиты не возобновлять.
