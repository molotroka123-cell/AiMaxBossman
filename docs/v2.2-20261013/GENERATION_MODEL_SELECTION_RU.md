# Генерация в пульте: выбор моделей и главный профиль

Связанный ID: **MC22-16**. Статус: **требование к реализации; новый общий селектор
ещё не активирован этой документацией**. Source checkpoint `main b046b3b3`.

## Пользовательский сценарий

Перед генерацией владелец видит четыре роли: «Промпт», «Фото», «Редактирование», «Видео».
В каждой роли — текущая модель, её готовность и кнопка смены. Главный предпочтительный
профиль — **uncensored**. Владелец может явно выбрать другой профиль. Решение сохраняется
до следующего изменения; текстовый профиль не переносится на свойства фото/видео.

Предлагаемый интерфейс `/genmodel` и `/genmodel prompt|image|edit|video` — **новый
контракт**, а не уже действующие команды. Существующий `/imgmodel` сохранить как
совместимый вход выбора фото. `/create`, `/pic`, `/vid`, `/edit`, обычная подпись с refs
и кнопки должны обращаться к одному и тому же выбранному профилю.

## Данные и маршрут

- Каталог визуальных моделей — существующий `GET /api/studio/models`. Показать model ID,
  роли/входы, provider, available/configured/demo/verification; наличие файлов не равно inference PASS.
- Текстовые модели — существующая локальная конфигурация Ollama/роутера. Не создавать
  второй реестр весов и не добавлять произвольный облачный endpoint из сообщения.
- Предпочтения — существующий encrypted Store отдельно по owner и роли. Схема ключей
  может расширять текущую `img_model:{person.key}`, с миграцией и совместимостью.
- При enqueue сохранять model ID, manifest revision/hash, роль, inputs, параметры и seed.
  Во время ожидания смена настройки влияет только на новые задачи. Перед inference
  сверить совместимость snapshot; изменение/удаление весов означает явный отказ или
  новое согласованное задание, а не молчаливую замену.
- Очередь, STOP, отмена, retries, ресурсы и доставка остаются общими. GPU-генерации
  выполняются с учётом уже работающих задач, без второй очереди и второго poller.

## Как выбирается главный uncensored-профиль

1. Конкретная модель подключена к нужному engine, имеет известные revision/hash и
   проверенные условия использования; пригодна для входов и доступна на машине.
2. Профиль подтверждён model metadata/происхождением fine-tune. Строка `uncensored` в
   имени, импорт весов или текстовый промпт не являются независимой сертификацией.
3. До живой проверки в карточке «подключена, не проверена»; после проверки — ссылка
   на результат с SHA, параметрами, временем и ограничениями.
4. Если пригодного профиля нет: «Uncensored для этой роли не готов», причина и список
   доступных альтернатив. Обычная модель запускается только по явному выбору владельца.
5. Смена модели выполняется только владельцем, не посетителем Jeff и не содержимым файла.

## Что действительно есть на checkpoint

| Роль | Исходники/поведение | Что требуется |
|---|---|---|
| Фото | `service.py`: статический IMAGE_MODELS, `/imgmodel`, encrypted preference | Общий каталог, owner check, проверенный профиль и snapshot |
| Редактирование refs | Qwen-Image-Edit-2509 закрепляется действующим маршрутом | Совместимый выбор; обычный редактор явно помечен обычным |
| Видео | VIDEO_MODEL указывает Wan2.2 TI2V 5B | Реальный селектор; выбранные A14B-веса отдельно подключить и проверить |
| Промпт | `gen_refine.py`: local Qwen, кеш выбранной модели | Явный выбор, cache по model ID, отдельные receipts |

UC/heretic ветки `direct_gen/sdcli.py` сами по себе не отдельные Studio model IDs.
Скачанный Wan A14B не равен работающему backend. Локальная запись manifest может
отличаться от source: фактическую привязку z-image-turbo проверять перед запуском.
Обычные Qwen-Image-Edit-2509 и Wan TI2V 5B не объявлять uncensored.

## Референсы, промпт и качество

`/refs on/off/clear` регулирует постоянные привязки до отмены. Привязка снимков —
conditioning, не обучение LoRA. Выбранный edit engine обязан поддерживать число/тип
входов; несовместимость показывается до запуска. Обычная смена одежды в допустимом
фото не должна отклоняться только из-за слова «переодеть». Промпт и референсы не могут
отключить общие правила обработки изображений и права владельца.

Для image/edit/video отдельно фиксировать размер, длительность/кадры, шаги, seed,
Qwen refinement, cold load, ожидание, inference при наличии отдельной метрики,
postprocess и доставку. Текущее `gen_s` не называть чистым inference. `/speed` должен
сопоставлять только совместимые model/revision/preset/размеры, а не смешивать разные веса.

## Приёмка MC22-16

Настоящий owner выбирает модель → preference переживает restart → задача ставится
в очередь со snapshot → настройка меняется → старое задание использует прежнюю модель,
новое — новую. Проверить недоступные/неподключённые веса, несовместимые refs, чужой
Telegram ID, отсутствие облачного fallback, STOP/отмену и restart без дубля. Один
нейтральный короткий результат через пульт с файлами/хешами и реальным временем.
Fake API и unit PASS отдельно; до этого статус NOT_RUN_FOR_2_2.
