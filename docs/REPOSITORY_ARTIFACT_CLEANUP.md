# Уборка бинарных артефактов из корня репозитория

## 1. Почему это делается

До уборки корень репозитория содержал **10 ZIP-архивов и 6 PNG**: 25 МБ из
40 МБ всего отслеживаемого дерева. Каждый клон, каждый прогон CI и каждый архив
тянули их с собой, хотя ни один из них не является исходным кодом.

## 2. Инвентаризация — что это было и что с ним сделано

**C** скриншот/справочный материал · **D** устаревший дубликат ·
**E** сгенерированный вывод.

то есть два архива описывают одно и то же состояние, и оба давно поглощены
рабочим деревом. Держать в корне обе копии одного снимка — чистый дубликат.

## 3. Что «убран из дерева» значит — и чего НЕ значит

`git rm` убирает файл из **текущего** дерева. Исторический blob остаётся в
репозитории, и файл **восстановим побайтно**. Проверено до уборки: для
`BOSSMAN_SKILLS_V1_OPENROUTER_MCP_TERMINAL.zip` и одного PNG sha256 рабочей
копии и версии из истории совпали.

Команда восстановления любого архива:

```bash
git show c7f26e6:<имя_файла.zip> > <имя_файла.zip>
```

`c7f26e6` — последний коммит, в котором все архивы ещё лежали в корне.

уменьшение репозитория требует переписывания истории — план вынесен отдельно в
`GIT_HISTORY_CLEANUP_PLAN.md` и **автоматически не выполняется**.

## 4. Итоговая раскладка

| Что | Где живёт |
|---|---|
| Код control plane | `command-center/` |
| Приложения | `apps/<имя-приложения>/` |
| Скиллы | `.agents/skills/` |
| Документация | `docs/` |
| Справочные изображения | `docs/reference-images/` (скриншоты владельца — в подкаталоге `owner-screenshots/`) |
| Исходные паки, архивы, сборки | **вне отслеживаемого дерева**: релизы GitHub либо внешнее хранилище |

## 5. `.gitignore`

Правила написаны так, чтобы новый пак не вернулся в корень сам собой, но
**законные ассеты приложений не пострадали**. Игнорируется архив **в корне**, а
не любой архив где угодно: `apps/*/assets/*.zip` или тестовая фикстура остаются
отслеживаемыми.

## 6. Что осталось не сделано

- **История не переписана** — по прямому требованию этого прогона. План есть,
  запуск за владельцем.
- **Архивы не выложены в GitHub Releases**: у учётных данных этой сессии нет
  прав на создание релиза (пуш тега уже отклонён с `HTTP 403`). Восстановление
  из истории описано в §3 и проверено.
