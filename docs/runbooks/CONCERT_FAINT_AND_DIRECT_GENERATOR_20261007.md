# Концерт Faint и прямой генератор «18+++» — runbook (07.10.2026)

Это задание на реализацию и измерение, а не отчёт об установленном стеке. Документ сам по себе не означает push, установку или PASS. Следующий прогон — 07.10; при переносе на 08.10 критерии сохраняются.

**Контракт одного продукта:** всё идёт через существующий Bossman (media backend, Motion/Video Studio, jobs, события, STOP, дерево). Второго backend, второй очереди и смены моделей Jeff нет. Ступень North Star на сегодня: SELF_IMPROVEMENT_INFRASTRUCTURE_PRESENT; SELF_REPAIR_SINGLE_CYCLE_PASS не достигнут (см. `docs/architecture/bossman-tree-20261005/evidence/selfrepair-20261006.md`).

## Цель

Ryzen AI Max+ 395 / Radeon 8060S / 128 ГБ общей памяти: клип 168,8 с из 45 шотов. Приоритет: реалистичность, одна узнаваемая певица и группа, инструменты как в треке, точное пение. Рабочий мастер 480p; 1080p — отдельный необязательный экспорт. 2,5 ч — цель оптимизации, не измеренный срок. RunPod только с отдельным разрешением владельца (сейчас `NOT_RUN`).

## Исправления исходной концепции

- Официальный Wan2.1-1.3B — T2V. Подтверждённая S2V-модель — Wan2.2-S2V-14B. Фиктивный «Wan2.1 S2V 1.3B FP8 Lightning» не создавать.
- DWPose извлекает позы, но не делает произвольный checkpoint pose-conditioned. Нужны совместимые веса и реальный вход; у Wan2.2-S2V есть `pose_video`.
- FP8 уменьшает вес, но ускорение зависит от runtime и kernels. 4 шага — только с проверенным distilled checkpoint/LoRA для выбранной базы.
- Whisper — речь; фонемы пения требуют отдельного alignment. Не обещать фонемную разметку за 1,5 минуты.
- LivePortrait — управление портретом, не универсальный refiner; после lip-sync может испортить рот. Только при доказанном улучшении.
- Апскейл не создаёт 60 настоящих к/с; интерполяция — отдельный эксперимент.
- LSE-C > 7,5 не доказывает реалистичное пение: указывать evaluator, версию, сегменты, смещение; смотреть губы, зубы, руки, стабильность лица.
- Внутреннюю архитектуру Higgsfield не заявлять; делаем свой workflow со сходными функциями.
- 128 ГБ — общий бюджет ОС, моделей и приложений. Не держать 15 моделей; LoRA по одной или ограниченным кэшем после замера.
- «$0» = нет платы за API; электричество и время не нулевые. «$35–50 за 15 обучений и 2–3 дня на APU» не подтверждено.

## Архитектура концерта

1. Вход: трек, разрешённые референсы, референсы сцены/движения, список инструментов; SHA256, длительность, sample rate.
2. Demucs: вокал/ударные/бас/прочее; оригинал остаётся финальной дорожкой. Определение инструмента — гипотеза до проверки.
3. `shot_manifest.json`: 45 сцен (start/end, текст, инструмент, персонаж, план, свет, движение, seed, checkpoint, workflow hash); сумма интервалов 168,8 с, стыки учитываются в бюджете.
4. База: A/B Wan2.1-T2V-1.3B и LTX-Video (если поддержан runtime); для ключевых планов певицы отдельно Wan2.2-S2V-14B. Один стиль/персонаж/свет на проект.
5. Губы: сначала исходная S2V-синхронизация; LatentSync 1.6 или MuseTalk только для нужных крупных планов, с тем же offset вокала.
6. Пост: LivePortrait факультативно; Real-ESRGAN сравнить с оригиналом; SeedVR — после базового PASS. FFmpeg монтирует исходную музыку без перекодирования, если совместимо; сравнивать decoded PCM.
7. Очередь — через существующий media backend и ComfyUI API-адаптер; сначала найти реальные модули в checkout.

## Реальное ускорение

- Demucs, embeddings, позы, маски — один раз; ключ кэша = вход, модель, версии, параметры; ошибки не кэшировать как успех.
- Короткие шоты, атомарное сохранение, resume по manifest hash.
- Тяжёлые GPU-стадии последовательно; не 45 diffusion jobs одновременно.
- Сначала BF16/FP16, затем A/B quantization, distillation, caching; VAE-tiling — экономия памяти, не гарантия скорости.
- Не улучшать забракованные шоты; апскейл после принятия монтажа.
- Jeff остаётся отзывчивым. **Измерено 07.10:** при загруженных моделях Ollama (≈56 ГБ) свободно было 1,1 ГБ ОЗУ, и ComfyUI падал на втором шаге S2V; после `ollama stop` свободно 83 ГБ. Перед тяжёлым рендером выгружать модели Ollama (Jeff подгрузит при запросе).

## Первый измеримый прогон (15 с)

Певица крупно, музыканты с инструментами, общий план — по 5 с; один аудиофрагмент, одинаковые референсы. Сохранить: manifest, сырой результат, логи, CSV (загрузка, генерация, lip-sync, post, wall time, peak RAM/GPU с методом замера, frames, native FPS, steps, dtype, checkpoint SHA, runtime/driver, retries; shared и dedicated отдельно).

Проверки: декодирование/длительность, нет чёрных кадров и NaN, стабильность персонажа, губы, инструменты, руки, свет; оценка Claude + просмотр владельца. ETA = Σ(секунд/кадр × кадры по стадиям) + загрузки + экспорт + повторы; ускорение ≥30% — только парным сравнением, cold/warm отдельно.

## Прямой генератор «18+++» (приоритет UX)

Локальная рабочая область для контента совершеннолетних. Без промежуточной LLM-модерации и скрытого изменения запроса; не обещать выполнение любого запроса — отказ, unsupported mode, OOM и runtime error показываются честно. Не для несовершеннолетних и не для несанкционированных интимных изображений реальных людей; обходов ограничений провайдера не разрабатывать.

Экран: селектор установленной video model → большое поле prompt → image/reference/negative (необязательно) → duration/resolution/seed → «Создать»; рядом доступность модели и память. Ниже: этап, очередь, elapsed, реальный прогресс, STOP, превью, сохранить, повторить с тем же seed, журнал ошибки.

- **DIRECT:** исходный prompt в выбранную video model без Qwen; настройки и служебные параметры видимы.
- **ASSISTED:** отдельно выбранный локальный Qwen предлагает редактуру/shot plan; пользователь видит оригинал и версию и выбирает сам. Точное имя Qwen — из model registry/runtime; ничего не выдумывать и не скачивать автоматически.
- Для каждого checkpoint: source, revision/hash, лицензия, runtime, T2V/I2V/S2V, ограничения входа; несовместимая модель недоступна с понятной причиной.
- Jobs: queued/loading/generating/postprocessing/completed/failed/cancelled; существующая авторизованная очередь и SSE/WebSocket. Процент только из реальных шагов, иначе stage+elapsed; ETA после собственного замера.
- Хранение: job_id, raw/effective prompt, параметры, результат, ошибки, provenance — в private participant storage, изоляция между участниками; личные промты/лица/аудио/секреты не в GitHub.

## Приёмка UX и обучения

Через настоящий Bossman UX/CMD: выбрать окно генератора, отправить prompt, увидеть события и playable файл; отменить mid-run; понятная ошибка при отсутствующих весах; повтор seed; изоляция истории; Jeff отвечает во время очереди; нет скрытой подмены модели/платного fallback; нет фоновых job после STOP. Заранее зафиксировать легальные тестовые сцены и критерии; отдельно считать долю успехов, отказов модели и ошибок runtime.

LoRA — только после повторяемого дефекта: согласованные данные персонажа, held-out шоты, сравнение base/LoRA по идентичности, движению, lipsync и времени на тех же seed; adapters под конкретную базу. RunPod: сначала оценка короткого шага, затем бюджет и STOP; до разрешения `NOT_RUN`. Самоулучшение = накопление проверенных workflow-рецептов, не автообучение весов.
