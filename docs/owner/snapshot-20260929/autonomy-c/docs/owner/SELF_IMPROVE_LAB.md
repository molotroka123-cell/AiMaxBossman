# Лаборатория самоулучшения Bossman

Инструмент: `tools/self_improve_lab.py` (в Windows-комплекте — `app-support\self_improve_lab.py`,
запуск `runtime\python.exe app-support\self_improve_lab.py …`). Только стандартная библиотека
Python: не нужен checkout, PYTHONPATH и путь `C:\Users\asd`.

Лаборатория ходит в **настоящий** Bossman по HTTP (заголовок `X-BCC-Token`) и ничего не решает
за него: задачу выполняет coding-сайдкар Bossman, лаборатория только готовит чистые копии,
держит бюджет времени, запускает скрытую проверку и записывает исход.

**Веса моделей не меняются.** Каждый отчёт несёт `weights: WEIGHTS_UNCHANGED`: «обучение» здесь —
это проверенный рецепт в памяти Bossman, который попадает в контекст следующей задачи.

## Варианты (сохранённые агенты)

Шесть обычных строк таблицы `agents` (видны на странице «Агенты», роль `lab:self-improve`).
Создаются идемпотентно: `POST /api/lab-agents/ensure` (лаборатория вызывает сама; два вызова —
по-прежнему 6 строк). Если настройки строки кто-то поменял, `ensure` возвращает их к эталону,
а выбранную владельцем модель не трогает.

Промпты — дословно тексты владельца (2026-09-23) плюс общая преамбула изоляции; строки,
сохранённые прошлой сборкой со старыми промптами, `ensure` правит на месте (те же id, без дублей).

| Вариант | Текст владельца (начало) | Тесты перед финишем | Память |
|---|---|---|---|
| `LAB · RAW` | «Улучши Bossman. Найди одну реальную проблему…» — базовая линия | нет | нет |
| `LAB · TOOL_FIRST` | «…Сначала исследуй систему инструментами… Найди reproducer…» | да | нет |
| `LAB · MEMORY` | «…До планирования запроси verified lessons…» — единственный с памятью | да | **да** |
| `LAB · PLAN_EXECUTE_VERIFY` | «…PLAN… EXECUTE… VERIFY… Не завершай без независимого подтверждения.» | да | нет |
| `LAB · RED_TEAM` | «Попытайся сломать одну функцию Bossman…» | да | нет |
| `LAB · USER_UX` | «Используй Bossman как обычный владелец…» | да | нет |

**Честность («одна модель — разный Bossman»):** у всех шести учеников одинаковые инструменты
(все шесть, у USER_UX вернулся `write_file`), шаги (40) и токены (4096); различаются только промпт,
правило «тесты перед финишем» и память. Каждая строка отдаёт отпечаток `fairness`.

### Наблюдатели (не ученики)

Три сохранённых профиля с ролью `lab:observer`: **CLAUDE_AUDITOR** (наблюдает и без причины не
помогает; исходы `OBSERVE / CORRECT_LEVEL_1 / CORRECT_LEVEL_2 / CORRECT_LEVEL_3 / STOP_FOR_SAFETY`),
**RESULT_VERIFIER** (только профиль и правила; сам код проверки — `bossman_v3.self_improvement.verifier`,
соседняя лента) и **UX_OBSERVER**. У них только чтение; вариантом сравнения их выбрать нельзя
(код 2), а `/api/coding-tasks` отказывает с 409 `LAB_OBSERVER_NOT_A_STUDENT` — иначе пустой список
инструментов превратился бы в полный набор сайдкара.

Память включена только у MEMORY — это контролируемое сравнение: если другой вариант вдруг
получил память (`memory.recalled = true`), его исход — `BLOCKED` (`MEMORY_LEAK_IN_CONTROL`),
а не засчитанный проход. MEMORY видит только рецепты, существовавшие **до** начала сравнения
(снимок `snapshot_recipe_ids`); чужой рецепт → `BLOCKED` (`MEMORY_SNAPSHOT_VIOLATED`).

## Фазы и команды

Общие параметры: `--base-url http://127.0.0.1:8800`, токен (`--token`, `BCC_TOKEN`,
`--token-file` или `--data-dir` — токен берётся из `<data-dir>\token`; по умолчанию
`%LOCALAPPDATA%\Bossman\CommandCenter`), `--out <папка отчётов>`, `--work-dir <папка копий>`
(**должна лежать внутри разрешённых корней кода Bossman**, иначе Bossman откажет — исход
`BLOCKED`), `--json`, `--poll-interval 10`.

```
# 1. свободное исследование (одна задача, без скрытой проверки → NOT_VERIFIED)
self_improve_lab.py explore --repo C:\Users\asd\Bossman\wt-lab --agent TOOL_FIRST --out lab

# 2. сравнение шести вариантов на ОДНОМ фиксированном кейсе
self_improve_lab.py compare --case sample --out lab --work-dir <корень кода>\lab-work
#    (свой кейс: --case D:\lab-cases\my_case.json)

# 2a. вмешательство учителя (можно из ДРУГОГО терминала, пока compare идёт)
self_improve_lab.py intervene --agent RAW --level 2 --hint "смотри на разделитель" --task <id> --out lab
self_improve_lab.py intervene --agent RAW --level 5 --hint "Claude написал патч сам" --out lab
#    (старая форма --variant RAW --kind hint|teacher_patch|cloud_fix --note ... работает)

# 2b. сводка турнира моделей (по одному compare-report.json на модель)
self_improve_lab.py tournament-report --report m1\compare-report.json --report m2\compare-report.json ^
    --bakeoff results\main-q5.json --out lab

# 3. урок: лучший проверенный проход → рецепт в память Bossman
self_improve_lab.py lesson --case sample --out lab

# 4. ПОЛНЫЙ перезапуск Bossman (делает owner-run), затем перенос на новый похожий кейс
self_improve_lab.py transfer --case sample-transfer --out lab --work-dir <корень кода>\lab-work

self_improve_lab.py status --out lab          # состояние
self_improve_lab.py make-sample --dest D:\x   # посмотреть синтетические репозитории
```

### compare — как устроен честный прогон

1. Для **каждого** варианта — новая копия репозитория на базовом коммите:
   `git clone --no-local` в новую папку, без remote. Что оставил предыдущий вариант, в
   следующей копии отсутствует; после варианта копия удаляется.
2. Задача уходит в `POST /api/coding-tasks` с `agent_id` варианта, `project_id` кейса и
   `use_memory` (true только у MEMORY).
3. Опрос `GET /api/coding-tasks/{id}` с **жёстким бюджетом** (по умолчанию 40 минут, из кейса
   или `--budget-minutes`). Срок записывается в state-файл при отправке и при продолжении
   **не продлевается** (новый `--budget-minutes` при resume игнорируется с предупреждением).
   Истёк — сохраняется запись задачи (`task-record-at-timeout.json`), делается попытка отмены,
   исход `TIMEOUT`, копия удаляется, запускается следующий вариант.
4. **Независимая проверка.** Возвращённый diff накладывается на **другую** чистую копию; файлы
   скрытой проверки пишутся только теперь, в папку, которой у ученика не было, и команда
   запускается вне песочницы ученика с минимальным окружением (без токенов и настроек Bossman).
   Правка защищённых путей или вне разрешённых — `SCOPE_VIOLATION` (провал). Если имя скрытого
   файла нашлось в копии ученика — `BLOCKED` (`VERIFIER_VISIBLE_TO_STUDENT`).
5. Файл кейса внутри исходного репозитория запрещён (ученик увидел бы проверку): код выхода 2.

### Исходы (ровно один на вариант)

| Исход | Когда |
|---|---|
| `STUDENT_UNASSISTED_PASS` | скрытая проверка прошла, вмешательств не было |
| `STUDENT_COACHED_PASS` | прошла, но была подсказка (`intervene --kind hint`) |
| `TEACHER_PATCH` | прошла, но был патч учителя или облачный фикс Claude — **никогда не проход ученика** |
| `FAIL` | проверка не прошла / diff пуст / не накладывается / нарушен scope |
| `TIMEOUT` | бюджет исчерпан |
| `BLOCKED` | Bossman отказал, задача заблокирована, утечка памяти в контрольный вариант, проверка видна ученику |

Числа в сводке раздельные: `student_unassisted_passes`, `student_coached_passes`,
`teacher_patches` — не складываются.

### Уровни вмешательства учителя (intervene)

| Уровень | Что | Влияние на исход |
|---|---|---|
| 0 OBSERVE | наблюдение без помощи | нет |
| 1 ATTENTION | вопрос/напоминание цели без подсказки | `STUDENT_COACHED_PASS` |
| 2 DIRECTION | направление: подсистема, файл, класс ошибки | `STUDENT_COACHED_PASS` |
| 3 DIAGNOSTIC | какой ввод/тест воспроизводит | `STUDENT_COACHED_PASS` |
| 4 SOLUTION_OUTLINE | решение словами, без патча | `STUDENT_COACHED_PASS` |
| 5 TEACHER_PATCH | патч учителя | `TEACHER_PATCH` — **никогда не успех ученика** |

Записывается: ученик, задача, время, уровень, подсказка (`--hint`, обязательна для 1–5),
ответ ученика (`--student-response`) и **проверенный эффект** — по скрытой проверке, а не по словам
(`VERIFIED_PASS_AFTER_INTERVENTION`, `NO_VERIFIED_EFFECT`, `TEACHER_PATCH_NOT_STUDENT_SUCCESS`, `PENDING`).
Запись сначала идёт в `interventions.jsonl` (только дописывание), и идущий `compare` вливает её при
каждом сохранении. Раньше подсказка из второго терминала затиралась, и проход с подсказкой
выглядел как «без помощи» — это исправлено и закрыто тестом.

### Наблюдатели на каждом варианте (исход не меняют)

- **CLAUDE_AUDITOR** — детерминированные детекторы по записи сайдкара и diff: зацикливание и
  отсутствие прогресса, нерелевантные правки, фиктивный reproducer (тест зелёный до правки кода;
  плюс тесты ученика перезапускаются на чистом базовом коммите и там обязаны упасть), тест без
  проверок, ослабленные проверки (удалён assert, skip/xfail, изменено ожидание), mock вместо PASS,
  выход за scope, потеря цели, порча проекта, разгон ресурсов. Нет срабатываний — `OBSERVE`.
- **UX_OBSERVER** — вызовы, неверные инструменты, ошибки схемы, промахи поиска и контекста,
  попадания памяти и полезные попадания, повторы, устаревшие наблюдения, потеря фокуса, лишние файлы,
  вмешательства, время до первой правки / гипотезы / reproducer / проверенного патча / итога.
  Нет записи (например, `TIMEOUT`) — `INSUFFICIENT_EVIDENCE` и пустые значения, а не нули.
- **Честность сравнения** — модель, квант, endpoint рантайма, исполнитель, базовый SHA, пути,
  полномочия, задача, бюджет времени и строки учеников (инструменты/шаги/токены/модель) обязаны
  совпасть; любое расхождение — `INVALID_COMPARISON` (код 7). Расхождение строк — отказ до запуска;
  расхождение во время прогона — все варианты всё равно доводятся до исхода, но `lesson` из такого
  сравнения не учится. `--context-tokens 32768` записывает размер контекста рантайма.
- **Главная метрика** — проверенная полезная работа в час настенного времени
  (`metrics.main.verified_useful_work_per_hour`), а не токены в секунду.

### lesson

Берёт лучший проверенный проход (сначала `STUDENT_UNASSISTED_PASS`, потом `STUDENT_COACHED_PASS`;
`TEACHER_PATCH` — только с `--allow-teacher-patch`, и тогда рецепт помечен как патч учителя).
Нет прохода — код 6 `NO_VERIFIED_PASS`, ничего не пишется. Рецепт = симптом → причина →
диагностика → действие → обязательная проверка → когда применять → контрпример + исполнимые
шаги только из разрешённых инструментов (`read_file`, `search`, `list_dir`, `edit_file`,
`write_file`, `run_tests`; никакой строки для shell). Тексты — из `lesson_template` кейса
(или `--notes файл.json`), шаги — из проверенного diff. Запись идёт через продукт:
`POST /api/coding-recipes`; Bossman примет рецепт только с доказательством
(`expected == actual` скрытой проверки) от независимого проверяющего и хранит его как урок
в существующем `LessonBook` (`<data dir>\learning`), откуда его читает и обычный recall задач.

### transfer

Требует **полного перезапуска** Bossman после `lesson`: `started_at` из `/api/identity` должен
отличаться, иначе код 4 `RESTART_NOT_DETECTED` (обход `--skip-restart-check` виден в отчёте).
Новый похожий кейс без коучинга, два плеча на агенте MEMORY: `CONTROL` (память выключена) и
`MEMORY` (включена). Отчёт отдельно:

- `memory_hit` — Bossman нашёл рецепт (`expected_recipe_hit`, плюс пробный
  `POST /api/coding-recipes/match`); **найденный рецепт ≠ решённая задача**;
- `solve` — исход скрытой проверки каждого плеча;
- `verdict`: `MEASURED_GAIN` (решила только MEMORY), `NO_MEASURED_GAIN` (исходы равны),
  `MEASURED_REGRESSION`, `INSUFFICIENT_EVIDENCE` (нет контроля или BLOCKED). Это n=1 —
  наблюдение, не доля.

## Кейс (JSON, схема `bossman.self-improve-case/1`)

```
{"schema": "bossman.self-improve-case/1", "case_id": "...", "project_id": "lab-synthetic",
 "source_repo": "D:/repos/x" | {"synthetic": "invoicekit"}, "baseline_commit": "HEAD|<sha>",
 "instruction": "...", "allowed_paths": [...], "protected_paths": [...],
 "hidden_verifier": {"command": ["{python}", "-m", "unittest", "discover", "-s", "{hidden}", ...],
                     "files": {"hidden_test_x.py": "..."} | "dir": "папка вне репозитория",
                     "timeout_seconds": 300},
 "model": null, "budget_minutes": 40, "lesson_template": {...}}
```

Команда — список аргументов, не строка shell; подстановки `{python}`, `{hidden}`, `{repo}`.
Встроенные кейсы (`sample`, `sample-transfer`; копии в `tools/self_improve_cases/`) строят
маленькие синтетические репозитории `invoicekit` / `stockkit` с настоящим посеянным дефектом:
разбор числа падает на десятичной запятой и неразрывных пробелах. На базовом коммите скрытые
тесты красные — проверено тестом. Кейсы нужны, чтобы доказать путь на детерминированной
тестовой модели до запуска настоящих моделей.

## Состояние, STOP, коды выхода

- `--state` (по умолчанию `<out>\lab-state.json`) переписывается атомарно после каждого шага.
  Повторный запуск той же команды продолжает: готовые варианты пропускаются, идущая задача
  опрашивается дальше с прежним сроком. `--fresh` — начать фазу заново.
- `--stop-file` (по умолчанию `<out>\STOP`): проверяется между опросами; при нём — сохранить
  состояние и выйти с кодом 5.
- Отчёты: `<out>\{explore,compare,lesson,transfer}-report.{json,md}`, `lesson-recipe.json`,
  журнал вмешательств `interventions.jsonl`, на вариант — `work\<run>\<вариант>\task-record.json`
  и `student.diff`.

| Код | Значение |
|---|---|
| 0 | фаза завершена (исходы записаны, какими бы они ни были) |
| 1 | внутренняя ошибка |
| 2 | ошибка использования / неверный кейс / проверка была бы видна ученику |
| 3 | API Bossman недоступен или токен отвергнут |
| 4 | BLOCKED: coding-задачи не готовы, перезапуск не обнаружен, нет агентов лаборатории |
| 5 | остановлено STOP-файлом (состояние сохранено) |
| 6 | NO_VERIFIED_PASS (урок не из чего писать) |
| 7 | INVALID_COMPARISON (варианты не делили модель/квант/рантайм/базу/права/бюджеты/задачу) |

Урок (`lesson`) теперь хранит в том же `LessonBook` ещё: наблюдаемую последовательность вызовов
(инструмент, путь, вердикт — без скрытых рассуждений), ссылки на код/тесты/evidence, модель, квант,
рантайм, уровень помощи учителя и неудачные подходы других вариантов (по скрытой проверке).
`transfer` дополнительно сообщает `lesson_applied` (найден + обязательная проверка рецепта зелёная +
скрытая проверка прошла) и изменения времени/помощи/решения при n=1 — это наблюдение, не выигрыш;
вердикт остаётся по решению задачи, веса не меняются.

**Windows-архив:** скрытая проверка и перезапуск тестов ученика на базе стартуют через
`-B -s -X utf8 -c <bootstrap>`, который сам кладёт репозиторий в `sys.path`: встроенный Python
архива игнорирует `PYTHONPATH` и не видит текущую папку. Проверено тестом с `python -I`.

## Что проверено, а что нет

Проверено тестами (`tests/test_self_improve_lab.py` на заглушке API, настоящая скрытая
проверка; `command-center/tests/test_coding_recipes.py`, `test_lab_agents.py` на настоящем
сервисе): чистая копия на вариант, бюджет → `TIMEOUT` и следующий вариант, независимость
проверки, классификация исходов, `NO_MEASURED_GAIN`, resume, STOP, recall рецепта через
движок задач после полного перезапуска сервиса.

**Не проверено здесь:** прогон на настоящем сайдкаре и настоящих моделях на машине владельца —
это делает owner-run. До него любые числа лаборатории — `NOT_RUN`.
