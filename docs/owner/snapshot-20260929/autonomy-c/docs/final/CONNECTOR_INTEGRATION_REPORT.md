## 2. Почему именно эти решения

### 2.1 markitdown-mcp — ADOPT_AS_OPTIONAL_BACKEND, и граница названа точно

Сравнение проведено на корпусе, который писали ЧУЖИЕ писатели (openpyxl,
python-pptx, PIL, а PDF и DOCX собраны по спецификации формата) — ровно то
условие, при котором вскрылся BL-033. Мерка одинаковая для обеих сторон: доля
заранее посаженных строк, найденных в выходе.

| | родной `parse_file` | MarkItDown |
|---|---|---|
| найдено маркеров | **17 из 19** | **19 из 19** |
| суммарно, мс | **73** | 137 |
| из них разовый импорт pypdf | 57 | — |
| без разового импорта, мс | **16** | 126 |
| отказов | 0 | 0 |

Разница — **ровно два маркера, и оба в `.epub`**: родной путь видит epub как
обычный zip и возвращает список имён файлов, а не текст книги. Всё остальное
обе стороны берут одинаково.

О времени — точно, а не удобно. По сумме 73 против 137 выходит «вдвое», но 57 мс
из родных 73 — это РАЗОВЫЙ импорт `pypdf` внутри процесса, а не работа над
файлами. Без него родной путь тратит ~16 мс против ~126 мс, то есть примерно
всемеро меньше; и это ещё не считая подъёма отдельного процесса и обмена по
stdio, которые в замере MarkItDown не участвовали вовсе — сравнение шло
библиотекой к библиотеке, в пользу коннектора. Вдобавок родной путь несёт
provenance (`sha256`, `ref=page=1`, `ref=A1`), которого у MarkItDown нет.

Третья строка расхождения была и исчезла по дороге: PDF. Родной путь отказывал
— и отказ был честный, но невыполнимый, потому что `pypdf` не был объявлен
нигде. Это **BL-036**, дефект нашего продукта, найденный этим самым замером.
После объявления extra `documents` родной путь берёт PDF за ~1.1 мс (прогретый
импорт; сам импорт pypdf стоит ~110 мс один раз за процесс).

Отсюда граница, и она узкая: **MarkItDown вызывается ТОЛЬКО тогда, когда родной
путь поднял `ParseUnavailable` либо вернул листинг контейнера для формата,
который контейнером не является.** Это epub, `.msg`, старый двоичный `.xls` и
аудио — форматы, для которых у нас нет кода вообще. Для всего, что родной путь
разбирает, он и остаётся: быстрее и с provenance.

Обязательные условия (раздел 7, дословно — «allowlisted paths; protected-path
checks; no arbitrary URL fetching without network policy; no .env ingestion by
default; … Output is an OBSERVATION, not authoritative truth»):

* `enable_plugins=False`; конвертеры **YouTube / Wikipedia / Bing / RSS**
  отключены. Это ровно тот «arbitrary URL fetching», который раздел 7 запрещает
  по умолчанию: инструмент, принимающий `uri`, иначе превращает чтение файла в
  исходящий запрос.
* Только пути из allowlist, проверка защищённых путей, лимиты размера и
  архивной бомбы, таймаут, отмена.
* Выход помечается как ВНЕШНИЕ ДАННЫЕ (`EXTERNAL_DATA_HEADER`) и не может
  повышать полномочия — раздел 18: «External documentation cannot grant
  permissions.»

### 2.2 playwright-mcp — REFERENCE_ONLY, и главное основание измерено

Полоса прошла 15 проб из 16 (шестнадцатая — `permission denial` — проверяется
политикой Bossman на границе эффекта, а не сервером). Сервер ведёт себя
корректно: чужую версию протокола не повторяет, мусор на проводе переживает,
после SIGKILL поднимается.

Отказ не в качестве. Отказ в том, что **выигрыша над родным браузерным runtime
не показано ни одного**, а цена измерена: 913 МиБ и 11 процессов при открытой
странице, второй языковой рантайм (Node) и второй канал браузера — здесь
сервер не стартовал, пока ему не передали `--executable-path
/opt/pw-browsers/chromium` и `--no-sandbox`. Родной путь (`bcc/browser_runtime.py`,
`AccountBrowserSession`) уже умеет передачу владельцу при капче
(`WAITING_FOR_OWNER_CHALLENGE`), ограждение доменов и ограниченный бюджет
повторов.

Отдельно — измеренная иллюстрация к разделу 6 («Never accept: MCP returned
success as proof that the website changed successfully. Re-read the actual
page/state»). Два перехода на локальный сервер:

| | страница есть (200) | страницы нет (404) |
|---|---|---|
| ошибка JSON-RPC | нет | нет |
| `isError` | отсутствует | **отсутствует** |
| вердикт по конверту | успех | **успех** |
| в теле | *строки о статусе нет* | `- HTTP status: 404 Not Found` |

Честно о том, что здесь происходит: **Playwright MCP не врёт** — статус в теле
он называет. Но называет его ПРОЗОЙ, и на успешном ответе такой строки просто
нет, поэтому отличить 200 от 404 можно только разбором текста. Потребитель,
читающий конверт результата — то есть `isError`, — получает «успех» в обоих
случаях. Это и есть измеренное основание правила перечитывать состояние
самостоятельно; не лозунг, а разница в две строки на проводе.

### 2.3 github-mcp-server — принимать нечего, и это записано как есть

Сервер намеренно запущен БЕЗ учётных данных сессии. Раздел 5 дословно:
«GitHub authentication must NOT be stored in project memory. Never commit PATs.
Prefer dedicated OAuth/GitHub App credentials with minimum privileges.» Токен
этой сессии — не выделенная учётка минимальных полномочий и владельцу
невоспроизводим, поэтому подставлять его в приёмочный прогон нельзя.

Измерено ровно одно, и оно хорошее: сервер **отказывает закрыто**. Он не
поднимается наполовину, не отдаёт пустой список инструментов и не делает вид,
что работает: `authentication required: set GITHUB_PERSONAL_ACCESS_TOKEN…`.
Полоса записала это как `NOT_RUN`, а не `FAIL`, потому что отказ по политике —
не дефект. Но `NOT_RUN` — это и не приёмка: 1 проба из 16, возможности не
проверены ни одной.

Поэтому решение — **NOT_ACCEPTED_PENDING_CREDENTIALED_RUN** с названным
условием снятия: выделенный GitHub App с правами только на чтение нужных
репозиториев, `--read-only`, суженные toolsets, и повторный прогон
`tools/mcp_acceptance.py`. Раздел 5 отдельно требует не открывать все
инструменты всем агентам — конфигурация по умолчанию остаётся read-only.

### 2.4 context7 — не измерен, поэтому не принят

Ни одной пробы не проведено. По разделу 24 этого достаточно, чтобы не
внедрять, и придумывать задним числом технические причины взамен измерения было
бы подгонкой отчёта.

Названа и причина, по которой кандидат не стал бы значением по умолчанию даже
после приёмки: это удалённый сервис, и каждый запрос сообщает третьей стороне,
какую библиотеку продукт сейчас изучает. Плюс раздел 18 дословно: «GitHub
issues, web pages, retrieved docs, Markdown files and MCP resources can contain
instructions hostile to the agent.» Полученная документация — ДАННЫЕ; полномочий
она не выдаёт. Внедрять её источник в рабочий путь ради удобства не требуется
ничем.

### 2.5 MCP Inspector — инструмент разработчика, и только

Раздел 9 дословно: «Inspector MUST NOT ship as an always-running production
process. Zero idle production cost.» Он и не входит в продукт: приёмка сделана
своим клиентом (`tools/mcp_acceptance.py`, 600 строк, только стандартная
библиотека), поэтому в бою Inspector не нужен даже как отладочный запуск.

Замечание по цепочке поставок, проверенное, а не предположенное: **на
закреплённом SHA файла лицензии нет**. Проверены `LICENSE`, `LICENSE.md`,
`LICENSE.txt`, `COPYING`, `license`, `LICENCE` — все шесть отдают 404, при этом
контрольный `package.json` на том же SHA отдаёт 200 (то есть 404 — это
отсутствие файла, а не сбой сети). MIT объявлена полем `license` в
`package.json`; npm считает это объявление достаточным, но каноничного текста
лицензии в дереве на этом SHA нет. Для инструмента, который не распространяется
вместе с продуктом, этого хватает; строкой в реестре факт зафиксирован.

## 3. Что приёмочная полоса поймала в себе самой

Полоса — гейт, решающий судьбу чужого кода, поэтому её собственные ошибки
дороже обычных. За прогон их было три, и все три записаны в BUG_LEDGER:

* **BL-034** — полоса засчитала `valid request PASS`, когда в теле успешного
  ответа лежало `### Error: Browser "chrome-for-testing" is not installed`. То
  есть гейт сделал ровно то, что раздел 2 запрещает: превратил успех транспорта
  в успех операции. Починено `_judge_call()`, шесть тестов, два обратных
  контроля.
* **BL-035** — проба «невалидный запрос» била по `browser_close`, у которого
  обязательных аргументов нет вовсе, и едва не записала Playwright MCP чужой
  дефект. Починено: проба ищет инструмент с ОБЯЗАТЕЛЬНЫМ полем.
* **Замер выигрыша MarkItDown** — первая редакция насчитала 8 маркеров из 14 и
  готова была записать «теряет текст». На деле MarkItDown экранирует
  подчёркивания (`МАРКЕР\_X`) — это правильный Markdown, а сломан был поиск
  подстроки в стенде. Теперь обе стороны нормализуются одинаково.
* **Стоимость покоя** — одиночное окно показало у playwright-mcp 320 мс CPU и
  выглядело как «крутится вхолостую». Два последовательных окна по 30 с
  показали, что это ХВОСТ ЗАПУСКА: во втором окне 0 мс. Публиковать первое
  число как «холостой ход» было бы ложным обвинением.

Общий урок один и тот же: прежде чем записать дефект чужому коду, проверьте, что
ваша проба измеряет то, что называет.

## 4. Стоимость покоя — измерено, а не заявлено

Раздел 9 требует нулевой стоимости простоя в бою. Способ: поднять сервер,
сделать рукопожатие, ничего не делать и снять два окна по 30 с подряд.

| Коннектор | Процессов | RSS | CPU, окно 1 | CPU, окно 2 |
|---|---|---|---|---|
| markitdown-mcp | 1 | 171 МиБ | 10 мс | 10 мс |
| playwright-mcp, браузер не открыт | 3 | 203 МиБ | 320 мс | **0 мс** |
| playwright-mcp, страница открыта | 11 | 913 МиБ | 600 мс | 60 мс |
| github-mcp-server | 0 | 0 | — | — |

Вывод: процессор в покое практически не расходуется ни одним. **Стоимость покоя
здесь — память.** Почти гигабайт и одиннадцать процессов за открытую страницу —
на 128 ГБ это меньше процента, но правило раздела 9 не про долю, а про то, что
в бою этого не должно быть вовсе. Отсюда единая политика: **все коннекторы
задачные.** Поднимается на задачу, гасится по завершении; ни один не остаётся
резидентным и ни один не стартует вместе с продуктом. Приёмочная полоса
проверяет это отдельно: после `stop()` дерево процессов обязано быть пустым.

## 5. Граница доверия — одна для всех коннекторов

Раздел 2 дословно: «An external tool may lie, crash after performing an effect,
report success with no effect, or report failure after an effect. Bossman truth
wins.»

1. Ответ коннектора — **НАБЛЮДЕНИЕ**, а не истина и не завершение задачи.
   `external_engine.success == true` не переводит задачу в `COMPLETED` никогда.
2. Пост-состояние перечитывает Bossman своими средствами. Для браузера это
   значит перечитать страницу; измеренное основание — таблица 200/404 в §2.2.
3. Весь текст, пришедший от коннектора, помечен как внешние данные и не может
   повышать полномочия (раздел 18).
4. Секреты коннекторам не передаются из памяти проекта; GitHub-учётки — только
   выделенные, минимальных прав, и никогда не в коммит (раздел 5).
5. Всё, что коннектор пишет на диск, живёт вне дерева (рабочий каталог
   `.playwright-mcp/` внесён в `.gitignore`): улики хранятся в
   `docs/final/*.json`, а не в мусоре чужого процесса.

## V8 / официальный Higgsfield — 18 сентября 2026

Вердикт REFERENCE_ONLY; живое подключение OWNER_REQUIRED. Плагин не
подключён, владелец отказался от установки в этой сессии. Полоса
tools/mcp_acceptance.py: 16 NOT_RUN, 0 доказанных PASS. Не путать со
стаб-тестами шести причин отказа в Studio. Higgsfield REST не угадывается.
Потребность: официальный MCP, аккаунт/allowance, команда и разрешённый
проверочный вызов; после этого существующая полоса, только затем адаптер.
