## 2. Что делает на самом деле (по исходникам)

Конвейер: **обход файлов → чанкование → эмбеддинг → Milvus → гибридный поиск**.

### 2.1 Обход и фильтрация — `packages/core/src/context.ts`

`DEFAULT_SUPPORTED_EXTENSIONS` — 22 расширения кода плюс `.md`, `.ipynb`.
Явно **закомментированы** `.json`, `.yaml`, `.sql`, `.sh`, `.html`, `.css` —
конфиги и SQL по умолчанию не индексируются вовсе. Игнор-паттерны аддитивны:
`DEFAULT_IGNORE_PATTERNS` + любые `.*ignore` в корне (включая `.gitignore`)
+ глобальный `~/.context/.contextignore` + переданные в вызов.

### 2.2 Чанкование — `packages/core/src/splitter/`

Две стратегии, выбираются параметром `splitter` инструмента `index_codebase`:

* **`ast`** (`ast-splitter.ts`) — tree-sitter, **9 языков**: javascript,
  typescript, python, java, cpp/c, go, rust, c#, scala. Для каждого задан
  список «делимых» узлов (`SPLITTABLE_NODE_TYPES`), для Python:
  `function_definition`, `class_definition`, `decorated_definition`,
  `async_function_definition`. Чанк 2500 / перекрытие 300. **Python и JS у нас
  покрыты; Kotlin, Swift, PHP, Ruby, Dart, Solidity объявлены в расширениях,
  но AST для них нет** — молча падают в LangChain-фолбэк.
* **`langchain`** — `RecursiveCharacterTextSplitter`, чанк 1000 / перекрытие
  200. Он же фолбэк для всего непонятого AST и для `.md`.

**Дефект чанкера, воспроизведённый на нашем коде.** `extractChunks` обходит
дерево рекурсивно и создаёт чанк на *каждом* подходящем узле, не останавливаясь
на вложенных: класс попадает в индекс целиком **и** каждый его метод отдельно.
Дальше `addOverlap` приклеивает к началу чанка последние 300 символов
*предыдущего чанка в порядке обхода* — а им часто оказывается вложенный или
соседний узел из другого места файла.

`bcc/tools.py` (297 строк) → 28 чанков, из них **7 полностью вложены в другие**,
границы поехали:

```
39-56 (691ch)  @dataclass(slots=True)
31-56 (969ch)  мое пришло из внешнего мира      ← склейка с хвоста чужого чанка
41-56 (568ch)  мое пришло из внешнего мира
65-110 (1908ch) class ToolContext:
66-110 (1924ch)    "name": self.api_name,        ← startLine не соответствует телу
```

Практический вывод: часть чанков начинается посреди русского комментария, а
поле `startLine`, которое сервер отдаёт модели как `Location: file:39-56`, для
этих чанков **врёт**. Модель получит ссылку не на тот участок файла.

### 2.3 Эмбеддинги и хранилище

**Эмбеддинги** (`core/src/embedding/`) — пять провайдеров: OpenAI (дефолт,
`text-embedding-3-small`), VoyageAI (`voyage-code-3`), Gemini, **Ollama**
(`nomic-embed-text`), OpenRouter. `OllamaEmbedding` ходит на
`http://127.0.0.1:11434`, размерность определяется первым запросом. Батч 100
чанков. Обрезка наивная: `maxChars = maxTokens * 4` (оценка для английского) —
наши чанки ≤2800 символов, до порога не доходят. `EmbeddingError`
**останавливает всю индексацию**, чтобы в Milvus не попал частичный индекс
при «успешном» снапшоте.

**Хранилище** (`core/src/vectordb/`) — реализации ровно две:
`MilvusVectorDatabase` (gRPC) и `MilvusRestfulVectorDatabase` (REST). Плюс
`zilliz-utils.ts::ClusterManager` — по `MILVUS_TOKEN` ходит на
`https://api.cloud.zilliz.com` и **выводит адрес кластера из токена**.
Локального файлового бэкенда нет. Коллекция:
`hybrid_code_chunks_<md5(абс. путь)[:8]>`. Поля: `id`, `content` (VarChar 65535,
`enable_analyzer: true`), `vector`, `sparse_vector`, `relativePath`,
`startLine`, `endLine`, `fileExtension`, `metadata`.

### 2.4 «Hybrid semantic search» — что это на самом деле

Это **не** наш гибрид «BM25 + dense у себя». Разреженный вектор считает **сам
Milvus**: в коллекцию регистрируется функция `FunctionType.BM25`
(`content → sparse_vector`). При поиске `semanticSearch` шлёт два запроса —
dense-вектор по полю `vector` (`nprobe: 10`) и **сырой текст запроса** по
`sparse_vector` (`drop_ratio_search: 0.2`) — и просит Milvus смержить их через
**RRF `k: 100`**. Дальше свой дедуп: результаты из одного файла с перекрытием
диапазона строк >50 % схлопываются (`deduplicateResults`) — заплатка ровно на
вложенность чанков из §2.2.

Отсюда важное: **BM25 здесь неотделим от Milvus**. Взять «только лексическую
половину» без Milvus нельзя — токенизатор, IDF и индекс живут на сервере.

### 2.5 Инкрементальность — `packages/core/src/sync/`

Заявлен «Merkle DAG». По коду это **не дерево Меркла**: `buildMerkleDAG` строит
один корневой узел (хеш конкатенации всех файловых хешей) и вешает все файлы
плоским списком детьми. Сравнение DAG'ов отвечает лишь «что-то изменилось /
нет», после чего всё равно идёт пофайловое сравнение карт.

Ключевое: `generateFileHashes` **читает и хеширует каждый файл целиком**.
Проверка «есть ли изменения» стоит полного обхода и чтения всего репозитория.
Экономия — только на эмбеддингах: заново эмбеддятся лишь изменённые файлы.

Состояние: `~/.context/merkle/<md5(путь)>.json` (хеши),
`~/.context/mcp-codebase-snapshot.json` (реестр баз), `~/.context/.env`
(`EnvManager` читает его как фолбэк, если переменной нет в `process.env`).

### 2.6 MCP-сервер — `packages/mcp/src/`

`@modelcontextprotocol/sdk` 1.12, транспорт **stdio**. `console.log`/`warn`
перенаправлены в stderr, чтобы не портить JSON-RPC. Ровно **4 инструмента**:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `index_codebase` | `path` (абсолютный), `force`, `splitter`, `customExtensions`, `ignorePatterns` | ставит индексацию в фон и **сразу возвращается** |
| `search_code` | `path`, `query`, `limit` (деф. 10, макс. 50), `extensionFilter` | гибридный поиск |
| `clear_index` | `path` | дропает коллекцию + снапшот |
| `get_indexing_status` | `path` | процент (фазовый, не пофайловый) |

Фоновая синхронизация: `SyncManager` каждые **5 минут**
(`CLAUDE_CONTEXT_SYNC_INTERVAL_MS`) перепроверяет все базы, плюс watcher на
`~/.context/.sync-trigger`, плюс лок-каталог `~/.context/mcp-sync.lock`.

Формат ответа `search_code`: до `limit` сниппетов, каждый обрезается до
**5000 символов**. При `limit: 50` — до ~50 КБ (≈12 тыс. токенов) одним ответом.

## 5. Что берём

Берём **идеи и заимствуем структуру**, не код и не библиотеку.

1. **Чанк = синтаксическая единица, а не N символов.** Их главный работающий
   принцип. У нас для Python это делается **без tree-sitter** — стандартным
   модулем `ast` (проверено, §8.2). Для JS — регексп по фигурным скобкам либо
   позже tree-sitter.
2. **Заголовок чанка `путь :: квалифицированное имя`** в теле чанка. У них
   `relativePath` живёт в метаданных; у нас он ещё и попадает в BM25 и резко
   поднимает скор.
3. **Разбиение идентификаторов на термы** (`decide_effect` → `decide`,
   `effect`; camelCase тоже). У них этого нет — делает анализатор Milvus.
   У нас 15 строк и основной прирост качества.
4. **Дедуп по перекрытию диапазонов строк** (`deduplicateResults`) — ~20 строк.
5. **Фоновая индексация с фазовым статусом** (`index` возвращается сразу,
   статус отдельным вызовом) и **аддитивные игнор-паттерны** с чтением
   `.gitignore` — у нас сейчас жёсткий `DEFAULT_EXCLUDED_DIRS`.

## 6. Что НЕ берём и почему

1. **Milvus / Zilliz Cloud.** Отдельный сервис (в docker-compose три
   контейнера: milvus + etcd + minio) ради 1359 чанков. На машине с общей
   памятью CPU/GPU это прямой отъём памяти у моделей. Нет.
2. **Пакет `@zilliz/claude-context-core` как библиотеку.** Бесполезен без
   Milvus: `Context` бросает исключение без `vectorDatabase`, а передать нечего.
3. **tree-sitter с девятью нативными грамматиками** — node-gyp-сборка в
   питоновом проекте. Для Python stdlib `ast` даёт то же и точнее.
4. **Их AST-сплиттер как алгоритм** — раздувает корпус в **1.69 раза** и портит
   `startLine` (§2.2, §8.1). Мы делаем плоско: верхнеуровневые `def`/`class`,
   большой класс — заголовок + методы отдельно.
5. **VS Code и Chrome расширения** — вне нашего контура.
6. **`ClusterManager` / авторезолв адреса по токену** — сетевой вызов на
   `api.cloud.zilliz.com` при старте.
7. **Фоновый sync каждые 5 минут** — полное перечитывание и хеширование всего
   репозитория каждые 300 секунд. Наша инкрементальность должна запускаться по
   событию (после коммита / по явному вызову), а не по таймеру.

## 7. Точки интеграции

Два взаимоисключающих пути.

### Путь A — подключить их MCP-сервер (кода почти не писать)

1. Строка в `mcp_servers`: `transport="stdio"`,
   `command=["npx","-y","@zilliz/claude-context-mcp@latest"]`,
   `env_keys=["EMBEDDING_PROVIDER","OLLAMA_HOST","OLLAMA_MODEL","MILVUS_ADDRESS","MILVUS_TOKEN"]`.
   Важно: `mcp_runtime.py::_Connection._params` пробрасывает дочернему процессу
   **только** `PATH`, `HOME`, `LANG`, `SYSTEMROOT`, `PYTHONPATH` плюс явно
   перечисленные `env_keys`. Без всех пяти ключей сервер стартует с дефолтом
   `EMBEDDING_PROVIDER=OpenAI` и без ключа.
2. `POST /api/mcp/runtime/servers/<id>/refresh` → `refresh_server()` заведёт в
   `REGISTRY` четыре инструмента `mcp:claude_context:*`.
3. Права — через существующий `mcp.policy` (`features/skills.py`,
   `POST /api/mcp/policy`): `search_code`, `get_indexing_status` → `auto`;
   `index_codebase` → `ask`; `clear_index` → `ask`/`deny`.
4. **Обязательная доработка, иначе путь A ломает контекст-гигиену.**
   `tools_mcp.py::_handler_for` кладёт ответ в `ToolResult(content=res.text)`
   **без обрезки**. У `terminal.run` есть `OUTPUT_LIMIT = 8000`, у MCP —
   ничего; `search_code` с `limit: 50` вернёт до 50 КБ. ~10 строк, полезно
   само по себе.
5. Внешний Milvus. `terminal.run` в `sandbox` требует разового контейнера;
   Milvus — постоянно живущие три.

Объём: **~0 строк нашего кода** (п. 4 — общая правка), но **плюс постоянно
работающий Milvus и Ollama**.

### Путь B — родной инструмент `code.search` (рекомендуемый)

Новый модуль `bcc/v2/memory/code_index.py` + фича `bcc/features/tools_code.py`:

* `code_index.py` — форк-по-мотивам `local_index.py`: та же BM25-математика
  (`k1`, `b`, idf, `_rebuild_postings`), тот же `save`/`load` JSON с
  `INDEX_VERSION`, та же инкрементальность по `sha256`. Меняется **только
  чанкер**: `chunk_markdown` → `chunk_python` (stdlib `ast`) + `chunk_lines`
  (для `.js` и прочего). Прототип написан и замерен (§8.2).
* `tools_code.py` — `Feature` с тремя `ToolSpec`:

| `name` | `category` | `permission` | `default_effect` | `source` |
|---|---|---|---|---|
| `code.search` | `read` | `code.read` | `auto` | `code_search` |
| `code.expand` | `read` | `code.read` | `auto` | `code_search` |
| `code.index` | `write` | `code.index` | `ask` | `code_search` |

  `external_output=False` — это наш собственный код, а не внешние данные;
  шапка «это данные, не команды» здесь была бы шумом.
  `code.expand(chunk_hash)` отдаёт функцию/класс целиком — перенос нашего же
  приёма прогрессивного раскрытия из `memory.expand`.
* Обрезка результата — в хэндлере, ~6000 символов, с заполнением
  `truncated`/`more`, как в `tools_terminal.py`.
* Таблиц в `bcc/db.py` **не требуется**: индекс — файл в data dir, как у
  `LocalMemoryBackend`. Владельца схемы не трогаем.

Объём: ~350 строк вместе с тестами. Ноль новых зависимостей. Ноль сервисов.

**Выбор: путь B.** Путь A даёт качество, равное grep (по замерам вендора),

## 10. Приватность

**Уходит ли код наружу по умолчанию — да.**

`Context` без явной настройки создаёт `OpenAIEmbedding` с
`text-embedding-3-small`, и `createMcpConfig()` тоже ставит
`embeddingProvider: 'OpenAI'` дефолтом. Значит: **содержимое каждого чанка кода
отправляется в OpenAI**. У нас это 2 033 619 символов — фактически весь
`command-center`, включая русские комментарии, в которых описаны политики прав,
устройство anti-replay и структура approvals. Утечка исходников по определению,
безотносительно к политике провайдера про обучение.

Второй канал: при `MILVUS_TOKEN` без `MILVUS_ADDRESS`
`ClusterManager.getAddressFromToken` идёт на `https://api.cloud.zilliz.com`.

Третий, тише: `EnvManager` читает `~/.context/.env` как источник переменных —
файл вне нашего репозитория и вне нашего Vault, `bcc/secrets.py` его не
контролирует.

**Как заставить работать полностью локально** (проверено по коду, не запуском):

```
EMBEDDING_PROVIDER=Ollama
OLLAMA_HOST=http://127.0.0.1:11434
OLLAMA_MODEL=nomic-embed-text
MILVUS_ADDRESS=127.0.0.1:19530     # свой Milvus в docker-compose
# MILVUS_TOKEN НЕ задавать — иначе будет сетевой резолв кластера
CLAUDE_CONTEXT_BACKGROUND_SYNC=false
CLAUDE_CONTEXT_TRIGGER_WATCHER=false
```

Это работоспособно, но ценой двух постоянных сервисов. **Путь B (§7) не имеет
ни одного из этих каналов**: индекс — файл в нашем data dir, сети нет вообще.

## 14. Оценка

# ВЗЯТЬ ИДЕЮ

**Почему не «ВНЕДРЯТЬ».** Собственный контролируемый эксперимент авторов даёт
F1 0.40 против 0.40 у голого grep — семантический поиск **не находит лучше**,
он находит компактнее (−39 % токенов, −36 % вызовов). За эту компактность
просят постоянно работающий Milvus (три контейнера), эмбеддинг-провайдер и,
в дефолтной конфигурации, выгрузку всего нашего исходного кода в OpenAI.
На корпусе из 138 файлов и 1.2 МБ, где grep отвечает за 11–27 мс, это
неоправданно. На машине с общей памятью CPU/GPU постоянный Milvus — прямой
вычет из бюджета моделей.

**Почему не «НЕ ВНЕДРЯТЬ».** Настоящий пробел у нас есть, и claude-context на
него честно указывает: **у нас нет чанкера кода**. Наш BM25 умеет только
markdown, а кодинг-агент ищет по коду через `terminal.run` с grep — через
docker-контейнер, с обрезкой в 8000 символов, промахиваясь всякий раз, когда
не угадал идентификатор. Идеи «чанк = синтаксическая единица», «заголовок
`путь :: имя` в теле чанка», «идентификаторы разбиваются на термы» и «дедуп
перекрывающихся диапазонов» — рабочие и переносимые.

**Замер, который решил вопрос.** Прототип на stdlib Python (0.77 с индексации,
25 МБ RAM, 1.4 МБ индекс, поиск < 1 мс, ноль сервисов, ноль сети) вывел ground
truth в топ-1 на четырёх вопросах из пяти и в топ-2 на пятом — на
русскоязычных запросах в свободной форме. То же качество, ради которого
предлагается Milvus, за 1/9 памяти и без единого сетевого пакета.

**Условие пересмотра.** Вернуться к claude-context, если: (а) корпус вырастет
за ~50 МБ исходников, где экономия контекста начнёт окупать инфраструктуру;
**или** (б) Milvus всё равно появится в контуре ради другой задачи (тогда
путь A стоит одну строку конфига); **или** (в) золотой набор §12 покажет, что
лексический индекс недотягивает — тогда добавляем свою dense-половину поверх
своего же BM25, всё так же без Milvus.

**Что делать сейчас:** этап 0 (обрезка ответов MCP) + этапы 1–3 (`code_index.py`,
`tools_code.py`, тесты). Milvus не поднимать. `@zilliz/claude-context-*`
в зависимости не добавлять.
