**Главная находка, воспроизведённая исполнением.** В паке `redact()` чистил
только форму `rtsp://user:pass@host` — и это доказано обходится: при **пустом

API, двух упавших job'ах, SQLite и всех файлах состояния.

**Четыре дефекта пака, воспроизведённые исполнением:**

1. 42 байта мусора с именем `model.stl` давали `PASS` и отчёт «PASS» — **потому
   что файл существует**;
2. `validate_mesh` вычислял `watertight` и **игнорировал результат**: открытый
   одиночный треугольник возвращал `status: PASS`;
3. битый STL падал с необработанным `TypeError` вместо честного отказа;
4. сканер G-code пропускал `M104S300` (300 °C, выше предела 260) и `M0500` —
   без пробела или с нулевым паддингом поиск команды не срабатывал.

Теперь `printable` ставит **только** `decide_printability`, а отвергнутая
геометрия пишется как `model.rejected.stl` и никогда как `model.stl`.

**Физическая безопасность.** `execute_physical` требует **одновременно** трёх
вещей: не-симуляторный транспорт, переменную `AI3D_ALLOW_PHYSICAL_PRINT` и токен
подтверждения, **привязанный к sha256 конкретного артефакта**. Небезопасный
G-code отвергается раньше всех трёх. Передача на TF-карту печать не запускает.
Smoke-тест печати существует, постоянно пропускается и написан так, чтобы
**упасть, а не пройти**, если его снимут с пропуска без станка.

Ядро работает на одной стандартной библиотеке: тест переимпортирует его с
принудительно отсутствующими fastapi/pydantic/numpy/trimesh/manifold3d/cadquery.

**Перенесённый дефект.** Ошибка пака `both=p.center` (центрированный цилиндр
выходит вдвое выше) **не исправлена**: без `cadquery` проверить исправление
нечем, а править геометрию вслепую — гадание. Записана как D-6.

## 5. Безопасность браузера — этап 1 browser-use (Фаза 5)

Долг, названный в `docs/research/browser-use.md` §4.2 самым ценным незакрытым
пунктом V2.2. Зависимость browser-use **не добавлена** — взяты только приёмы.

| Дефект | Статус | Доказательство |
|---|---|---|
| Значение поля пароля уходило в снимок для модели | **DONE** | REAL TESTED на живом Chromium |
| `browser.login` принимал пароль обычным аргументом | **DONE** | REAL TESTED |
| Устаревшая ссылка могла попасть в другой элемент | **DONE** | REAL TESTED |
| `.first` молча выбирал одну из нескольких кнопок | **DONE** | REAL TESTED |

**Доказательство утечки, а не рассуждение о ней.** На той же странице, тем же
Chromium:

```
СТАРОЕ выражение отдавало модели : ['Pa55w0rd-KANAREYKA-7f3a91e2']
канарейка в старом выводе       : True
канарейка в новом снимке        : False
```

Что изменилось:

1. **Пароль.** У поля `type=password` отдаётся `secret: true` и
   `filled: true/false` — модель знает, что поле заполнено, но не знает чем.
   Вторая линия — `redact_secrets()`: всё, что рантайм подставлял в сессию,
   вычищается из любого видимого модели вывода, включая случай ввода пароля в
   поле `type=text`.
2. **`browser.login`.** Модель называет `credential_id`; пароль достаёт рантайм
   из зашифрованного хранилища и вводит через `fill_secret`. В `tool_calls.args`
   и в контексте модели пароля нет. Учётка может быть привязана к домену: на
   чужой странице подстановка не происходит — редирект не уводит пароль не туда.
   API учёток отдаёт только `has_password`.
3. **Устаревшая ссылка.** Каждый снимок увеличивает поколение и проставляет
   `data-bcc-ref` плюс отпечаток. Действие по `ref` проверяет поколение,
   наличие элемента и отпечаток; при несовпадении — отказ, и **ничего не
   нажимается**.

Покрытие: `tests/test_v22_browser_security.py` — 7 тестов, 5 на настоящем
Chromium. Существующие браузерные тесты не менялись и проходят.
