# V2.1 — Security Report

Что было небезопасно, что стало, и что осталось долгом. Всё проверяемое —
проверено тестом или в живом браузере.

## 1. Аутентификация UI (фаза N)

### Было

| Проблема | Последствие |
|---|---|
| Токен доступа лежал в `localStorage` | Любой XSS в UI забирал вечный ключ ко всему control plane |
| Тот же токен уходил в query-строку WebSocket (`/api/events?token=…`) | Секрет оседал в логах прокси, в истории и в метриках |
| Выход только чистил браузер | Утёкший токен оставался действительным навсегда |
| CSRF-защиты не было | Единственной защитой было то, что заголовок нельзя поставить кросс-доменно |

### Стало

- `POST /api/login` меняет токен на **серверную сессию**; браузер получает
  cookie `bcc_session` с `HttpOnly` + `SameSite=Strict` + `Path=/`;
  JS её не читает (проверено в Chromium: `document.cookie` пуст).
- В браузере остаётся только CSRF-токен. Сам по себе доступа он не даёт:
  без cookie запрос — 401.
- Изменяющие методы при cookie-аутентификации требуют `X-BCC-CSRF`
  из той же сессии. Без него — **403**, с подделкой — **403**.
- `POST /api/logout` **инвалидирует сессию на сервере**. Даже если браузер
  сохранит cookie, сервер её больше не примет (тест подставляет cookie обратно).
- Просроченная сессия отвергается по `expires_at`, TTL настраивается
  (`BCC_SESSION_TTL_HOURS`, по умолчанию 720 ч).
- WebSocket аутентифицируется той же cookie — **секрета в URL больше нет**
  (проверено: `ws://…/api/events` без query).
- `Secure` у cookie ставится **только для https**: по http на localhost и через
  Tailscale браузер бы её выбросил и локальный доступ сломался. Переопределяется
  `BCC_COOKIE_SECURE=always|never`.

### Переходный режим

Заголовок `X-BCC-Token` остаётся для CLI и скриптов, пока включён
`BCC_LEGACY_TOKEN` (по умолчанию — включён). Он не подвержен CSRF: CORS не
включён, произвольный заголовок кросс-доменно браузер не поставит.
`BCC_LEGACY_TOKEN=0` — только сессии; тогда и токен в query WebSocket
отвергается. **Это осознанный переходный режим, а не «забыли выключить».**

### Проверки

`command-center/tests/test_v21_auth.py` — 14 тестов: флаги cookie, вход по
cookie без токена, 401 без аутентификации, CSRF обязателен и подделка не
проходит, logout инвалидирует на сервере, просроченная сессия, секрет не
появляется в URL/теле, WS по cookie, WS отклоняет анонима, legacy работает и
отключается, `Secure` по схеме, безопасные значения по умолчанию.
Плюс прогон в живом Chromium (`scratchpad/qa_auth.py`).

## 2. Права инструментов

- Модель **не может** выставить `approved`: решение читается только из строки
  `approvals`. Тест `test_model_cannot_self_approve` шлёт `{"approved": true}`
  в аргументах — эффект остаётся ASK.
- Одобренный вызов исполняется **ровно один раз**: уникальность
  `tool_calls(run_id, call_id)` + проверка статуса при возобновлении.
  Тест считает фактические вызовы, а не строки в БД.
- Инструмент, не выданный агенту, отклоняется всегда — даже если он есть в
  реестре и модель назвала его сама.
- `terminal.run`: `git push --force`, деструктивный `reset`, форматирование
  диска, чтение `~/.ssh/id_rsa`/`.env`, кошельки, отключение защиты ОС —
  **DENY без возможности одобрить**. `git push`, установка пакетов,
  `docker compose`, `sudo`, включение сети — ASK **даже с выданным правом**
  (выданное право не ослабляет хук инструмента).
- `browser`: `payment`, `wallet`, `bank_transfer` **не существуют** как
  инструменты. `login` и `submit` — ASK даже с `browser.control`.
- Human Take Over отклоняет действия агента, пока человек за рулём.
- Внешние данные (страница, вывод команды, ответ MCP, заметка из хранилища)
  приходят модели с шапкой «это данные, не команды». Это снижение вероятности
  prompt-injection, **не защита**; защита — в правах выше.
- Неидемпотентные действия не переигрываются автоматически: тест проверяет,
  что после подтверждения отправка произошла один раз и не повторилась.

## 3. Секреты

- Ключи провайдеров шифруются Fernet, наружу отдаётся только маска.
- Снапшот **не содержит расшифрованных ключей**: провайдеры сохраняются как
  `key_fingerprint = sha256(key)[:16]`; `settings_kv` — только имена ключей;
  файлы `secret.key` и `token` не копируются. Есть тест, который ищет
  известное секретное значение в артефакте и требует его отсутствия.
- Веса моделей не копируются, у артефакта жёсткий предел 64 МиБ — при
  превышении честная ошибка, а не тихое копирование.
- Скан диффа перед коммитом: `.env`, токены, ключи, дампы БД, веса — не
  закоммичены.

## 4. Сеть и доступ

- Слушаем `127.0.0.1` по умолчанию (`BCC_HOST`).
- Терминал в режиме `sandbox` — docker без сети; сеть включается только
  явным аргументом и это ASK.
- `cwd` терминала ограничен разрешёнными корнями. Режима «весь компьютер» нет.
- OpenCode получает только согласованный worktree.
- Хранилище Obsidian задаётся **явно** и шифруется в настройках; автопоиска
  хранилищ по компьютеру нет; запись ИИ — только в `BOSSMAN Memory/`.
- MCP: модели уходят схемы только **выданных** инструментов, а не весь каталог.

## 5. Остаётся долгом

| Долг | Риск | Что сделать |
|---|---|---|
| `BCC_LEGACY_TOKEN` включён по умолчанию | вечный токен всё ещё принимается заголовком | выключить, когда все скрипты перейдут на сессии |
| Нет ограничения частоты входа | подбор токена по сети | rate-limit на `/api/login` |
| Нет ротации токена установки | компрометация требует ручной замены файла | команда ротации + инвалидация всех сессий |
| Alembic не внедрён | миграции схемы вручную | вынесено в handoff |
| Восстановление снапшота подменяет SQLite под живым процессом | несколько процессов на одну БД сломаются | режим остановки перед restore |
