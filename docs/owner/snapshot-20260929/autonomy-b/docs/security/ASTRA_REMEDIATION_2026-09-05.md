## Изменения поведения после установки

1. Старые завершённые журналы без полной новой подписи/привязки не переподписываются автоматически. Их состояние требуется сверить с фактическими результатами. Не удалять журнал ради повторного необратимого действия.
2. Legacy Core API принимает `completion_contract`, например `{"mode":"action","files":[{"path":"result.txt","contains":"готово"}]}`. Проверка пути относится к workspace агента. Пока для другого типа эффекта нет независимого верификатора, состояние будет `unverified`. Информационный ответ — `answered`.
3. Существующие облачные модели должны подтвердить цены: OpenRouter — принудительный Refresh каталога; для вручную зарегистрированного провайдера — явно задать обе известные цены. Неизвестные цены не заменять произвольными нулями. Подтверждённый бесплатный тариф с обоими нулями поддерживается. Канонический hard cap Fable сохранён.
4. Неопределённые внешние расходы и эффекты остаются заблокированными до сверки. Цена локальной модели не требует облачного тарифа. Evidence TTL по умолчанию 300 секунд; контракт может явно задать `evidence_max_age_seconds` до 86400. Истёкшее доказательство не делает старое действие безопасным для повторения.
5. Публичный MINIMIZED-контракт с непроверенными аргументами не отправляется на другой узел. У произвольного project/team scope без зарегистрированного владельца нет наследования/экспорта по умолчанию.
6. Контекстные лимиты относятся к используемым оценщикам токенов; это не гарантия точного tokenizer count всех моделей.
7. Solana live execution и неподтверждённое создание HD-кошельков остаются выключенными. Архив не включает торговые операции и не включает неподтверждённую функциональность.

## Внешняя приёмка

После установки и локальных тестов создать отдельную ветку/PR и дождаться checks на SHA именно этого изменения. Затем владелец репозитория может выполнить:

```sh
python tools/astra_branch_protection.py
python tools/astra_branch_protection.py --apply
python tools/astra_branch_protection.py --check
```

Требуется установленный `gh`, вход в GitHub и право администратора репозитория. Первая команда только печатает JSON. `--apply` отказывается заменять уже существующую защиту; в этом случае необходимые checks нужно объединить с текущими правилами вручную. Никакие GitHub-настройки при подготовке ZIP не менялись.

Workflow `ASTRA acceptance`: Ubuntu/Windows portable, отдельные runner-тесты, еженедельный прогон, ручной hardware job для заранее настроенного self-hosted Linux runner с меткой `bossman-sandbox`. Браузерная/Windows/аппаратная проверка и зелёный новый remote SHA остаются незакрытыми условиями приёмки.
