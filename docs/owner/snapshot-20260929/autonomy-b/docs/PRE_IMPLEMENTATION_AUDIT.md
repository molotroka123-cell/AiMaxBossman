
`MANIFEST.json` содержит sha256 каждого файла — сверяемо.

**Обнаруженная архитектура.** Приложение **событийное, а не видеопотоковое**:
`Tapo motion / ONVIF → motion gate → временная выборка RTSP → локальный
разбор кадра → корреляция с CRM/расписанием → состояние → SQLite`.
Стек: FastAPI + uvicorn + httpx + opencv-python-headless + numpy.
Кадр берётся вызовом внешнего `ffmpeg` (`RTSP.jpeg()`), не через OpenCV-capture.

Ключевые сущности `core.py`: `Settings`, `RTSP`, `MotionGate`, `State`,
`CRMContext`, `CRM`, `Detector` (baseline + разница по зонам), `classify`,
`Store` (SQLite).

Заявленные политики пака: без распознавания лиц, без хранения сырого видео,
аудио выключено, личность сотрудника — из CRM, не из пикселей.

## 3. Что переиспользуем, что переписываем, что отвергаем

### APP1

| Решение | Что именно |
|---|---|
| **ПЕРЕИСПОЛЬЗУЕМ** | событийная модель (motion gate вместо непрерывного видео); зоны кресла/рабочей области; профиль приватности (нет лиц, нет сырого видео, аудио выкл.); идея `redact()` для RTSP-URL; профиль CRM как источник личности; схема SQLite как отправная точка |
| **ПЕРЕПИСЫВАЕМ** | `redact()` покрывает только URL — пароль всё равно попадает в `Settings`, исключения и телеметрию; нет таймаутов у вызова `ffmpeg`; нет переподключения и backoff; нет ограничения очереди кадров; нет health/статуса; нет явного разделения real/mock камеры и модели; нет корректного завершения |
| **ОТВЕРГАЕМ** | `FINAL_PROMPT_TO_PASTE.txt` и `MASTER_PROMPT_FOR_CLAUDE.md` — это инструкции ко мне, а не код продукта; в репозиторий как исходники не идут |

### APP2

| Решение | Что именно |
|---|---|
| **ПЕРЕИСПОЛЬЗУЕМ** | стадийный конвейер; `DesignSpec`; профиль принтера с разделением verified/unverified; шлюз требований (не гадать размеры); проверки меша и вписывания; манифест артефактов; примеры дизайнов |
| **ПЕРЕПИСЫВАЕМ** | `validate_mesh` — уровень проверки надо довести до manifold/watertight/вырожденных треугольников/несвязных компонент; нет истории заданий, отмены, таймаутов, лимитов диска; нет контрольных сумм; нет безопасности имён файлов; нет детерминированного экспорта; нет обработки битого STL; физические действия принтера не отделены от цифровой генерации |
| **ОТВЕРГАЕМ** | то же — файлы-промпты |

## 4. Риски безопасности, найденные до имплементации

| # | Риск | Где | Как закрываем |
|---|---|---|---|
| 1 | **Пароль камеры в открытом виде** в `Settings.camera_password` и в собранном RTSP-URL. `redact()` чистит только текст URL — трассировка исключения, лог `ffmpeg` и отладочный вывод останутся с паролем | APP1 `core.py:29,60` | секрет только через хранилище/окружение, объект-обёртка без `__repr__`, единая точка сборки URL, запрет пароля в аргументах и логах, тест-канарейка |
| 2 | **Наружная передача**: `CRM` ходит по HTTP с токеном | APP1 `core.py:122` | таймауты, отсутствие токена в логах, отключено по умолчанию (`AWV_CRM_KIND=none`) |
| 3 | **Приватность**: камера в кабинете. Сырое видео, аудио, распознавание лиц | APP1 | остаются выключенными по умолчанию, явные флаги, снимки без лиц |
| 4 | **Физическое действие**: нагрев и движение принтера | APP2 | цифровая генерация и физическая печать — разные слои, старт печати только по явному подтверждению человека |
| 5 | **Путь/имя файла** из пользовательского ввода в артефактах STL/G-code | APP2 `artifacts.py` | нормализация и запрет выхода за каталог задания |
| 6 | **Внешние бинарники** (`ffmpeg`, `openscad`, слайсер) вызываются подпроцессом | обе | таймауты, ограниченный вывод, честный отказ при отсутствии бинаря |

Отдельно: пароль-канарейка в тестах помечается `ci-secret-scan: allow`
поштучно, а не отключением сканера.
