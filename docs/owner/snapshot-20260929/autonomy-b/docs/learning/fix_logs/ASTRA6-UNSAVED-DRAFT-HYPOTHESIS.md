## Task
Проверить, теряется ли несохранённая правка кода сайта при уходе со страницы по боковому меню

## Symptom
Предполагалось: автосохранение отложено на SAVE_DELAY_MS=900, переход по меню перерисовывает экран, редактор исчезает вместе с таймером, и час работы владельца пропадает молча.

## Reproduction
Настоящий Chromium и настоящий BCC: создать проект, напечатать правку в textarea.bd-code, НЕ сохранять, кликнуть пункт бокового меню, вернуться на страницу и прочитать значение редактора.

## Evidence
- Опрос сервера по секундам после ухода со страницы: t+500 мс — версия 2, прежний код; t+1000 мс — версия 3, правка владельца; далее стабильно до t+4000 мс.
- Мутация «убрать отложенное сохранение для страницы, которой нет на экране» (editorNode.isConnected) роняет проверку с сообщением «за 15000 мс сервер так и не получил правку».
- grep по command-center/ui: обработчика beforeunload в продукте нет ни одного, он встречается только внутри вендорного ui/vendor/grapesjs/grapes.min.js.

## Hypotheses considered
- таймер автосохранения живёт в DOM страницы и умирает вместе с ней
- черновик нигде не сохраняется, поэтому возврат показывает серверный код
- переход по меню отменяет отложенный запрос

## Rejected hypotheses + why
- «таймер умирает вместе со страницей» — опровергнуто замером: setTimeout живёт в модуле, а не в DOM, и hashchange его не отменяет
- «правка теряется» — опровергнуто: на t+1000 мс сервер уже содержит правку владельца, версия выросла с 2 до 3
- «нужен хук ухода со страницы» — опровергнуто мутацией: с ним и без него поведение одинаково

## Root cause
Дефекта нет. Отказ первой проверки объяснялся двумя ошибками инструмента: селектор пункта меню (.nav-item — кнопка с data-page, а не ссылка с href) и wait_for_function с предикатом, возвращающим Promise — сам объект обещания уже истинен, поэтому ожидание кончалось до ответа сервера и читало DOM, пока запрос был в полёте.

## Relevant code paths
- command-center/ui/pages/web_designer.js
- command-center/ui/app.js
- command-center/tests/test_unsaved_draft_navigation.py

## Fix strategy
Починки нет и не должно быть. Внесённый хук ухода со страницы откачен, продуктовый код не изменён. Вместо починки закреплён настоящий инвариант: правка, брошенная внутри окна автосохранения, обязана дойти до сервера.

## Alternatives considered
- оставить хук ухода «на всякий случай» — отвергнуто: усложнение работающего роутера без причины
- хранить черновик в localStorage — отвергнуто: решает несуществующую задачу и создаёт риск воскрешения черновика поверх более свежего кода
- поднять SAVE_DELAY_MS — отвергнуто: не относится к делу и спрятало бы настоящую регрессию, если бы она появилась

## Why this fix was chosen
Измерение опровергло гипотезу, а чинить несуществующий дефект — значит вносить сложность, которую потом никто не сможет обосновать. Ценность осталась в тесте: свойство неочевидно и хрупко, достаточно кому-то «прибраться», сняв отложенное сохранение для снятой с экрана страницы, и тихая потеря данных появится по-настоящему.

## Adversarial variants
- уход без единой правки — версия не создаётся (негативный контроль)
- отложенное сохранение отменяется для снятого с экрана редактора — проверка краснеет
- ожидание через wait_for_function с Promise — зеленеет даже на потерянной правке, поэтому опрос ведётся из теста

## Regression
2 passed на настоящем Chromium; мутация роняет первый тест

## Generalizable lessons
- Строка аудита и правдоподобная гипотеза — не факт. Отказ теста сначала объясняется ошибкой инструмента, и только потом дефектом продукта.
- Прежде чем чинить, снимите мутацию: если с починкой и без неё поведение одинаково, чинить было нечего.
- Предикат, возвращающий Promise, в ожидании браузера истинен немедленно — такая проверка зеленеет на любом исходе, включая потерю данных.
- Отсутствие дефекта стоит записывать так же подробно, как его наличие: иначе следующая модель потратит тот же час и внесёт ту же ненужную правку.

## Teach local model
- Прежде чем чинить — снять мутацию: одинаковое поведение с починкой и без неё означает, что дефекта не было.
- Отказ проверки сначала объясняется ошибкой инструмента (селектор, форма ожидания), и только потом дефектом продукта.
- Ожидание с предикатом, возвращающим Promise, истинно немедленно и зеленеет на любом исходе.

## Limitations / follow-up
- Проверено на Linux с настоящим Chromium; на Windows отдельно не измерялось.
- Остаточный риск не закрыт и не измерен: закрытие вкладки или перезагрузка внутри тех же 900 мс. hashchange таймер переживает, выгрузка документа — нет.
- Это запись об инженерном случае для последующего извлечения; веса модели не обучались.
