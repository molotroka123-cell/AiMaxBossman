## 4. FIX (реальные ошибки, найденные прогоном)

1. **`bcc/features/tools_facts.py` звал несуществующий API `FactStore`** (`query`, `current_only`, `object_value`, `known_at`) → `GET/POST /api/memory/facts` падали 500, а инструмент `memory.fact.add` внутри approval-flow возвращал TypeError (ошибка инструмента — данные, run продолжался). Это сломало и верификацию исполнения в approve-path.
   - Fix 1: `bcc/v2/memory/facts.py` — `FactStore.search` принимает `query` (подстрочный фильтр) и `current_only`; `FactStore.as_of` принимает `known_at` (маппится на уже поддерживаемый `known_as_of` в `query_facts`) и `query`.
   - Fix 2: `bcc/features/tools_facts.py` — `object_value=` → `object=` в `http_add_fact` и `tool_fact_add`.
   - Целевой регрессионный тест: `command-center/tests/test_v22_facts_api.py` — 3 теста (HTTP add/search/query, as-of+known_at, tool-хендлер). Результат: **6 passed** (вместе с test_v22_facts.py).
   - Повтор live-path: approve/reject flow прогнан заново — `fact stored=True` / `False`, 67/67 PASS.

Других ошибок acceptance-теста не найдено (два 404 в первом прогоне были артефактами самого harness-экстрактора: UI дергает POST этих policy-эндпоинтов, а не GET).
