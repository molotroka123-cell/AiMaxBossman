## Главный факт: обе исходные линии СОДЕРЖАТСЯ целиком

Спецификация требует не потерять работу ни одной из линий. Это проверяемо, и
проверено:

```
git rev-list --count origin/<ветка>..HEAD     # насколько мы впереди
git rev-list --count HEAD..origin/<ветка>     # что НЕ перенесено
```

| Линия | Впереди на | **Не перенесено** |
|---|---:|---:|
| `claude/bossman-control-v03-43igbk` | 298 | **0** |
| `claude/bossman-final-completion-kymr05` | 124 | **0** |
| `night/v7-convergence-20260908` (база PR) | 173 | **0** |

Ноль в правом столбце — это и есть ответ на «не потеряли ли мы чужую работу».
У обеих исходных линий вершина является ПРЕДКОМ текущей: `git merge-base HEAD
origin/<ветка>` возвращает саму вершину ветки. Ни один коммит не остался
позади, и ни одна линия не была перезаписана.

## Оговорка, без которой эти числа опасны

Прошлый прогон начинался с **подрезанного** клона (`.git/shallow`, привязка к
`45027d3e`). На таком клоне `git merge-base` возвращает пустоту,
`git rev-list --max-parents=0` называет корнем обычный коммит середины истории,
а линии выглядят как 855 коммитов против 50 **без общего предка**. Прочитанное
буквально, это означало бы «две несвязанные истории» — и оправдало бы
перезапись одной линии другой.

**Поэтому первая строка таблицы выше — `is-shallow-repository = false`.** Все
остальные числа имеют смысл только при ней. Проверяйте её ПЕРЕД тем, как делать
выводы из `merge-base`, счётчиков коммитов или поиска корня.

## Что не надо доверять при проверке «а есть ли этот код»

`build/lib/` внутри `command-center/` и `bossman-core/` хранит копии модулей с
ДРУГИХ веток. Поиск по рабочему каталогу даёт по ним ложные совпадения — на
прошлом прогоне такая проверка едва не привела к выводу «адаптер уже есть».
Проверять надо по дереву ветки:

```
git ls-tree -r --name-only <ветка> | grep bcc/hybrid
```
