# Десять новых фич: флаги, ручки, что каждая делает

Все десять **выключены по умолчанию**. Выключенный флаг означает: приложение
ведёт себя ровно как до них. Включать по одной и смотреть, что получилось.

Флаг включается значением `1`, `true` или `yes`; всё остальное, включая
отсутствие переменной, — выключено.

| Флаг | Что включает | Ручки |
|---|---|---|
| `BOSSMAN_PROVENANCE_ENABLED` | паспорт факта у показателей | `GET /api/provenance`, `GET /api/provenance/{key}` |
| `BOSSMAN_DIAG_BUNDLE_ENABLED` | сбор архива для разбора сбоя | `POST /api/diag/bundle`, `GET /api/diag/bundle` |
| `BOSSMAN_LOCAL_FIRST_ENABLED` | решение «локально или в облако» | `GET /api/local-first`, `.../decisions`, `POST /api/local-first/decide`, `.../thresholds` |
| `BOSSMAN_FAILURE_TO_CASE_ENABLED` | черновик обучающей записи из сбоя | `GET /api/failure-cases`, `GET /api/failure-cases/{id}`, `DELETE /api/failure-cases/{id}` |
| `BOSSMAN_ACTION_PREVIEW_ENABLED` | предпросмотр действия до нажатия | `POST /api/preview`, `GET /api/preview/actions` |
| `BOSSMAN_SPEND_METER_ENABLED` | счётчик денег и жёсткий потолок | `GET /api/spend`, `POST /api/spend/limit`, `POST /api/spend/check` |
| `BOSSMAN_OFFLINE_MODE_ENABLED` | честный офлайн-режим | `GET /api/offline`, `GET /api/offline/can/{capability}` |
| `BOSSMAN_SECOND_OPINION_ENABLED` | второе мнение перед необратимым | `GET /api/second-opinion`, `.../decisions`, `POST /api/second-opinion/check` |
| `BOSSMAN_UNIFIED_SEARCH_ENABLED` | один поиск по всему | `GET /api/search?q=…` |
| `BOSSMAN_WATCHDOG_ENABLED` | сторож запуска приложения | `GET /api/watchdog`, `GET /api/watchdog/history` |

Читающие ручки отвечают и при выключенном флаге, честно указывая
`enabled: false`. Ручки, меняющие состояние, при выключенном флаге отказывают.

---

## Что стоит включить первым

**`BOSSMAN_WATCHDOG_ENABLED`** — отвечает на «нажал ярлык, ничего не открылось»
человеческим языком: что случилось, на чём это видно, что сделать. Здоровое
состояние даёт пустой список: сторож, который всегда что-то находит, бесполезен.

**`BOSSMAN_DIAG_BUNDLE_ENABLED`** — вместо ручного сбора логов один архив.
Токен инсталляции в него не попадает: проверено побайтово по всем частям.

**`BOSSMAN_SPEND_METER_ENABLED`** — потолок жёсткий: при исчерпании прогон не
стартует и модель не вызывается. Режима «предупредить и пропустить» нет.
Умолчания консервативные (10 USD в сутки, 5 USD на миссию), меняются ручкой
или переменными `BOSSMAN_SPEND_METER_DAILY_USD` / `..._MISSION_USD`.

## Что пока только слой, без экрана

`provenance`, `local_first`, `action_preview`, `second_opinion`,
`unified_search`, `offline_mode` доступны через API, но кнопок в интерфейсе для
них ещё нет. Это следующий шаг, и он честно не сделан, а не «почти готов».

## Два места, где фича ждёт подключения снаружи

- **`second_opinion`**: проверяющий подключается функцией `set_verifier`. Пока
  он не подключён, любое необратимое действие через гейт получает «не смог
  проверить» и блокируется — это правильное поведение fail-closed, но важно
  знать до включения флага на боевых путях.
- **`local_first`**: модуль выносит вердикт и ведёт журнал, но исполнение к
  нему ещё не подключено. Вызовов моделей он не делает — ни локальных, ни
  платных.

## Границы, которые сознательно не переходили

- Ни одна фича не делает платных вызовов и не ходит в сеть без включённого
  флага и уже настроенного адреса.
- Ничего не пишется в каталог репозитория: все файлы фич живут в `data_dir`.
- Корпус обучения `data/learning` не трогает никто: `failure_to_case` кладёт
  черновики отдельно, и запись в корпус остаётся решением владельца.
