# «Процесс работы» — что владелец видит и чего не видит

Русское имя панели в интерфейсе: **Процесс работы**. Английское понятие:
*Thinking process*. Открывается кнопкой в верхней строке, сочетанием **Ctrl+.**
и из командной палитры; состояние «открыта/закрыта» запоминается.

## Что панель показывает (только факты исполнения)

| Поле | Откуда | Пример |
|---|---|---|
| задача / прогон | `task.*` события и `/api/tasks` | «Разбор почты» |
| состояние | `task.queued/started/paused/stopped`, `waiting_approval` | «выполняется» |
| шаг из максимума | `task.progress` | «2 из 5» |
| модель / маршрут | `task.progress`, `router.fallback` | «qwen-14b» |
| текущий инструмент и его длительность | `tool.called` | «fs.read · 120 мс» |
| чего ждёт | `task.progress.waiting_approval`, `gate_hook_failed` | «решение владельца (terminal.run)» |
| повторы / запасная модель | `router.fallback` | «1» |
| ошибки | `tool.denied`, `hook.*`, `run.log level=error` | «0» |
| прошедшее время | таймер по времени старта | тикает раз в секунду |
| проверенный результат | `evaluation.completed` | «проверка: PASS» |
| лента событий | общая шина сервера | последние 200, показываются 80 |

## Чего панель НЕ показывает — и не будет

- сырую «цепочку рассуждений» модели;
- скрытые рассуждения, черновики и служебные буферы;
- reasoning-токены провайдера;
- промпты и системные инструкции;
- ключи, токены, cookie, содержимое учётных данных.

События приходят из той же серверной шины, что и остальной интерфейс, и уже
очищены сервером (`bcc/events.py: redact`) — панель не имеет отдельного канала
и не может показать больше, чем видит дашборд.

## Границы и производительность (измерено)

Поток из 900 событий подряд, затем ещё 300:

| Показатель | Ограничение | Факт |
|---|---|---|
| событий в памяти | `MAX_EVENTS = 200` | ≤ 200 после обеих волн |
| строк в DOM | 80 | ≤ 80 |
| перерисовок | склейка по кадру (`requestAnimationFrame`) | < половины числа событий |
| отзывчивость | не хуже базовой более чем на 50 мс | в пределах допуска |

Ключевое изменение этой приёмки: перерисовка панели больше не выполняется на
каждое событие — она склеивается в один кадр. Без этого плотный поток давал
полную перерисовку ленты сотни раз в секунду.

## Ответы, ради которых панель существует

- Агент жив? — тикает время и идут события.
- Что он делает? — инструмент и шаг.
- Он застрял? — состояние, время без событий, «ожидание».
- Чего он ждёт? — «решение владельца (…)» с переходом в очередь подтверждений.
- Что проверено? — строка `evaluation.completed`.
- Что дальше? — следующее событие ленты; ничего не додумывается.
