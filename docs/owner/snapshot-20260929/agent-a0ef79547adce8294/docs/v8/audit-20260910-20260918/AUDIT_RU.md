# Bossman V8: ретроспективный аудит и визуальная документация

## Объект, период и границы

Период истории: **с 10 сентября 2026** до текущего снимка вечером 18 сентября по **UTC−04**; поздние коммиты имеют дату 19 сентября UTC. Начальная рабочая линия этого прохода — `claude/bossman-final-convergence-hu2702`, SHA `d4381e6c6f1640e0992942a864ed4e75ad78b21a`. Во время проверки обнаружена более новая существующая линия **`release/bossman-owner`**, SHA **`692b5c01264d3e4a92b77debb8f63855001f72b8`**.

Сравнение этих SHA: release впереди на восемь достижимых коммитов, не отстаёт. Поздняя дельта включает CI, inventory, решения по переносу PR, исправление README/scorecard и тесты; она не основание заново объявлять предыдущую Windows-приёмку пройденной новым архивом. Первичная проверка закончилась на этой точке. Перед публикацией release продвинулась ещё на три коммита до `172d39e1bbb6cc7894ed1ab1a70d749f8f44b465`; эта дельта также прочитана и сохранена. Публикация визуального README направлена в уже существующую release-линию, без создания ещё одной ветки, reset, force-push или удаления истории.

Это **ретроспективный аудит основных классов изменений, документов и заявлений о готовности**, а не построчная security-проверка каждого файла всех веток. История читается с учётом слияний. Название коммита подтверждает намерение автора; рабочее поведение требует кода и отдельного результата проверки. Полные source/runtime-наборы, Windows, GPU, Telegram и live-модели в этом документационном проходе заново не запускались.

Изучены страницы истории с 10 сентября, ключевые изменения, текущая матрица, реестр кандидатов, документация метрик и Telegram; восемь первых и три последующих коммита release сверены отдельными compare. Число коммитов не выдаётся за число новых возможностей. Данные Trading Lab не смешиваются с изменениями приложения.

## Главный вывод

Путь за этот период: **раздельные линии → сведение → реальная Windows-поставка → более строгая приёмка → Studio и Telegram → измерение отзывчивости и защита отката**.

Есть реальные принятые Windows-кандидаты с профилями 40/42/44/46 сценариев. Есть дополнительные реализации, появившиеся после них. Нет основания переносить прежний PASS на последний HEAD, считать offline Telegram живым или обещать скорость Ryzen по Linux-контролю.

**Полный V8 Total в этом аудите не объявляется закрытым.** Расширенный README отделяет проверенный исторический baseline, существующий код, live-pending и будущие идеи.

## Производительность: допустимые и недопустимые выводы

### PERF-METRICS-001

Данные из `docs/v8/evidence/metrics-async-summary.json`: 20 чередующихся пар, контролируемое ожидание 250 мс; медиана независимого callback 240.744474 → 0.352174 мс; p95 240.926903 → 0.460381 мс. Сам sample 250.706322 → 251.219064 мс. Быстрый контроль: около 0.15 мс дополнительной цены переноса.

Вывод: системное чтение перестаёт удерживать основной цикл. **Не вывод:** весь UI или модель стали в сотни раз быстрее; физический Radeon проверен; Windows проходит бюджеты. График начинается с нуля и не растягивает маленький столбец для эффекта.

### Бюджет интерфейса

8/4 секунды cold/warm, p50/p95 150/400 мс, 1000/3000 мс для галерей, RSS/CPU пределы — **целевые значения**, не достигнутые показатели Windows. Reference-навигация 72.1/107.2 мс и 1.1% CPU короткого тихого контроля не подменяют полный installed soak. Не повторяется необоснованный вывод «без конкурирующей нагрузки будет точно не хуже»: это требует повторного эксперимента.

Незавершённый `responsiveness-reference-soak.json` с `completed:false` остаётся недостаточным доказательством. Изменение измерителя после нахождения BL-086 не переносит PASS на все старые результаты.

## Telegram: что именно вошло

Рассмотрен опубликованный пакет `67c8e757…`: отдельный opt-in процесс, локальный текстовый диалог, явный SearXNG-поиск, owner/guest, preview/confirm, собственные результаты, model-independent status, optional Claude/OpenRouter с согласием и бюджетом.

79 offline-контрактов относятся к тестовым ответам внешних API и реальным локальным SQLite/HTTP-границам. Повторные 74 проверки не суммируются с ними как независимое покрытие. Модель не получает shell/desktop. Нужен живой round-trip и проверка в новом ZIP.

Не закрыты этим кодом: full-host outage, always-on relay, неограниченный внутренний контекст, Telegram voice/photo input, календарные напоминания и удобный root-ярлык в Windows. Отказ локальной LLM — не то же событие, что отключение компьютера. Эти границы сохранены в README.

## Дополнительные OSS-кандидаты

Назначение сверено по первичным upstream-страницам; полный review исходников/лицензий всех проектов в этом проходе не выполнялся.

- `petergyang/no-ai-slop`: редакторский skill, не обучение весов и не гарантия качества модели.
- `tonhowtf/omniget`: преимущественно downloader/организация материалов; нельзя объявить универсальным поисковым backend только по названию. Дополнительные MCP-возможности требуют отдельной интеграции.
- `Untrivial-ai/agent-orchestrator`: идеи разделения рабочих областей, делегирования и ревью; не основание заводить второй control plane.
- `pranshuparmar/witr`: диагностика происхождения процессов; применимость конкретной версии к native Windows должна проверяться, WSL не подтверждает host-процессы.
- `0xranx/OpenContext`: внешний проектный контекст. В истории Bossman есть native-authoritative/shadow-решение; не объявляется основным production store.
- Higgsfield: собственный творческий fork внутри Bossman нельзя путать с использованием чужого сервиса. На `172d39e1…` прежнее полное отклонение PR #59 исправлено: часть механизмов уже лучше в каноне, ряд настоящих пробелов имеет `PORT_REQUIRED`, адаптеры — `OWNER_HARDWARE_ONLY`. Перенос ещё не завершён и live-готовность не доказана.

Визуальный README не устанавливает ни один из этих проектов. Их текущие README не являются доказательствами совместимости с Bossman, безопасности кода или наличия на компьютере владельца.

## Поздняя дельта перед публикацией

Сравнение `692b5c01… → 172d39e1…`: три коммита, без изменений README. Добавлены `CONVERGENCE_DECISIONS.md`, проверка обязательных workflow по exact SHA, её тесты и тест однократного потребления approval; дополнен ledger. Авторский отчёт о новом тесте не заменяет собственный live-прогон.

Критическое уточнение: прежнее полное отклонение PR #59 было основано на неверной трактовке запроса владельца. Последняя матрица отличает собственный fork внутри Bossman от подключения сервиса. `job_store`, `content_buffer`, `persona`, `segment_qa`, `route_inputs`, `pipeline`, `workspace` и доказательство отправки требуют переноса; канонические media/probe, browser-защиты и protected paths переиспользуются. Этот README не утверждает, что перенос уже сделан, и не сохраняет устаревшее «всё отклонено». Приоритет интегратора P2 не разрешает потерять ранее согласованную способность.

Гейт workflow различает отсутствие, очередь, отмену и завершённый успех: отсутствие обязательного job не зелёный результат. Другая ветка/соседний SHA не закрывают гейт кандидата.

## Что остаётся до полного закрытия

1. Закрыть воспроизводимый денежный риск Studio BL-084 отдельным отрицательным контролем до первого POST; Telegram-политика его не чинит.
2. Завершить CI на exact candidate и проверить окончательный ZIP, не подменяя результатами старого baseline.
3. Довести owner-facing запуск Telegram и реально пройти телефон → локальная модель → агент → результат → restart.
4. Настроить и проверить локальный OpenCode с независимым GUI-driver. Наличие MD не даёт модели зрение и мышь.
5. Измерить cold/warm, UI latency и полное дерево процессов установленного Windows-приложения, затем целевого Ryzen.
6. Проверить живую генерацию каждого заявленного media-направления, права на данные и восстановление в редакторах.
7. Провести update/rollback между действительными архивами; новые поколения схемы не защищают задним числом старую программу.
8. Получить достаточное same-model Intelligence Preservation evidence; подготовленный runner не равен измерению.
9. Закрыть согласованный перенос недостающих частей собственного Higgsfield/Social Farm по текущей матрице, не удаляя их из scope молча.
10. Опубликовать один точный application ZIP с доступной записью хеша/размера/исходников и инструкцией отката.

Это список остающихся требований, не новое заявление о девяти воспроизведённых runtime-багах. Истина об отдельных finding — актуальный BUG_LEDGER и исполненные проверки.
