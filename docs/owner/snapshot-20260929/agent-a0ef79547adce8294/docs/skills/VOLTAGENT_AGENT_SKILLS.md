# Восемь скиллов для AiMaxBossman

Запрос владельца: отобрать и добавить нужные навыки из
https://github.com/VoltAgent/awesome-agent-skills.
База пакета: `b57b4ce981458581600adc2ee6836abca58be6fb`.

## Что добавлено

Это **адаптации инструкций**, а не полные плагины из чужих репозиториев.
Канонический каталог сохранён: `.agents/skills/<id>/SKILL.md`.
У каждого файла есть условия применения, порядок работы, ожидаемое
доказательство результата, источник, коммит, лицензия и описание изменений.
Скиллы не являются новой моделью и сами по себе не дают инструментов.

| Скилл | Зачем Bossman | Когда использовать |
|---|---|---|
| systematic-debugging | Искать причину сбоя, а не увеличивать таймауты вслепую | Баги и падающие проверки |
| test-driven-development | Проверка, которая ловит баг до исправления и проходит после | Узкие исправления |
| webapp-testing | Проверять реальные кнопки, видео, каталоги, сохранение и перезапуск | Приёмка интерфейсов |
| differential-review | Проверять конкретный diff и не терять старые защитные исправления | PR, безопасность, freeze |
| property-based-testing | Проверять инварианты на множестве граничных входов | Состояние, evidence, парсеры, время |
| variant-analysis | Находить тот же дефект в соседних путях | После подтверждённого бага |
| frontend-design | Делать интерфейс понятнее без смены принятого стиля и стека | Исправление UX; редизайн после freeze |
| mcp-builder | Проектировать понятные инструменты со строгими входами и результатами | Одобренные интеграции после freeze |

Источники: Anthropic, Jesse Vincent / obra, Trail of Bits. Полные неизменяемые
ссылки и хеши находятся в `voltagent-agent-skills.lock.json`, условия лицензий —
в `THIRD_PARTY_NOTICES.md` и `licenses/`.

## Что намеренно не добавлено

`verification-before-completion` дублировал бы `proof-before-done`;
`skill-creator` — `skill-forge` / `skill-evaluator`; общий model-evaluation,
video-editing и browser-research уже имеют свои скиллы. Remotion не подменяет
нынешний FFmpeg-редактор; новый React/TypeScript-стек ради скилла не устанавливаем.
Не импортированы массовые торговые/платёжные действия, публикация контента,
облачные подписки, upstream-скрипты, hooks и бинарники. Этому пакету они не нужны.

## Использование

Перед интеграцией:

```sh
python tools/validate_curated_agent_skills.py
python -m pytest -q tests/test_curated_agent_skills.py
```

Без pytest второй шаг можно выполнить стандартной библиотекой:

```sh
python -m unittest discover -s tests -p test_curated_agent_skills.py -v
```

Это проверки **целостности и формата**, не доказательство эффективности модели
и не барьер против атакующего, который может переписать весь checkout.
Обновление текста вместе с манифестом требует доверенного review.
Валидатор ничего не скачивает, не устанавливает и не запускает из скиллов.

Для задачи агент читает 1–2 релевантных файла, например:
`systematic-debugging` + `webapp-testing` для сломанного preview,
`differential-review` + `variant-analysis` для проверки PR,
`test-driven-development` + `property-based-testing` для инварианта journal.
Не вставлять весь набор в системный промпт и не увеличивать права агента.
Поля activation в манифесте — контракт интеграции, а не замена runtime policy.

**Подключение локальным агентам ещё нужно подтвердить:** существующий Skill
Library/scanner должен увидеть каталог, а маршрутизатор — выбрать нужный скилл
на реальной задаче. Само наличие файла этого не доказывает. Этот пакет не
изменяет runtime, конфигурацию активной Windows-сессии или N0/autonomy flags.
Не создаём второй реестр или планировщик. Opus проверяет канонический путь.

План обучения — сначала read-only и sandbox: выбор скилла, корректные аргументы,
реальный результат, отсутствие лишних действий, стоимость/контекст. Только
проверенные трассы без секретов могут поступать в существующий learning loop.
Публичная инструкция не становится политикой или обучающей истиной автоматически.
