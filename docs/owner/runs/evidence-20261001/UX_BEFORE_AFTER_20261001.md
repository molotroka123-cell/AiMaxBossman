## Вывод про «UX +30 %»
**Не доказано целиком, доказано частично.**
- Реально лучше на ≥30 %: время до первого значимого элемента на холодной главной (оговорка про выброс), первый текст длинного ответа через API (−63 %), самый первый вызов `/api/apps` (−99 %).
- Лучше на 10–30 %: первый текст короткого ответа, `/health` после старта.
- Без изменений (в пределах шума): load, TBT, клик → отрисовка, накладные расходы Bossman, установившиеся API.
- Хуже: холодная главная тяжелее (+11 % запросов, +16 % байт) из-за нового UI.
- Единой метрики «UX» нет; заявлять «+30 %» одной цифрой было бы нечестно. Данные по железу владельца: **это измерение на пустых данных**, а не на рабочей базе владельца (там ожидаются иные цифры, как и у предыдущего perf-отчёта на синтетике).

Не измерялось: реальная локальная модель (TTFT модели), рабочая база владельца, мобильный экран, длительная нагрузка.
