## 2. Дефект расчёта банков (главный)

Старый код отдавал «побочный банк» одной суммой лучшей руке среди игроков, вложивших больше победителя, и в сплитах
делил «мёртвые деньги» поровну, не различая уровни вкладов. Воспроизведено (стеки 500 / 100 / 300, самый большой
пушит, остальные коллируют all-in; руки: A лучшая, B вторая, C худшая):

* ожидается (правило уровней): A 300, B 400, C 200 (неуравненные 200 возвращаются C);
* было: B получал 600, C 0 (чужая неуравненная ставка отдавалась второй руке);
* сплит A/B при вкладах 100/300/300: ожидается A 150, B 550; было A 250, B 450 (A забирал деньги уровня, которого
  не покрывал).

Исправление: чистая функция `settlePots` (`src/engine/potSettlement.js`): уровни по вкладам, неуравненная часть
возвращается владельцу и не облагается рейком, мёртвые деньги идут в банк своего уровня, ничья делится по банкам,
нечётная фишка — первому победителю слева от кнопки. Сохранение фишек проверяется на каждой раздаче
(`сумма после + рейк == сумма до`, было допущение ±1).

## 3. Рейк и комиссия — допущения

* Схема: процент от оспоренного банка (неуравненная ставка исключена), потолок в фишках, «no flop, no drop»,
  снимается с основного банка первым; округление вниз.
* Параметры брались из `cashFormats.js` (5% / 4.5% / 4%, потолки 3 bb … ). Это СХЕМА приложения, не расписание
  реальной комнаты: реальные комнаты различают число игроков, возврат рейкбэком и т.п. Для оценки «живой» прибыли
  значения надо подставить из реальной комнаты.
* Турниры: рейк не применяется (взнос/фи турнира в приложении не моделируется).
* В отчётах ставки считаются ПОСЛЕ рейка; в таблице арены отдельно указан суммарный рейк стола (bb/100 раздач).

## 4. Воспроизводимость (seed)

| Контур | Было | Стало |
|---|---|---|
| Колода/ИИ в приложении | `crypto.getRandomValues`, воспроизвести нельзя | по умолчанию то же (для реальной игры), `seedRng(seed)` включает детерминированный PRNG (mulberry32; не криптостойкий) |
| Эквити | недетерминировано | `calculateEquity(..., {seed})` — локальный PRNG |
| Сессия | — | `tools/simulate-session.mjs --seed N`: два прогона seed=3, 25 раздач → одинаковый sha256 |
| BotLab | seed уже был (дубль-раздача, `decision_seed`) | + рейк; `report` с тем же seed даёт те же числа (тест) |

Оговорка: `App.jsx` использует `Math.random()` для косметики (чат, имена, респавн) — не часть расчётов, не
сидируется.

## 5. Неопределённость и ограничения (как они показаны пользователю)

* Эквити — против СЛУЧАЙНЫХ рук; для реальных диапазонов оно завышено/занижено. Отчёт и `calculateEquity` помечают
  допущение (`assumption`).
* Монте-Карло: показываются stderr и 95% ДИ. Таблица префлоп-эквити BotLab (`sims_per_class` = 4000) имеет
  стандартную ошибку ≈ 0.7 п.п. (напр. 72o vs 1: 0.354 при эталоне ≈ 0.346).
* Win-rate: ДИ по раздачам/блокам; отчёт пишет, сколько рук нужно для ±5 bb/100 (по наблюдённой дисперсии). 300 рук
  дают ДИ шириной в сотни bb/100 — вывода о силе игры делать нельзя.
* Ранжированные таблицы (`gtoRanges.js`, `solverRanges.js`) — происхождение/версия солвера не подтверждены; в
  отчёте границы VPIP/PFR помечены как эвристика, а не солвер.
* Короткий all-in-рейз «переоткрывает» торги (не исправлено); несколько неполных рейзов подряд в Python-движке тоже
  не переоткрывают (задокументировано).
* **Политика/риск, не правка кода:** десктопный Screen Parser (`desktop/main.js`, `overlay.html`) делает снимок всего
  экрана и отправляет кадр в облачный Claude через Vercel-эндпоинт (`https://pokertrain.vercel.app/api/claude`) и
  в режиме «Live» даёт совет в реальном времени. Он ничего не нажимает, но для чужих покерных комнат это
  недопустимый режим, а кадры уходят в облако. Рекомендация: в сборке для тест-матча отключить (флаг конфигурации по
  решению владельца). Я это не менял и не запускал.
