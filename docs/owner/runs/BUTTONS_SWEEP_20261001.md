# Обход «каждой кнопки» нового UX Bossman, 01.10.2026

Приказ владельца: «протестируй каждую кнопку». Прошлый обход (`docs/owner/runs/UX_SWEEP_20260930.md`) нашёл 461 элемент на 49 маршрутах, но нажал
по одному на пару «подпись + класс» (294). Этот прогон добирает остальное: все видимые и доступные элементы на каждом маршруте, внутри всех окон
(до трёх уровней), в состояниях «пусто» / «формы заполнены» / «есть данные», и весь новый чат `/chat.html`.

Код: ветка `owner/buttons-20261001` (`%USERPROFILE%\Bossman\wt-buttons-1001`), база `9251414d`, 13 коммитов с правками (раздел 4). Живой сервис из
`wt-bugtest-0930`, живой Bossman владельца на :8801, Jeff, Telegram-компаньон и `%LOCALAPPDATA%\Bossman\*` не трогались (после прогона :8801 отвечает как и раньше).

## 2. Методология

**Стенд.** Побочный экземпляр кода `wt-buttons-1001` на `127.0.0.1:8861`, пустой каталог данных `%USERPROFILE%\Bossman\bugtest-20261001\buttons\data`
(`BCC_DATA_DIR`), `python -X utf8 -m bcc` из `venv-calls`; `import bcc` проверен: разрешается в `wt-buttons-1001\command-center`. Для сервера:
`LOCALAPPDATA`, `APPDATA`, `USERPROFILE`, `HOME`, `BOSSMAN_TELEGRAM_CONFIG` перенаправлены в `...\buttons\sandbox` (после инцидента прошлого обхода с профилем
Telegram), ключи и токены из окружения убраны, `HTTP(S)_PROXY=http://127.0.0.1:9` с `NO_PROXY=127.0.0.1` — любая попытка сервера выйти в интернет падает сразу
(поэтому «облачные» кнопки отвечают честным «нет связи», а не уходят наружу). Токен доступа не печатался и не сохранялся (проверено поиском по каталогу результатов).
Модель для чата — локальная заглушка OpenAI-совместимого API на :8862 (`fake_llm.py`, это тестовый двойник, не модель): без неё у ответов не было бы кнопок.
Один Chromium 1440×900 за раз (Playwright, `chat`: ещё 390×844 для проверки телефона).

**Проходы** (все сырые результаты — `buttons_raw.json`, построчно `raw_*.jsonl`):

**Что фиксируется при каждом нажатии:** запросы и их статусы (тела ответов ≥400 и всех не-GET), `console.error/warn`, `pageerror`, диалоги
(`confirm` принимается — данные одноразовые), всплывающие окна, скачивания, выбор файла (подставляется `dummy-upload.txt`), уведомления, изменения текста
`#view`/окон, смена адреса/окна, состояние самого элемента, число узлов DOM и значения полей. Фон (опрос) вычитается 600-мс замером перед нажатием.
Решение: OK — есть наблюдаемая реакция; HONEST_REFUSAL — реакция это отказ с текстом/ответ 4xx; DEAD — реакции нет; ERROR — исключение, 5xx, мусорный текст,
английская фраза в сообщении, запрос во внешнюю сеть, сорвавшийся клик. Скриншоты — только для DEAD/ERROR (`shots\`, 128 файлов).
