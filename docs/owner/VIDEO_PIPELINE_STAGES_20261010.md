## Пороги гейтов анимации (зафиксированы 10.10 ДО прогона инструмента `tools/video_gate/animation_gate.py`)

Сравниваются декодированные кадры исходника (как его видит Bossman: после CFR-нормализации) и результата, каждый кадр, без выборки.
Маска M = объединение рамок лиц исходника, расширенных на 0.6 стороны (Gate 1: 0 из 90 кадров меняли пиксель вне неё).
В Gate 0 маски нет: эффекты не применяются, меняться не должно ничего.

| Порог | Как меряется | Gate 0 (без эффектов) | Gate 1 (face swap) |
|---|---|---|---|
| T1 кадры | число кадров, FPS (±0.01), длительность (±1 кадр); выравнивание: для кадра i результата ближайший по MSE (вне M) кадр исходника из i−2..i+2 должен быть i | 100% кадров | 100% кадров |
| T2 пиксели вне M | lossless-промежуточный файл: max\|Δ\| по всем кадрам; итоговый H.264: min по кадрам PSNR вне M | max\|Δ\| = 0; PSNR ≥ 40 дБ | max\|Δ\| = 0; PSNR ≥ 40 дБ |
| T3 мимика | 68 точек лица (2dfan4), средний сдвиг / межзрачковое расстояние | ≤ 0.02 | ≤ 0.05 |
| T4 тело | 33 точки MediaPipe Pose (visibility ≥ 0.5), средний сдвиг / длина торса (плечи→бёдра; если бёдер нет — ширина плеч) | ≤ 0.02 | ≤ 0.02 |
| T5 optical flow | Farneback на ½ разрешения, средняя ошибка конечной точки между потоками t→t+1 исходника и результата, вне M | ≤ 0.25 px | ≤ 0.25 px |
| T6 дрожание | RMS второй разности по времени от (точки лица результата − исходника) / межзрачковое | ≤ 0.01 | ≤ 0.02 |
| T7 личность (только Gate 1) | arcface к фото: среднее, разброс; исходное лицо к фото | — | ≥ 0.75; ≤ 0.06; ≤ 0.30 |

Артефакты каждого прогона: report.json (команда, версии, sha256 входов/выходов, метрики по кадрам), side-by-side видео
(исходник | результат | карта |Δ|), контакт-лист 8 контрольных кадров. Контрольные клипы выбраны заранее:
`gate1/src-raw.avi` (90 кадров F1, 1320×1002) и `video-testset-private/ref-clip-01.mp4` (441 кадр, 1280×720) — приватно, локально.

## Gate 0 — сходство анимации (конвейер Bossman без эффектов), прогон 10.10

Клип: `ref-clip-01.mp4` (441 кадр, 1280×720, 30 к/с). Вход: `tools/video_gate/gate0_passthrough.py` (CFR → 2 куска без
потерь → склейка → поза-гейт → finish). Замер: `animation_gate.py --gate 0` (e741ea99). Артефакты (локально, приватно):
`Videos/Bossman-Genjutsu/gate0-20261010/{v2-lossless,v2-final,v2-final-crf10}/` — report.json, side_by_side.mp4, contact_sheet.jpg.

| Файл | Метрика | T1 кадры/выравнивание | T2 пиксели | T3 лицо | T4 тело | T5 поток | T6 дрожание | Итог |
|---|---|---|---|---|---|---|---|---|
| мастер без потерь (`lossless.mp4`) | v1 и v2 | 441/441, 100% | max\|Δ\| = 0 | 0.000 | 0.000 | 0.000 | 0.000 | **PASS** |
| выдача H.264 crf 16 | v1 | 92.5% | 41.7 дБ | 0.024 | 0.049 | 0.141 | 0.352 | FAIL |
| выдача H.264 crf 16 | v2 | 100% | 41.7 дБ | 0.024 | 0.055 | 0.141 | 0.352 | FAIL (T3, T4, T6) |
| выдача H.264 crf 10 | v2 | 100% | 42.8 дБ | 0.017 | 0.051 | 0.118 | 0.277 | FAIL (T4, T6) |

- v1 → v2 (исправление метода, пороги те же): исходник телесинхронизирован — соседние кадры-«близнецы» (MSE 0.01–0.03 при
  медиане 190), сжатый кадр совпадает с обоими; v1 засчитывала это как сдвиг. Лицо/тело в v1 брались «самое большое» в каждом
  клипе отдельно — в сцене с двумя девушками сравнивались разные люди.
- Мастер без потерь бит-в-бит равен исходнику, поэтому всё отклонение выдачи — только итоговое сжатие. Отклонения T4/T6
  сидят в размытых кадрах и кадрах в очках (лицо > 0.05 только на 10 кадрах: 265–334; тело — 97 кадров с низкой видимостью).
- Вердикт: **конвейер обработки — PASS** (ничего не меняет). **Выдача H.264 — FAIL по T4/T6** из-за шума кодека; пороги
  не менялись. Изменение продукта: итоговое кодирование crf 16 → 10 (`faceswap.DELIVERY_CRF`), это закрыло T3.

## Wan2.2-Animate (кандидат Stage 1, локально) — журнал попыток 10.10
1. try1: невалидный JSON настроек (обратные слэши) — ошибка настройки, исправлено.
2. try2: режим «Replace» требует маску-видео — построена локально (FaceFusion background_remover u2net_human → бинарная маска, заливка дыр).
3. try3: модель загрузилась (150 с, краш 06.10 на загрузке больше не воспроизводится), упал на VAE-кодировании: MIOpen EvaluateInvokers → HIP unspecified launch failure.
4. try4: падение на подготовке int8-весов (Comfy Kitchen HIP kernels).
5. try5: `int8_kernels=disabled` + `MIOPEN_FIND_MODE=FAST` → VAE-кодирование 1 окна 1 мин 14 с; денойзинг идёт (~11 мин/шаг, 6 шагов, 2 окна).
Причина нестабильности: ROCm под Windows для gfx1151 — preview; Triton не компилирует свои ядра (нет stdlib.h), часть быстрых ядер падает.
