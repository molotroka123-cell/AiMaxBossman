# Гейт готовности к живой торговле (11.10.2026)

Статус документа: **подготовлен агентом, решение принимает только владелец**. Агент не включает живую торговлю, не подписывает, не создаёт ключи и не двигает средства. Переход на реальные торги — отдельное действие владельца; каждое живое действие подтверждается отдельно (раздел 4).

Машинно-проверяемая версия порогов: `bossman-core/bossman/trading_learning/live_gate.py` (`evaluate_gate`, тесты `tests/test_trading_live_gate.py`). Без доказательств функция отвечает `NO_GO`; даже при выполнении всех критериев она отвечает «ожидает подтверждения владельца» и не меняет `TRADING_EXECUTION=OFF`.

## 2. Измеримые критерии (все обязательны)

Все статистические критерии считаются только по out-of-sample / forward-paper сделкам, параметры заморожены ДО периода проверки (хеш плана в отчёте).

| № | Критерий | Порог |
|---|---|---|
| G1 | Размер выборки | ≥100 независимых сделок out-of-sample и ≥3 непересекающихся периода/режима |
| G2 | Преимущество после издержек | нижняя граница 95% bootstrap-ДИ среднего чистого дохода на сделку > 0; при 2× издержек среднее остаётся > 0. Если ДИ включает ноль — отчёт обязан это сказать, статус `NO_EDGE_PROVEN` |
| G3 | Лучше эталонов | разность со стратегиями «cash» и «hold» (с теми же издержками): нижняя граница ДИ > 0 |
| G4 | Просадка | максимальная просадка paper ≤20% выделенного капитала |
| G5 | Forward-paper | ≥14 дней на живых котировках без подгонки; расхождение факт/котировка по проскальзыванию ≤25% |
| G6 | Учение «стоп-кран» (kill switch) | проведено ≥3 раза, остановка ≤5 с, новых ордеров 0, открытые заявки отменены; журнал приложен |
| G7 | Учение «перезапуск» | процесс убит в середине позиции; после старта состояние сверено с биржей/кошельком, дублей ордеров 0 (идемпотентные client_order_id) |
| G8 | Минимум полномочий | ключ биржи только `trade`, вывод (withdraw) отключён, allowlist IP; на Solana — отдельный горячий кошелёк с ограниченным балансом, казначейский ключ не торгует (`core/wallet_policy.py`); плечо запрещено/ограничено (спот 1× по умолчанию); позиция ≤5% банкролла, суммарная экспозиция ≤20% |
| G9 | Дневной стоп убытка | ≤3% банкролла/сутки, после срабатывания торговля стоит до ручного включения владельцем; недельный стоп — по решению владельца |
| G10 | Мониторинг | heartbeat, алерт на расхождение paper/live, алерт на срабатывание стопов, доставка в пульт владельца |
| G11 | Секреты и подтверждения | ключи не в репозитории и не в открытом `.env`; подтверждение владельца на каждое действие (раздел 4) |

## 3. Порядок после выполнения G1–G11 (этапы, каждый — отдельное решение владельца)

1. Shadow: решения на живых котировках без ордеров (≥14 дней; это G5).
2. Микро-размер: сумма определяется владельцем (ориентир — не более 1% риск-капитала), ≥30 сделок, автоматический возврат в paper при любом нарушении G4/G9.
3. Только после сравнения «микро-live vs paper» (расхождение в пределах G5) владелец решает о расширении лимитов. Агент лимиты сам не повышает.

## 4. Подтверждения владельца (по каждому действию отдельно)

Нужны отдельные явные подтверждения с указанием действия, суммы и времени для: создания/выдачи ключа API; пополнения горячего кошелька (сумма); включения живого режима; любого повышения лимита; любого вывода средств. Подтверждение, выданное агентом/моделью самому себе, недействительно (`OwnerApproval` в `safety.py` отклоняет такие идентичности).

## 5. Что агент не делает никогда

Живые ордера, подпись, выпуск/деплой токена, движение средств, платные запросы без согласия; накрутку объёма, круговые сделки, сокрытие связей кошельков. Код такого рода удалён из `solana_volume_suite` (commit 6f6a3873) и не восстанавливается.

## 6. Оговорки

- Низкий риск симуляции не равен низкому риску реальности: очередь заявок, MEV, отказы транзакций, комиссии сети, изменения правил площадок и ликвидность в стрессе не моделируются полностью.
- Множественные проверки (много стратегий/параметров) повышают долю ложных находок; лаборатория выбирает параметры только на обучающем окне, но риск остаётся (1 из 20 ложных кандидатов в контроле без издержек).
- Это не финансовая и не юридическая консультация; налоги, лицензирование и правила площадок — на стороне владельца.
