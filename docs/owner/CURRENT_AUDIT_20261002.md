## Изображения и локальный runtime

Для Viggle Qwen-Image-2.1 Turbo подготовлена [спецификация owner-run](../models/viggle_qwen_image_2_1_turbo.md). Ранее на Windows была выявлена блокировка импорта ROCm/Torch: Smart App Control отклонил неподписанную `hiprtc0715.dll`; веса Viggle не скачивались и изображения не генерировались. В этой сессии локальный исполнитель команд и Computer Use повторно завершились до запуска с `setup refresh had errors`; текущий runtime, свободное место и память проверить не удалось.

Тестовый запрос на 4–5 шагов не является доказанным профилем. Официальный Viggle v0.3 базово задаёт 6 шагов; 5-шаговый вариант оставлен только экспериментальным до сравнения. Профиль лицензирован только для non-commercial research/evaluation до отдельной коммерческой лицензии. См. [официальную карточку](https://huggingface.co/Viggle/Qwen-Image-2.1-viggle-turbo).

## Состояние 2.0 и пульта

Последняя проверка Command Center (не перепроверена в этом срезе): `http://127.0.0.1:8801/health/live` отвечал alive, но сообщал `build_sha: null` и `SOURCE_IDENTITY_UNKNOWN`; core на 8800 не отвечал, защищённые API возвращали 401. Это недостаточно для owner verification. Поэтому 2.0 не объявляется готовым.

Причина текущей недоступности управления компьютером не установлена. Инструменты завершались на старте; я не закрывал процессы и не удалял файлы.
