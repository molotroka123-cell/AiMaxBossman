# Пайплайн «Модель → видео» в пульте: спецификация под наше железо (22.10.2026)

Владелец 22.10: «Делаем это отдельным пайплайном в разделе пульт» + этапы: первый идеальный кадр (FLUX.1, LoRA /
IP-Adapter / PuLID, KiaraSuperSpace), движение (Wan2.1 Animate / AnimateDiff + ControlNet OpenPose по видео-референсу),
апскейл (Topaz / ComfyUI-Upscale). Ниже — что из этого уже есть в Bossman, чем заменить то, чего нет, и как это
выглядит как ОДИН пайплайн в пульте с этапами и одобрениями. Ничего не установлено и не запущено: документ, не приёмка.

## 0. Железо: важная поправка к присланному плану

План предполагает NVIDIA RTX 3090/4090 + CUDA (ComfyUI-Manager, Topaz, AnimateDiff-Evolved, PuLID). У нас **AMD Ryzen AI
Max+ 395 / Radeon 8060S, 128 GB единой памяти, Vulkan через `sd-cli`** — CUDA нет, RunPod запрещён владельцем 11.10.
Это не блокер: на этом же ПК уже работают (живые задачи в `direct_gen`, статусы `completed` вчера) FLUX.1 schnell, FLUX2
Klein 4B, SDXL epicRealism, Qwen-Image 2.1 / Edit-2509 (I2I, до 3 референсов), **Wan2.2 I2V 14B**, Wan2.2 S2V 14B.
Веса **Wan2.2 Animate 14B** (fp8 + relight LoRA) уже лежат в `media-runtime/ComfyUI/models` — модель помечена
`unsupported`: «ANIMATE needs a driving video and pose inputs; the Direct window has no such input yet». Этот пайплайн
как раз и добавляет такой вход. Чего нет совсем: ControlNet, AnimateDiff, PuLID/IP-Adapter, апскейлер (папки пустые,
`custom_nodes` пуст — наш рантайм ходит в ComfyUI по API со своими workflow-шаблонами, а не через Manager).

## 2. Пайплайн в пульте: `/model_video` (одна команда, четыре этапа, одобрение между этапами)

Реализация — в существующем `bcc/telegram_companion` рядом с `/animate` и `/facelock`, очередь и приоритеты — те же
`direct_gen` + governor (генерации владельца не прерываются). Каждый этап = отдельная задача `direct_gen` с `job_id`,
результат приходит в пульт с подписью-происхождением (где и чем сгенерирован) и кнопками «Дальше / Переделать / Стоп».

**2.1 Приём.** `/model_video` → пульт просит: (а) 2–5 фото лица модели, (б) референс-видео движения (до 10 с, ≤ 50 МБ),
(в) описание сцены. Файлы остаются в `inbox-model-video/<run_id>/` на ПК; ничего не уходит в облако. Первый кадр
референса вырезается `ffmpeg` (уже используется в FaceLock). Проверка согласия: пайплайн запускается только для
персон из списка согласий (`consent.json`, ведёт владелец) — иначе отказ без генерации.

**2.2 Первый кадр.** `qwen-image-edit-2509` I2I: референсы = фото лица ×2 + кадр позы; промпт = сцена + «та же поза, что
на третьем референсе». 4 варианта → FaceLock-оценка сходства по каждому → в пульт топ-2 с числом сходства. Владелец
выбирает или «переделать» (можно указать `flux1-schnell` как базу + edit поверх).

**2.3 Движение.** `wan2.2-animate-14b`: character = выбранный кадр, driving = референс-видео; 480p, 4 шага с
`lightx2v` LoRA (уже в `loras/`), relight LoRA по флагу. Резерв: `wan2.2-i2v-a14b-uncensored` (без следования позе).
Лимит 30 мин на задачу (как у текущих видео), прогресс — существующий `video_progress`.

**2.4 Полировка и приёмка.** Апскейл ×2 (после установки Real-ESRGAN; до этого — пропуск с пометкой), затем Video
FaceLock: сходство лица по N кадрам, порог из `facelock` настроек; ниже порога — в пульт не отправляется как «готово»,
а идёт как «черновик, сходство X%». Итог: mp4 + json-квитанция (модели, seed, пороги, время, `job_id` каждого этапа).

## 3. Что нужно от владельца (решения, не код)

1. Согласие персоны — файл/запись в `consent.json` до первого запуска.
2. LoRA: экспериментировать с локальным обучением на AMD (не обещаю результат) или обходиться Edit-2509 + FaceLock.
3. Апскейлер: разрешить установку Real-ESRGAN (BSD-3) — после проверки лицензии и веса.
4. Облако (Luma/Kling): по умолчанию выключено; включать только поклипно с явным «да».

## 4. Как доказать, что работает (гейты, до слов «готово»)

1. `wan2.2-animate-14b` — живой прогон на синтетике (сгенерированный персонаж + 3-секундный референс движения с
   открытого датасета), `completed`, длительность, пиковая память; это снимает `unsupported`.
2. Перенос лица: 10 первых кадров Edit-2509 vs FaceLock-сходство; порог «годно» задаёт владелец по результату.
3. Полный прогон `/model_video` в пульте с одобрениями на каждом этапе, квитанция, 0 обращений в облако (аудит `direct_gen`).
4. Лист дерева `media.model_video_pipeline` → VERIFIED только после пунктов 1–3 на точном SHA.

Для Argon: это один лист зоны `media` в `ARGON_FINAL_RUN_MASTER_PROMPT_20261022_RU.md`; порядок — сначала 2.3
(снять `unsupported` у Animate), потом 2.2, потом команда в пульте.
