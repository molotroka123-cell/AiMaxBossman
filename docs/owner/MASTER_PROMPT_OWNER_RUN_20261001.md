## 2. Правила безопасности (нарушение = стоп)

- Данные владельца `%LOCALAPPDATA%\Bossman\CommandCenter` (реальный `bcc.db`) НЕ трогать без проверенного
  бэкапа. Прогон — в отдельном `BCC_DATA_DIR` и на отдельном порту (8831/8832), см. §4.
- Smart App Control не выключать; задачу BossmanKeepAwake не трогать.
- Логины, платные действия, публикации, сообщения другим людям, управление чужими аккаунтами,
  деньги, удаление данных — только через существующие approvals и с одобрения владельца.
- Секреты не печатать и не коммитить (токены, ключи, .env, credentials). Отчёты — без секретов.
- Скрытые рассуждения модели (chain of thought, run.reasoning_delta) никому не показывать.
- Самоулучшение: автономное применение ВЫКЛЮЧЕНО до проверки владельцем. Нельзя менять свои правила
  безопасности, права, лимиты и canonical. Кандидат без проверок не продвигается.
- Не имитируй результаты: если что-то не запускалось — пиши NOT_RUN. Не выдавай облачные модели за локальные.
- Среда Python: системный Python 3.12 может тянуть editable-установку СТАРОГО checkout. Всегда
  `PYTHONPATH=<worktree>\command-center;<worktree>\bossman-core;<worktree>`, короткий `--basetemp`
  (например `C:\bt\run`), command-center не класть в PYTHONPATH для root/core тестов.

- Окно ~5 часов; последние 30 минут — только итоговая проверка, handoff, коммит/пуш, отчёт.

  не вставляй огромные логи (читай tail/grep), длинные прогоны — в фон с записью в файл.
- Мелкие задачи отдавай самому Bossman на бесплатных/локальных моделях, только если они реально доступны
  и цена 0/0 подтверждена в каталоге; флаг агента ставится ПОСЛЕ exec:
  `bossman -p "<задача>" exec --agent <id>`. Экономию не заявлять без telemetry (модель, маршрут, токены, $).
- Тесты: на ПК владельца можно запускать целевые выборки (свои файлы), полный прогон — один раз на
