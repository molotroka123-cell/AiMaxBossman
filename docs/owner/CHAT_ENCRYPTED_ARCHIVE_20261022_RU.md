# Долгое нажатие на чат: зашифрованный архив и удаление навсегда (22.10)

Запрос владельца: «Долгим нажатием на чат можно навсегда удалить его или архивировать в зашифрованную папку».

## Как пользоваться (телефон)

1. Откройте ящик «Чаты». Удерживайте строку чата 0,5 секунды (на ПК: правая кнопка мыши или Shift+F10 / клавиша «Меню»). Сдвиг пальца больше чем на 8 px или раннее отпускание отменяют жест, обычное касание открывает чат как раньше.
2. Лист действий: «Архивировать в зашифрованную папку», «Удалить навсегда», «Отмена».
3. Архив: одно подтверждающее нажатие «Зашифровать». Результат: «Зашифровано, чат убран из списка. Ключ хранится на ПК (DPAPI)».
4. Удалить навсегда: нужно набрать последние 6 символов id чата (они показаны в листе). Шлюз телефона проверяет ввод, а Bossman на ПК повторно требует `confirm=<id чата>`.
5. В ящике есть пункт «Зашифрованный архив»: список с кнопками «Восстановить» и «Удалить архив» (второе спрашивает подтверждение).

Если операция не удалась, чат остаётся в списке, а сообщение об ошибке показано в листе.

## Как это устроено

- Файл сессии чата шифруется как непрозрачные байты (AES-256-GCM, случайный nonce 12 байт, id чата в AAD). Модуль не разбирает содержимое, не пишет его в журнал и не отдаёт в API.
- Архив: `<каталог данных>\chat-archive\<id>.bcarchive` (заголовок BCARC, версия, nonce, шифртекст).
- Порядок: зашифровать, записать атомарно, прочитать с диска и расшифровать, сверить sha256, убедиться, что живой чат не менялся, пометить метаданные, и только потом удалить живой файл. Пока проверка не прошла, живой файл и есть резервная копия. Любой сбой откатывает пометку и удаляет только новый архив.
- Восстановление: расшифровка, запись в каталог живых сессий (если чат с таким id уже есть, ответ 409), проверка sha256, затем архивный файл удаляется. Подмена id файла, порча хотя бы одного байта или чужой ключ дают отказ без потерь.
- Названия в списке архива берутся только из метаданных окна (`threads-meta.json`), а не из расшифрованного содержимого. Если у чата не было названия, показывается «Чат …abc123».

API на ПК: `POST /api/chat/threads/{id}/archive-encrypted`, `GET /api/chat/archive`, `POST /api/chat/archive/{id}/restore`, `DELETE /api/chat/archive/{id}`. Шлюз телефона: `/m/api/threads/{id}/archive-encrypted`, `/m/api/archive`, `/m/api/archive/{id}/restore`, `DELETE /m/api/archive/{id}`, `/m/api/threads/{id}/delete-forever`.

## Где лежит ключ

`%LOCALAPPDATA%\Bossman\keys\chat-archive.key`: 32 случайных байта, созданные при первой архивации и обёрнутые Windows DPAPI (область текущего пользователя Windows). Ключ не пишется в журнал, не возвращается ни одним API и не входит в git (`git`-проверка есть в тесте). Переопределение пути: переменная `BOSSMAN_KEYS_DIR`. Вне Windows (только тесты) ключ хранится файлом с правами 0600, в журнал пишется предупреждение.

Нет файла ключа, а архивы уже есть: ответ 503 `CHAT_ARCHIVE_KEY_UNAVAILABLE`, новый ключ не создаётся (он сделал бы старые архивы нечитаемыми). Повреждённый файл ключа не перезаписывается.

## Если ключ потерян

**Архивы без ключа восстановить невозможно.** Это следствие шифрования, обходного пути нет и не должно быть. Ключ обёрнут DPAPI: он открывается только тем же пользователем Windows на том же ПК. Переустановка Windows, смена пароля через сброс, перенос профиля или копия только папки `chat-archive` на другой ПК означают потерю архивов. Поэтому копируйте вместе файл `chat-archive.key` и папку `chat-archive` только через средства, которые сохраняют привязку к пользователю (обычный бэкап профиля), и не рассчитывайте на открытие архива на другом ПК.

## Что НЕ сделано и чего нужно остерегаться

- Не проверялось на iPhone: iPhone в этой работе не было. Проверены jsdom (жест, лист, ввод id, ошибки) и тесты шлюза. Поведение долгого нажатия в Safari на iOS (жест при прокрутке, системное меню, вибрация: на iOS `navigator.vibrate` недоступен) нужно проверить руками.
- Живой файл чата после архивации удаляется обычным удалением, без затирания. На SSD старые блоки могут остаться до перезаписи.
- Вложения чата (`chat\attachments`) не шифруются и остаются на месте. Удаление навсегда их тоже не трогает (как и раньше).
- Название чата в `threads-meta.json` остаётся открытым текстом: оно нужно для списка архива.
- Задачи и ответы чата хранятся в базе Bossman, а не в файле сессии: архивация шифрует только файл сессии (список ходов), ответы в базе остаются как были.
- Перед архивацией остановите выполняющийся ответ в этом чате: если в чат дописали ход во время архивации, она откажет (409), но запущенную задачу сама не остановит.
- Ключ защищён учётной записью Windows, а не отдельным паролем. Кто работает на ПК под вашей учётной записью, может расшифровать архивы.
