# Обучение Gemma 2 на арендованном GPU, датасет HF 95 ГБ — архитектура и расчёт времени (23.10.2026)

Запрос владельца: «Подготовь архитектуру для обучения модели на арендованных мощностях моей Gemma 2 на датасете,
что я выбрал на Hugging Face; сегодня вечером запустим; датасет 95 ГБ; рассчитай время».

## Что нужно от владельца до вечера (без этого запуск невозможен)

1. **Какая Gemma 2**: 2B, 9B или 27B (на ПК в ollama есть `gemma4-31b-uncensored`, это не Gemma 2). Время ниже дано для всех трёх.
2. **ID датасета на HF** (`org/name`, конфиг, сплит) и его лицензия: гейт `tools/training_secure_gate.py` требует
   происхождение; сторонний датасет для весов допускается только твоим явным решением (это оно) — в манифест пишем
   `source=owner_selected_hf`, лицензию и sha256 снимка.
3. **Провайдер аренды.** RunPod запрещён твоим правилом 11.10; если снимаешь запрет — скажи словом «RunPod можно».
   Иначе: Lambda (стабильно), Vast.ai (дешевле, interruptible). Твоя процедура RunPod/kohya (09.10) переиспользуется один в один.
4. **Правило личных данных действует**: на арендованный GPU уходят только датасет HF и базовые веса, никаких
   фото/голоса/чатов/методички Jeff. Ключи — только HF read-token на время загрузки.

## Архитектура (ничего нового не изобретаем: HF `transformers` + `peft` + `trl`, гейт из дерева)

| Слой | Решение |
|---|---|
| Данные | `datasets` streaming с HF → токенизация → packed-шарды `arrow` на локальном NVMe пода (95 ГБ raw ≈ 20–25 млрд токенов при ~4 байт/токен). Снимок: `manifest.json` (sha256 шардов, число токенов), гейт `training_secure_gate.py --dataset <snapshot> --lock requirements-train.lock --venv <venv> --require-offline` → PASS обязателен |
| Среда | отдельный venv на поде из `requirements-train.lock` с хэшами (`--require-hashes`), `PIP_NO_INDEX` после прогрева, `HF_HUB_OFFLINE=1` на время обучения, `litellm` запрещён (компромисс 21.10), `trust_remote_code=False`, только `safetensors` |
| Модель | базовая Gemma 2 по закреплённой ревизии HF + sha256; **LoRA/QLoRA** (r=16–64, все linear) — не полный fine-tune: вес адаптера сотни МБ, откат мгновенный |
| Обучение | `trl.SFTTrainer`, bf16, packing, seq 4096, grad-checkpointing, lr 1e-4 (LoRA), cosine, warmup 2%; чекпоинт каждые 30 мин на диск пода + копия на ПК (rsync) — обрыв аренды не теряет работу |
| Оценка | holdout 1% датасета (perplexity до/после) + 20 задач `tools/llm_task_bench.py` до/после; красная команда: инъекции/секреты (тесты рантайма) на адаптере; без прироста — `OUTCOME_UNPROVEN`, в продукт не идёт |
| Доставка | адаптер + `provenance.json` (dataset sha256, lock-хэш, base revision, команда) → на ПК → слияние в GGUF для ollama только после оценки |

## Расчёт времени (честные формулы, bf16, LoRA; на подготовку данных +1–3 ч)

Compute ≈ 6 × параметры × токены (LoRA экономит ~25–35 %, но forward/backward по базе остаются).
Полезная производительность: H100 ≈ 400 TFLOPS, A100 ≈ 200 TFLOPS (реально 35–45 % от пика).

| Gemma 2 | Весь датасет, 1 эпоха (~22 млрд токенов) | 1 % датасета (~220 млн токенов) | 5 % (~1,1 млрд) |
|---|---|---|---|
| 2B | 8×H100: ~3,5 дня; 1×H100: ~27 дней | 1×H100: **~2 ч**; 8×H100: ~20 мин | 1×H100: ~10 ч; 8×H100: ~1,5 ч |
| 9B | 8×H100: ~16 дней; 1×H100: >4 мес | 1×H100: **~9 ч**; 8×H100: ~1,3 ч | 8×H100: ~6,5 ч |
| 27B | 8×H100: ~7 недель | 8×H100: **~4 ч**; 1×H100 (QLoRA): ~30 ч | 8×H100: ~20 ч |

Вывод: **за один вечер весь 95 ГБ датасет не проходит ни одна Gemma 2**. Реалистичный вечерний прогон —
Gemma 2 9B, LoRA, 1 % датасета (~220 млн токенов, стратифицированная выборка) на 1×H100: ~9 ч + 2 ч подготовка;
или Gemma 2 2B на том же объёме: ~2 ч + подготовка. Полный проход — многодневная аренда 8×H100 (ориентир 9B: 16 дней,
≈ $8–10 тыс. при $25/ч), что имеет смысл только после доказанного прироста на 1–5 %.

Загрузка 95 ГБ с HF на под: 15–60 мин при 0,5–1 Гбит/с; токенизация 22 млрд токенов: ~1–2 ч на 16 vCPU.

## Стоимость аренды (ориентир 23.10; проверить прайс провайдера перед стартом)

Ставки: 1×H100 80GB ≈ $2.5/ч (Vast.ai $1.8–2.5, Lambda ≈ $3), узел 8×H100 ≈ $22/ч, 1×A100 80GB ≈ $1.5/ч.
Время = обучение из таблицы выше + 2 ч подготовки (скачивание, токенизация, гейт) + 10 % запас на чекпоинты/копирование.
Диск 300 ГБ NVMe ≈ $0.1–0.3/ч, трафик с HF обычно бесплатен; выключать под сразу после копирования адаптера.

| Gemma 2 | 1 % датасета (~220 млн токенов) — вечерний прогон | 5 % (~1,1 млрд) | Полная эпоха (~22 млрд) |
|---|---|---|---|
| 2B | 1×H100: ~4,5 ч → **≈ $11–14** | 1×H100: ~13 ч → ≈ $33–40 | 8×H100: ~3,5 дня → ≈ $1 900–2 200 |
| 9B | 1×H100: ~12 ч → **≈ $30–36**; 8×H100: ~3,5 ч → ≈ $80 | 8×H100: ~9,5 ч → ≈ $210–240 | 8×H100: ~16 дней → ≈ $8 500–9 600 |
| 27B | 8×H100: ~6,5 ч → **≈ $140–160**; 1×H100 QLoRA: ~33 ч → ≈ $85–100 | 8×H100: ~24 ч → ≈ $530–600 | 8×H100: ~7 недель → ≈ $26 000–29 000 |

На A100 вместо H100: время ×2, цена ×0.6 → итог ≈ +20 % к сумме при вдвое большем ожидании.
Рекомендация по деньгам: сегодня 9B LoRA на 1 % за ≈ $30–36 (или 2B за ≈ $12) → утром оценка; полная эпоха — только после
доказанного прироста на 1–5 %, и тогда это бюджет в тысячи долларов, а не вечер.

## Порядок вечером (каждый шаг = улика)

1. Владелец: размер Gemma 2, ID датасета, провайдер (и слово по RunPod). 2. Под: venv из lock, гейт supply chain.
3. Стриминг 1 % датасета → шарды → манифест → гейт датасета PASS. 4. Старт SFT с чекпоинтами + watchdog (как в
RunPod-процедуре 09.10: автостоп при бездействии, лимит часов). 5. Утром: оценка holdout + бенч 20 задач → отчёт в пульт
с числами до/после и стоимостью аренды. 6. Под выключить сразу после копирования адаптера.
