# Mimics 2.0 — определение гейта и пороги (зафиксированы 10.10.2026 ДО первого прогона)

Определение владельца (10.10, дословно): «Mimics 2.0 мимика на 99% похожая на референс человека по видео без артефактов
когда накладываем лицо».

Перевод в проверяемое: после замены лица (Genjutsu / FaceFusion) **выражение лица на результате совпадает (до 99%)
с выражением человека в исходном видео, и в месте наложения лица нет артефактов**. Это не Gate 1 (там проверяется,
что лицо ЗАМЕНЕНО и осталась анимация головы); Mimics 2.0 проверяет выражение лица ВНУТРИ заменённого лица.

Инструмент: `tools/video_gate/mimics_gate.py` (metric_version `m1`). Правило из `VIDEO_PIPELINE_STAGES_20261010.md`
действует и здесь: пороги ниже зафиксированы коммитом ДО запуска инструмента на результатах; метрика меняется
только как исправление метода, со старым результатом в записи (`m1` остаётся рядом с `m2`).

## Что сравнивается

Пара (исходное видео, результат замены) — **одни и те же кадры**, каждый кадр, без выборки. Результат — доставляемый
файл (H.264 crf 10 из `faceswap.finish`), исходник — как его видит Bossman (кадры после CFR-нормализации).
Выражение лица извлекается одним и тем же независимым открытым экстрактором из обеих сторон:
MediaPipe FaceLandmarker (Apache-2.0, 478 точек + 52 blendshape-коэффициента), режим IMAGE (без внутреннего
сглаживания по времени, чтобы кадры были независимы). Лицо выбирается по исходнику (самое крупное), в результате —
ближайшее к нему.

## Пороги

| Код | Что меряется | Порог |
|---|---|---|
| M1a | средняя по кадрам косинусная близость 52 blendshape (без `_neutral`) исходник ↔ результат | ≥ 0.99 |
| M1b | медиана по каналам корреляции Пирсона во времени для каналов jawOpen, mouthSmileL/R, eyeBlinkL/R, browDownL/R, browInnerUp, browOuterUpL/R, mouthPucker, cheekPuff, eyeSquintL/R; берутся только каналы с std(исходник) ≥ 0.05; их должно быть ≥ 2 | ≥ 0.99 |
| M1c | медиана по тем же каналам отношения амплитуд std(результат)/std(исходник) | в [0.90, 1.10] |
| M2 | ошибка контуров выражения: средний по кадрам и признакам модуль разности признаков (результат − исходник), в долях высоты лица (точки 10→152). Признаки: раскрытие рта (13–14), ширина рта (61–291), вертикальное положение левого/правого угла рта относительно центра губ, раскрытие левого/правого глаза (159–145, 386–374), высота левой/правой брови над глазом (105–159, 334–386); измеряются в системе координат линии глаз; из каждого признака вычитается его медиана по клипу (геометрия лица другого человека не считается ошибкой выражения) | ≤ 0.01 (1% высоты лица) |
| M3a | швы: отношение средней величины градиента (Собель, серый) результата к исходнику в кольце вокруг области изменения (± 0.03 высоты лица от границы маски изменений, маска = макс. по каналам \|результат − исходник\| > 8) | ≤ 1.35 |
| M3b | швы: избыток цветового скачка ΔE76 (Lab) между полосой внутри и снаружи границы, результат минус исходник, max(0, ·), среднее по кадрам / 95-й перцентиль по кадрам | ≤ 4.0 / ≤ 8.0 |
| M3c | резкость лица: медиана по кадрам отношения дисперсии лапласиана внутри овала лица результата к исходнику | в [0.70, 1.30] |
| M3d | личность (arcface к фото-эталонам): минимум по кадрам; для варианта дополнительно среднее не ниже среднего baseline на том же клипе − 0.03 | ≥ 0.45; ≥ baseline − 0.03 |
| M3e | потерянные лица: кадры, где лицо в исходнике найдено, а в результате (FaceFusion yolo_face или MediaPipe) нет | = 0 |
| M3f | дрожание T6 (RMS второй разности отклонения 68 точек / межзрачковое, как в `animation_gate.py`) | ≤ 0.02 (порог Gate 1) ИЛИ ≤ 1.10 × baseline на том же клипе |
| M0 | покрытие: доля кадров, где MediaPipe нашёл лицо и в исходнике, и в результате; кадры без лица в M1/M2 не входят | ≥ 0.95, иначе клип не засчитывается |

Вердикт клипа: PASS, если пройдены все M0, M1a–c, M2, M3a–f. Вердикт этапа «Mimics 2.0 99%»: PASS на ≥ 3 клипах
(реальных, из доставляемого конвейера) подряд без единого FAIL.

## Контроли (считаются в каждом прогоне, до вердикта)

1. **Noise floor (положительный контроль).** Исходник, перекодированный как доставка (libx264 crf 10, preset slow,
   yuv420p), сравнивается с самим исходником теми же формулами M0–M3 (кроме M3d, M3e: лица нет подменённого).
   Это потолок инструмента: насколько «99%» вообще достижимо при кодеке. Должен проходить M1/M2/M3a–c/M3f;
   иначе инструмент недостоверен и вердикт клипа = `INSTRUMENT_INVALID`.
2. **Замороженное выражение (отрицательный контроль, уровень метрики).** Ряд blendshape и контуров результата
   заменяется кадром 0 на все кадры. Должен ПРОВАЛИТЬ M1a/M1b/M2, иначе клип «неинформативен» (в нём нет
   выражения) и не засчитывается ни как PASS, ни как FAIL.
3. **Сдвиг во времени (отрицательный контроль, уровень метрики).** Ряд результата сдвигается на 12 кадров.
   Должен ПРОВАЛИТЬ хотя бы M1b или M2.
4. **Вставленный шов (отрицательный контроль, пиксели).** В 12 равномерно выбранных кадрах результата внутри
   овала лица яркость +14 жёстким краем; и отдельно, в тех же кадрах, внутри овала гауссово размытие σ = 2.
   Первое должно ПРОВАЛИТЬ M3a или M3b, второе — M3c.

## Варианты улучшения выражения (проверяются по одному, тем же гейтом)

Только открытые, локальные, DirectML/CPU. Окно для вариантов: 96 кадров с наибольшей активностью выражения в
**исходнике** (сумма дисперсий jawOpen, eyeBlinkL/R, mouthSmileL/R, browInnerUp по окну, шаг 8 кадров; выбирается
по исходнику до взгляда на результаты), нарезка lossless; baseline на этом окне пересчитывается тем же пресетом.

| Вариант | Что | Флаги поверх пресета `quality` |
|---|---|---|
| V0 | baseline = пресет `quality` продукта | — |
| V1 | пресет `lively` (как в продукте сейчас) | restorer live_portrait, factor 40 (= 0.48 силы) |
| V2–V5 | развёртка FaceFusion `expression_restorer` (MIT, KwaiVGI LivePortrait ONNX) | factor 50 / 67 / 83 / 100 (= сила 0.6 / 0.8 / 1.0 / 1.2; шкала FaceFusion 0–100 → 0–1.2) |
| V6 | лучший factor, но restorer ПОСЛЕ enhancer | порядок процессоров swapper, enhancer, restorer |
| V7 | `face_editor` (LivePortrait, статичные ползунки — НЕ управляется исходником) | значения по умолчанию; ожидание: нет выигрыша, фиксируется как ограничение |

Лучший вариант выбирается по M1a на C1-окне; затем он и V0 прогоняются на окнах C4 и C5. Провалившиеся варианты
остаются в отчёте. Если нужен CUDA — в отчёте точный рецепт RunPod, ничего не арендуется.
