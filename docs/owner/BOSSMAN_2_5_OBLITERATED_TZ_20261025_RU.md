## 1. Зачем этап

За 3 месяца собрана мощная локальная инфраструктура, но **выручки ноль** и каждый день повторяются одни боли:

| Боль | Факт (замеры 24–25.10) |
|---|---|
| Тяжёлые задачи дерутся за 120 ГБ общей памяти | Jeff перезагружал Gemma (27–32 ГБ) каждые 10 мин и дважды убил генерацию видео; 720p LTX не влез |
| Видео людей с артефактами | LTX-2.5 размазывает быстрые движения; Wan VACE — smoke PASS, в продукт не встроен |
| Продукт для денег не собран в один поток | лендинг /studio/ живой, 3 образца есть, путь заказ → сдача делается руками |
| Паритет поверхностей | в Telegram-пульте нет Studio, ниш, памяти, звонков |
| Самоулучшение не доказано | уроки в памяти не меняли исход (замер), нет набора «до/после» на новых задачах |

**Цель 2.5:** один Bossman, который (1) выполняет платные заказы Motion Studio от заявки до сдачи на локальном
стеке, (2) сам управляет ресурсами ПК, (3) кодит и улучшает себя связкой локальных, бесплатных и платных облачных
моделей — и **доказывает** улучшение на скрытых сценариях, а не словами.

«Obliterated» = снимаем искусственные ограничения в **локальном** мозге (uncensored/abliterated модели по умолчанию
для локального чата и креатива владельца), но жёсткие пределы (раздел 2) не трогаем.

## 3. Сквозные принципы (для всех модулей)

- **P1 Одна система.** Один Task Kernel, одна очередь, одна память, один router, один STOP. Расширяем
  существующее (`tools/resource_governor`, `bcc/features/studio_orders.py`, `tests/owner_scenarios/`,
  `tools/coding_swarm.py`, `tools/three_model_audit.py`), вторую систему не создаём. Сначала готовый OSS.
- **P2 Одна задача — один ID.** Телефон, desktop, CLI и Telegram видят один task ID, статус, ожидающие
  подтверждения и итоговый отчёт.
- **P3 Вывод модели — не доказательство.** `SUCCEEDED` ставит только верификатор (тест, постусловие, хеш, просмотр
  владельца). Kimi предлагает, Qwen независимо проверяет конкретный diff, решает интегратор, принимает владелец.
  Ни одна модель не утверждает свой патч.
- **P4 Честные статусы.** `PASS | FAIL | BLOCKED | NOT_RUN | UNKNOWN_OUTCOME | RECONCILE_REQUIRED`. Внешнее действие
  с неизвестным исходом после сбоя не повторяется молча — только сверка (reconcile).
- **P5 Отчёт привязан к версиям.** Каждая квитанция в `docs/audits/`: source SHA, runtime SHA, task ID, точные
  provider/model ID, число вызовов, стоимость, проверки (команды и счёт), SHA-256 артефакта, решение владельца.
- **P6 Фича доказана, а не обёрнута** (правило 23.10): unit-тесты + живая проверка через реальный пульт +
  квитанция в merge-коммите.

## 4. Модули и критерии приёмки

### M0. Только боевой режим (P0, вводная (в))
С 25.10 Bossman работает только в боевом режиме: тестовые разговоры архивируются и убираются из рабочих списков.
- Тестовые разговоры определяются **только по метаданным** (источник/флаг теста, создатель-агент, тестовый
  participant, префикс заголовка из тестовых наборов) — содержимое не читается.
- Архив: зашифрованная выгрузка на `D:\Bossman\archive\test-conversations\<дата>\` + список id; затем удаление из
  рабочей БД. Новые тестовые прогоны пишут в отдельную тестовую БД (`BCC_DATA_DIR` тестов), не в боевую.
- **Приёмка:** (1) dry-run показывает число и id кандидатов без содержимого; (2) после прогона в боевой БД 0
  разговоров с тестовыми маркерами; (3) восстановление из архива проверено на копии БД; (4) тест: прогон pytest
  не создаёт записей в боевой БД; (5) квитанция с числами и SHA-256 архива.

### M1. Motion Studio — денежный путь (P0, первым)
Один пакет, продаём вручную сейчас, не дожидаясь платформы.
- **Пакет:** ролик ≤ 10 с, 720×1280, 1 вариант, 1 правка, срок 48 ч, без лиц/голосов людей. Цена — решение
  владельца (OWNER_REQUIRED). Пресет — лучший из готовых (`product_spin` или `hand_reveal`), выбирается после
  проверки лицензии LTX-2.5 (если коммерция запрещена — замена на локальную модель с разрешающей лицензией).
- **Автомат заказа** поверх `studio_orders`: `draft → quoted → accepted → preflight → generating →
  qc_failed|qc_passed → owner_review → rework|approved → delivered → closed`, плюс `cancelled` и
  `reconcile_required`. Каждый переход — событие с причиной.
- **Manifest заказа:** входы (хеши), пресет, модели и версии, сиды, параметры, артефакты (SHA-256), время, ретраи.
  Повторный запуск идемпотентен (ключ = order_id + шаг), без дублей рендера.
- **Gate сдачи (жёсткий):** нельзя перейти в `delivered` без: license_id модели с commercial_use=true, права на
  исходники клиента, consent_artifact_id если есть человек/лицо/голос, видимая метка ИИ + водяной знак,
  provenance-хеш, «да» владельца.
- **QC:** контакт-лист + кадры на пиках движения; метрики (резкость по Лапласиану, разница соседних кадров) пишутся
  как сигналы; пороги калибруются на 3 образцах и первых заказах; решение — всегда просмотр владельцем.
- **Себестоимость:** `∫P·dt × тариф + облако + труд владельца (мин) + ретраи`; P — с датчика, если нет — оценка по
  замеренному профилю с пометкой `estimated`.
- **Сдача:** ссылка/архив владельцу в пульт; ссылка для клиента случайная, ограничена по сроку, отзываемая;
  отправляет только владелец.
- **На время платного рендера** действующий governor работает в режиме `pause` для Jeff (до M2).
- **Приёмка:** (1) unit-тесты автомата: недопустимые переходы отклоняются, `delivered` без gate невозможен;
  (2) тест F7: клиент A не видит заказ клиента B, личность берётся из серверного токена, не из заголовка;
  (3) живой прогон: ручная заявка → сдача ≤ 48 ч на локальном стеке, квитанция себестоимости; (4) один прогон
  с принудительным сбоем посреди рендера — нет дубля, статус `reconcile_required` или чистое продолжение.

### M2. Resource Governor 2.0 (P0, вторым)
Расширение `tools/resource_governor/` (WARM-UP, GENERATION GUARD, LOAD GUARD, Jeff keep/pause уже есть).
- **Замеренные профили:** `ConsumerProfile` (adapter, флаги `gpu_exclusive`, `ollama_residency`, политика
  вытеснения) и `Measurement` (config_hash модели/разрешения/длительности/шагов, P95 пика, число замеров ≥ 10,
  включая холодный старт). Запуск с неизвестным профилем — отказ с причиной, не «на удачу».
- **Аренды:** два вида — `resident` (модель в памяти) и `compute` (активная генерация, максимум одна). Журнал
  SQLite WAL, один писатель (процесс governor), `idempotency_key`, TTL + heartbeat, fencing-token (поздний worker
  со старым токеном не стартует). Инвариант: `sum(reserved) + candidate ≤ controlled_budget`, бюджет — измеренный,
  а не номинальные 120 ГБ.
- **Приоритеты** (v1): владелец-интерактив > Jeff-ответ > заказ Studio > фоновые генерации > самоулучшение.
  Очередь: приоритет → aging → FIFO.
- **Jeff/Ollama:** весь доступ через adapter; конечный `keep_alive` (не `-1`), продлевается арендой; выгрузка =
  дождаться нуля потоков → `keep_alive: 0` → опрос `/api/ps` → подтверждение освобождения памяти → только
  потом снять резерв. Не подтверждено за таймаут — тяжёлая задача не стартует. Профили с `gpu_exclusive`
  (LTX 720p, Wan VACE) выгружают всё; фото — Jeff остаётся, если влезает по аренде (правило владельца 21.10).
- **Вытеснение:** сначала выгрузка неактивных моделей, затем остановка фоновой задачи на checkpoint. Платный
  рендер не убивается ради фона. Soft-порог запрещает новые запуски, hard-порог — управляемая отмена фона;
  пороги калибруются (не жёсткие 3/8 ГБ).
- **Рестарт:** новый epoch; `running` → `unknown`; сверка `/api/ps` и своих процессов по Job Object/identity (не
  только PID). Принимается обратно только процесс с валидным токеном; иначе останавливается **только своё**
  дерево процессов (чужие не трогаем — AGENTS.md). Платный рендер автоматически не повторяется.
- **API/UI:** `GET /api/resources/state`, `POST /api/resources/lease`, `DELETE /api/resources/lease/{id}`;
  карточка «Ресурсы» в пульте с причиной ожидания.
- **Приёмка:** (1) property-тест «сумма резервов ≤ бюджет» на 1000 случайных последовательностей; (2) 50
  параллельных запросов — нет двойной выдачи; (3) тест fencing и рестарта; (4) живой: 20 циклов «чат Jeff +
  генерация фото» без ручной перезагрузки Gemma; (5) неделя без «предохранитель убил генерацию» при работающем
  Jeff (журнал governor).

### M4. Учимся у сильных моделей (P1, вводная (б))
- **Сбор:** рассуждения и ответы Kimi K3.1 Pro (и других облачных при наличии) по задачам роя сохраняются
  локально: `D:\Bossman\datasets\cloud-reasoning\<YYYY-MM-DD>.jsonl`. Схема строки: `id, ts, provider, model_id,
  task_id, source_sha, prompt_sha256, prompt (только санированный код/синтетика), reasoning, answer, verifier_outcome
  (тесты PASS/FAIL), cost_usd, training_use, terms_ref`.
- **`training_use = PENDING_TERMS_CHECK`** у каждой записи, пока условия Moonshot/7API явно не разрешат обучение;
  смена статуса — только после проверки условий и решения владельца, с ссылкой на текст условий. Датасет
  никогда не в git и не пушится; в облако не уходит.
- **Использование до разрешения:** только как источник оценки и образцов (few-shot) и исполняемых уроков
  (проверки, чек-листы-тесты), не для обучения весов. Обучение — после разрешения, только локально (RunPod запрещён).
- **Доказательство переноса:** урок/образец засчитывается, только если локальная модель на **новых** скрытых
  сценариях M5 (категория coding/self-repair) с ним лучше baseline без него. Уроки, не давшие прироста, помечаются
  `NO_TRANSFER` и не используются в боевом промпте.
- **Приёмка:** (1) тест: запись без `training_use` или с личными данными отклоняется; (2) тест: экспорт в
  обучающий набор невозможен при `PENDING_TERMS_CHECK`; (3) отчёт переноса: baseline vs с уроками на ≥ 30 скрытых
  задачах, с доверительным интервалом.

  (McNemar / bootstrap). Пороги фиксируются до прогона.

## 8. Предложение правки AGENTS.md (не применено, решает владелец)

Сейчас AGENTS.md говорит: «Argon remains the sole product integrator» (раздел про делегирование Gemma) и
«One integrator changes shared product code at a time». Владелец 25.10 ведёт Claude как интегратора, а Kimi/Qwen/
бесплатные модели — как кодеров. Предлагаемая формулировка:

> **Integrator (owner 25.10).** Claude is the product integrator for Bossman 2.5: the only writer of shared product
> code, it applies patches, runs checks, commits to work branches and opens PRs. Kimi K3.1 Pro, Qwen 3.8 Flash, free
> cloud models (Nemotron Ultra :free, Gemini Flash, …) and local models are coders/reviewers: they return patches and
> reviews as text and never approve their own patch. Argon, if running, audits the same SHA. One integrator changes
> shared product code at a time; the owner alone approves merges to main, spending and external actions.

Плюс строка кэпа: «Qwen 3.8 Flash (OpenRouter) — $2/day; qwen3.8-max — off unless the owner sets a cap».
