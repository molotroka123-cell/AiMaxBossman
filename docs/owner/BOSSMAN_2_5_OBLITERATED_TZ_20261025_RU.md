# Bossman 2.5 «Obliterated» — техническое задание

Дата: 25.10.2026. Основа: main `48c66884`. Статус: ЧЕРНОВИК v1 → ревью Kimi K3.1 Pro + Qwen 3.8 Flash + бесплатные модели → v2 → код.

## 1. Зачем этап

За 3 месяца собрана мощная локальная инфраструктура (чат, агенты, Direct Gen, пульт, Jeff, War Terminal, исследование ниш, аудиты), но **выручки ноль** и каждый день упираемся в одни и те же боли (замеры 24–25.10):

| Боль | Факт |
|---|---|
| Тяжёлые задачи дерутся за 120 ГБ общей памяти | Jeff перезагружал Gemma (27–32 ГБ) каждые 10 мин и дважды убил генерацию видео; 720p LTX не влез |
| Видео людей с артефактами | LTX-2.5 размазывает быстрые движения; перенос позы (Wan VACE) — smoke PASS, но не встроен в продукт |
| Продукт для денег не собран в один поток | лендинг /studio/ живой, 3 образца есть, но заказ → генерация → проверка → сдача делается руками |
| Паритет поверхностей | в Telegram-пульте нет Studio, ниш, памяти, звонков |
| Решения без вопросов | правило трёх моделей есть как скрипт, не встроено в Bossman |

**Цель 2.5:** один Bossman, который (1) сам управляет ресурсами ПК, (2) выполняет платные заказы Motion Studio от заявки до сдачи на локальном стеке, (3) кодит себя связкой локальных, бесплатных и платных облачных моделей под контролем владельца.

«Obliterated» = снимаем искусственные ограничения в **локальном** мозге (uncensored/abliterated модели по умолчанию для локального чата и креатива), но **жёсткие пределы владельца не трогаем**: приватность (личное не уходит в облако), STOP, бюджеты, согласие на лица/голоса, метка ИИ, никаких рассылок/публикаций/платежей без «да» владельца, запрет обхода фильтров face-swap.

## 2. Модули

### M1. Resource Governor 2.0 (P0)
Арбитр тяжёлых задач на общей памяти.
- Реестр «тяжёлых потребителей»: Ollama-модели (Jeff/Gemma, чат), sd-cli (фото/видео), WanGP, LTX, обучение. У каждого — оценка пика памяти (из замеров) и приоритет.
- Правило: одновременно максимум **одна** тяжёлая GPU-задача + Jeff/Gemma, если влезают по памяти с запасом ≥ 8 ГБ; иначе задача ждёт в очереди с понятной причиной.
- Приоритеты: владелец-интерактив (чат/фото по запросу) > Jeff-ответ > заказ клиента Studio > фоновые генерации > исследование/самоулучшение.
- Вытеснение: перед запуском тяжёлой задачи governor просит Ollama выгрузить неактивные модели (keep_alive=0); Jeff не перезагружает Gemma, пока идёт задача с более высоким приоритетом.
- Сторож памяти встроенный (сейчас в каждом скрипте свой): free < 3 ГБ → остановить задачу с наименьшим приоритетом, записать причину, сообщить в пульт.
- API: `GET /api/governor/state`, `POST /api/governor/lease`, `DELETE /api/governor/lease/{id}`; мобильная карточка «Ресурсы».
- Тесты: свойство «сумма пиков активных аренд ≤ лимит», вытеснение по приоритету, отказ без падения, восстановление после рестарта.

### M2. Motion Studio Pipeline (P0, деньги)
Заявка → заказ → генерация → проверка кадров → сдача.
- Заявки: Netlify Forms (после включения владельцем) + ручной ввод в пульте → `studio orders` (уже есть).
- Типы заданий Direct Gen: `product_spin`, `hand_reveal`, `lifestyle_pushin` (LTX-2.5 576×1024 → RIFE → 720×1280, метка AI + водяной знак), `pose_dance` (Wan2.2 VACE + DWPose из лицензионного видео-драйвера).
- Автоматическая проверка кадров (контакт-лист + кадры на пиках движения, эвристики размытия/двоения) + обязательный просмотр владельцем перед сдачей.
- Себестоимость из реальных секунд × энергия (датчик), маржа в заказе.
- Сдача: ссылка/архив владельцу в пульт; клиенту отправляет только владелец.
- Лицензии моделей: таблица; LTX-2.5 — проверить коммерческие условия до первого платного клиента.

### M3. Coding Swarm (P1): Kimi + Qwen + бесплатные + Claude
Bossman кодит себя.
- **Kimi K3.1 Pro** (7API, $0.10/Mtok) — архитектор и реализатор сложных частей.
- **Qwen 3.8 Flash** (OpenRouter, $0.15/$0.47 за Mtok) — быстрые реализации, тесты, ревью.
- **Бесплатные** (владелец 25.10: «бесплатки пусть тоже участвуют»): Nemotron 3 Ultra :free, Gemini 3 Flash, Nemotron 3.5 Lightning :free, North-mini-code :free — второе мнение, генерация тестов, поиск багов, объём; GLM 5.3 Flash (7API, почти бесплатно) — ревью.
- **Claude** — ТЗ, интеграция, проверка, коммиты; локальные модели — рутинные правки.
- Поток: задача → контекст (только код репозитория, без личных данных, скан на секреты) → Kimi пишет патч → Qwen + бесплатные пишут тесты и ревью → локально применяется, гоняются тесты → Claude проверяет и коммитит в ветку. В main — только с зелёными тестами и квитанцией.
- Облачные кодеры — **только чат** (патчи текстом). Kimi с доступом к ПК — только с подтверждением владельца на каждую команду.
- Бюджеты: Kimi/GLM — 7API под-ключ $5; Qwen ≤ $2/день (новый кэп); бесплатные — в пределах их лимитов (не обходить). Стоимость каждого вызова — в квитанции.
- Решения без вопросов: `tools/three_model_audit.py` → сервис `/api/decide`.

### M4. Obliterated local brain (P1)
- По умолчанию локальный чат/креатив — лучшая uncensored модель, которая влезает рядом с governor (кандидаты: gemma4-31b-uncensored, qwen38-27b-uncensored, community-qwen-uncensored); бенч на синтетических задачах владельца, выбор по метрикам.
- Дубли Ollama (3 версии Qwen3.8-27B, тестовая gemma3 26.7 ГБ) — предложение на удаление с подтверждением владельца.
- Жёсткие пределы из раздела 1 — неизменны и покрыты тестами.

### M5. Паритет поверхностей (P1)
- Telegram-пульт: `/studio`, `/niche`, `/mem` (только поиск/сводка), `/calls`, `/gov`.
- Мобильный пульт: карточка «Ресурсы» (M1), «Заказы» с переходом к роликам на проверку (M2).

### M6. Безопасность — хвосты аудита 24.10 (P2)
F6 (site_audit редиректы), F7 (личность клиента Studio из заголовка → токен клиента), F10 (DNS-rebinding в читателях), F5 (имя хоста tailnet из кода по умолчанию), живое нажатие STOP на свободном ПК.

## 4. Критерии приёмки 2.5
- Неделя без «предохранитель убил генерацию» при работающем Jeff (журнал governor).
- Заказ Studio проходит путь заявка → сдача ≤ 48 ч на локальном стеке, с квитанцией себестоимости.
- ≥ 1 оплаченный пилот (бизнес-метрика; без неё 2.5 = «инфраструктура готова, спрос не проверен»).
- Все новые функции: unit-тесты + живая проверка через реальный пульт + квитанция в `docs/audits/`.
- Затраты на облачных кодеров ≤ кэпов, учтены по вызовам.
