## 1. Почему «189 на метрику» и при каких допущениях

Гейт (`tools/intelligence_preservation_gate.py`) считает нижнюю границу удержания как
`base + wilson_lo(gained) − wilson_hi(lost)` для парных данных (одни и те же задачи в полосах raw и full).
При нуле потерянных и нуле приобретённых задач и базовой точности 1.0 граница ≥ 0.98 тогда и только тогда,
когда `z²/(n+z²) ≤ 0.02`, то есть `n ≥ 1.96² · 0.98 / 0.02 = 188.2` → **189**. Проверено численно функцией
`wilson()` самого гейта: n=188 → 0.9800 (ровно на пороге), n=189 → 0.9801.

Допущения этой цифры: 95 % Wilson, парные задачи, **ноль** расхождений между полосами, базовая точность **1.0**.
При реальных базовых точностях нужно больше задач даже при нуле потерь:

| базовая точность raw | минимум n на метрику |
|---|---|
| 1.00 | 189 |
| 0.65 (coding, rc21) | 292 |
| 0.58 (unknown, rc21) | 327 |
| 0.475 (reasoning, rc21) | 401 |
| 0.23 (structured, rc21) | 831 |

Непарная граница (без отчёта `paired`) при точности 1.0 требует ~1000 задач и при 0.9 не проходит никогда.
Preflight раннера трактует 189 как минимум для **каждой** метрики, включая второстепенные.
