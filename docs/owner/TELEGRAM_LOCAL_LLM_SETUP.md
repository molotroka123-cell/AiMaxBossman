# Telegram → Bossman → локальные модели: инструкция владельца

Статус: код и офлайн-контракты готовы (ветка `feat/telegram-local-llm-20260922`).
Живая доставка через Telegram — **OWNER_REQUIRED**: её можно проверить только
на вашем компьютере с вашим ботом. Ни один реальный токен в репозитории не
хранится и не должен храниться.

## 1. Что это и как устроено

Используется уже существующий в продукте модуль **Telegram Companion**
(`bcc.telegram_companion`). Отдельный бот-сервер не нужен:

```
Telegram (ваш личный чат)
   │  long polling getUpdates — входящий порт и публичный адрес НЕ нужны
   ▼
Telegram Companion (python -m bcc.telegram_companion, отдельный процесс)
   ├── обычное сообщение ──► MAIN  Qwen3.8-27B   http://127.0.0.1:8081/v1
   ├── /fast вопрос ───────► FAST  Qwen3.6-35B-A3B http://127.0.0.1:8082/v1
   │     (если MAIN не ответил вовремя — автоматически FAST, облако НЕ используется)
   ├── /task, /confirm, /result ─► Bossman Command Center http://127.0.0.1:8800
   │     (задачу выполняет агент Bossman со своими правами и подтверждениями)
   └── /status, /watch, /lock ──► проверка связи с Bossman (только владелец)
```

Важно понимать:

* **Беседа** идёт напрямую в локальную модель (только loopback-адреса
  `127.0.0.1`/`::1`, другие адреса конфиг не принимает). Инструментов у беседы
  нет: модель не может ничего запустить на компьютере.
* **Поручения** (`/task`) идут в Bossman: сначала бот показывает точный текст,
  потом вы подтверждаете `/confirm <код>` в течение 5 минут. Выполняет
  выделенный агент Bossman с его обычными правами.
* **Подтверждения опасных действий (approvals) из Telegram не нажимаются** —
  это намеренная граница. Если задача ждёт подтверждения, бот пришлёт
  сообщение «Задача #N ждёт подтверждения в приложении Bossman», а решение
  принимается в приложении.
* **Облако выключено** по умолчанию. Оно включается только если вы сами
  настроите ключ OpenRouter, лимит расходов > 0 и отдельно в чате `/cloud on`.
* Бот отвечает **только** Telegram-ID из списка (владелец + до 7 гостей),
  **только** в личном чате. Все остальные сообщения молча отбрасываются и не
  сохраняются. Пересланные сообщения, группы и каналы не принимаются.

## 2. Создать бота (@BotFather)

1. В Telegram откройте **@BotFather** → `/newbot`.
2. Имя: любое, например `Bossman Home`. Username: должен заканчиваться на
   `bot`, например `my_bossman_home_bot`.
3. BotFather выдаст токен вида `1234567890:AA...`. **Это пароль**: не
   отправляйте его никому, не вставляйте в чаты, в git, в скриншоты.
4. Рекомендуется: `/setjoingroups` → **Disable** (бот не нужен в группах),
   `/setprivacy` → Enable.
5. Используйте **отдельного** бота. Не используйте бот, у которого настроен
   webhook для других уведомлений Bossman: компаньон работает через polling и
   откажется стартовать (`WEBHOOK_CONFLICT_USE_SEPARATE_COMPANION_BOT`),
   чтобы не сломать чужой webhook.

## 3. Узнать свой числовой Telegram ID

Нужен числовой **user ID** (не @username). Способы:

* напишите боту **@userinfobot** (или @getmyid_bot) — он ответит `Id: 123456789`;
* в личном чате user ID и chat ID совпадают — компаньон это и требует.

Этот ID — ваш allow-list. Не публикуйте его вместе с токеном.

## 4. Подготовить модели

Модели запускаются вашим скриптом `C:\Users\asd\Bossman\start-models.ps1`
(llama.cpp b10964 Vulkan). Обязательные флаги: `--jinja --reasoning off`.
Без `--reasoning off` Qwen тратит весь лимит токенов на рассуждения и
возвращает пустой ответ — бот ответит «локальная модель сейчас не отвечает».

```powershell
# MAIN (основная)
powershell -ExecutionPolicy Bypass -File C:\Users\asd\Bossman\start-models.ps1 -Target main
# FAST (по желанию; нужна свободная RAM — см. раздел 10)
powershell -ExecutionPolicy Bypass -File C:\Users\asd\Bossman\start-models.ps1 -Target fast
```

> Осторожно: `-Target stop` останавливает **все** llama-server, включая
> GPT-OSS на 8083 и любые идущие прогоны.

Проверка, что сервер жив, и **точное имя модели**:

```powershell
(Invoke-RestMethod http://127.0.0.1:8081/v1/models).data.id
```

llama-server без `--alias` называет модель полным путём к файлу, и в ответе
присылает именно это имя. Компаньон сверяет имя в ответе с конфигом, поэтому в
конфиг нужно вписать ровно эту строку. На этой машине (без `--alias`):

| Роль | URL | `id` модели |
|---|---|---|
| MAIN | `http://127.0.0.1:8081/v1` | `C:\Users\asd\Bossman\models\qwen38-27b\Qwen3.8-27B-UD-Q5_K_M.gguf` (проверено 2026-09-22) |
| FAST | `http://127.0.0.1:8082/v1` | `C:\Users\asd\Bossman\models\qwen36-35b-a3b\Qwen3.6-35B-A3B-UD-Q5_K_M.gguf` (NOT_VERIFIED: FAST не был загружен; выведено из start-models.ps1) |

Удобнее: при следующем перезапуске моделей добавить в `start-models.ps1`
`'--alias','main'` / `'--alias','fast'` — тогда `id` будет просто `main`/`fast`.

## 5. Bossman (Command Center)

Беседа работает и без Bossman. Для `/task`, `/result`, `/status` нужен
запущенный Command Center на `127.0.0.1:8800`:

```powershell
# пока ярлык Start-Bossman.cmd сломан (Edge relaunch), запуск сервера напрямую:
cd C:\Users\asd\Bossman\app\BOSSMAN-Windows-x64-0c1cbe651f52
.\runtime\python.exe -m bcc
```

Для поручений:

1. Токен Command Center лежит в `%LOCALAPPDATA%\Bossman\CommandCenter\token`.
   Его вводят в форму настройки (поле «Токен Command Center»). Не пересылайте его.
2. В приложении Bossman создайте **отдельного агента** для поручений из
   Telegram (с минимально нужными правами и бюджетом) и запомните его числовой
   ID. Без агента `/task` честно ответит «исполнитель не назначен».

## 6. Настроить компаньон (токен — только локально)

Рекомендуемый способ — зашифрованная настройка через локальную форму:

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\asd\Bossman\wt-telegram\scripts\Start-TelegramCompanion.ps1 -Mode setup
```

Откроется страница `http://127.0.0.1:<порт>` (только на этом компьютере).
Заполните: токен бота, ваш Telegram ID, сервер модели
`http://127.0.0.1:8081/v1`, точное `id` MAIN из раздела 4, адрес Bossman
`http://127.0.0.1:8800`, токен Command Center, ID агента.

Результат:

* `%LOCALAPPDATA%\Bossman\telegram-companion\config.json` — настройки без секретов;
* `%LOCALAPPDATA%\Bossman\telegram-companion\credentials.enc` — токены, зашифрованы,
  права только у вашей учётной записи.

Затем **откройте `config.json` в блокноте и добавьте** (важно: в JSON обратные
слэши удваиваются):

```json
  "local_timeout": 180,
  "fast_url": "http://127.0.0.1:8082/v1",
  "fast_model": "C:\\Users\\asd\\Bossman\\models\\qwen36-35b-a3b\\Qwen3.6-35B-A3B-UD-Q5_K_M.gguf",
  "fast_timeout": 60
```

Почему 180 секунд: MAIN на этой машине генерирует ~8.8 токена/с и
обрабатывает запрос ~57–71 токен/с (по логам `main-server.err.log`). Ответ в
512 токенов — около 60 с плюс чтение истории, до ~100 с. Значение по умолчанию
(15 с) почти всегда даст «модель не отвечает». FAST (~53 токена/с) укладывается
в 60 с. Если FAST не нужен — не добавляйте строки `fast_*`.

> Поля `fast_*` и `local_timeout` больше 60 поддерживает только код этой ветки.
> Установленная сборка 0c1cbe65 их не знает (выдаст
> `LOCAL_CONFIGURATION_ERROR`). Пока нет новой сборки, запускайте с
> `-RepoRoot C:\Users\asd\Bossman\wt-telegram` (см. раздел 7) — тогда
> используется runtime установленного продукта и код из этой ветки.

Альтернатива без формы (для опытных): создать `config.json` вручную и положить
секреты в `%LOCALAPPDATA%\Bossman\telegram-companion\companion.env`:

```
TG_COMPANION_BOT_TOKEN=<токен от BotFather>
TG_COMPANION_CORE_TOKEN=<содержимое файла token Command Center>
```

Скрипт читает только ключи `TG_COMPANION_*`, только в свой процесс, значения
не печатает и откажется читать файл, лежащий внутри git-репозитория. Файл не
зашифрован — зашифрованная настройка через форму надёжнее. Секреты в
`config.json` компаньон не принимает намеренно.

Allow-list (гости): в `config.json` массив `people`. Ровно один `owner`, до
семи `guest`. Для каждого `user_id` = `chat_id` (личный чат). Гостям не
назначайте агента с доступом к вашим данным. Удаление человека из `people`
отзывает доступ сразу, даже для уже поставленных в очередь сообщений.

## 7. Запуск на Windows (порядок)

1. Модели (раздел 4): MAIN обязательно, FAST — по желанию.
2. Bossman (раздел 5) — если нужны поручения.
3. Диагностика компаньона:

   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\Users\asd\Bossman\wt-telegram\scripts\Start-TelegramCompanion.ps1 -Mode diagnose -RepoRoot C:\Users\asd\Bossman\wt-telegram
   ```

   Ожидается `telegram.status = AUTH_AND_POLLING_CONFIG_OK_NOT_E2E`,
   `local_model.status = CATALOG_ENTRY_ONLY_NOT_INFERENCE`. Если
   `MODEL_NOT_LISTED` — в `served_ids` показано точное имя, скопируйте его в конфиг.
4. Запуск:

   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\Users\asd\Bossman\wt-telegram\scripts\Start-TelegramCompanion.ps1 -RepoRoot C:\Users\asd\Bossman\wt-telegram
   ```

   Окно должно оставаться открытым. Остановка — `Ctrl+C`. Второй экземпляр не
   запустится (`ANOTHER_COMPANION_IS_RUNNING`).

Автозапуск при входе в Windows (по желанию) — через Планировщик заданий:
действие `powershell.exe -ExecutionPolicy Bypass -WindowStyle Minimized -File
...\Start-TelegramCompanion.ps1 -RepoRoot ...`, триггер «При входе в систему».

## 9. Поведение при перезапуске и долгих задачах

* Сообщения, пришедшие пока компаньон выключен, Telegram хранит до 24 часов;
  после запуска они будут обработаны по порядку.
* Сообщение, которое обрабатывалось в момент аварии/остановки, **не
  повторяется** (помечается `interrupted_unknown`) — чтобы не выполнить
  действие дважды. Просто задайте вопрос ещё раз.
* Уведомления о завершении задач приходят с задержкой до `monitor_seconds`
  (60 с). Повторно после перезапуска не отправляются.
* Модель отвечает на одно сообщение за раз; остальные ждут в очереди (до 4 на
  человека). Команды `/status`, `/help`, `/model` идут отдельной быстрой очередью.
* Память беседы — последние 4 пары реплик, зашифрована, хранится 7 дней;
  `/forget` очищает её.

## 10. Неполадки

| Симптом | Причина / что сделать |
|---|---|
| «локальная модель сейчас не отвечает» на каждое сообщение | (1) в конфиге не то имя модели — запустите `-Mode diagnose`, скопируйте `served_ids`; (2) мал `local_timeout` — поставьте 180; (3) модель запущена без `--reasoning off` — пустой ответ; (4) сервер не запущен. После сбоя MAIN не опрашивается 45 с (в это время отвечает FAST, если настроен). |
| Ответ обрывается, `[Ответ ограничен длиной.]` | Лимит `max_tokens` (512 по умолчанию, до 2048). Больше токенов = дольше ответ MAIN. |
| Пустые ответы / странные `<think>` | Нет `--reasoning off` или `--jinja` у llama-server. |
| Ошибка контекста / обрезание | Компаньон отправляет системный промпт + до ~8000 символов истории + ваше сообщение (≤4000 символов) — это укладывается в 32k. Если сервер запущен с `-np 2` и маленьким `-c`, каждому слоту достаётся половина. |
| Не хватает памяти | MAIN(128k) + GPT-OSS(64k) оставляют ~20 ГБ; все три модели одновременно не помещаются. Для Telegram достаточно MAIN; FAST держите только если GPT-OSS не нужен. Не запускайте FAST во время тяжёлых прогонов. |
| `WEBHOOK_CONFLICT_USE_SEPARATE_COMPANION_BOT` | У бота настроен webhook. Создайте отдельного бота. |
| `AUTH_DENIED` | Неверный/отозванный токен. В BotFather `/revoke` → новый токен → удалить `config.json` и `credentials.enc` (или только `credentials.enc` + env-файл) и настроить заново. |
| `CONFLICT` | Этот же бот опрашивается другим процессом/компьютером. Оставьте один. |
| `ANOTHER_COMPANION_IS_RUNNING` | Уже запущен второй экземпляр. |
| `/task` → «исполнитель не назначен» | В конфиге у вас `agent_id: null` — создайте агента в Bossman и впишите ID. |
| `/status` → «Bossman не отвечает» | Command Center не запущен или неверный токен. Беседа при этом работает. |

## 11. Безопасность

* Токен бота и токен Command Center — только в `credentials.enc` (шифрование)
  или в локальном env-файле вне репозитория. Никогда в git, чатах, скриншотах.
  При утечке — `/revoke` в BotFather.
* Telegram — внешний облачный сервис: текст ваших сообщений и ответов модели
  проходит через серверы Telegram. Не пишите боту пароли и ключи.
* Бот принимает только перечисленные ID и только личные чаты; чужие сообщения
  не сохраняются. Удаление ID из `people` отзывает доступ сразу.
* Модели и Bossman доступны только по loopback; компаньон не открывает
  входящих портов (polling), наружу ходит только к `api.telegram.org`
  (и к OpenRouter — только если вы сами включили облако).
* Беседа не имеет инструментов. Реальные действия — только через
  `/task` + `/confirm` + права агента + подтверждения в приложении Bossman.
* `/lock` из Telegram блокирует новые поручения; разблокировать можно только
  локально, при остановленном мосте: `Start-TelegramCompanion.ps1 -Mode unlock-delegation`.

  см. `command-center/tests/telegram_contracts/`.
* Проверено на этой машине: llama-server b10964 в ответе возвращает путь к

* **NOT_VERIFIED**: точное `id` FAST (модель не была загружена).
