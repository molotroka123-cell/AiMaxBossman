Статус: ТЗ, не активация и не сертификат. Источники: слова владельца 09.10, `AGENTS.md` (NORTH STAR, поправки 08.10), аудит 09.10 (`audit-20261009/REPORT_20261009.md`), `docs/owner/INTEGRATION_PLAN_PR99_20261008.md`, `run-20261008/PLAN_20261008.md`.
Same-product contract: CLI, дашборд и Telegram — одна поверхность одного Bossman (один backend, память, задачи, реестр моделей, бюджет, STOP).
Решение владельца 09.10: **«Пофиг на звонки, доделывай боссмана»** — телефонные звонки Jeff (вход в Telegram, живой звонок, голос в звонках) вынесены из критического пути, см. WS3.

## 1. Цель и определение «финал»
Финал = **рабочий Bossman и Jeff** (без телефонных звонков), у которого **каждая функция дерева проверена, внедрена и протестирована**. Чтобы это не было словами, у каждого листа есть уровень доказательства:

| Уровень | Что значит | Источник |
|---|---|---|
| L1 code | код есть по пути в реестре | registry |
| L2 tests | тесты листа проходят **на текущем SHA** (не «записан прогон») | CI/локальный прогон + артефакт |
| L3 ci | зелёный workflow на точном SHA | check-runs API |
| L4 installed | квитанция `installed_pytest` на установленной сборке | `tree_apply_evidence` |
| L5 owner_pc | живая проверка на ПК владельца по сценарию | `USER_TEST.md` + артефакт |

Каждый лист получает ровно одну судьбу: **ACTIVE** (цель ≥ L4, у owner-facing функций L5), **OFF** (не полезен; выключается только через `tree_registry_sync`/`tree_apply_evidence` по списку, который одобряет владелец), **RETIRED**, **PARKED** (отложено решением владельца, сейчас — звонки), **REFERENCE** (OSS/skill-записи: либо подключены и протестированы, либо «не используем» с лицензией и причиной).
Финал достигнут, когда: нет ACTIVE-листа ниже цели, нет листа без судьбы, сайт = локальное дерево = SHA установленной сборки, пройдены ступени North Star раздела 5.

## 4. Рабочие потоки (WS) и критерии приёмки
**WS0 Идентичность и CI.** Один SHA кандидата = ветка = установленная сборка = SHA в дереве. Красные тесты: `video_cancel_button`, флак `ops_terminal_browser`, `pytest py3.11` «database is locked» (собрать логи, диагностика). Приёмка: все обязательные workflow зелёные на точном SHA (кроме retention до замера), установленная сборка владельца = SHA.
**WS1 Дерево.** По 13 зонам: (а) автопробы листа → квитанции L4; (б) схлопнуть дубли (267 пар `cap-*/module-*`, 17 дублей по метке); (в) 44 узла вне registry → `tree_registry_sync`; (г) 51 узел без источника → найти файл или `idea`; (д) OSS-записи: лицензия (copyleft/без лицензии — только отдельным процессом), по каждой решение; (е) список «не полезно → OFF» владельцу на одобрение. Приёмка: таблица судеб 875/875; ACTIVE ≥ L4; расхождение сайт/seed/registry = 0.
**WS2 Единый runtime и бюджет.** Telegram «cloud chat» через `Registry.adapter_for` и общие лимиты (сейчас напрямую в OpenRouter, `adapters.py:1113`); gateway free-only = правила Command Center; дневной $-потолок на платные провайдеры (OpenRouter, Mistral) кодом, а не только константа Anthropic ($3). Приёмка: тесты на отказ при превышении и на отсутствие тихого перехода на платное, одинаковые правила во всех входах.
**WS3 Jeff (без звонков).** Единый Jeff в общем runtime: память участников с согласием, Master Parser, отчёты в пульт, текстовые правила. **PARKED по решению владельца 09.10:** вход в Telegram, живой звонок, голос в звонках (XTTS/Piper), замеры задержки, автоответчик (он остаётся OFF по умолчанию; замечания F5–F7, F10, F11 — в бэклоге с низким приоритетом, F1–F4, F8, F9 уже закрыты тестами). Приёмка: чат/память/пульт Jeff через единый backend; листья звонков помечены PARKED, а не «зелёными».
**WS4 Самоулучшение 2.1 (North Star).** Три цикла подряд на свежих кейсах, независимая проверка hold-out, перенос без рецептов, доказанный откат, затем soak. ## 5. Лестница North Star (обязательный минимум к финалу)
`SELF_IMPROVEMENT_INFRASTRUCTURE_PRESENT` ✔ → `SELF_REPAIR_SINGLE_CYCLE_PASS` ✔ → `SELF_REPAIR_3_CYCLE_PASS` → `TRANSFER_MEASURED_GAIN` → `24H_SOAK_PASS` → `48H_SOAK_PASS` → `WEEK_MODE_READY` → `REVENUE_CAPABLE_PILOT`. Спецификация и скриншот ступенью не считаются. Коммерческий пилот — только с одобренным владельцем сценарием; ближайший кандидат «видео → структурированные материалы».

## 6. Как исполняет Bossman (а не Claude)
1. Backend кандидата на свободном порту с отдельным каталогом данных; провайдеры NIM/OpenRouter/Mistral переносятся из реестра владельца (ключи расшифровываются в памяти и шифруются хранилищем нового экземпляра).
2. Каждый пункт WS — задача Bossman: контекст (лист/файлы), воркер по лестнице, изолированный кандидат, тесты, независимая проверка hold-out, ревью; применение по Apply владельца или явной политике; Claude — аудитор, не автор патчей, которые считаются обучением.
3. Квитанции → `tree_apply_evidence` → публикация дерева (чистый клон сайта, не рабочий).
4. Отчёт каждой фазы в пульт: числа «до/после», списание бюджета, «экономия против облака».

## 7. Фазы и оценки (оценки, не обещания)
P0 (1 день): WS0 + backend-исполнитель + снимок дерева «до». P1 (3–5 дней): WS1 автопробы по зонам + WS2. P2 (1–2 дня, нужен владелец): установка сборки, UX-прогон (без звонков). Итого ~2 недели; звонки (PARKED) добавят 2–3 дня, если их вернут.
