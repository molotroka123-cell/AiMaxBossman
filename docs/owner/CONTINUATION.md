## 2. Как владелец даёт задачи (оператор Qwen, уровень L1 Lab)

- Пульт Telegram (только владелец): `/work <задача>`, `/work_status`, `/work_stop`, `/work_yes N`, `/work_no N`.
  API: `/api/qwen-operator/*` (агент «Qwen-Operator L1 (uncensored)», роль `operator:l1-lab`, бюджет 0 $).
- Оператор работает в изолированной копии репозитория (`%LOCALAPPDATA%\Bossman\CommandCenter\qwen-operator\lab-*`),
  в лабораторной ветке `lab/op-*`: правит код, пишет тесты, гоняет их, коммитит, не пушит и не сливает.
- Модели по умолчанию: планировщик, кодер, диагност — Qwen uncensored (контекст 256k); независимый проверяющий —
  бесплатная облачная модель другого семейства (`NOT_INDEPENDENT`, если недоступна). Дедлайна на задачу нет;
  ограничения: 3 попытки на ошибку, проверка обязательна, откат при ухудшении, STOP владельца.
- Отчёт по задаче — с чеками: какие модели вызваны, токены, стоимость, команды, вывод тестов, diff, коммит. Не писать
  «готово» без чеков; пустой результат и отсутствие данных — не успех.

## 3. Что разрешено и что решает владелец

Оператор не применяет изменения сам. Пока конституция v1 закреплена или не закреплена, действует правило 4: применять
только при одобрении Claude и Codex на один SHA; пин `%LOCALAPPDATA%\Bossman\autonomy\constitution.sha256` не создан,
автономный цикл заблокирован. Чтобы перейти на независимых проверяющих (код ворот уже в `main`, спит до пина): владелец
запускает в СВОЁМ окне PowerShell `tools\adopt_constitution_v2.ps1 -Build <корень сборки>` и вводит пин. Агент пин не пишет.

На любом из пунктов «решает владелец» оператор НЕ падает и НЕ обходит: останавливает только этот шаг и отправляет в пульт
одно сообщение — действие, зачем оно нужно, рекомендация, опасения, кнопки «Разрешить/Отклонить» — остальные шаги идут:

деньги, покупки, подписки; публикации и сообщения третьим лицам; создание и раскрытие ключей; удаление важных данных без
резервной копии; отключение механизмов защиты; смена политики безопасности и конституции; force-push; развёртывание,
способное остановить рабочий Bossman; обход selftest; выпуск в `main`.

7. Тесты, нестабильные по времени под нагрузкой Linux-раннера (разные в каждом прогоне); дефект в лаборатории оператора:
   проверяющий пропустил расхождение «докстринг ↔ поведение» — поднимать качество проверки.

## 6. Правила поведения оператора

- Правда важнее скорости: «реализовано» ≠ «проверено на машине владельца»; каждое число — с источником.
- Не трогать защищённое: конституцию, ворота одобрения, бюджеты, vault и ключи, собственные охранные модули.
- Не публиковать и не слать наружу личные материалы; ключи, vault и DPAPI никогда не пушатся и не отправляются.
- Один интегратор для общих файлов; в `git add` — только свои пути; push без force; при изменении remote — остановиться.
- Улучшаться дальше — по командам владельца: каждая команда → план → лаборатория → тесты → независимая проверка → отчёт
  с чеками → решение владельца о выпуске.
