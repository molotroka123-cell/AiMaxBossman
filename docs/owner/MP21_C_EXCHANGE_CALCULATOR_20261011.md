## 4. Формулы, единицы, правила

Код: `tools/exchange_volume/` (`timeutil.py`, `parse.py`, `calc.py`, `reconcile.py`, `cli.py`), только stdlib, `Decimal`.

- **Время.** `ts_utc = ts_export_local - offset` (offset берётся из каждого сообщения). Бизнес-время: **Europe/Prague** по правилу EU DST, встроено (tzdata на этом ПК нет). Это допущение, не проверенное у оператора. Бизнес-месяц: 21-е .. 20-е включительно, имя по закрывающему 20-му.
- **Валовый объём (USDT, прямой)** = сумма суммы USDT-ноги каждой учтённой сделки (одна нога, не in+out). `usdt_received_from_clients` = Σ in-ноги USDT, `usdt_paid_to_clients` = Σ out-ноги USDT.
- **Сделки без USDT-ноги** (EUR>CZK и т.п.): `unpriced`, количество и нативные суммы выводятся, в USDT не переводятся. Перевод возможен только по внешнему CSV курсов (`ts_utc,base,quote,rate,source`): берётся последний курс не позже времени сделки, не старше `--rate-max-age-h` (24 ч), иначе остаётся `unpriced`; в `deals.csv` пишутся курс, источник и время курса, итог отдельным полем `gross_usdt_converted_external_rate`.
- **Курс.** В чате рыночных курсов нет. Выводится только исполненный курс пары `Σout/Σin` (VWAP), он точный по данным.
- **Комиссия / чистый объём.** В сообщениях комиссии нет, поэтому `commission_usdt = null`, `net_usdt_direct = null` (не 0). В режиме `--db` комиссия считается только если у **всех** учтённых сделок периода есть `fee` в USDT; иначе null. `net = gross_direct - commission`.
- **Дубли.** Сделка = дубль, если у более ранней учтённой сделки идентичные обе ноги (валюта и сумма до копейки) и разрыв ≤ 10 мин (репост). Идентичные пары позже в тот же день **не удаляются**, считаются кандидатами (`same_day_identical_candidates_kept`). Предыдущий расчёт удалял любые одинаковые за день: это может занижать объём.
- **Внутренний оборот.** Автоматически не удаляется. Зеркальные пары (X>Y, затем Y>X с теми же суммами в тот же день) только помечаются (`mirror_pair_candidate`); по PARSER_SPEC §6 это обычно две реальные сделки. Исключение только по списку ref от оператора (`--exclusions`). «Долг» (долг/dolg/odtat) выводится из сделок как `debt`.
- **Не угадывается:** сообщения с >2 парами сумма+валюта (`complex`, 87), с направлением, но без валюты (`incomplete`, 23), с разделителем и ровно 3 цифрами после него вроде `99.999` (`ambiguous_amount`, 8), неподдерживаемые валюты. Для complex первые две пары показаны как provisional и **в точные итоги не входят**.
- **Проверка правдоподобия** (не коррекция): сделки, чей исполненный курс отличается от медианы пары более чем на 25%, помечаются `implied_rate_outlier` и остаются в итогах; их число и объём выводятся по периодам.
