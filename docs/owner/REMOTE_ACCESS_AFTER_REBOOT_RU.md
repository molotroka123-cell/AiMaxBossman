# Удалённый доступ к ПК владельца после перезагрузки (11.10.2026)

Запрос владельца: с телефона, когда дома никого и монитора нет, включать Claude Code Remote
Control, продолжать Claude, открывать ChatGPT, перезагружать ПК — и чтобы после перезагрузки
всё поднялось само, а Windows входила сразу на рабочий стол.

## Что сделано (код, протестировано)

| Команда пульта (owner-only) | Фраза | Что делает |
|---|---|---|
| `/remote` | «Включи удалённый Claude» | Запускает keeper → `claude remote-control --name Bossman-Owner-PC --spawn=session --permission-mode <claude_permission_mode>`; если такой процесс уже есть — сообщает PID и ссылку, второй не запускает |
| `/remote_status` | «Статус удалённого доступа» | Процессы по имени сессии, маркер Connected, последняя ссылка `https://claude.ai/code/session_…`, последние ошибки из журнала |
| `/remote_stop` | — | Останавливает только то, что запустил пульт; ставит STOP для keeper'а |
| `/claude_open` | «Открой Claude» | Терминал с `claude` в `claude_cwd` (без монитора бесполезен — для телефона `/remote`) |
| `/claude <текст>` | «Продолжи Claude: …» | Существующий мост: продолжает записанную сессию (`--resume`) |
| `/chatgpt` | «Открой ChatGPT» | Запуск установленного приложения `OpenAI.Codex_…!App`. Ограничение: открыть конкретный диалог Codex по команде приложение не умеет — это сказано в ответе |
| `/reboot` → кнопка | «Перезагрузи компьютер» | Отказ при рендере/обучении (`facefusion`, `sd-cli`, `kohya`, `ffmpeg`, `wan`…), checkpoint `%LOCALAPPDATA%\Bossman\remote\reboot-checkpoint-*.json`, подтверждение в течение 5 мин, `shutdown /r /t 90`, `/reboot_cancel` = `shutdown /a` |

Правила: проверка владельца на каждом вызове (как в `/claude`); нужен `claude_bridge: true`;
STOP (`delegation_locked`) блокирует все запуски и перезагрузку, остаются статус и отмена;
сырой shell из Telegram по-прежнему недоступен; чужие процессы не убиваются; пароль
Windows нигде не читается и не хранится. Режим Remote Control берётся из существующего поля
`claude_permission_mode` (новых ключей в config.json нет — установленный пульт старой сборки
падает на незнакомых ключах, это проверено 11.10 и откатано).

Тесты: `command-center/tests/test_companion_remote_access.py` (25): отказ гостю, выключенный
мост, STOP, запуск с нужным режимом, повтор без дубля, `--help`/чужое имя не считаются
живыми, отсутствие launcher/папки, статус со ссылкой и ошибками, пустой журнал, stop только
своего, ChatGPT с ограничением, терминал, не-Windows, отказ при рендере, checkpoint +
подтверждение, истёкшее окно, отмена, фразы, fallback режима `plan` → `default`.

## Keeper `tools/claude_remote_service.ps1`

Ждёт сеть (claude.ai:443, до 15 мин), не стартует второй экземпляр с тем же именем,
вызывает стартер Codex `tools/start_claude_remote.ps1` (проверка ветки и `origin/HEAD`), до 5
перезапусков с задержкой, журнал `%LOCALAPPDATA%\Bossman\remote\claude-remote.log`, файл
`STOP` останавливает цикл, `DISABLED` отключает автозапуск. Сам Claude дополнительно
отказывает второму `remote-control` в той же папке («This folder is already served…») — это
зафиксировано реальным прогоном keeper'а 11.10 15:33 с тестовым именем сессии (ошибка и код
выхода попали в журнал; действующий Remote Control не трогался).

## Автозапуск после входа

Задача `BossmanClaudeRemote` (ONLOGON, задержка 1 мин, без лимита времени, повторный
экземпляр игнорируется) запускает keeper с `-PermissionMode bypassPermissions` (явное
требование владельца) из checkout `wt-unified-20261010`. Bossman (backend :8801, Jeff, пульт)
поднимают существующие задачи `BossmanOne-1..3`, Jeff 2.0 — `BossmanJeff2`.
`BossmanLocalGenBench` отключён (владелец: «разгрузи комп, чтобы не шумел»).

## Шаг владельца: вход сразу на рабочий стол

Скрипт `owner-autologon-20261011.ps1` в папке Bossman (вне репозитория): запуск с UAC,
отключает «требовать Windows Hello», скачивает Sysinternals Autologon64 и один раз
спрашивает пароль в окне. Пароль уходит только в Autologon (зашифрованный LSA-секрет),
в файлы, Git и журнал не пишется; пароль аккаунта сохраняется — сетевой/RDP вход по-прежнему
требует его. Отмена: Autologon64 → Disable.
