сообщение. Промт ничего не запускает сам: каждое действие идёт по твоим разрешениям, STOP — твой.

**Правила, которые нельзя нарушать:**
- «Код написан» ≠ «работает». Уровни CODE → TEST → CI → OWNER_HW считай раздельно. Не заявляй обучение по попаданию в память, правке учителя, повтору известной задачи или ослабленному тесту.
- Ключи, vault, личные данные, веса и кэши не печатать и не публиковать (в логах только имена). Платёжные действия, регистрации, вход в аккаунты, капчи, отправка наружу, торговля — только с подтверждением владельца. Платных воркеров не включать.
- Не выключать компьютер и не останавливать Jeff, Пульт и backend без бэкапа. STOP владельца сильнее любой задачи.
- Автоответчик Jeff не включать, пока открыты F1–F4. Не force-push, не создавать «финальную» ветку, не сливать в `main` без зелёного обязательного CI.
- Статус листа на дереве меняется только через `tools/tree_registry_sync.py registry … --ci-evidence … --owner-evidence …` с файлами доказательств — руками никогда. `tree_apply_evidence.py` правит только seed и в реестр не пишет.

**Порядок работы:**
0. Проверь состояние: SHA `main`, открытые PR, красные проверки. Если PR #99 не влит — доведи его CI до зелёного (не ослабляя тесты) и **остановись**: слияние в `main` — отдельное решение владельца после независимой проверки. Продуктовые изменения в `main` автоматически не сливаются (AGENTS.md).
1. Шаги на ПК из раздела 4 плана: установка с точного SHA, `tools\local_completeness_manifest.py` (PowerShell: `"$env:USERPROFILE\Bossman"`), `tools\keys_guard.py verify` (только если #99 уже слит — иначе команды нет на `main`). Попроси владельца запушить `consolidate/jeff-20261007` и всё, что покажет manifest. Не заявляй «ничего не потеряно» без свежего manifest.
2. Бери листья из раздела 5 по очереди, один лист — один PR из изолированной ветки. Для каждого пройди ворота пользы (раздел 2): нужда и замер «до» → два конкурента open source (если применимо) → тест красный на текущем коде → исправление → тест зелёный → подключение к существующему backend → PR → зелёный обязательный CI на точном SHA → доказательство на этом ПК (Windows/AMD, Telegram, голос, GPU, экран — реально, с квитанциями).
3. Лист без доказанной пользы не вносить: запиши причину (`НЕ ВНЕДРЕНО: …`) и предложи владельцу решение.
4. Блокеры (24–48 ч Jeff, UX +30%, Computer Use, K1m6a → навыки, самоисправление 3 цикла) закрывай прогонами и замерами по разделам 2–4, а не кодом. Для K1m6a — протокол `k1m6a_exam` (запечатанный эталон, locked test, BASELINE → LESSONS → RESTART_TRANSFER); вердикт — только из `aggregate`.
5. После каждой волны (3–5 листьев) пришли владельцу отчёт: что внесено (PR, SHA), уровень по листу раздельно, что не получилось, что осталось на ПК, прогресс по лестнице North Star
   (SELF_IMPROVEMENT_INFRASTRUCTURE_PRESENT → SELF_REPAIR_SINGLE_CYCLE_PASS → SELF_REPAIR_3_CYCLE_PASS → TRANSFER_MEASURED_GAIN → 24H_SOAK_PASS → 48H_SOAK_PASS → WEEK_MODE_READY → REVENUE_CAPABLE_PILOT) и подтверждение контракта «один Bossman».

**Остановись и спроси владельца, если:** нужен платёж, вход в аккаунт, отправка наружу, ключ, запись в Telegram от его имени; тест нельзя пройти без ослабления; лист требует нового ядра вместо подключения к существующему; не уверен, что действие обратимо.

**Не считать завершением:** документ, скриншот, зелёный лист на сайте, новая точка входа. Завершение — доказательство на ПК по точному SHA `main`.
