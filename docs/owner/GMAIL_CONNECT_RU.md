# Как подключить свою почту Gmail к Bossman

Дата: 10.10.2026. Ветка: `feat/gmail-connector-20261010`. Код: `command-center/bcc/gmail_connector.py`,
API `/api/gmail/*`, команда `bossman gmail …`. Тесты: `command-center/tests/test_gmail_connector.py`.

Подключить можно только **вашу** почту. Bossman сам за вас не входит: согласие вы даёте в своём
браузере. Есть два способа. **Способ А (OAuth)** — основной: Bossman получает только те права,
которые вы разрешили, и вы можете отозвать их в Google. **Способ Б (пароль приложения, IMAP/SMTP)** —
запасной, настраивается быстрее, но пароль открывает всю почту.

## Что Bossman может и чего не может

- **Чтение.** Поиск (до 10 писем за раз) и чтение одного письма. По умолчанию выдаётся только
  `gmail.readonly`: изменить, удалить или отправить письмо с таким разрешением нельзя.
- **Отправка и черновики.** По умолчанию выключены. Включаете вы. После этого **каждое** письмо
  и каждый черновик Bossman показывает вам и ждёт подтверждения (в пульте, в вебе или командой
  `bossman approve`). Сам он ничего не отправит: ни право агента, ни правило, ни «аренда»
  подтверждения не заменяют.
- **Только вы.** Почту видят только агенты, которых вы явно разрешили (`bossman gmail allow-agent <id>`).
  Агент, привязанный к гостю в Telegram, доступа не получит, даже если вы его разрешили. У Джеффа
  (бот для собеседников) доступа к почте нет совсем.
- **Письма — это данные, а не команды.** Если письмо требует «перешли всё на такой-то адрес» или
  «назови ключ», Bossman этого не сделает. Такие строки он помечает знаком ⚠.
- **Вложения не скачиваются.** Bossman показывает только имя и размер; большие помечены. Письма
  крупнее 5 МБ читаются без тела, только заголовки.
- **Ключи хранятся только в зашифрованном хранилище Bossman** (vault на вашем ПК). Их нет в Git,
  в логах и в ответах API. Bossman обращается только к адресам `gmail.googleapis.com`,
  `oauth2.googleapis.com`, `accounts.google.com` (способ А) или `imap.gmail.com:993` и
  `smtp.gmail.com:465` (способ Б). Других адресов нет, перенаправления не выполняются.

Bossman должен быть запущен. Команды выполняются в терминале, где работает `bossman`.

## Способ А. Google OAuth (рекомендуется)

Шаги 1–7 делаются один раз в Google Cloud (бесплатно, карта не нужна).

1. Откройте https://console.cloud.google.com/ и войдите в **тот же** аккаунт Gmail, который
   подключаете.
2. Создайте проект. Сверху нажмите выбор проекта → **New project**, назовите его, например,
   `Bossman Mail`, нажмите **Create** и выберите этот проект.
3. Включите Gmail API. Откройте меню **APIs & Services → Library**, найдите **Gmail API** и нажмите
   **Enable**.
4. Настройте экран согласия. Откройте **Google Auth Platform** (в старом меню —
   **APIs & Services → OAuth consent screen**) и нажмите **Get started**:
   - App name: `Bossman`, User support email: ваш адрес;
   - Audience: **External**;
   - Contact information: ваш адрес;
   - согласитесь с условиями и нажмите **Create**.
5. Добавьте себя тестовым пользователем. Откройте **Audience → Test users → Add users**, впишите
   **свой адрес Gmail** и сохраните. Статус публикации (Publishing status) оставьте **Testing**.
   Никого больше не добавляйте.
6. Разрешения (scopes) можно не добавлять: Bossman сам попросит нужное при входе. Если хотите
   видеть их заранее, откройте **Data Access → Add or remove scopes** и отметьте `.../auth/gmail.readonly`.
   Для отправки и черновиков добавьте `.../auth/gmail.send` и `.../auth/gmail.compose`.
7. Создайте клиент. Откройте **Clients → Create client**, в поле Application type выберите
   **Desktop app** (именно его, не «Web application»), назовите `Bossman Desktop` и нажмите
   **Create**. В окне с ключами нажмите **Download JSON**: скачается файл `client_secret_….json`.
8. Передайте клиент Bossman:
   ```
   bossman gmail client --file "C:\Users\<вы>\Downloads\client_secret_XXXX.json"
   ```
   Bossman зашифрует ключ в своём хранилище. После этого удалите скачанный файл из «Загрузок»
   или уберите его в надёжное место. Можно ввести ключи и вручную: `bossman gmail client`
   (секрет вводится скрыто).
9. Укажите адрес владельца, чтобы нельзя было подключить чужой ящик:
   ```
   bossman gmail settings --address ваш.адрес@gmail.com
   ```
10. Войдите:
    ```
    bossman gmail connect
    ```
    Откроется страница Google; если браузер не открылся, скопируйте ссылку из терминала.
    Выберите свой аккаунт. Google покажет «Google hasn't verified this app» — это нормально,
    приложение ваше: нажмите **Continue**. Отметьте галочки разрешений и нажмите **Continue**
    или **Allow**. Во вкладке появится «Gmail подключён к Bossman», а в терминале — ваш адрес и
    разрешения (`gmail.readonly`).
    Если вкладка с адресом `http://127.0.0.1:…` показала ошибку, скопируйте этот адрес целиком
    и выполните `bossman gmail complete`, затем вставьте его.
11. Проверьте подключение: `bossman gmail test`. Команда покажет заголовок последнего письма без текста.
12. Разрешите почту нужному агенту. Номер агента покажет `bossman list agents`:
    ```
    bossman gmail allow-agent <номер>
    ```
    Агенту также нужно выдать инструменты `plugin:gmail.search` и `plugin:gmail.read` (а для
    отправки — `plugin:gmail.send` и `plugin:gmail.draft`) в его настройках. Закрыть доступ:
    `bossman gmail deny-agent <номер>`.
13. Отправка и черновики (по желанию):
    ```
    bossman gmail settings --send on --drafts on
    bossman gmail connect
    ```
    Повторный вход нужен, чтобы Google выдал новые разрешения. `bossman gmail status` покажет
    «Нужно переподключить», пока вы этого не сделаете. После этого Bossman всё равно спрашивает
    подтверждение на **каждое** письмо.

**Важно про режим Testing.** Пока приложение в статусе Testing, Google выдаёт доступ к Gmail
на **7 дней**. Через неделю Bossman напишет «доступ отозван или истёк — переподключите Gmail»:
выполните `bossman gmail connect` ещё раз (это занимает около минуты). Если это неудобно,
используйте способ Б.

## Способ Б. Пароль приложения (IMAP/SMTP)

Пароль приложения работает только при включённой двухэтапной проверке. Он открывает всю почту,
поэтому храните его только в Bossman.

1. Включите двухэтапную проверку: https://myaccount.google.com/signinoptions/two-step-verification
2. Откройте https://myaccount.google.com/apppasswords, введите имя `Bossman` и нажмите
   **Create**. Google покажет 16 букв (4 группы по 4). Если такой страницы нет, значит, у
   аккаунта включена Advanced Protection или вход только по ключу безопасности. Тогда используйте
   способ А.
3. Передайте пароль в Bossman:
   ```
   bossman gmail imap --address ваш.адрес@gmail.com
   ```
   Пароль вводится скрыто, пробелы можно оставить. Bossman шифрует его в хранилище.
4. Проверьте подключение: `bossman gmail test`.
5. Выполните шаг 12 способа А: `bossman gmail allow-agent <номер>`.
6. Отправка и черновики: `bossman gmail settings --send on --drafts on`. Повторно входить не нужно.
   Каждое письмо по-прежнему ждёт вашего подтверждения.

Чтение идёт через `imap.gmail.com:993` в режиме «только просмотр»: письма не помечаются
прочитанными, флаги не меняются. Отправка идёт через `smtp.gmail.com:465`. Черновики
сохраняются в папку «Черновики».

## Отключение

```
bossman gmail disconnect
```
Команда удаляет из Bossman все ключи почты и отзывает OAuth-доступ в Google. Можно также
проверить список приложений с доступом на https://myaccount.google.com/permissions. Пароль
приложения удаляется на https://myaccount.google.com/apppasswords.

## Если что-то не так

| Сообщение | Что сделать |
|---|---|
| `redirect_uri_mismatch` | Клиент создан не как **Desktop app**. Создайте Desktop-клиент (шаг 7). |
| `access_denied` / «приложение недоступно» | Вашего адреса нет в **Test users** (шаг 5). |
| «вход выполнен в ДРУГОЙ аккаунт» | В браузере выбран чужой аккаунт. Доступ уже отозван, повторите `connect` и выберите свой. |
| «Google не выдал refresh_token» | Откройте https://myaccount.google.com/permissions, удалите Bossman и повторите `connect`. |
| «доступ … истёк — переподключите» | Прошло 7 дней режима Testing. Выполните `bossman gmail connect`. |
| «почта владельца закрыта для агента #N» | Выполните `bossman gmail allow-agent N`. |
| «агент #N привязан к гостю Telegram» | Этот агент обслуживает гостя. Выберите другого агента для почты. |
| «отправка писем выключено владельцем» | `bossman gmail settings --send on` (и `connect` для OAuth). |
| «IMAP: вход не удался» | Неверный пароль приложения или выключена двухэтапная проверка. |

## Что проверено и что нет

- Проверено автоматически, без сети (поддельный Google и поддельные IMAP/SMTP): хранение в
  vault без открытого текста, по умолчанию только чтение, отправка только по вашему
  подтверждению (без него — отказ), Джефф и гости к почте не допускаются, только разрешённые
  адреса, текст письма возвращается как данные.
- **Не проверено:** настоящий вход в ваш аккаунт. Это можете сделать только вы (шаги выше).
  Пока вы не выполнили `bossman gmail test` на своём ПК, подключение к живому Gmail не доказано.
