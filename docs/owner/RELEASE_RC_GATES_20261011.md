# Bossman 2.1: список ворот релиз-кандидата для постороннего человека (11.10.2026)

Назначение: что должно быть доказано, прежде чем архив Bossman можно отдать человеку, который не владелец.
Документ фиксирует **критерии и способ проверки** до прогона; результаты и точный SHA лежат в
`docs/owner/RELEASE_RC_REPORT_20261011.md`. Слова «готово», «freeze», «PASS» здесь не используются без прогона.

Единица выпуска: один ZIP `BOSSMAN-Windows-x64-<sha12>.zip`, собранный `tools/build_windows_bundle.py`
(профиль `release`, входы закреплены `tools/windows_bundle_lock.json`). Исходный репозиторий **не** является
артефактом выпуска (в нём лежат скриншоты владельца, журналы сессий и т. п.; см. ворота G3).

Статусы: PASS (есть прогон с rc 0 на этом SHA), FAIL, NOT RUN (не запускалось, причина названа),
OWNER_REQUIRED (нужно действие владельца/аккаунта), CI_REQUIRED (проверяется только GitHub Actions).

## 1. Установка и первый запуск (G1, G2)

Условия PASS:

1. Архив распаковывается в каталог с пробелами и не содержит абсолютных путей сборочной машины.
2. `MANIFEST.json`: `source_sha` равен проверяемому SHA, `source_dirty=false`, `build_inputs.locked=true`,
   `required_downloads` пуст (профиль `release`).
3. Каждый файл из `SHA256SUMS` присутствует и совпадает по хэшу; ZIP имеет собственный SHA-256, записанный отдельно.
4. Продукт стартует из `runtime\python.exe`, `import bcc` указывает на runtime архива, а не на репозиторий.
5. Старт на **новом пустом** `BCC_DATA_DIR` и свободном порту (не 8800/8801): создаётся `bcc.db`, `/api/health` отвечает 200.
6. Вход: UI открывается, доступ защищён токеном/сессией (запрос без сессии к закрытому API даёт 401/403).
7. Мастер первого запуска открывается на пустых данных; страницы не показывают необработанных ошибок.
8. Из UI создаётся задача, кнопка STOP останавливает её; в журнале есть запись.

Не входит: установка на чужом ПК без Python (проверяется только на этой машине в изолированном каталоге);
SmartScreen/Defender для неподписанного ZIP (архив **не подписан**: нужен сертификат подписи кода,
OWNER_REQUIRED).

## 2. Нет приватных данных в артефакте (G3)

Три прохода по распакованному архиву:

* **Секреты:** `tools/ci_secret_scan.py` (паттерны ключей, энтропия, запрещённые имена `.env`, `.pem`, `*.key`, содержимое ZIP) +
  отдельный проход по всему архиву, включая `.pyc` и `.json`.
* **Пути и ПИИ:** поиск строк `C:\Users\asd`, `\Users\<имя>`, `timurdarwaish`, `molotroka`, имён машины, e-mail,
  Telegram id владельца, IP-адресов LAN.
* **Файлы:** инвентарь по расширениям и размерам: изображения, видео, `*.safetensors`, `*.gguf`, `*.ckpt`, `*.onnx`, `*.pt`, `*.db`,
  `*.sqlite`, `*.jsonl`. Любое изображение/видео/веса/БД в архиве объясняется (иконка продукта, тест-фикстура) или удаляется.

Критерий: 0 секретов; 0 личных путей и идентификаторов владельца вне явно объяснённых (напр. имена в тестовых канарейках
с пометкой `ci-secret-scan: allow`); 0 весов моделей и LoRA; 0 баз данных; личные медиа отсутствуют.
Каталог `app-support/owner-final-run/` и `app-support/intro_video/` проверяются отдельно: это материалы владельца,
которые попадают в архив по списку сборщика.

Известный риск уровня репозитория (не архива): в git лежат `docs/reference-images/owner-screenshots/`,
`docs/testing/sessions/*.jsonl`, `docs/media/*.mp4`. Репозиторий нельзя публиковать как продукт без очистки истории
(`docs/GIT_HISTORY_CLEANUP_PLAN.md`). Выпуск = только ZIP.

## 3. Лицензии (G4)

Принцип: в архив **не вкладываются** веса моделей, FaceFusion, MatAnyone, F5-TTS, FLUX, Wan, Ollama-модели.
Они ставятся пользователем отдельно (`model_fetch.py`, `media_bootstrap.py`), и условия берутся у источника.
Первая колонка ниже: что именно записано в репозитории или в этой работе; пометка «у источника» означает, что
точная формулировка должна быть перечитана перед коммерческим применением (в этой сессии без сети не перепроверялась).

|---|---|---|

### 3.3. Что должно быть выполнено

1. В архиве нет файла с расширением `.safetensors`, `.gguf`, `.ckpt`, `.onnx`, `.pt`, `.bin` крупнее 1 МБ.

## 5. STOP и восстановление (G6)

* Кнопка STOP в UI останавливает активную задачу и не даёт очереди подхватить следующую до явного возобновления.
* Перезапуск процесса не теряет очередь и журнал (тесты: очередь, STOP, восстановление, журнал: 98 passed по MP21-A).
* `Collect-Diagnostics.cmd` собирает ZIP с вырезанными секретами.
* Не заявляется: глобальный hotkey аварийной остановки (отсутствует по `MP21_FINAL_REPORT_RU.md`); живое управление рабочим столом не проверялось.

## 6. Обновление и откат (G7)

* Данные пользователя лежат вне папки архива (`%LOCALAPPDATA%\Bossman\CommandCenter` или `BCC_DATA_DIR`).
* Обновление: распаковать новый архив рядом, не удаляя старый; перед первым запуском копия каталога данных.
* Откат: запустить `Start-Bossman.cmd` старого архива; при несовместимой миграции вернуть копию каталога данных
  (`docs/owner/ROLLBACK_RU.md`). Миграция назад на старую схему **не проверялась** в этой работе (NOT RUN).

## 7. Что передаётся человеку вместе с ZIP

SHA-256 ZIP (отдельным файлом), `SHA256SUMS`, `MANIFEST.json`, `README.md`, `INSTALL.md`, `KNOWN_LIMITATIONS.md`,
`LICENSES/`, `docs/owner/ROLLBACK_RU.md`, таблица лицензий моделей, заявление о приватности (разд. 8).

## 8. Заявление о приватности (черновик для передачи)

* Bossman работает на вашем компьютере. Данные (база задач, память, журнал, ключи) лежат в каталоге данных на вашем диске;
  ключи шифруются локально и не передаются разработчику.
* Без ключей облачных провайдеров и без включённых каналов (Telegram, Gmail) данные не покидают компьютер.
  Если вы вводите ключ провайдера, текст ваших запросов и вложения уходят этому провайдеру по его условиям.
* Режим `BOSSMAN_LOCAL_ONLY=1` запрещает вызовы облачных моделей на границе провайдера; он **не** блокирует
  все возможные исходящие соединения (веб-поиск, Telegram, Gmail, загрузка моделей).
* Лица и голос: используйте только свои материалы или материалы людей, давших согласие. Продукт не отправляет
  личные медиа наружу сам, но облачные видео/изображения-провайдеры, если вы их включили, получают то, что вы им даёте.
* Телеметрии на сервер разработчика в этой сборке нет (проверка: поиск статических адресов отправки в разд. 2 отчёта).
  Юридический текст политики конфиденциальности не написан юристом; это техническое описание.

## 9. Поддержка и известные ограничения (G9)

Поддерживает владелец, канала поддержки для третьих лиц нет (OWNER_REQUIRED: назвать контакт).
Ограничения: `KNOWN_LIMITATIONS.md`; кроме того, по `WHERE_WE_STOPPED_20261011.md`: автономность и 24-часовой прогон
не доказаны, управление рабочим столом не проверено вживую, видео-гейты на трудных клипах FAIL,
прибыльность торговли не доказана, коммерческого клиента нет.

## 10. Что эти ворота НЕ могут доказать локально

* G12 (CI на точном SHA): нужен GitHub Actions; локальный прогон не заменяет его.
* Установка на чужой машине без Python, SmartScreen, подпись кода.
* Живые облачные провайдеры (нужны ключи владельца и разрешение на расход).
* Юридическая чистота лицензий (чтение условий у источника, не юридическая консультация).
