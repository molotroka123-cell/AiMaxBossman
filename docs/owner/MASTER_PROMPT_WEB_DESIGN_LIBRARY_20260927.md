Место в общем плане: **Фаза 4.5** мастер-промта `docs/owner/MASTER_PROMPT_FINAL_ACCEPTANCE_AND_UX_20260927.md`
— только в ветке `feat/bossman-1.8-jeff-voice-chat-ux`, после `FREEZE_1_5_1_7=PASS`.
Правила раздела 0 того мастер-промта действуют здесь целиком (NO FAKE GREEN, без новых полномочий, секреты не печатать).

## Цель

Web Designer Bossman по короткому описанию владельца делает сайт, который **не выглядит
сгенерированным ИИ**: кинематографичный hero (в т. ч. с видео), осмысленная типографика,
одна смелая деталь, быстрая загрузка. Для этого Bossman получает локальную, проверенную
по лицензиям библиотеку стилей, палитр, шрифтовых пар, UX-правил и приёмов, а качество
каждого сайта измеряется, а не декларируется.

## 3. Что сделать

### 3.1 Вендоринг открытых библиотек (MIT / Apache)
- `ui-ux-pro-max-skill`: данные (`styles`, `palettes`, `fonts`, `ux-rules`) из закреплённого коммита →
  `command-center/bcc/skills_catalog/ui-ux-pro-max/data/`. Поиск — наш маленький модуль на stdlib
  (без их CLI, без npm, без сети). Шрифты для офлайна — локально в `ui/vendor/`.
- `anthropics/skills frontend-design` — обновить адаптацию до актуального коммита.
- Всё — через существующий паттерн: запись в `THIRD_PARTY_NOTICES.md`, текст лицензии в `licenses/`,
  новый lock-файл `design-library.lock.json` (commit, blob SHA, SHA-256 адаптаций), `instructions_only`.
- Лицензия не подтверждена → не вендорим (UI-Prompt, веб-каталоги).

### 3.2 Формат записи библиотеки Bossman
Одна запись = один воспроизводимый рецепт (структура по образцу #7):
```yaml
id: cinematic-video-hero-01
source: {library: ui-ux-pro-max | owner-private | bossman, commit_or_ref: ..., license: MIT}
fits: [portfolio, agency, product-launch]        # тип сайта
style: {name: ..., mood: ..., avoid: [...]}      # из стилей #1 и правил #2
tokens: {colors: {...}, fonts: {display: ..., body: ...}, radius: ..., spacing: ...}
sections: [hero, proof, offer, details, cta]     # порядок и роль каждой
hero: {type: video|image|type-only, asset_prompt: ..., poster: required, loop_s: 6-10}
motion: {signature_moment: ..., reduced_motion: fallback}
budget: {lcp_ms: 2500, hero_video_mb: 4, js_kb: 200}
checks: [anti_slop, contrast_aa, mobile_390, lighthouse]
```

### 3.3 Приватные платные библиотеки владельца (vividsites, MotionSites)
- 👤 Владелец сам покупает и сам импортирует: Настройки → «Мои библиотеки промтов» → вставить/загрузить.
- Хранение: `%LOCALAPPDATA%\Bossman\CommandCenter\design_prompts_private\` — вне Git, вне бандла, не в логах.
- Используются только для сайтов владельца. Не публикуются, не коммитятся, не отдаются третьим лицам;
  в облачную модель уходят только если владелец разрешил облако для этой задачи (как с приватной памятью).
- Карточка каждого импорта хранит источник и условия лицензии, которые владелец подтвердил.

### 3.4 Бриф Web Designer v2
Новая версия `CREATIVE_BRIEF_VERSION = "library-grounded-v2"` рядом с v1 (v1 не удалять, пока v2 не
доказан замерами):
1. **Разбор задачи** — бизнес, аудитория, одна цель страницы, реальный контент (без lorem ipsum).
2. **Подбор по библиотеке** — 3 записи из §3.2 под тип сайта + палитра + шрифтовая пара из #1.
3. **Три варианта направления** — коротко, со скриншотом превью; 👤 владелец выбирает (или «на твой вкус»).
4. **Сборка** по выбранной записи; одна «подписная» деталь, остальное — сдержанно (правило #2).
5. **Hero-видео** (если выбрано): Studio генерирует 6–10 с петлю → mp4/webm ≤ 4 МБ + постер-кадр;
   автоплей без звука, `prefers-reduced-motion` → постер; видео не блокирует первый показ.
6. **Проверка** — §4, затем существующие гейты превью/версий Web Designer.

Формулировки v1 вида «ultra-premium / luxury / world-class» в v2 заменить конкретикой из библиотеки —
такие слова сами по себе тянут модель к шаблонному «AI-дизайну».

### 3.5 Как Bossman «учится» (честно)
- Каждый собранный сайт получает оценку §4 + оценку владельца (1–5 и одна фраза).
- Запись в существующий LearningStore: какая запись библиотеки, какой бриф, какие оценки, что владелец поправил.
- Выбор записей для следующего сайта учитывает эти оценки.
- Рост качества заявляется **только** по замеру на отложенном наборе брифов (holdout), которых не было
  в обучении: v2 против v1, те же модели. Совпадение с памятью или повтор известного брифа — не обучение
  (правило `AGENTS.md`).

## 5. Библиотека промтов для агентов

Шапка — из мастер-промта (раздел «Библиотека промтов»), вставлять первой.

**W1 — Проверщик источников и лицензий**
> Для каждого источника из §1: открыть репозиторий/сайт, записать точный коммит, лицензию (текст файла
> LICENSE, не описание), что именно разрешено брать. Итог — таблица «источник / коммит / лицензия /
> можно вендорить да-нет / почему». Ничего не скачивать в продукт.

**W2 — Вендоринг**
> По таблице W1 вендорить только разрешённое, строго по паттерну `docs/skills/THIRD_PARTY_NOTICES.md` +
> lock-файл с SHA-256, `instructions_only`, без установщиков и сети. Написать локальный поиск на stdlib и
> тесты: поиск находит стиль/палитру/шрифты по типу сайта; при отсутствии данных — понятная ошибка.

**W3 — Бриф v2**
> Реализовать `library-grounded-v2` в `web_designer_creative_brief.py` рядом с v1 и шаг выбора из трёх
> вариантов в Web Designer. Fallback-генератор не трогать. Тесты: бриф собирается детерминированно из
> записи библиотеки; без моделей работает fallback.

**W4 — Hero-видео**
> Связать Web Designer со Studio: генерация петли 6–10 с, сжатие ffmpeg в mp4/webm ≤ 4 МБ, постер,
> reduced-motion, ленивая загрузка. Тест на реальном файле: размер, длительность, постер, отсутствие
> блокировки первого показа.

**W5 — Оценщик (не автор)**
> Прогнать §4 на 10 брифах: 5 обучающих и 5 отложенных (holdout). Сравнить v1 и v2 на одних моделях.
> Отчёт по каждому сайту: скриншоты, оценки, нарушения. Не править код.

**W6 — Демо владельцу**
> Сделать три сайта для реальных задач владельца (например Fresh Vibes, BossBlocks, личная страница)
> по v2 с одним вариантом hero-видео; показать; записать оценки владельца в LearningStore.

### Промты-заготовки внутри Bossman (что Web Designer подставляет сам)

**Разбор задачи:**
> Кто открывает этот сайт, что он должен сделать на странице, что его убедит. Какой реальный контент
> у владельца уже есть (тексты, фото, цифры). Одна цель страницы одним предложением.

**Направление по записи библиотеки:**
> Стиль: {style.name}, настроение: {style.mood}. Токены: {tokens}. Порядок секций: {sections}.
> Подписная деталь одна: {motion.signature_moment}. Всё остальное — сдержанно. Избегать: {style.avoid}
> и anti-slop списка. Реальный контент владельца, без выдуманных цифр и отзывов.

**Hero-видео для Studio:**
> Петля {loop_s} с, {описание сцены по бренду}, спокойное движение камеры, без текста в кадре,
> тона из палитры {colors}, пригодно как фон под заголовок (тёмная/светлая зона под текст).
