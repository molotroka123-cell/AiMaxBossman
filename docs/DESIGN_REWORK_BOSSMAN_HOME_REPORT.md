# Редизайн главной BOSSMAN — отчёт

Дата: 2026-08-28. Ветка `claude/bossman-control-v03-43igbk`.

Задача: превратить главную из панели разработчика в лаунчер приложений и
агентов — «операционная система», а не «админка». Ниже что было, что стало и
что осталось.

---

## 1. Что было

Посадочной страницей был `ui/pages/overview.js` (Home V2): строка статуса,
поле Quick Command, четыре одинаковых узких блока (Active Mission, Needs You,
Agents, Compute) и лента событий. Приложений на главной **не было вообще**.

Архитектура интерфейса: ванильный ESM без фреймворка, собственный гиперскрипт
`h()` (`ui/components.js`), реестр страниц с контрактом
`{ id, title, icon, nav, render(ctx), onEvent(ev) }`, маршрут через
`location.hash` (`#/<id>?params`). Токены темы — в `:root` файла `style.css`.

Основание было пригодным, поэтому оно не переписывалось. Переписывать
работающий каркас ради нового вида — это менять то, что видно, ценой того, что
работает.

Три ограничения, которые определили решения:

1. **Реестра приложений в ядре не существовало.** Файлы
   `apps/<имя>/app.manifest.yaml` лежали в репозитории, но их не читала ни одна
   строка кода. Проверено поиском по всему дереву.
2. **Приложения — самостоятельные сервисы.** Их манифесты объявляют
   `imports_bossman: false`; ядро их не импортирует и не запускает.
3. **Семнадцать существующих страниц** пользуются классами `style.css`.
   Редизайн не должен был превращаться в ремонт всех семнадцати.

---

## 2. Что изменено

### 2.1. Манифест стал источником истины (новое)

`command-center/bcc/features/apps.py` — `GET /api/apps` и `GET /api/apps/{id}`.
Читает `apps/<имя>/app.manifest.yaml`, нормализует (два существующих
приложения назвали блок контракта по-разному: `control_contract` и `control`) и
опрашивает приложение по HTTP, если оно слушает порт.

В манифесты добавлен блок `ui:` — описание карточки:

```yaml
default_port: 8890
ui:
  subtitle: Precision CAD & Generative 3D
  icon: cube
  accent: "#a06bff"
  theme: violet
  order: 2
  health_path: /health
  metrics_path: /api/metrics
  facts:
    - { label: Принтер, value: "ELEGOO Neptune 3 Plus" }
    - { label: Очередь, from: "metrics.queue_depth", fallback: "пусто" }
  actions:
    - { id: open, label: "Открыть", primary: true }
```

Факт с `value` — постоянный, факт с `from` — живой: значение берётся из ответа
приложения по пути в JSON, а если его нет, показывается `fallback`. Факт не
исчезает при отсутствии данных: пропавшая строка читается как «этого не
бывает», а правда в том, что данных сейчас нет.

**Приложение появляется на главной, добавив блок `ui:`, и ничего больше.**
Ни строчки в интерфейсе. App #5 и App #6 не потребуют правок вёрстки.

Границы: ядро ничего из манифеста не исполняет — это данные. Приложение,
которое не отвечает, показывается остановленным с честной причиной, а не
исчезает из списка.

### 2.2. Слой дизайн-системы (новое)

`command-center/ui/theme.css` подключается **после** `style.css` и ничего в нём
не переписывает: старые страницы выглядят как раньше. Все новые классы с
префиксом `bx-`.

| Группа | Что введено |
|---|---|
| Поверхности | `--bx-bg`, `--bx-surface(-2,-3)`, `--bx-hairline(-2)`, чернила трёх уровней |
| Акценты | `--bx-azure/violet/ember/mint/amber/rose`; `--bx-accent` — переменная карточки, приходит из манифеста |
| Типографика | роли, а не размеры: `--bx-hero`, `--bx-h1/h2`, `--bx-card-title`, `--bx-body`, `--bx-caption`, `--bx-metric`, `--bx-pill`. Все на `clamp()` — масштаб сам подстраивается под ширину |
| Шрифт | `Inter → SF Pro Display → Segoe UI Variable → system-ui`. Без загрузки из сети: BOSSMAN работает локально, и внешний шрифт превратился бы в зависимость от интернета |
| Шаг сетки | `--bx-1…--bx-9` (4…56px) |
| Радиусы | `--bx-r-sm/r/r-lg/r-xl/r-full` (10…26px) |
| Тени и свечения | `--bx-shadow`, `--bx-shadow-lg`, `--bx-glow`, `--bx-inner` |
| Кнопки | `primary / secondary / subtle / ghost / icon / pill`, размеры `sm/lg/xl/block`, состояния: hover, active, `:focus-visible`, disabled, `is-loading` |
| Пилюли и значки | `.bx-pill` с тонами `ok/info/accent/warn/err/idle` и режимом `is-live` |
| Карточки | `.bx-panel`, `.bx-app` с визуальной областью, `.bx-feed-item` |
| Индикаторы | `.bx-bar`, `.bx-metric`, `.bx-line` |

Тёмная тема — основная; светлая переопределяет только поверхности и чернила,
структура общая. Есть `prefers-reduced-motion`.

Одно решение стоит назвать: **светится только основная кнопка**. Если светятся
все, не выделена ни одна.

### 2.3. Новая главная (новое)

`command-center/ui/pages/home.js`, идентификатор `home-v3`. Порядок блоков —
это порядок вопросов, которые задаёт человек, открывая систему:

| Блок | Отвечает на вопрос |
|---|---|
| Hero + пилюли | в каком состоянии система |
| Командная строка | что я хочу, чтобы она сделала |
| **Мои приложения** | чем я пользуюсь |
| Сейчас идёт | что происходит без меня |
| Агенты | кто занят |
| Вычисления | на чём это работает |
| Здоровье системы | что сломано |
| Последние события | что было |

Командная строка — фокус страницы: крупное поле, растущее под текст,
переключатели режимов (Умно / Авто / С агентами) и одна большая кнопка
«ЗАПУСТИТЬ» с подсказкой сочетания клавиш.

### 2.4. Лаунчер и оболочка приложений (новое)

`ui/pages/apps.js` + `ui/pages/appcards.js`.

Карточка строится из манифеста целиком: иконка, название, подзаголовок, значок
состояния, до четырёх фактов, кнопки из блока `actions` (первая с
`primary: true` — крупная). Тематическая картинка выбирается по полю `theme`; у
незнакомой темы есть нейтральный вариант, поэтому новое приложение не обязано
трогать этот файл.

Приложение открывается **внутри оболочки BOSSMAN**: маршрут `#/apps?open=<id>`,
сайдбар и верхняя строка остаются на месте, меняется рабочая область.
Приложения — отдельные HTTP-сервисы, поэтому внутри области открывается их
собственная страница в песочнице `sandbox="allow-scripts allow-forms
allow-same-origin allow-popups"`. Это честно: BOSSMAN не притворяется, что
нарисовал её сам, но и не выбрасывает человека в чужую вкладку.

Если приложение не запущено, показывается его состояние, причина и команда
запуска. **BOSSMAN его не запускает** — поднимать чужой процесс без ведома
владельца он не должен.

### 2.5. Иерархия сайдбара (изменено)

`ui/app.js`: навигация собирается по разделам. Страница объявляет раздел полем
`section`; всё, что его не объявило, считается системным.

```
ОСНОВНОЕ    Главная · Приложения · Миссии · Агенты · Подтверждения
СИСТЕМА     Модели · Задачи · Расписания · Система · Настройки · Роутер ·
            AI Governor · Ресурсы · Скиллы · Терминал · Benchmark Lab ·
            Браузер · Карта агентов · NL-оркестрация · Форки · Self-Healing ·
            OpenRouter · Пульт · Workflow Builder · Изображения
```

Порядок основного раздела задан явно (`MAIN_ORDER`) — он отражает частоту
использования, а не порядок, в котором страницы когда-то написали.

Посадочная страница выбирается по старшинству `home-v3 → overview → home`.
Вытесненные страницы остаются доступны по прямой ссылке (`#/overview`,
`#/home`), но из меню уходят: две «главных» рядом — это вопрос «а какая
настоящая».

Нижняя панель телефона показывает только основной раздел.

### 2.6. Исправленный дефект в ядре интерфейса

`ui/components.js`, обработка `style` в `h()`. Было `Object.assign(el.style, …)`,
которое **молча игнорирует пользовательские свойства CSS** (`--что-то`):
`CSSStyleDeclaration` проглатывает неизвестный ключ без ошибки. Присваивание
выглядело выполненным, а стиль не менялся.

Обнаружено не чтением кода, а рендером: все карточки приложений вышли одного
синего цвета, хотя акценты в манифестах разные. Теперь пользовательские
свойства идут через `setProperty`. Это чинит акценты карточек и любой будущий
код, который задаёт переменную инлайном.

## 4. Чем проверено

Не «должно работать», а прогнано:

- Интерфейс поднят на живом сервере BOSSMAN и открыт настоящим Chromium
  (Playwright, `/opt/pw-browsers/chromium-1194`), с реальным входом по токену.
- Отрисовано: 3 карточки приложений из манифестов
  (`AI WebCam Vision`, `AI 3D Maker`, `BOSSMAN Social Farm`), два раздела
  сайдбара, шесть панелей, командная строка. **Ошибок в консоли: 0.**
- Снимки сделаны на 1580×1000 и на 390px, оба просмотрены глазами; найденные
  на них дефекты (наезд значка на заголовок, обрезанная кнопка, растянутые
  пустые панели, неработающий акцент) исправлены и переснято.
- Полный набор тестов ядра: **384 passed, 1 skipped**.

Три приложения показаны как «остановлено», потому что они действительно не
запущены. Это не заглушка — это правда, полученная опросом их портов.

## 5. Что осталось

1. **Живые факты не проверены на работающем приложении.** Механизм `from:`
   написан и покрыт разбором, но ни одно приложение сейчас не запущено, поэтому
   все факты отдаются из `value`/`fallback`. Проверять надо на поднятом
   `AI WebCam Vision`.
2. **Спарклайн в блоке здоровья.** В образце есть линия истории; сейчас там
   список компонентов. Данные для линии в `/api/system` есть (`history`),
   компонент `sparkline()` в `components.js` тоже — не связаны.
3. **Страница `Система` и раздел `СИСТЕМА` называются одинаково.**
   Переименование существующей страницы — решение владельца, а не побочный
   эффект редизайна, поэтому не трогал.
4. **Светлая тема новой главной не просмотрена глазами.** Токены разведены и
   структура общая, но снимок не делался. Говорить «поддерживается» на этом
   основании нельзя.
5. **Действия карточки, кроме основного, ведут на ту же страницу приложения.**
   `«Живой вид»` и `«Новая модель»` передают `action` в маршрут, но приложения
   этот параметр пока не читают.
