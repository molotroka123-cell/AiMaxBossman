# PIT dataset и будущий garbage sorter\n\nCollection-first нужен, чтобы сначала накопить реальные примеры полезной и бесполезной памяти, а уже потом учить автоматическую сортировку.\n\nНа каждый допустимый memory candidate сохраняем:\n- candidate_id, category, key, normalized value;\n- extractor model/version, confidence, evidence kind;\n- first_seen, last_seen, observation_count;\n- source turn id;\n- retrieval_count и факт попадания в model context;\n- correction_count, contradiction_count;\n- user forget/delete outcome;\n- utility feedback;\n- token cost;\n- итоговую label.\n\nLabels:\nUNKNOWN, USEFUL, DURABLE, TEMPORARY, DUPLICATE, SUPERSEDED, NOISE, ANNOYING, WRONG, FORGET_REQUESTED, SENSITIVE_BLOCKED, SECRET_BLOCKED.\n\nSECRET_BLOCKED значения не попадают в обучающий dataset вообще.\n\nTrain/eval нельзя делать на одних и тех же людях. Сначала owner + добровольные тестеры дают collection data; затем более поздние unseen turns идут в holdout; после этого отдельные добровольные новые пользователи используются как transfer set.\n\nSorter сначала работает только в shadow mode: предлагает KEEP/DROP/TTL, но high-recall collector продолжает сохранять допустимые candidates. Только после измеренного gain на holdout sorter получает право автоматически compact L1 → L2.\n\nГлавная метрика — verified personalization utility при нулевой cross-user leakage, а не максимальный compression ratio.
