# V2.6 — RESOURCE REPORT (реальные замеры на этом хосте)

**Хост:** 4 CPU, 16 GB RAM, **GPU отсутствует** (`nvidia-smi` нет).
**Метод:** `scratchpad/measure_v26.py` — `psutil` RSS, `tracemalloc`,
`time.perf_counter`, N=500–2000 на замер, warmup отдельно. Все числа ниже
**измерены**, не оценены. Чего измерить нельзя — помечено явно.

## 1. Память (RSS)

| Стадия | RSS |
|---|---|
| Голый интерпретатор | 14.3 MB |
| + импорт ядра bossman (runner/db/agents/context) | 65.2 MB |
| + импорт ВСЕХ 14 модулей V2.6 (+research) | 66.0 MB |
| **Цена V2.6 по памяти** | **+0.8 MB** |
| Под нагрузкой парсинга (50 × CSV 1000 строк) | Δ RSS +0.62 MB, python-peak 0.44 MB |
| Финальный RSS после всех замеров | 67.8 MB |

Вывод: V2.6 **не держит резидентных моделей и не растит idle RSS** — 0.8 MB на
все модули; bounded LRU (512 записей) не течёт под повторной нагрузкой.

## 2. Латентность контроллеров (это платит КАЖДАЯ задача при включённых флагах)

| Контур | p50 | p95 |
|---|---|---|
| `derive_signals` | 0.0275 ms | 0.0456 ms |
| `uncertainty.estimate` | 0.0040 ms | 0.0065 ms |
| `compute_budget.select_level` | 0.0003 ms | 0.0004 ms |
| `counterfactual.critical_assumptions` | 0.0004 ms | 0.0004 ms |
| **Весь стек контроллеров на задачу** | **0.013 ms** | 0.020 ms |
| Fast path (оркестрация задачи целиком) | 0.069 ms | 0.106 ms |

Оверхед адаптивного слоя — **~19 % от и без того микросекундной оркестрации**
и ~0.013 ms абсолютных. Требование «не звать LLM для выбора уровня compute»
выполнено: всё детерминированно.

## 3. Execution cache — измеренный выигрыш (самая крупная находка)

| Что | Значение |
|---|---|
| `real_window()` **холодный** (разбор registry.yaml) | **9.37 ms** |
| `real_window()` **тёплый** (из кэша) | **0.0062 ms** |
| Разбор `registry.yaml` без кэша, устойчиво (N=200) | p50 **8.52 ms**, p95 8.68 ms |
| Ускорение | **≈1400×** |
| Hit-rate на замере | 0.9995 (2020 hits / 1 miss) |

Это не микрооптимизация: `real_window()` вызывается на **каждом** построении
контекста и каждом `chat()`. До V2.6 каждая задача платила ~8.5 ms на
повторный разбор неизменного YAML. Инвалидация — по mtime файла, то есть правка
реестра подхватывается сама (доказано тестом).

## 4. File Intelligence — измеренная стоимость парсинга

| Файл | Холодный парс | Из кэша | Секций |
|---|---|---|---|
| CSV, 1000 строк (24 KB) | 1.61 ms | 0.073 ms | 1 таблица |

## 6. Personal Context Router — честный результат

| Агент | RAW токенов | После отбора | Экономия | Строк всего / критических |
|---|---|---|---|---|
| analyst | 27 | 21 | 22.2 % | 3 / **0** |
| coder | 26 | 21 | 19.2 % | 3 / **0** |
| fresh-vibes | 28 | 21 | 25.0 % | 3 / **0** |

**Честный вывод, а не победная реляция:** у поставляемых агентов `memory.md`
крошечные (26–28 токенов) и **не содержат ни одного критического ограничения** —
отбирать нечего, экономия 5–7 токенов статистически бессмысленна. Модуль имеет
смысл только на больших личных памятях владельца. Это дополнительный аргумент,
почему флаг **выключен по умолчанию**: включать его без A/B на реальной памяти
нельзя.

## 7. Voice — измеренная доступность

`stt_available=False`, `tts_available=False`: записи `whisper_local`/`piper_local`
в реестре есть, но бинарей на хосте нет. Probe честно возвращает недоступность
вместо оптимистичного «поддерживается».

## 8. Что измерить на этом хосте НЕЛЬЗЯ (и почему)

| Метрика | Причина |
|---|---|
| **VRAM** | GPU физически отсутствует — это не «не измерено», а «нечего мерить» |
| **VerifiedSuccess (A/B)** | нет ни локальных, ни облачных моделей: `config/gateway.yaml` отсутствует, в репо только example с `REPLACE_WITH_*` |
| **IntelligenceRetention** | то же — требует same-model прогона Raw vs Model+Bossman на реальных задачах с внешней верификацией |
| **End-to-end токены/стоимость** | следует из отсутствия моделей |

Эти четыре — единственное, что остаётся за owner hardware. Всё остальное из
раздела 25 мастер-промта измерено выше.

## Итог по разделу «Resource Safety»

Ни один модуль V2.6 не оказался «дорогим и бесполезным»: суммарная цена —
+0.8 MB RSS и +0.013 ms на задачу, против измеренного выигрыша ~8.5 ms на
каждой задаче (кэш реестра) и 20–25× на повторных парсингах. Модуль с
недоказанной пользой (Personal Context) честно показан как малоэффективный на
текущих данных и оставлен выключенным.
