## V7 architecture audit

### What V7 should NOT be

- another dashboard redesign
- another generic memory layer
- dozens of hard-coded agents
- a model catalog expansion
- autonomy obtained by weakening approvals or fresh verification
- self-modification without promotion evidence

### Highest-value V7 gaps

#### G1 — no authoritative World State Graph
Facts exist in DBs, logs, UI state and tools, but there is no single typed model of `fact + source + timestamp + freshness + confidence + scope + invalidation`.

#### G2 — Mission IR is not yet the primary execution contract
Intent, obligations, budgets, privacy, proof and rollback need one versioned compile target rather than being inferred independently in downstream layers.

#### G3 — routing is capability-oriented, not expected-utility-oriented
Bossman should choose among deterministic tool path, small model, large model, specialist, multi-agent and human escalation using measured success/latency/cost/risk/resource pressure.

#### G4 — recovery is retry-heavy rather than strategy-changing
A failed browser path should be able to switch to accessibility/API/alternate tool/human escalation according to policy instead of repeating the same failure mode.

#### G5 — local models are resources, not a cognitive fabric
Residency, routing, role assignment and escalation should be coordinated across small/medium/large/vision/tool models with measured memory pressure.

#### G6 — successful missions do not yet compile safely into promoted skills
The system needs trace -> candidate skill -> deterministic replay -> adversarial test -> shadow -> benchmark -> canary -> promotion -> rollback.

#### G7 — attention/QoS lacks goal-level economic scheduling
Owner-visible work, critical CI failures, recovery and background media should compete via explicit priority/deadline/value/resource rules.

#### G8 — the owner UX exposes tools more than reality
The primary experience should answer: what Bossman believes, what it intends to change, why this strategy was chosen, what evidence proves success, and what needs owner input.

## Recommended V7 order

1. contracts first: World State + Mission IR + proof/freshness semantics
2. observation adapters and state reconciliation
3. deterministic strategy candidates and scoring
4. adaptive router with shadow-only decisions first
5. Local Cognitive Fabric residency/routing
6. strategy fallback/recovery
7. attention/QoS scheduler
8. skill compiler + promotion pipeline
9. dynamic mission teams
10. goal-first Mission/Reality UI

Do not start self-improving behavior before replay, canary, rollback and evidence contracts are testable.
