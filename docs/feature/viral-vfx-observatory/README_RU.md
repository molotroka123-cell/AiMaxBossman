## Что работает в коде

**Video Studio:** 24 эффекта и 6 составных пресетов. PHONK HARD, PHONK DARK,
DRIFT, LUXURY FAST, CRYPTO HYPE, CINEMATIC VIRAL. Среди атомов: punch zoom,
beat shake, RGB split, glitch, motion trail, focus hit, зерно/VHS/scanlines,
контраст/exposure, vignette, цветовые стили. Это локальные фильтры общего
FFmpeg-компилятора, того же, который делает preview/export. Не второй редактор.
Звук не заменяется; геометрические/цветовые эффекты не меняют длительность/FPS.

Откройте проект → выделите визуальный клип → **Viral VFX · Phonk** → пресет,
интенсивность, BPM и сдвиг → **Проверить VFX-план** → отдельное **Применить VFX**.
План проходит обычный VideoService dry-run, ревизию и operation_id. Повторная
доставка не добавляет эффект дважды, чужая правка вызывает conflict; работает
история/undo. Старый Viral VFX на выбранном клипе заменяется, другие эффекты
сохраняются. Аудиоклип и locked-дорожка отвергаются, не принимаются как no-op.

Опция **9:16 / 30 fps / 15 с** задаёт настройки и диапазон 0–15 с. На таймлайне
должно уже быть 15 с материала. Она не скачивает/генерирует недостающие сцены
и не обрезает оригиналы. При экспорте отдельно выберите **Диапазон**. BPM/offset
задаются вручную: анализ аудио, поиск drop и автоматическая нарезка не реализованы.
Резкое движение может быть неприятным; начните с низкой интенсивности. Полноэкранный
строб не добавлен. Это не гарантия фотобезопасности или виральности.

**Studio/Higgsfield:** 3 черновика сцен по 5 с внутри существующего Studio.
«Вставить только промпт» меняет обычное поле; не нажимает Generate, не меняет модель,
тариф или разрешения. Генерация и импорт результата в Video Studio идут штатным
путём. Это не новые проприетарные эффекты Higgsfield, не работающая генерация без
провайдера и не обещание точной длительности модели. Музыка — разрешённый файл владельца.

**Brain & Observatory:** одна страница с шестью представлениями:

| Представление | Реальный источник и граница |
|---|---|
| Brain View | Выбранная задача, model/run/tool/approval IDs, состояния и записанные проверки. Не скрытые рассуждения/нейроны модели. |
| Live Agent Graph | Сохранённые связи agent→task→run→model/tool; обновление через существующую шину событий открытой страницы. Не придуманные связи сотрудничества. |
| Memory Map | ID и lineage фактов выбранного проекта/задачи; supersession только внутри окна. Не embedding similarity, не тексты/личные файлы. |
| Learning View | Реальные skill_evaluations, числовые метрики базы/кандидата; verdict отдельно от applied. Нет кнопки обучения весов или автоприменения. |
| UI→API X-Ray | Opt-in, последние 120 запросов штатного api.js этой вкладки: метка действия, шаблон маршрута, HTTP, latency. Не перехватывает raw fetch/WS и не выдумывает server/DB spans. |
| Self-Analysis | Счётчики ошибок/ожиданий и отсутствующих записей проверок в ограниченном окне. Не IQ-балл, не автономная починка ядра. |

Путь: `#/observatory`. Выберите задачу; Memory Map также принимает точный project ID.
Состояние выбора живёт в URL, данные читаются из существующей БД после рестарта.
Нет новой базы, второго агента, фонового монитора, cloud inference или зависимости.
UNKNOWN/пустая выборка/503 не становятся PASS. completed/HTTP_OK не означают
независимую проверку бизнес-результата.

## Приватность и полномочия

Новые backend-ручки — только GET под штатной аутентификацией BCC. Запросы выбирают
метаданные, не prompts, chain-of-thought, содержимое памяти, ключи, тела, результаты
инструментов или личные имена файлов. Learning показывает метаданные экземпляра;
Memory — только указанную область. X-Ray по умолчанию OFF, хранится лишь в памяти
вкладки, исключает auth/provider/egress и стирается при границе сессии. Старый
in-flight ответ не восстанавливает trace после logout. ASK/DENY не изменены.

## Что реально проверено локально

Linux / Python 3.13.5 / Node 22.16 / FFmpeg 7.1.5. Основа — распакованные wheels
предыдущего local bundle с точечными изменениями; **не чистая установка нового
wheel/application ZIP**. aiosqlite 0.21.0 восстановлен для тестовой среды из
неизменённых upstream файлов на `82eb2d2b05c257e247acba561b2548cca7fa365a`,
Git blob каждого файла сверен; эта временная зависимость не vendored в продукт.

- **48 Python checks PASS**: все 30 пресетов реально обработаны FFmpeg,
  различающие пиксели, сохранение постоянной alpha, нулевая интенсивность,
  отрицательные параметры, настоящие HTTP/SQLite, auth/GET-only, scope,
  защита приватных полей, отсутствующие/ошибочные данные, dry/apply/replay/
  conflict/reopen/undo. 2 тяжёлых группы запускались отдельно, не пропускались.
- **1 native render PASS** отдельно: реальный 15-секундный MP4, **180×320**,
  30 fps / **450 декодированных кадров**, аудио, полный decode и хеши. Это
  прокси-разрешение CPU-теста, НЕ измерение 1080p/Ryzen/Radeon.
- **1 Chromium DOM check PASS**: все шесть представлений, граф→задача,
  изменение BPM сбрасывает согласованный план, dry-run и одиночное применение
  при двойном клике. DOM настоящий, API/идентификаторы — явные fixtures;
  это не running-app браузерная приёмка.
- **14 Node checks PASS**: общий API transport с fetch doubles, privacy/session,
  ограничение trace, typed VFX-plan, реальные ID-связи графа. Не live-model.

Исправлен найденный пиксельными тестами дефект: vignette терял прозрачность,
а noise изменял alpha. Теперь vignette обрабатывает RGB и сохраняет alpha,
зерно работает в явно заданном planar RGB и не шумит alpha. Все 30 проверены снова.

**Локальные ограничения не скрыты:** running-app Chromium E2E остановлен до входа

1080p/perf/soak, настоящая модель/музыка/Higgsfield этим не сертифицированы.

## Обязательный CI перед слиянием

`.github/workflows/viral-vfx-observatory.yml` запускает группы в отдельных процессах,
проверяет checkout SHA и JUnit (нет failures/errors/skips), требует реальный Chromium
с работающим приложением, не переписывает тесты из CI. Его зелёный результат
относится только к своему SHA и SOURCE_FEATURE_ACCEPTANCE, не ко всему V8.

Нужно: зелёный feature workflow включая running-app UI, общий регрессионный CI,
проверка конфликта со свежим release, новая сборка и owner/Windows-проверка перед
заявлением готовности установленной версии. Пока это не выполнено — не сливать
и не подменять принятый application ZIP. Результаты этой сессии не приписывать
старому 448db2ee или новой вершине release.
