### Дефект, который заявка называла открытым, — уже исправлен

PR #60 сообщала об `OPEN_REPO_P1`: в неразворачиваемой установке
(`pip install .`, без `-e`) `pinned_sha()` возвращал пустую строку, потому что
манифест искался по `parents[3]`, а из `site-packages` это каталог
интерпретатора. Для владельца это не мелочь: он запускает **установленный**
продукт, а не рабочую копию, и в каждый конверт разбора уезжал бы пустой
`upstream_sha`.

В канонической ветке этого больше нет. `command-center/bcc/file_intelligence/
discovery.py` пробует сначала упакованный путь и только затем путь рабочей
копии:

```python
_PACKAGED_MANIFEST = Path(__file__).resolve().parents[1] / "_integrations" / ...
_CHECKOUT_MANIFEST = Path(__file__).resolve().parents[3] / "integrations" / ...
```

Комментарий в файле описывает ровно тот отказ, о котором писала заявка.

**Вывод:** закрытие PR #60 не отнимает ни одной способности. Потерян был бы
только исторический документ заморозки — его можно перенести отдельным
коммитом, если владелец хочет сохранить числа того прогона.

## PR #59 — НЕ поглощена. Решение за владельцем

```
 1  bossman-core/tests/test_ui_drift_repair.py
 1  .github/workflows/social-farm-ci.yml
```

### Почему я не предлагаю её влить

Существо заявки — **вождение веб-интерфейса Higgsfield селекторами**. У
владельца на этот счёт стоящее правило: «Higgsfield — только официальный MCP
и аккаунт владельца. Не предлагай его повторно без нового запроса». Влить
эту заявку значило бы обойти правило кодом, поэтому я её не предлагаю и
принимать решение за владельца не буду.

Своя же заявка честно говорит о пределе: набор селекторов помечен
`0.1.0-unverified`, писан по документированному интерфейсу, а не по
наблюдённому; аккаунта Higgsfield в среде нет; ни один файл в её тестах не
пришёл от Higgsfield.

### Довод заявки про CI больше не действует

PR #59 писала, что у `apps/social-farm` «не было задания CI никакого вида» и
500 тестов жили только у того, кто запускал их руками. На момент заявки
(08.09) это было верно. Сейчас — нет: `shipped-apps.yml` поднимает задание
`social-farm` на двух версиях Python, ставит настоящий Chromium и ffmpeg и
прогоняет тесты, а `require_acceptance_results.py --minimum-tests 10`
стережёт от тихого пропуска. В канонической ветке там 24 файла и 287 тестов.

### Что в ней может стоить отдельно от Higgsfield

Два файла выглядят независимыми от способа доступа к Higgsfield, и в
канонической ветке одноимённых нет:

* `selector_repair.py` (232 строки) — починка селекторов при дрейфе
  интерфейса силами OpenHands, с защищёнными путями: обнаружение вызовов,
  изоляция, скрытие секретов и реестр способностей править нельзя, а диффы,
  которые пропускают тест, удаляют утверждение, глотают исключения или жмут
  по координатам, недопустимы.
* `media_routing.py` (114 строк) — наблюдение как «значение + источник +
  возраст», где неизмеренный или устаревший факт ЗАКРЫВАЕТ маршрут, а не
  открывает его.

Оба — идеи, а не готовые куски: переносить их можно только по смыслу, с
собственными тестами, и к Higgsfield они отношения не имеют.

## РЕШЕНО МНОЙ. Владелец делегировал технические решения (execution override 19.09)

Правило владельца: «Salvage capabilities, not branch history» и «Do NOT import
duplicate architecture merely because it exists». Оба файла проверены по этому
правилу — и оба ОТКЛОНЕНЫ, потому что способность уже есть, и в каноническом
виде она сильнее.

### `media_routing.py` (114 строк) — ОТКЛОНЁН, способность уже есть

Его существо — «неизмеренный или устаревший факт ЗАКРЫВАЕТ маршрут, а не
открывает». В канонической ветке это уже сделано, и слово в слово тем же
доводом, в `command-center/bcc/features/reality.py::memory_reading`:

> a STALE reading is not a smaller number, it is the absence of a current one,
> and a path that needs memory must not be sized against it.

Тот же ключ `process.host`, та же проверка `read.status != "FRESH"`, тот же
отказ при отсутствующем `ram_available_mb`.

Канонический вариант СИЛЬНЕЕ: рядом стоит `memory_requirement()`, который
отвергает NaN, ±inf и отрицательные требования прямо на ручке (422). В версии
PR #59 этой проверки нет вовсе. Перенос заменил бы более строгую проверку
менее строгой.

Единственное, чего в отклонённом файле нет у одноимённой функции, — сводка
здоровья провайдера четырьмя состояниями. Но сам факт `provider.models`
публикуется `reality/observers.py:171`, и здоровье уже разбирается в
`reality/strategy.py`. Тридцать строк сводки не стоят второго модуля с
собственным экземпляром тех же правил.

### `selector_repair.py` (232 строки) — ОТКЛОНЁН, механизм уже есть и общий

Его ценная часть — защищённые пути: OpenHands может править набор селекторов,
адаптер и тесты, но не обнаружение вызовов, не изоляцию, не скрытие секретов и
не реестр способностей.

В канонической ветке это уже есть, и не для одного случая селекторов, а как
ОБЩИЙ механизм:

* `apprentice/live_workspace.py` — `protected_paths` неизменяемы
  (`protected path is immutable`), проверка на записи и на восстановлении;
* `apprentice/openhands_client.py` — `_validate_scope` вызывается ДВАЖДЫ:
  до отправки задания и по изменённым файлам после него.

`selector_repair.py` — частное применение этого механизма к одному набору
селекторов. Переносить частный случай поверх работающего общего значит заводить
второй экземпляр правил. Отклонено по тому же правилу владельца.

### Что это значит для PR #59 в целом

Ни один из 39 файлов не переносится:

* 28 файлов (`apps/social-farm/src/social_farm/generation` и тесты к ним) —
  вождение веб-интерфейса Higgsfield селекторами. Противоречит стоящему правилу
  владельца: только официальный MCP и его аккаунт.
* 2 файла разобраны выше — способность уже есть, канонический вариант сильнее.
* 6 документов `docs/ai_streamer` — описывают именно отклонённый подход.
* 1 workflow — вытеснен: `shipped-apps.yml` уже поднимает `social-farm` на

Ветка остаётся в Git, история восстановима, ничего не стирается.
