# Epoch 8 — План реализации

Порядок не менять: каждая фаза начинается с тестов и негативных контролей,
заканчивается прогоном Windows-архива и обновлением `docs/final`. Ни одна
фаза не считается сделанной по отчёту — только по строкам вердиктов из
`ACCEPTANCE_AND_FREEZE_GATES.md`.

## Приоритеты

- **P0** — без этого студии нет: каталог, протокол провайдера, очередь,
  галерея с provenance, приёмка на архиве.
- **P1** — то, ради чего студия нужна владельцу: облачная генерация по ключу
  (OpenRouter, Higgsfield HTTP), связка с Video Studio и агентами, бюджет.
- **P2** — усиление: Higgsfield MCP, локальная пост-обработка, TTS, персонажи.

## Фаза 0 — Baseline и контракт (P0, без изменения поведения продукта)

1. Замер до изменений (правило §7): время `import bcc.app`, RSS/CPU покоя
   процесса с очередью Images за 60 с, время первого ответа
   `/api/images/models`, размер архива. Записать в
   `docs/v8/METRICS_BASELINE.md` (файл создаётся прогоном, не заранее).
2. `tools/studio_models.json` + `bcc/studio/catalog.py` (загрузчик с
   самопроверкой, CLI `--json/--check`), первые записи: `comfyui:*` (из
   `image_configuration`), `openrouter:google/gemini-2.5-flash-image`,
   `openrouter:google/gemini-3.1-flash-image`, `openrouter:minimax/hailuo-3-max`,
   `openrouter:bytedance/seedance-2.0-mini` — ровно те, что уже вызывались
   скриптами репозитория; цены — `null`, пока не измерены.
3. `bcc/studio/provider.py` — протокол, состояния, маппинг причин на
   `model_health`; `bcc/studio/providers/comfyui.py` как обёртка.
4. Тесты первыми: `tests/test_studio_catalog.py` (валидность, уникальность,
   отвергнутые чужие значения), `command-center/tests/test_studio_provider_states.py`
   — **пары**: законный ответ проходит / 401, 429, 404, nsfw, битый JSON дают
   пять разных состояний и ни одно не проходит как `completed`.
5. Строки: `BOSSMAN_STUDIO_CATALOG=<n> verified=<k> unverified=<m>`.

Выход: продукт не изменился; каталог и протокол есть; baseline записан.

## Фаза 1 — Очередь, галерея, «Студия» (P0)

1. `studio_jobs`/`studio_runs` (аддитивная миграция), `process_one()` по
   образцу Images с отменой посреди рендера; пакетный опрос активных заявок.
2. Provenance-запись на каждый результат, неизменяемость триггером; тест:
   попытка изменить завершённую запись отвергнута БД.
3. Галерея (скоупы, просмотрщик с provenance, reuse, корзина с
   восстановлением, массовые операции), composer с панелью настроек по схеме.
   Страница `images` переименована в «Студия», старые ссылки работают.
4. Миграция `image_assets` → `studio_runs` (старые записи получают
   `provider=mock-image|comfyui`, `cost_usd=NOT_CAPTURED:pre-v8`).
5. Тесты: `test_studio_gallery_ui.py` (61-й прогон не вытесняет 1-й; reuse
   даёт идентичный `plane`; корзина → восстановление), `test_images_cancel_button`
   расширен на `surface=video` со стабом провайдера; развёртка UI покрывает
   новые кнопки (категории `dead/error/disabled_silent/vanished` = 0).
6. Реестр приёмки: модуль `test_studio_*` добавлен в
   `tools/acceptance_registry.json` (профиль `windows-installed`, минимум
   растёт ровно на число новых сценариев), фильтр путей workflow расширен.
7. Прогон Windows-архива: `BOSSMAN_BUNDLE_ACCEPTANCE=PASS`, профиль
   `windows-installed` `N/N`, развёртка `PASS`.

Выход: студия работает на локальных провайдерах (`mock-image`, ComfyUI);
облака ещё нет.

## Фаза 2 — Облачная генерация по ключу владельца (P1)

1. `bcc/studio/providers/openrouter.py`: images + videos + остаток бюджета;
   ключ через `openrouter_identity.resolve` (Vault ⟶ env); каждый вызов через
   `GovernedAdapter`; лимиты `governor.cloud_budget_usd` (дневной) и на
   заявку. `tools/hailuo_rescue.py` и `tools/seedance_shorts.py` переводятся
   на адаптер (или помечаются как унаследованные — решение фиксируется в
   `BUG_LEDGER`).
2. Диалог эгресса: первая отправка медиа владельца провайдеру требует
   подтверждения; тест: без подтверждения `submit` не вызван.
3. Стаб-сервер OpenRouter в тестах (по образцу
   `test_owner_acceptance_tool_path.py`): очередь → статус → файл; пары
   состояний из фазы 0 против стаба; бюджет: превышение → `stop`, платная
   модель при `free_only` не вызвана.
4. Живая проверка в workflow: шаг `studio_live_owner` из `app-support`
   архива — 1 изображение + 1 видео минимальной длительности на явно
   бесплатных маршрутах; без ключа → `OWNER_REQUIRED` (код 2), с ключом —
   `PASS|FAIL` с provenance в уликах. Строка `BOSSMAN_STUDIO_LIVE=openrouter:…`.
5. `analysis.generation_status()` Video Studio читает БД провайдеров и
   возвращает `AVAILABLE` только при `VERIFIED = true` (живая проверка на
   этой машине), иначе прежний `BLOCKED`.

Выход: с ключом владельца студия генерирует в облаке под бюджетом; без ключа
— честный `OWNER_REQUIRED`.

## Фаза 3 — Higgsfield как провайдер (P1 → P2)

1. **Сначала MCP — это официальный путь.** Полоса
   `tools/mcp_acceptance.py` для официального MCP-сервера Higgsfield: 16 проб,
   стоимость покоя, сеть, секреты, откат → строка вердикта в
   `docs/final/CONNECTOR_INTEGRATION_REPORT.md`. При `ADOPT_AS_OPTIONAL_BACKEND`
   пишется `bcc/studio/providers/higgsfield_mcp.py`; при меньшем вердикте —
   `REFERENCE_ONLY`, и фаза 3 на этом честно заканчивается.
   `bcc/studio/providers/higgsfield_http.py` НЕ пишется, пока владелец не даст
   официальную документацию REST: на 17.09 контракт не подтверждён
   (`docs.higgsfield.ai` закрыт egress-прокси), а форма из чужого клиента —
   гипотеза. До документации запись каталога несёт
   `OWNER_REQUIRED: official REST contract not supplied`.
2. Записи каталога для моделей Higgsfield — только те, что владелец включил,
   с параметрами из `models_explore get` (схема совпадает с W1: options /
   min / max / default); `supports_unlim` отражается меткой «безлимит пробного
   периода», а не «бесплатно».
3. Матрица отказов §22 (`docs/final/FAILURE_MATRIX.md`): для провайдера
   Higgsfield названы тесты по строкам 1, 3, 5, 6, 7, 8, 14, 15, 16, 18, 19.
4. Кредиты владельца — часть приёмки, а не сюрприз: `balance` официального
   сервера на 17.09 даёт `credits = 0`, план `free`. Отказ по кредитам
   обязан приходить как `insufficient_credit` → `OWNER_REQUIRED`, отдельно от
   429 и от отсутствующего ключа; тест на это — пара к остальным пяти.
5. Живая проверка 2 модели × 3 задачи (изображение, image-to-video,
   отмена) — `BOSSMAN_STUDIO_LIVE=higgsfield:PASS|OWNER_REQUIRED|FAIL`.

Выход: Higgsfield доступен как один из провайдеров, выключенный по умолчанию,
с той же семантикой отказов и бюджета.

## Фаза 4 — Результат в работе (P1)

1. Video Studio: `media.import` из галереи с `provenance_ref`; действие
   «Сгенерировать для этого места» в панели «ИИ»; раскадровка → пакет заявок
   с общей коллекцией; e2e: промпт → клип на таймлайне → экспорт с
   квитанцией (`export_receipt`) → перезапуск → всё на месте.
2. Web Designer: вставка изображения из галереи в существующий `edit`.
3. Агенты: инструмент `studio.generate` под `gate_completion`; тест
   «наблюдение ≠ улика»: `completed` провайдера без проверенных байтов —
   задача не `COMPLETED`.
4. Потоки B (сайт) и E (видео) из `docs/final/owner_flows.json`
   перепроверяются с генерацией; вердикты пишутся туда же.

## Фаза 5 — Усиление (P2)

1. Пост-обработка: рефрейм FFmpeg (в продукт), апскейл и удаление фона —
   кандидаты через матрицу пяти ответов; тест на настоящем бинаре или
   `OWNER_REQUIRED`.
2. TTS: через провайдера (OpenRouter/Higgsfield `text2speech_v2`-класс) с
   теми же состояниями; локальный TTS — кандидат (`piper` уже упоминался в
   `docs/v2_6`, статус «заглушка» — не считать сделанным).
3. Персонажи/референсы владельца: папка референсов в памяти (vault
  заметок), привязка к заявке ролью `reference`; никаких «Soul ID» без
  провайдера.
4. Приёмка на железе владельца: `app-support/target_hardware_acceptance.py`
   получает сценарий студии (локальный ComfyUI, если установлен); до
   прогона на целевой машине — `OWNER_REQUIRED`.

## Зависимости

- Фаза 1 зависит от фазы 0 (каталог, протокол).
- Фаза 2 зависит от ключа владельца для живой части; репозиторная часть — нет.
- Фаза 3 зависит от ключа Higgsfield и решения владельца о base URL.
- Фаза 4 зависит от фазы 1 (галерея) и любого одного провайдера с `VERIFIED`.
- Фаза 5 не блокирует заморозку.

## Что делается первым в каждом коммите

1. Тест, который падает на текущем коде (воспроизведение).
2. Негативный контроль к каждой новой проверке (пара «проходит / отвергается»).
3. Правка минимального объёма без новых зависимостей.
4. `python tools/skips_registry.py --check`, затем `--check` после
   регенерации, если менялись skip-маркеры.
5. Коммит явными путями, push в общую ветку (Aster пишет параллельно).
