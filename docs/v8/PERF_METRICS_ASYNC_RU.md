# PERF-METRICS-001: чтение железа не должно блокировать основной цикл

Статус: **реализация и целевые проверки выполнены в Linux-контейнере; новая Windows-поставка ещё не принята**. Это узкая оптимизация, не новый freeze V8 Total.

## Причина и изменение

`MetricsSampler.sample()`, async-обработчик `/api/system` и резервное чтение в `features/resources._snapshot()` синхронно вызывали `MetricsSampler.read()`. В нём есть файловые/system-вызовы и best-effort GPU subprocess с существующим тайм-аутом 5 с. Пока такое чтение ждёт, остальные задачи того же asyncio loop не обслуживаются. Воспроизведение контролирует блокирующее чтение через событие; это не утверждение о зависшем физическом Radeon.

Добавлен `read_async()` поверх существующего синхронного `read()`. Блокирующая часть выполняется в общем executor; одновременно выполняющееся чтение одно на sampler. После его завершения следующий запрос читает заново — новый долгий кэш не вводился. Все три async-клиента переключены на этот путь.

Отмена одного запроса не отменяет чтение для остальных. Дочитавший поток сам не пишет в БД и не публикует события: отменённый sampler не продолжает запись. Ошибки доходят до активного читателя, а ошибка после отмены всех читателей забирается callback. Результаты читателей копируются, включая вложенные GPU-данные.

Показатель CPU берётся в исходном потоке event loop: перенос `cpu_percent(interval=None)` в произвольный executor-thread без этого менял бы его базу сравнения и мог бы отдать первый ноль. Синхронный диагностический hook `read()` остаётся совместимым, в том числе для existing missing-data tests.

## Измерение до/после

20 чередующихся пар: в GPU-read тестовый wait 250 мс, независимый callback должен сработать через 10 мс. CPU/RAM/disk читает настоящий psutil контейнера; GPU-read, DB и шина контролируемые. Это **не** полноценный UI, Windows, модель или измерение реального драйвера.

| Метрика, мс | До | После |
|---|---:|---:|
| Медиана опоздания независимого callback | 240.744 | 0.352 |
| p95 опоздания callback | 240.927 | 0.460 |
| Медиана завершения самого slow sample | 250.706 | 251.219 |
| Медиана sample без искусственной задержки, 40 пар | 0.247 | 0.397 |

Работа прибора не ускорилась: она перестала блокировать остальную программу. Накладные расходы на быстром контроле около 0.15 мс. Нельзя превращать эту таблицу в «весь Bossman ускорился в сотни раз» или обещание скорости Radeon.

Числа и границы проверки — `evidence/metrics-async-summary.json`. Полные локальные отсчёты, JUnit, снимки, diff и script воспроизведения переданы владельцу отдельным пакетом; raw SHA-256 записан в JSON. Результат можно повторить, получив исходный metrics.py из указанного baseline и запустив одинаковые controlled-I/O испытания.

## Проверки

`command-center/tests/test_metrics_async_read.py`: 16 новых случаев. Вместе с неизменёнными 5 случаями `test_metrics_gpu.py` — **21 passed, 0 failed**. До правки тот же набор: **11 failed, 10 passed**; часть отрицательных контролей проверяет новый async-интерфейс, а три отдельных поведения воспроизводят блокировку в старых действующих путях.

Проверены: periodic loop, реальный API handler, cold resource fallback, 32 одновременных запроса с одним чтением, отмена одного/всех читателей, поздняя ошибка, восстановление после ошибки, отсутствие поздней записи после отмены, graceful stop, независимость вложенных результатов, корректный CPU-thread baseline, запрет admission без измеренной RAM даже при ручном override. GPU parser/cache tests взяты без изменения; Git blob сверен.

Это unit/in-process boundary tests с явными DB/bus doubles, **не** SQLite/Windows/браузерная приёмка. Проверен синтаксис файлов и AST: в api/resources единственное исполняемое изменение — ожидание async-чтения. Схема БД, auth, budget, cancellation-policy, модельные результаты и verification не менялись.

## Сохранено и что ещё проверить

GPU_CACHE_TTL=5.0, NVIDIA_TIMEOUT=5.0, SAMPLE_SECONDS=10.0 сохранены. Новых runtime-зависимостей, моделей, отдельных демонов и отключённых гейтов нет. Штатный thread executor переиспользуется; запущенное системное чтение нельзя насильно убить отменой asyncio — оно завершается в пределах существующих ограничений источника. Поэтому физическая проверка долгого/ошибочного системного вызова всё ещё нужна.

Публикация поверх актуальной ветки, без отката Fable: исходная работа начиналась на 28e05b08, затем сохранены 1aa62216 (Unicode runners) и d5622af (metrics smoke). Три исходных runtime blob не изменились в этой параллельной дельте.

Перед включением нового ZIP в known-good: полный Command Center 3.11/3.12/3.14, Windows paths, lifecycle/resource tests, root/Core и существующий Windows installed contract 46/46. Затем GUI: открыть System/Resources во время другой задачи; проверить Stop и рестарт; подтвердить реальные значения и отсутствие зависших собственных процессов. Исторический accepted ZIP не заменять и не метить новым SHA.

Дальнейшая оптимизация — только после замера: большие галереи, частота перерисовки, cold/warm startup и полное дерево процессов. Новые внешние движки из прежнего запроса сюда не добавлены: no-ai-slop, OmniGet, agent-orchestrator, witr, OpenContext и Higgsfield требуют отдельной проверки назначения/лицензий/интеграции. Никакого заявления, что шесть независимых агентов уже запускались.
