## BossBlocks-001

Goal: from one Bossman CMD/UX instruction, spend at most four hours building an
original Minecraft-like voxel sandbox vertical slice, autonomously test it,
repair all known defects in the declared scope, package it and hand the final
build to the owner to play.

**All development actions must flow through Bossman CMD/UX and the same Bossman
backend.** Direct human edits, hidden parallel scripts, direct IDE intervention
or a separate orchestration product invalidate GREEN.

Jev directs. Product code is authored by LOCAL/FREE workers or bounded GLM-5.3-Flash through the Coding Limit Saver. Claude may teach/escalate through an
already authorized Bossman path. **Aster never writes product code**; Aster independently audits, continuously
identifies improvements and turns verified findings into lesson/skill candidates
for the rest of Bossman.

The target is not "perfect software forever". GREEN means **zero known defects
inside the frozen benchmark acceptance scope after the final owner-equivalent
simulation and independent verification**.

- complete truthful Instagram profile;

This pilot is accepted as a social bootstrap only after live owner evidence. It does **not** become `VERIFIED_REVENUE_LOOP_PASS` until later real lead/booking/revenue attribution is measured.
