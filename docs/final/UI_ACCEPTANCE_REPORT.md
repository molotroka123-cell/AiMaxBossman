# Приёмка интерфейса: каждая кнопка нажата (раздел 23)

Задание формулирует требование без обиняков: «владельцу неинтересна
теоретически блестящая система с мёртвыми кнопками… Zero unexplained dead
buttons in primary owner workflows».

Проверялось не наличие кнопки в разметке, а то, что происходит ПОСЛЕ нажатия.
Инструмент — `scripts/ui_acceptance_sweep.py`: поднимает настоящий Command
Center на временном каталоге данных, входит настоящим токеном через форму
входа, открывает каждую страницу реестра `ui/pages/index.js` и нажимает каждый
видимый орган управления. Машинный результат — `docs/final/ui_acceptance.json`.

## Две «ошибки», и почему это не дефекты

Классификатор относит нажатие к `error`, если после него была ошибка в
консоли, исключение страницы или ответ 5xx. Он НАМЕРЕННО строгий: послабление
вида «ошибка в консоли не считается, если пользователю что-то показали»
спрятало бы настоящие падения, которые тоже показывают всплывашку. Поэтому оба
оставшихся случая разобраны руками.

| Страница | Нажатие | Что видит владелец |
|---|---|---|
| OpenRouter | `Connect` без ключа | «Вставьте ключ · без ключа подключаться нечем» — видимое сообщение с подсказкой |
| Операторский канал | `Отправить` с пустым полем | «Команда пустая» — отказ ЛОКАЛЬНЫЙ, на сервер запрос не идёт |

Оба — правильное поведение: действие невозможно, причина названа
по-человечески. В консоль это попадает потому, что тот же механизм показа
сообщений пишет и туда. Дефектом это не является, и «чинить» его правкой
классификатора было бы подлогом.

## Что обход НАШЁЛ и что из этого починено

### BL-027 — панель приложений перекрывала кнопки (настоящий дефект продукта)

Единственный настоящий дефект продукта среди 115 нажатий — и он был серьёзнее,
чем выглядел. На странице «Пульт» кнопка START не нажималась. Журнал вызова
Playwright назвал виновника дословно: `<nav id="desktop-dock"> intercepts
pointer events`.

Корень оказался глубже перекрытия: панель объявлена `position: fixed;
bottom: 14px`, но её прямоугольник измерен как **top=1637 при высоте окна
900**. Закрепления за окном не было вообще, потому что у `.shell` под
`@supports` стоит `backdrop-filter`, а элемент с `backdrop-filter` становится
содержащим блоком для потомков с `position: fixed`.

Для владельца это значило: **на любой странице длиннее окна панель приложений
не видна вовсе** — она стоит внизу документа, за краем экрана; появляется
только если домотать до самого низа, и там ложится поверх последних кнопок.
Основная навигация работала лишь на страницах, помещавшихся в окно целиком.

Починено двумя частями (панель вынесена из `.shell`; `.view` получил запас
снизу), регрессия — `command-center/tests/test_desktop_dock_overlap.py`
настоящим кликом мыши, с обратным контролем. Полный разбор — `BUG_LEDGER.md`.

### BL-025 — обрыв соединения давал 500 и traceback

Каждая перезагрузка страницы, пришедшаяся на отправку пачки событий
телеметрии, оставляла необработанный `ClientDisconnect` в журнале сервера.
Маячок телеметрии отправляется в том числе на уходе со страницы, то есть обрыв
здесь — штатное поведение браузера. Той же правкой закрыт 500 на испорченном
теле запроса.

### Пустое задание в чате Video Studio

Нажатие «Отправить» с пустым полем уходило НА СЕРВЕР и возвращало владельцу
разработческую строку «неверный запрос: text — String should have at least 1
character». Соседний экран (Операторский канал) на то же действие отвечает
локально и по-человечески. Теперь так же: отказ до сети, сообщение
«Задание пустое: напишите, что сделать, или приложите файл.»

### BL-026 — отказал сам измеритель, и это чуть не стало «70 дефектами»

Первый прогон обхода дал 70 ошибок подряд. Поверить им означало бы начать
«чинить» 70 исправных кнопок. Переход по одному якорю страницу не
перезагружает, и первый же открытый диалог перехватывал указатель для всех
последующих нажатий.

Позже тем же образом чинилось ещё одно завышение: кнопка, ВЫКЛЮЧЕННАЯ на время
дочитывания данных, попадала в отчёт как «TimeoutError». Владелец в такой
ситуации просто ждёт; развёртка теперь ждёт тоже и относит такую кнопку к
«выключена», а не к «сломана».

**Инвариант:** прежде чем поверить в массовый отказ продукта, проверьте, не
отказал ли измеритель. Форма «первая единица работает, все следующие нет»
почти всегда описывает состояние, утёкшее между измерениями.

## Пять страниц без органов управления — каждая объясняет себя

Обход отдельно выделяет страницы, на которых видимых кнопок нет вообще: такая
страница для владельца потенциальный тупик. Проверены все пять; тупиков нет.

| Страница | Что показано вместо кнопок |
|---|---|
| File Intelligence | «ПРИВАТНОСТЬ: НЕИЗВЕСТНО — не удалось доказать, где обрабатываются данные. Пока это так, File Intelligence отказывает» — отказ fail-closed с названной причиной |
| Карта агентов | «Агентов нет — создайте хотя бы одного на странице „Агенты“» — пустое состояние с указанием следующего шага |
| Развилки | «Выберите задачу, чтобы увидеть её запуски» — есть список выбора, кнопки появляются после выбора |
| Обучение трейдингу | «БУМАЖНЫЙ РЕЖИМ / ТОРГОВЛЯ: OFF» — страница состояния, торговля выключена намеренно |
| Поиск в интернете | «Страница только показывает: искать умеет модель инструментами web.*» — прямо объявлена как показывающая |

## Шесть «исчезнувших» элементов

Все шесть — карточки шаблонов Веб-дизайнера («Лендинг», «Портфолио», «Кафе»,
«Магазин», «Блог», «Агентство»). Они видны, пока проектов нет; после создания
проекта экран показывает список проектов, и карточек там уже не должно быть.
Развёртка перечисляет органы управления на одной отрисовке, а нажимает на
следующей — между ними состояние изменилось. Это свойство продукта, а не
дефект; засчитывать такие случаи как «работает» было бы неправдой, поэтому у
них свой класс.

## Чего этот обход НЕ доказывает

* «Мёртвый» означает «наблюдаемых последствий нет ни по одному из четырёх
  каналов» (разметка, адрес, запрос, консоль). Кнопка, которая пишет только в
  `localStorage`, выглядела бы мёртвой. Ноль мёртвых нажатий означает, что
  таких случаев не нашлось, а не что канал измерен.
* Обход нажимает, но не проверяет СМЫСЛ результата: «открылся диалог» не
  значит «диалог правильный». Смысл проверяют владельческие потоки
  (`OWNER_FLOWS_REPORT.md`) и предметные наборы тестов.
* Органы управления, спрятанные за состоянием (внутри диалогов, после выбора
  элемента списка), в 115 нажатий не попали: обход работает по первому экрану
  каждой страницы.

## Как повторить

```
python scripts/ui_acceptance_sweep.py --json docs/final/ui_acceptance.json
python scripts/ui_acceptance_sweep.py --pages web_designer --headed   # с окном
```

Нужен настоящий Chromium. Без него инструмент ОТКАЗЫВАЕТСЯ работать, а не
переходит в режим «проверим разметку»: раздел 23 требует настоящего браузера,
и подделывать здесь нечем.
