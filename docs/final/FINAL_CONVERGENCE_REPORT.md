## Самая дорогая ошибка прогона — и почему она здесь записана

Пикер Web Designer был диагностирован как «CSS-трансформ на iframe ломает
доставку ввода». Диагноз выглядел причинным: снимаешь трансформ — клики
проходят. По нему уже была написана правка, переносящая масштаб на обёртку.

Правка НЕ внесена, потому что гипотеза не выдержала проверки на отдельном
стенде: кадр по HTTP с `sandbox="allow-scripts"` (непрозрачный источник →
отдельный процесс), 16 сочетаний песочницы, трансформа/zoom, места масштаба и
величины масштаба. Во всех шестнадцати клик доходит до документа кадра с
ПРАВИЛЬНЫМИ координатами. То же подтверждено на самом продукте: при масштабе
0.5 клик в (40,40) приходит в кадр как (79,80).

Настоящих причин оказалось две, обе в тестах:

* `frame_locator(...).click()` сам считает точку и промахивается через
  масштабированный кадр в отдельном процессе; при окне 1280×720 превью вообще
  оказывается ниже видимой области, и событие теряется молча, без ошибки
  актуальности;
* первое событие мыши по новой раскладке кадра Chromium разрешает асинхронно и
  теряет; второе приходит правильно.

Вывод, который стоит дороже самой починки: «убрал X — заработало» не является
причинной связью, пока тот же эффект не воспроизведён на стенде без остального
продукта.

## Что осталось красным и почему это правильно

**Intelligence Preservation.** Гейт требует файл замера
`docs/benchmark/intelligence-preservation-current.json`. Файла нет, потому что
в сборочном окружении нет ни учётных данных модели, ни локальных весов.
Синтезировать его запрещено: это ровно тот случай, против которого написан
раздел 28. Инструмент для честного замера теперь существует
(`scripts/intelligence_retention_run.py`) и отказывается выдавать результат,
если лейны совпали или прогон неполон.

## Владельческие сценарии

Проверяются не списком в документе, а `scripts/verify_clean_install.py`: он
собирает дистрибутивы из чистого экспорта ТЕКУЩЕГО коммита, ставит их в пустой
venv, поднимает установленный продукт БЕЗ чекаута на пути импорта и ходит по
HTTP. Именно так были найдены два дефекта, которых в чекауте не существует:
установленный продукт отвечал 404 на `/`, а данные владельца писались внутрь
`site-packages`.

## Ограничения этого прогона, названные прямо

* Живого запуска на Windows не было: проверены пути, консольные обёртки и
  кодировка вывода, но не сам запуск.
* Локальная модель не поднималась.
* Целевое железо отсутствует; см. `docs/final/TARGET_HARDWARE_REPORT.md`.
* Продуктовая линия (гибридные порты, File Intelligence, OpenHands) живёт на
  соседней ветке и в этот прогон НЕ сводилась: механическое слияние уже
  однажды уничтожило работу. Это решение владельца, а не побочный эффект
  интеграционного прохода.
