# Откат

Документ отвечает на один вопрос: как вернуть рабочее состояние, если правки
этого прогона окажутся хуже, чем то, что было.

## Точки возврата

| Что | SHA | Чем ценна |
|---|---|---|
| Вершина прогона сведения | `0c59982dbc333d7944dca803d7f83444ea515132` | всё, что описано в отчётах |
| Коммит слияния | `48f8da94e28bf9b4a611a5f193879e7a73fc8415` | момент, когда две линии стали одной |
| Линия сборки ДО слияния | `5b673262dbee69c1f460253ba874111fad95cbfb` | гибридные порты, File Intelligence, OpenHands, один Windows-архив — БЕЗ правок линии управления |
| Линия управления ДО слияния | `76d1fd2a` (вершина `claude/bossman-control-v03-43igbk`) | контракт сборки колеса, раннер гейта интеллекта, память проекта, целевое железо, корпус Trader Apprentice — БЕЗ работы линии сборки |
| Заморозка рантайма линии управления | `04f5938f69a3918a95c3172836bdfcf3c370358a` | последняя точка, где Video Studio была зелёной в CI с установленным FFmpeg |
| Опорная заморозка владельца | `910ca901ddcd84c13d65f9246dfec394088c29bf` | ранее принятый владельцем exact SHA, дальняя точка |

Полный список с тем, что на каждой точке измерено И что на ней НЕ показывали, —
`docs/final/KNOWN_GOOD_SHAS.json`.

## Откат целиком

```
git fetch origin claude/bossman-final-convergence-hu2702
git checkout -B откат 5b673262dbee69c1f460253ba874111fad95cbfb
```

**Важно понимать, что именно теряется.** Слияние было НЕ надстройкой над одной
линией, а объединением двух. Откат на любую из двух вершин ДО слияния
возвращает не «состояние без правок этого прогона», а состояние без ПОЛОВИНЫ
продукта:

* откат на `5b673262` теряет контракт сборки колеса, раннер гейта удержания
  интеллекта, восстановленную память проекта, приёмку целевого железа и
  исправленное превью Video Studio;
* откат на `76d1fd2a` теряет гибридные порты, File Intelligence, OpenHands,
  один скачиваемый Windows-архив и вечернюю приёмку по точному SHA.

Поэтому откат целиком — крайняя мера. Обычно нужнее точечный откат ниже.

Ветки НЕ перематывать силой: раздел 27 задания запрещает затирать чужую
работу. Откат живёт отдельной веткой, решение о её продвижении принимает
владелец.

## Точечный откат правок этого прогона

Каждая правка лежит в своём коммите и снимается по отдельности, не трогая
остальные:

| Что откатить | Коммит | Что вернётся |
|---|---|---|
| проверку полосы FULL в гейте интеллекта | `380e5811` | гейт снова примет текстовую абляцию за прогон обвязки (BL-014) |
| решения по девяти кандидатам OSS | `229967b0` | четыре строки вернутся в PENDING, точные SHA пропадут |
| `ContextStoreRuntime` и теневое зеркало | `435e67a1` | контекст-стора не станет; родная память не пострадает — она та же таблица `decisions` |
| калибровку негативного контроля латентности | `ba3e509f` | тест снова будет краснеть на хостах с быстрым полом хранилища (BL-009) |
| память проекта и фикс теста браузера | `0c59982d` | отчёты вернутся к состоянию до сведения |

```
git revert --no-commit <коммит>
```

Три колонки схемы (`decisions.namespace`, `.provenance`, `.record_kind`)
добавлены идемпотентным ALTER и при откате кода остаются в базе пустыми. Это
безопасно: `DecisionStore` их не читает, а `create_all` не удаляет колонок.
Удалять их вручную не нужно и не рекомендуется.

## Правки линии управления, пришедшие со слиянием

Они тоже самостоятельны и снимаются независимо:

| Коммит | Что вернётся | Чем это грозит |
|---|---|---|
| `28c2aaae`, `43d0c08d` | тест колеса снова зовёт pip с `--no-build-isolation` | Command Center CI py3.12 снова красный на `BackendUnavailable` |
| `9a387477` | исчезает раннер удержания интеллекта | гейт остаётся красным, и закрыть его снова будет нечем |
| `2f40d0cc` | исчезают документы памяти проекта | следующая модель снова начинает с нуля |
| `4dea03ab`, `679d2291`, `04f5938f` | превью Video Studio снова mp4/H.264 и медленное; помощник снова ищет кадр по подстроке URL | превью не играется в поставляемом браузере; приёмка редакторов снова мигает |

## Что откатом НЕ лечится

* красный гейт удержания интеллекта — он красный из-за ОТСУТСТВИЯ замера, а не
  из-за кода. Нужна машина с локальной моделью, а не revert;
* отсутствие прогона на целевом железе;
* отсутствие FFmpeg или `pytest` в окружении: девять тестов Video Studio и один
  тест миссии падали именно поэтому, и вернулись в зелёное после установки
  инструментов, а не после правки кода (BL-015).

## Проверка после отката

```
python scripts/verify_clean_install.py
python -m pytest tests -q
cd command-center && python -m pytest tests -q
```

Состояние считается восстановленным, только когда `CLEAN_INSTALL=PASS`.
Чекаут, который импортируется, но не ставится, доказательством не является.
