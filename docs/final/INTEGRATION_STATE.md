# Состояние интеграции внешних проектов

Назначение документа — чтобы следующая модель НЕ написала второй комплект
адаптеров, не заметив первого. Раздел 5 задания это прямо запрещает.

## Где искать существующую работу

Порты возможностей и реестр адаптеров существуют и покрыты тестами — на ветке
`claude/bossman-final-completion-kymr05` (PR #62), НЕ на канонной
`claude/bossman-control-v03-43igbk`:

```
command-center/bcc/hybrid/capabilities.py   типизированные порты
command-center/bcc/hybrid/registry.py       реестр: возможность → бэкенд,
                                            откат на legacy по здоровью
command-center/bcc/hybrid/sidecar.py        ОДИН менеджер жизненного цикла
command-center/bcc/hybrid/evidence.py       наблюдение ≠ улика
command-center/bcc/hybrid/adapters/windows_mcp.py
docs/hybrid/THIRD_PARTY_DECISIONS.md        лицензионный разбор кандидатов
```

Реестр уже объявляет ровно те возможности и бэкенды, которые перечислены в
задании: `desktop`, `browser`, `web_editor`, `video`, `local_model`;
`legacy`, `windows_mcp`, `browser_use`, `grapesjs`, `weave`, `localai`.

**Как проверять:** `git ls-tree -r --name-only <ветка> | grep bcc/hybrid`.
Рабочим каталогом проверять НЕЛЬЗЯ: локальный `build/lib` хранит копии с
другой ветки и даёт ложные совпадения — на этом прогоне такая проверка едва
не привела к ошибочному выводу.

## Решения по кандидатам (приняты на kymr05, здесь не пересматриваются)

| Проект | Решение | Причина в одну строку |
|---|---|---|
| Windows-MCP | ADOPT_AS_OPTIONAL_BACKEND | механика Windows UI полезна, но нужен отпечаток цели перед эффектом и независимая проверка пост-состояния |
| browser-use | REFERENCE_ONLY | скрывает бюджет повторов от губернатора и объявляет успех при заблокированном эффекте |
| GrapesJS | ADOPT_AS_OPTIONAL_BACKEND | зрелая механика визуального редактирования; истина проекта остаётся у Bossman |
| Weave | REFERENCE_ONLY | родной конвейер FFmpeg уже детерминирован и проверен; выигрыша нет, накладные расходы есть |
| LocalAI | REJECT | непрозрачное владение жизненным циклом моделей против авторитета Bossman над бюджетом памяти |

## Кандидаты, добавленные этим заданием

| Проект | Состояние на 2026-09-11 | Что требуется до решения |
|---|---|---|
| OpenContext | НЕ ИНТЕГРИРОВАН, следов в репозитории нет | порт `ContextStoreRuntime` с режимом SHADOW: родная память остаётся авторитетной, OpenContext получает копии и отвечает как дополнительный источник кандидатов. Требования: изоляция пространств имён по проекту, атрибуция источника, обнаружение устаревания, отсутствие секретов в приёме |
| ai-file-sorter | НЕ ИНТЕГРИРОВАН; на kymr05 есть родная File Intelligence | сначала лицензионный преflight. До ясности — OPTIONAL_EXTERNAL_BACKEND или REFERENCE_ONLY, без вендоринга кода в ядро |
| Open-Source-Face-Recognition-SDK | НЕ ИНТЕГРИРОВАН | лицензия не проверена. Без явно совместимой лицензии — REFERENCE_ONLY или REJECT. Подсистема обязана быть выключена по умолчанию и не требоваться для загрузки |
| video-shotcraft | НЕ ИНТЕГРИРОВАН | использовать как слой знаний и рецептов кадров, не как постоянно живущий сервис |

Ни один из этих четырёх не интегрирован на этом прогоне намеренно: раздел 31
задания ставит сохранение работающего продукта выше необязательных
интеграций, а базовая линия на момент прогона была красной в трёх местах.
Сначала базовая линия.

## Обязательное правило для любого внешнего движка

```
внешний результат
  → наблюдение
  → независимая проверка Bossman
  → улика
  → гейт завершения
  → COMPLETED
```

`external_engine.success == true` НИКОГДА не отображается напрямую в
`task == COMPLETED`. Если движок доложил успех, а реальность не изменилась —
задача не выполнена.
