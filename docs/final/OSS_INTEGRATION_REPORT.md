# Отчёт по интеграции внешних проектов

## Короткий ответ

**Ни один внешний движок не сделан умолчанием.** Один — OpenContext — подключён
в ТЕНЕВОМ режиме за портом. Два отклонены. Остальные остаются необязательными
бэкендами или справочными.

Это следствие правил задания, а не нехватки времени: раздел 4 («NO NEW OSS
ENGINE MAY BECOME DEFAULT UNTIL BASELINE IS GREEN») и раздел 31 (сохранение
работающего продукта выше необязательных интеграций).

Предыдущая редакция этого отчёта заканчивалась выводом «свести две линии —
отдельная осознанная операция владельца». Операция выполнена (`48f8da94`), и
порты теперь лежат на одной ветке с продуктом.

ложные совпадения.

Дублироваться может не только адаптер. На этом прогоне слияние принесло ДВА
раннера гейта удержания интеллекта, писавших один и тот же файл (BL-014).
Перед тем как считать возможность закрытой, стоит спросить, не пишет ли в тот
же артефакт что-то ещё.

## OpenContext: что именно подключено

```
событие Bossman
  → нормализация (build_record)
  → фильтр секретов
  → происхождение и пространство имён
  → РОДНАЯ память (авторитетная; её отказ проваливает операцию)
  → зеркало OpenContext (по возможности; его отказ НЕ проваливает ничего)
```

Родное хранилище — ТА ЖЕ таблица `decisions`, которой пользуется
`bcc.context_os.DecisionStore`, плюс три колонки. Второй базы рядом нет.

Сделать зеркало авторитетным нельзя настройкой: `is_authoritative` зашит в
`False` и не является параметром конструктора. Раздел 7 разрешает думать о
переводе OpenContext в основные только после ДЛИТЕЛЬНОЙ проверки
эквивалентности — её в этом прогоне не было, и отчёт этого не скрывает.

Сценарий §7 проверен целиком на настоящей SQLite: запись → смерть процесса →
новая сессия достаёт именно это решение с происхождением; другой репозиторий
его не видит; обновление выигрывает; устаревшая версия проигрывает; после
перезапуска остаётся последняя верная.

## Жёсткие границы, записанные до кода

* **OpenContext:** никаких ключей, токенов и паролей в открытом виде; никакого
  слепого приёма `.env` и приватных секретов; биометрия по умолчанию не
  хранится; изоляция пространств имён; атрибуция источника; обнаружение
  устаревания. **Выполнено и покрыто тестами**, включая обратные контроли.
* **ai-file-sorter:** никаких массовых переименований без ДЕТЕРМИНИРОВАННОЙ
  карты отката; `auto_apply_allowed: false`; `--auto-apply` в списке
  запрещённых флагов.
* **Face SDK:** границы записаны, но применять их не к чему — проект отклонён.
* **Все сайдкары:** ленивый старт, остановка по бездействию, никакого
  постоянного резервирования GPU, никакого опроса вхолостую. Измерено: продукт
  в покое — ОДИН процесс, дочерних нет, после остановки сирот нет.

## Правило, которое не подлежит смягчению

```
внешний результат
  → наблюдение
  → независимая проверка Bossman
  → улика
  → гейт завершения
  → COMPLETED
```

`external_engine.success == true` НИКОГДА не отображается прямо в
`task == COMPLETED`. Движок доложил успех, а реальность не изменилась —
задача не выполнена. Наблюдение и улика остаются РАЗНЫМИ объектами; это
выражено типами: `Observation` против `EvidenceCandidate`, а у контекст-стора
ещё и третьим — `ContextCandidate`, потому что вспомненное предложение не
доказывает, что мир изменился.
