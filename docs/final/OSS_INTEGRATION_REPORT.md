# Отчёт по интеграции внешних проектов

## Короткий ответ

**На этом прогоне ни один новый внешний движок не внедрён и ни один не сделан
умолчанием.** Это следствие двух правил задания, а не нехватки времени:

* раздел 4: «NO NEW OSS ENGINE MAY BECOME DEFAULT UNTIL BASELINE IS GREEN».
  Базовая линия на начало прогона была красной в трёх местах;
* раздел 31: сохранение работающего продукта стоит выше необязательных
  интеграций.

Сделано другое, и оно было обязательным: найдена УЖЕ СУЩЕСТВУЮЩАЯ работа по
интеграции, чтобы не написать её второй раз.

## Что уже построено и где это лежит

Раздел 6 требует сначала искать по ВСЕМ веткам. Поиск дал результат: порты
возможностей, реестр адаптеров и менеджер сайдкаров существуют — но на ветке
`claude/bossman-final-completion-kymr05` (PR #62), не на канонной:

```
command-center/bcc/hybrid/capabilities.py   типизированные порты
command-center/bcc/hybrid/registry.py       возможность → бэкенд, откат на legacy по здоровью
command-center/bcc/hybrid/sidecar.py        ОДИН менеджер жизненного цикла
command-center/bcc/hybrid/evidence.py       наблюдение ≠ улика
command-center/bcc/hybrid/adapters/windows_mcp.py
command-center/bcc/file_intelligence/       родной governed-анализ файлов
bossman-core/bossman/apprentice/openhands_*  кодовый бэкенд и семь наборов тестов
```

Реестр объявляет ровно те возможности, которые перечислены в задании:
`desktop`, `browser`, `web_editor`, `video`, `local_model`; бэкенды `legacy`,
`windows_mcp`, `browser_use`, `grapesjs`, `weave`, `localai`.

**Поэтому второй комплект портов здесь НЕ написан.** Свести две линии — это
отдельная осознанная операция владельца: механическое слияние уже однажды
уничтожило работу (PR60 → PR61).

Проверять наличие надо через `git ls-tree -r --name-only <ветка>`, а не по
рабочему каталогу: локальный `build/lib` хранит копии с другой ветки и даёт
ложные совпадения. На этом прогоне такая проверка едва не привела к неверному
выводу.

## Жёсткие границы, записанные до кода

Записаны здесь и в `sources.lock.json`, чтобы следующая модель не «упростила»
их в процессе:

* **OpenContext:** никаких ключей, токенов и паролей в открытом виде; никакого
  слепого приёма `.env` и приватных секретов; биометрия по умолчанию не
  хранится; изоляция пространств имён по проекту; атрибуция источника;
  обнаружение устаревания.
* **ai-file-sorter:** никаких массовых переименований без ДЕТЕРМИНИРОВАННОЙ
  карты отката.
* **Face SDK:** выключено по умолчанию; никакого фонового сканирования камеры;
  никакой незаметной постоянной слежки; обработка локальная; выгрузка в облако
  только по отдельному разрешению; биометрические шаблоны по умолчанию не
  хранятся.
* **video-shotcraft и все сайдкары:** ленивый старт, остановка по
  бездействию, никакого постоянного резервирования GPU, никакого опроса
  вхолостую (раздел 16).

## Правило, которое не подлежит смягчению

```
внешний результат
  → наблюдение
  → независимая проверка Bossman
  → улика
  → гейт завершения
  → COMPLETED
```

`external_engine.success == true` НИКОГДА не отображается прямо в
`task == COMPLETED`. Движок доложил успех, а реальность не изменилась —
задача не выполнена. Наблюдение и улика остаются РАЗНЫМИ объектами
(раздел 5); на продуктовой линии это уже выражено отдельным модулем
`bcc/hybrid/evidence.py`.
