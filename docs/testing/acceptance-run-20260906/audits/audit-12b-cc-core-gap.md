## Ответ на «что минимально нужно, чтобы UI Bossman увидел desktop-оператора Core» (предложение, не реализация)

1. **Конфиг-мост** (bcc/config.py): `BCC_CORE_URL` + device-токен в `data_dir` (файл, права 600, тот же паттерн, что токен UI).
2. **Прокси-роут** в bcc: `POST/GET /api/computer/tasks`, `/pause|/resume|/stop|/take-control` — тонкое проксирование на Core с Bearer-токеном; ошибки 401/403/ConnectError возвращать как честные статусы (паттерн уже есть: `features/offline_mode.py:189-199`).
3. **Инструмент + контракт**: ToolSpec `computer.task` (ask, exec) + расширение APPS_ACTION исполнителем `computer` — тогда «открой Блокнот» получает реального исполнителя и доказуемый evidence.
4. **UI**: панель «Компьютер» (список задач оператора + статус waiting_approval с переходом в существующую очередь approvals) на mission_console или отдельной страницей.
5. **Видимость цепочки**: doctor/диагностика «Core доступен? токен валиден? scope chat есть? profiles computer_control включён?» — иначе владелец получит 403/404 без причины (поверх уже открытых OBSERVER-DEPS-001 и GATEWAY-URL-V1 из CHECKPOINT_2).

Альтернатива без кода CC: поднять Core UI и пользоваться `/computer/tasks` через curl/Tailscale — но это и есть сегодняшнее «ручное» состояние, неприемлемое для владельца единственного UI.

## Проверено — моста нет ни в одну сторону

- `command-center` → Core: 0 вызовов (A12b-01); `bossman-core` → CC: тоже нет (Core не знает о CC; единственные мосты Core — /remote для мобильных/туннеля и Telegram).
- CC умеет показывать «миссии» только своих research-задач; Core умеет исполнять desktop-цели, но не показывает их нигде (A12b-04). Пересечение — пустое множество.
