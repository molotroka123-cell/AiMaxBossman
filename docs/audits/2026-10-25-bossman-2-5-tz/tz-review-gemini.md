### 1. Пять критических пробелов и рисков

1.  **Риск: Троттлинг и деградация шины памяти.** 120 ГБ общей памяти на iGPU означают, что CPU и GPU делят одну шину. При одновременной работе Jeff (LLM) и LTX (Video) скорость генерации упадет не в 2, а в 5-10 раз из-за коллизий доступа к памяти.
    *   **Исправление:** Ввести в Governor понятие «Exclusive Mode». Если запущена генерация видео (M2), Governor обязан принудительно выгружать ВСЕ модели Ollama, включая Jeff, оставляя только системный API-слой. Никакого «если влезают».
2.  **Пробел: Отсутствие контроля целостности весов.** При частых перезагрузках и нехватке места (120 ГБ забиваются быстро) модели могут биться или подгружаться частично.
    *   **Исправление:** Добавить в реестр ресурсов (M1) проверку контрольных сумм (SHA-256) перед «арендой» и мониторинг `vram_usage` через `rocm-smi` (для AMD), а не только по системному `free`.
3.  **Риск: «Зомби-процессы» sd.cpp/Ollama.** При падении FastAPI-бэкенда или скрипта арендованная память не освобождается.
    *   **Исправление:** Governor должен работать как отдельный watchdog-процесс. Каждая аренда (lease) должна иметь `TTL` (Time To Live). Если процесс-клиент не обновил `heartbeat` за 30 секунд — Governor убивает процесс-клиент через `SIGKILL` и чистит память.
4.  **Пробел: Юридическая «мина» LTX-2.5/Wan.** Ты планируешь платные заказы. Лицензия LTX-2.5 требует уточнения для коммерции, а Wan 2.1/2.2 имеет специфические ограничения на генерацию лиц.
    *   **Исправление:** Добавить в M2 автоматическое наложение невидимого водяного знака (Steganography) и явный лог: «Модель X, Лицензия Y, ID заказа Z».
5.  **Риск: Конфликт версий Python/ROCm.** Разные модели (LTX vs Wan) часто требуют разных версий библиотек или драйверов.
    *   **Исправление:** Изолировать каждый тип генератора в отдельный Docker-контейнер с пробросом GPU или использовать жестко разделенные Conda-окружения, которыми управляет Governor.

### 2. Что отсечь для быстрого выхода на первый заказ

Твоя цель — деньги. Сейчас ТЗ перегружено «игрушками» для разработчика.
*   **Убрать M3 (Coding Swarm):** Это бесконечная доработка инструмента ради инструмента. Кодь руками или через Cursor/Claude в чате. Тебе не нужна автоматическая фабрика кода, пока нет выручки.
*   **Убрать M4 (Obliterated Brain):** Поиск «лучшей uncensored модели» — это потеря времени. Выбери одну (например, Dolphin-Llama3 или Qwen-2.5-Coder-Instruct) и работай на ней.
*   **Отложить M5 (Паритет поверхностей):** Мобильный пульт не нужен. Telegram-бота достаточно для 100% задач на старте.
*   **Отложить M6 (Хвосты аудита):** Если ты единственный пользователь, DNS-rebinding и tailnet-имена подождут. Сфокусируйся на `F7` (токен клиента), чтобы не смешать заказы.

### 3. Дизайн M1 Resource Governor

**Структуры данных (Python/Pydantic):**
```python
class Resource(BaseModel):
    id: str # "ollama_gemma", "sd_cpp_ltx"
    peak_ram_gb: float
    priority: int # 0-100 (100 - владелец)
    keep_alive_support: bool

class Lease(BaseModel):
    id: str
    resource_id: str
    owner_pid: int
    expires_at: datetime
    status: str # "active", "pending", "evicting"
```

**Алгоритм выдачи аренды:**
1.  Запрос `POST /lease {resource_id, priority}`.
2.  Считаем `Current_Free_RAM` (через `psutil` + `rocm-smi`).
3.  Если `peak_ram_gb + 8GB (buffer) < Current_Free_RAM`: Выдаем `Lease`.
4.  Если нет:
    *   Ищем активные `Leases` с `priority < текущий`.
    *   Если нашли: посылаем `SIGTERM` владельцу, ждем 5 сек, затем `SIGKILL`.
    *   Если ресурс — Ollama: вызываем `POST /api/generate {model: ..., keep_alive: 0}` для выгрузки.
5.  Если места всё равно нет: Ставим в очередь (Queue) или возвращаем `403 Busy` с ETA.

**Обработка Ollama keep_alive:**
*   Governor должен перехватывать все вызовы к Ollama.
*   При старте тяжелой видео-задачи: `keep_alive` для всех моделей Ollama ставится в `0` (немедленная выгрузка после ответа).

**Рестарт:**
*   При запуске Governor проверяет таблицу `Leases` (в SQLite). Если там есть активные записи — проверяет живы ли `owner_pid`. Если нет — объявляет память свободной.
