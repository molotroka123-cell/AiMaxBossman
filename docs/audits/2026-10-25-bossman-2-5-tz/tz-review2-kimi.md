**Общая оценка:** это программа развития инфраструктуры, а не кратчайший путь к выручке. Для первого заказа нужны один надёжный заказной сценарий, минимальный Governor и ручная продажа. Остальное сейчас конкурирует за время с деньгами.

## 1. Пять главных пробелов и рисков

1. **Нет продукта, который владелец прямо сейчас продаёт.**  
   «≥1 оплаченный пилот» — не план продаж. Нет фиксированного объёма, цены, входных требований, числа правок и условий приёмки.  
   **Исправление:** один пакет на лучшем готовом пресете: например, ролик до 10 секунд, один вариант, одна правка, фиксированная цена и срок. Продавать вручную по трём существующим образцам; бриф, согласия и оплату принимать без новой автоматизации.

2. **M1 в текущем виде всё равно может убить оплаченный рендер.**  
   Номинальные 120 ГБ — не доступный бюджет. `free < 3 ГБ` — уже авария. Нет оценок по конфигурации, TTL аренд, idempotency, защиты от нескольких писателей и безопасной семантики вытеснения. Остановка «самой низкоприоритетной» задачи может не освободить память либо уничтожить часы работы.  
   **Исправление:** резервирование до запуска по замеренному P95-пику, единый transactional writer, heartbeat/fencing, вытеснение только на checkpoint; аварийный STOP как последняя мера. Дизайн ниже.

3. **Studio описана списком шагов, а не надёжным заказным контуром.**  
   Нет конечного автомата заказа, повторного запуска без дублей, manifest входов/настроек/артефактов и критериев брака. Размытие и двоение не доказывают пригодность лиц, рук, товара и движения. `pose_dance` после smoke-теста нельзя включать в коммерческий SLA.  
   **Исправление:** один пресет, рубрика приёмки владельцем, версионируемый manifest и безопасные retry. До оплаты проверить лицензии моделей, прав на исходники и драйверы, согласия на лица/голоса. Себестоимость считать как `∫Pdt × тариф + облако + труд + ретраи`, а не «секунды × энергия».

4. **F7 ошибочно отнесён к P2.**  
   Идентичность клиента из заголовка — потенциальный обход авторизации. Публичные заявки и ссылки сдачи расширяют поверхность атаки.  
   **Исправление:** F7 и живой STOP — блокеры удалённой автоматизации. Клиентские токены случайные, авторизация только на сервере; ссылки сдачи ограниченные и отзываемые. F6/F10 тоже становятся P0, если соответствующие сервисы доступны извне.

5. **Coding Swarm создаёт видимость проверки, но не гарантирует корректность.**  
   Модели могут написать тесты под ту же неверную интерпретацию. Квитанция подтверждает расход, а не качество; автоматический коммит по ней недопустим.  
   **Исправление:** M3 отложить. При возврате — sandbox, allowlist путей и команд, независимый CI, обязательные регрессионные тесты от человека, branch protection; ни одна модель не утверждает собственный патч.

## 2. Что убрать или отложить до первой оплаты

**Оставить:** лучший существующий пресет, ручной ввод заказа, минимальный Governor для Ollama и этого генератора, контакт-лист, обязательный просмотр владельцем, AI-метку/водяной знак, локальный архив и журнал времени/ретраев.

**Отложить:** `pose_dance`, остальные пресеты, Netlify Forms, сложные видеоэвристики, датчик энергии, полный паритет поверхностей, M3 и `/api/decide`, M4-бенчмарки и чистку моделей, автономные решения трёх моделей. В пульте достаточно статуса заказа, кнопок «принять/на доработку» и причины ожидания ресурсов.

Продажу начать **до завершения платформы**. Если заказ можно выполнить вручную под наблюдением, не откладывать оплату ради автоматизации.

## 3. Конкретный дизайн M1 Resource Governor

### Данные

SQLite WAL; отдельный процесс-владелец Governor, остальные компоненты — клиенты.

- `ConsumerProfile`: `id`, adapter, resource flags (`gpu_exclusive`, `ollama_residency`), `estimate_key`, `preempt_policy`, timeout.
- `Measurement`: `estimate_key` с `config_hash` модели/разрешения/длительности/шагов, `p95_peak_bytes`, число замеров, дата.
- `Lease`: `id`, `task_id`, уникальный `idempotency_key`, профиль, приоритет, состояние, `reserved_bytes`, deadline, `heartbeat_at`, TTL, `epoch/fencing_token`, причина ожидания.
- `Event`: все переходы, замеры, выгрузки, отмены и причины.
- `Config`: измеренный memory budget, резерв ОС, soft/hard-пороги.

Jeff/Gemma учитывается отдельной residency-арендой; её память входит в общий резерв.

### Выдача аренды

1. `POST /lease` выполняется через `BEGIN IMMEDIATE`; повтор с тем же ключом возвращает прежний результат.
2. Неизвестный профиль или конфигурация без замера — отказ, а не запуск «на удачу».
3. Кандидату выделяется `P95 peak + калиброванный запас`. Проверяются:  
   `sum(active_reserved) + candidate_reserved <= controlled_budget`, GPU-mutex, текущее памятное давление и отсутствие неучтённых тяжёлых процессов.
4. При нехватке — очередь: приоритет, затем aging, затем FIFO. Сначала выгружаются неактивные модели; затем запрашивается checkpoint-остановка низкоприоритетной задачи. Невытесняемая задача не убивается.
5. Worker запускает процесс только с действующим fencing token, продлевает аренду heartbeat’ами. Просроченный token не даёт позднему worker’у стартовать.
6. Soft-порог запрещает новые запуски; hard-порог инициирует управляемую отмену. Если память продолжает падать — STOP управляемых задач. Пороги калибруются, а не фиксируются blindly на 3/8 ГБ.

### Ollama

Весь доступ Jeff/чата — через adapter, иначе Governor не контролирует систему.

- На рабочих запросах явный **конечный** `keep_alive`; residency-аренда продлевает его. Не использовать бессрочный `-1`.
- Выгрузка: дождаться нуля активных streams → отдельный unload-запрос с `keep_alive: 0` → опрос `/api/ps` и подтверждение освобождения памяти → только затем снять резерв.
- Не ставить `keep_alive: 0` на обычные ответы Jeff: это вернёт постоянные перезагрузки.
- Если выгрузка не подтверждена за timeout, следующую тяжёлую задачу не запускать.

### Рестарт

После старта создаётся новый `epoch`; все `running` переводятся в `unknown`. Governor сверяет `/api/ps` и принадлежащие ему Windows Job Objects/процессы с проверкой identity, а не только PID.

Процесс принимается обратно только если adapter умеет безопасное adoption. Иначе-owned process tree останавливается, модели выгружаются, резервы пересчитываются. Checkpointable-задачи возобновляются из manifest; платный рендер без идемпотентности автоматически не повторяется. Слепой `taskkill` и массовый retry запрещены.

## 4. Первые пять задач кодинга

1. **Реестр и измеритель памяти.**  
   **Готово:** Jeff/Ollama и один Studio-generator имеют профили; ≥10 повторов худшей конфигурации, включая холодный старт; сохранены пики, Available/Commit и `config_hash`; рассчитан стартовый бюджет.

2. **Ядро аренд.**  
   **Готово:** API, SQLite-переходы, очередь, TTL, heartbeat, idempotency и fencing. Тесты: неизменяемость memory budget, GPU-mutex, aging, 50 параллельных запросов без двойной выдачи.

3. **Реальные адаптеры и восстановление.**  
   **Готово:** Jeff и выбранный sd.cpp-путь не работают в обход Governor; 20 циклов «чат + генерация» без ручной перезагрузки Gemma. Принудительный рестарт Governor не оставляет неучтённых процессов и не запускает заказ дважды.

4. **Один вертикальный Studio-заказ.**  
   **Готово:** ручной бриф → заказ → аренда → генерация → manifest/контакт-лист → просмотр владельцем → архив. Есть безопасный retry, права/согласия, AI-метка; F7 закрыт тестом; сдача без approval невозможна.

5. **Минимальный пульт и release-контур.**  
   **Готово:** статус, причина очереди, approve/rework и STOP доступны владельцу. Три эталонных заказа проходят end-to-end, один — после вынужденного сбоя; журнал содержит время, ретраи, стоимость и финальное решение владельца. Только после этого расширять пресеты.
