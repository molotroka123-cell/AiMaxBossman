## 1. Честная граница планировщика: Детерминированное ядро vs Локальная LLM (D-003)

Пакет [`command-center/bcc/os_agent/__init__.py`](../../../command-center/bcc/os_agent/__init__.py) объединяет P0–P3/P5 возможности управления ПК и явно фиксирует границу ответственности между детерминированным кодом и локальной моделью:

### Что решает ТОЛЬКО детерминированное ядро (0% доверия к тексту модели):
1. **Классификация риска каждого шага (`classify_pc_action`, T0–T3):**
   - `T0` (чтение, список окон/процессов/служб, скриншот, статус): выполняется автоматически.
   - `T1` (обратимые действия в пределах рабочих папок `workspace_dir`, запуск Блокнота/Калькулятора, локальные тесты): автоматически в режиме `L2`/`L3` с резервной копией и инструкцией отката.
   - `T2` (удаление файлов, остановка чужих процессов, запись вне безопасных корней, `git push`/`merge`, сетевые утилиты): **всегда** требует кнопки владельца в пульте (или явного окна доверия для не-критичных T2).
   - `T3` (секреты, Vault/DPAPI, неизменяемое ядро, отключение защитника/брандмауэра/UAC, платежи, удаление без бэкапа, `force-push`, `--no-verify`): **безусловный запрет (`deny`)**, который не может быть снят ни промптом, ни уровнем автономности, ни самой LLM.
2. **Быстрая компиляция канонических операций (`compile_plan_for_prompt`):**
   - Типовые команды владельца (чтение/запись/копирование файла, список окон, скриншот, открытие локальной страницы, запуск Блокнота) компилируются детерминированно в проверяемые шаги без лишней задержки LLM.
3. **Проверка результата фактом (`verified`):**
   - Успех шага засчитывается только по объективному пост-состоянию: код возврата процесса (`exit_code == 0`), фактическое наличие файла и совпадение SHA-256, непустой заголовок PNG-скриншота, найденный HWND окна.
4. **Защита от косвенных prompt-инъекций (D-013):**
   - Содержимое файлов (`pc.read_file`), OCR (`pc.ocr_read`), DOM браузера (`pc.browser_act`) и имена файлов в каталогах (`pc.list_dir`) сканируются `_PROMPT_INJECTION_RE`, помечаются `tainted=True` и оборачиваются в `EXTERNAL_DATA_HEADER`. При `tainted_by_injection=True` любые последующие мутирующие/командные шаги блокируются (`T3 deny`).
5. **Неизменяемый журнал аудита с якорем головы (`AuditJournal`, D-025):**
   - Каждое действие пишется в `audit.jsonl` со сквозным `seq`, `prev_hash` и `entry_hash` (SHA-256), а актуальная голова цепочки сохраняется в `audit.jsonl.head`. `verify_chain()` обнаруживает как правку/перестановку внутри журнала, так и отрезание хвоста (tail truncation) или удаление файла журнала.

### Что решает локальная LLM (`gemma4-31b-uncensored-ctx32k:latest` / `plan_pc_task_with_llm`):
1. **Декомпозиция свободных формулировок владельца:** когда запрос не укладывается в детерминированный шаблон `compile_plan_for_prompt`, локальная модель Gemma 4 31B предлагает последовательность вызовов инструментов.
2. **Диагностика и самоисправление (до 3 попыток):** при сбое шага модель анализирует вывод ошибки и предлагает исправленный шаг.
3. **Человекочитаемый отчёт на русском языке (D-029):** модель формирует краткий отчёт для пульта владельца на чистом русском языке.
4. **Ограничение:** каждый предложенный моделью шаг проходит через тот же детерминированный фильтр `classify_pc_action` и гейты `finalize.py` / `action_contract.py`. Модель не может повысить свои права или обойти подтверждение владельца.

## 2. Приоритет локальных моделей (D-001, D-002)

В [`command-center/bcc/features/pc_agent.py`](../../../command-center/bcc/features/pc_agent.py) закреплён детерминированный выбор модели `select_preferred_local_model` / `local_model_priority_key`:

| Приоритет | Модель | Назначение |
|---|---|---|
| **0 (Основная)** | `gemma4-31b-uncensored-ctx32k:latest`, `gemma4-31b-uncensored:latest`, `gemma4:31b` | Главная локальная модель владельца в Ollama (`127.0.0.1:11434`, $0) |
| **1 (Резерв)** | `bossman-main-qwen38-27b-q5:latest`, `bossman-community-qwen-uncensored:latest`, `bossman-fast-qwen36-35b-a3b-q5:latest` | Резервные локальные модели в Ollama ($0) |
| **2 (Опциональный ускоритель)** | `qwen3.8-flash-next-iq3_s`, `strata-qwen38-flash-next-iq3s` | Опциональный локальный сервер Strata (`127.0.0.1:8090`, если запущен) |

Ни в `ensure_argon_agent`, ни в `call_local_qwen` сортировка по `models.id DESC` больше не позволяет Strata (`id=107`) вытеснить живую `gemma4-31b-uncensored-ctx32k:latest`.

## 3. Единая таблица прав оператора (`PERMISSION_KEY_TABLE`, D-028)

Неизменяемое ядро `command-center/bcc/permissions.py` использует точечные канонические ключи, тогда как часть ранних профилей агентов (агенты 40, 41, 50) содержала короткие ключи (`read`, `write`, `exec`). Функция `normalize_operator_permissions` синхронизирует обе схемы без модификации `permissions.py`:

| Канонический ключ (`bcc/permissions.py`) | Совместимые ключи профиля | Назначение |
|---|---|---|
| `filesystem.read` | `read` | Чтение файлов и структуры проекта (`code.read`, `code.search`, `code.expand`, `code.status`, `code.workspace_map`, `pc.read_file`, `pc.list_dir`) |
| `filesystem.write` | `write` | Запись и патч файлов в рабочих корнях (`code.write`, `code.patch`, `pc.write_file`, `pc.edit_file`) |
| `terminal.read` | `read`, `exec` | Чтение статуса и вывода терминала (`terminal.status`) |
| `terminal.run` | `exec` | Выполнение команд в терминале (`terminal.run`, `pc.run_command`) |
| `browser.read` | `browser`, `read` | Чтение DOM и скриншотов браузера (`browser.read_dom`, `browser.screenshot`) |
| `computer.observe` | `computer_read`, `read` | Наблюдение за экраном и окнами ПК (`computer.observe`, `pc.observe_screen`, `pc.list_windows`) |
| `computer.control` | `computer_act` | Управление окнами и вводом (`computer.act`, `pc.desktop_act`) |
