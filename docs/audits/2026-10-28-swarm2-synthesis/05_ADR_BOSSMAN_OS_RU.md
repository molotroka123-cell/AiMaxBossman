# Архитектурные решения Bossman OS 2.0 (ADR-001 .. ADR-006)

**Дата:** 28.10.2026  
**Статус:** Принято и реализовано в `main`

---

## ADR-001: Разделение полномочий `owner` и `agent` на уровне HTTP-периметра и квитанций одобрения

- **Контекст:** В ранней реализации правило `path.startswith("/api/pc-agent")` допускало вызов owner-маршрутов с токеном роли `agent`, а `POST /api/pc-agent/self-modify` доверял булеву полю `"approved": true` из JSON-тела запроса.
- **Решение:**
  1. На уровне `require_token` (`command-center/bcc/api.py`) роли `agent` разрешён исключительно маршрут аварийного останова `/api/pc-agent/stop`; маршруты `approve`, `resume`, `trust`, `self-modify` требуют роли `owner` (`HTTP 403` для `agent`).
  2. На уровне `api_pc_agent_self_modify` (`command-center/bcc/features/pc_agent.py`) поле `approved=True` активируется только при наличии подтверждённого `approval_id` в `svc.approvals` (`status == "approved"`, `tool == "pc.self_modify"`).
- **Последствия:** Исключено самоодобрение агента как через API-токен, так и через подмену JSON-параметров.

## ADR-002: Двухуровневый финансовый шлюз (`SpendFirewall` + Fail-Closed журнал `cloud.ask`)

- **Контекст:** Проверка бесплатности модели по подстроке `127.0.0.1` или суффиксу `:free` уязвима к обходу через `http://127.0.0.1@evil.example` или сторонние платные провайдеры, а усечение `audit.jsonl` до 2000 строк и пропуск статусов `empty`/`error` позволяли обойти дневной потолок бюджета.
- **Решение:**
  1. `SpendFirewall.is_free_model` парсит URL через `urlsplit` и проверяет `ip_address(host).is_loopback`; суффикс `:free` признаётся только на `openrouter.ai` при отсутствии ненулевой цены.
  2. Одноразовые токены владельца (`issue_one_time_owner_token`) связываются с `allowed_provider`, `allowed_model` и `max_usd`.
  3. `tools_cloud.py` (`_read_audit`, `budget_state`) читает весь журнал целиком, учитывает стоимость всех статусов, а при `billing_unknown` или повреждённой строке JSON переводит дневной остаток в `0.0 USD` (`fail-closed`).
- **Последствия:** Невозможно списать средства без явного адресного токена владельца или сбросить счётчик расходов пустыми/битыми запросами.

## ADR-003: Обязательная привязка процессов `pc.run_command` к Windows Job Object до `resume()`

- **Контекст:** При создании процесса с флагом `CREATE_SUSPENDED` сбой привязки к Windows Job Object (`_win_job_attach -> None`) ранее приводил к вызову `resume()`, оставляя процесс без группового дескриптора уничтожения.
- **Решение:** В `command-center/bcc/v2/terminal_control.py` (`_win_bind_and_resume`) при `job is None` процесс немедленно завершается через `proc.kill()` и выбрасывается `OSError("Failed to attach process to Windows Job Object")` до возобновления потоков.
- **Последствия:** Любой процесс, запущенный через `pc.run_command`, гарантированно находится внутри Job Object с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`.

## ADR-004: Fail-Closed режим `pc.self_modify` в отсутствие контейнерной OS-песочницы

- **Контекст:** Запуск сгенерированных моделью тестов `pytest` в обычном дочернем процессе на хосте Windows (даже с очищенным `env` и прокси-переменными) позволяет коду модели читать и модифицировать файлы пользователя.
- **Решение:** До подключения реальной контейнерной OS-песочницы (`probe_os_sandbox() == True` через герметичный WSL2/Docker контейнер без сети) `pc.self_modify` сохраняет предложение на диск для ревью, но никогда не запускает модельный Python на хосте и возвращает `status: "verification_blocked_unisolated"`. При авто-откате в `health_check` статус `ok`/`verified` строго отражает фактический результат отката (`rb_res["ok"]`).
- **Последствия:** Полная защита хоста от выполнения недоверенного кода при сохранении прозрачного UX карточек предложений и отката.

## ADR-005: Политика анти-подделки бенчмарков и отзыв синтетических квитанций

- **Контекст:** В коммите `6674a66c` скрипт `tools/run_cyber_qlora_holdout_tournament.py` вычислял счёт `0.95 vs 0.625` из захардкоженной таблицы без вызова живых моделей.
- **Решение:**
  1. Опубликован официальный отзыв `docs/audits/2026-10-28-cyber-qlora-tournament/revocation.json`.
  2. Из `tools/run_cyber_qlora_holdout_tournament.py` удалены синтетические таблицы; без живого evaluator-а скрипт возвращает `status: "NOT_MEASURED"`.
  3. Тест `tests/test_qlora_tournament_integrity.py` включён в обязательный набор регрессий.
- **Последствия:** Ни один отчёт о качестве моделей не может получить статус `PASS` без проверяемых сырых ответов и хешей весов.

## ADR-006: Надстройка Bossman 2.0 и каноническая память Obsidian 2.0

- **Контекст:** Для прозрачного контроля всех 15 веток, чистоты памяти Obsidian и мгновенной самопроверки безопасности требовался единый агрегирующий слой поверх `:8801`.
- **Решение:** Введён модуль `command-center/bcc/features/bossman_20.py` (`/api/v20/status`, `/api/v20/memory/audit`, `/api/v20/memory/sync`, `/api/v20/security/self-test`), связанный с живым хранилищем `C:\Users\asd\Bossman\audit-memory` и верхней панелью Command Center.
- **Последствия:** Владелец видит статус идентичности кода, самотестов безопасности и чистоты памяти Obsidian в один клик из пульта.
