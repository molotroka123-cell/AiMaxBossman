## 3. Что не доказано или рискованно
1. **Этап 3 North Star** и фраза «Bossman самоулучшается сам»: пока только одиночный цикл, при участии оператора.
2. **Автоответчик Jeff** (ветка `consolidate/jeff-20261007`): мой аудит дал MERGE_WITH_FIXES. Не должен попадать в main до правок F1 (STOP в движке ответов), F2 (раскрытие ИИ без привязки к приветствию), F3 (неопознанный звонящий обходит allow-list), F4 (полный номер остаётся в `credentials.enc`). Живой Telegram не пробовали.
3. **Интернет-исследование заработка (локальная модель):** 33% числовых утверждений подтверждены источниками, остальные выдуманы. Использовать как набор гипотез, не как план.
4. **Генерация (Z-Image, FLUX, Wan 2.x, ACE-Step):** файлы на диске есть, пробных генераций я не запускал; тестировалось только с поддельным ComfyUI. Чистой text-to-video модели Wan нет.

7. **Зелёные листья по `integration`-квитанциям и `recorded`-ссылкам** нуждаются в выборочной перепроверке: часть старых FAIL-квитанций (47) остаётся в истории.

## 4. Что я бы делал завтра (порядок)
1. Свести ветки в одну линию (fast-forward или явное слияние после аудита, без force); зафиксировать один SHA.
2. Принять или отклонить `keys_guard` и `key-intake` по аудиту; ключи и vault не пушить (скан по значениям перед каждым пушем).
3. Закрыть F1-F4 автоответчика бесплатными/локальными воркерами, повторный аудит, затем вливание.
4. Аудит всех записей дерева секциями: первый проход бесплатные модели, второй платный аудитор (Haiku 5.5, GLM 5.3 Flash только как аудиторы); решение INTEGRATE / KEEP / RETIRE с причиной.
5. Switch установленной сборки одним SHA, проверка `/health/live`, Jeff, Пульт, стикеры, ключи после перезагрузки.
6. Публикация дерева и сверка SHA сайта, сборки и отчёта.
