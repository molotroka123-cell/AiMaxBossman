## Правила, зашитые в код

1. Гипотеза открывается при >= 3 одинаковых сбоях (агент + класс ошибки).
2. Предлагающий видит только очищенный класс ошибки и счётчик, но не отложенные задачи.
3. Хеш набора отложенных задач фиксируется в журнале до запуска; изменение даёт BLOCKED; пересечение с примерами сбоев даёт BLOCKED.
4. Проверяющий должен отличаться и по роли, и по модели; иначе NOT_RUN. Самопроверка не доказательство.
5. База считается один раз на хеш набора и переиспользуется (заморожена).
6. PASS только если строго выше доля прохождения и **ноль регрессий** и в рамках лимитов. PASS ведёт лишь в AWAITING_OWNER.
7. Лимит стоимости по умолчанию 0 USD; положительным он может стать только из уже существующего `long_run.json` (читается, не пишется).
8. Слово «улучшено» выводится только после PASS; иначе `NOT_RUN: воспроизводимого выигрыша нет`.

```
База (заморожена): доля прохождения / стоимость / токены
Кандидат:          доля прохождения / стоимость / токены
Разница: <delta>     Регрессии: <список id или пусто>
Предлагающий: <роль/модель>     Проверяющий: <роль/модель> (должен отличаться)
Стоимость итого: <USD> при лимите <USD>
Изоляция сети на уровне ОС: NOT_RUN
Откат: N/A до применения; после применения команда в журнале

Вывод: <улучшение подтверждено ... | NOT_RUN: воспроизводимого выигрыша нет, улучшение не заявляется>
```

## Как это использовать (после ревью, не сейчас)

- Карта ботов: `python -m bcc.self_improve botmap --live http://127.0.0.1:8801 --token-file <файл токена> --out <каталог>` (только GET; токен не печатается).

## Ограничения (честно)

- **Не проверено на живых данных**: ни одного реального эксперимента не запускалось, цикл не подключён к планировщику, поэтому «самообучение» и «улучшение» не заявляются (в живом журнале 0 записей).
- Изоляция процессов не уровня ОС: сеть и запись вне каталога запрещены API песочницы и чистым окружением/прокси, но враждебный процесс от того же пользователя ОС их обойти может (нужен контейнер/AppContainer): **NOT_RUN**.
- Токен владельца защищает от агентов, идущих через этот API, но не от кода с правами того же пользователя Windows, который перепишет файлы напрямую (нужен отдельный аккаунт или аппаратный ключ): **NOT_RUN**.
- Генератор состояния агентов видит только окно задач из снимка (`tasks_seen`), `never_run` означает отсутствие задач в окне.
- Состояние Jeff, Telegram-пульта, limits-out orchestra, tree_self_repair_cycle: `N/A`, у них нет статусного endpoint.
- Запущенный backend собран из `c25413930eb2` и помечен `SOURCE_IDENTITY_STALE`; новый код живой системой не используется до перезапуска и сборки (это решение владельца).
- Четыре теста `tests/test_autonomy_api.py` падают и без этих изменений (проверено удалением feature-модуля); код autonomy не затронут.
