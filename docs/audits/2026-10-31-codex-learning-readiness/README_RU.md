## Что добавлено

1. **`bcc/v2/memory/lessons.py`** — уроки поверх `facts`.
   - Обязательные поля: `source` (http(s)-URL, `codex-session:<id>`, `claude-session:<id>`, `bossman-run:<id>` или `file:<путь>`), `observed_at`, `valid_from` (→ колонка `valid_at`), `author` (codex|claude|bossman|owner).
   - Статус вычисляется из событий-проверок (`source_kind=lesson_check`). Писатель задать его не может.
   - Секреты чистятся до записи. Идемпотентность — по sha256(category, title, body, source).
   - Тело урока — не больше 4000 символов, запрос — не больше 16 КБ.
   - Облачные и удалённые писатели (codex/claude, заголовок `X-Bossman-Writer: cloud`, не-loopback адрес) не пишут в приватные категории владельца.
2. **`bcc/features/memory_lessons.py`** — эндпоинты на существующей памяти:
   - `POST /api/memory/lessons`: идемпотентно, лимит 30 в минуту и 300 в час на автора, слишком большой запрос → 413.
   - `GET /api/memory/lessons`, `/stale?max_age_days=N`, `/policy`, `/{id}`.
   - `POST /{id}/verify`: сервер САМ прогоняет связанную проверку — `business_exercise:<id>` с answer или решённую `skill_evaluation:<id>`. Ссылка вида «pytest прошёл» на слово не принимается.
   - `POST /{id}/refute`: нужны источник и причина.
   - `POST /{id}/freshness`: скачивает источник и ищет `expect_text`. Исходы: confirmed, not_found, unreachable, no_check_text. Статус `verified` эта проверка НЕ ставит.
   - Инструменты: `memory.lesson.add` (ask; пишет от имени bossman, приватные категории закрыты) и `memory.lesson.search` (auto, помечен как внешние данные).
3. **Учебные бизнес-упражнения.** Логика — в `bcc/business_exercises.py`, проверка — в независимом чекере `bcc/business_exercise_checker.py`, HTTP — в `features/learning_exercises.py`.
   - Четыре синтетических задания: сверка счетов и платежей, сравнение цен в USDT/EUR/CZK через Decimal (1000 USDT × 25 CZK/USD × 1.03 = 25 750.00 CZK), квалификация лидов из CSV, НДС 21/12/0 %.
   - Правда посажена руками в `_PLANTED` и пишется в каталог ключей ВНЕ корней агента: `BCC_EXERCISE_KEYS_DIR`, по умолчанию `%LOCALAPPDATA%\Bossman\exercise-keys`. Если этот каталог внутри data_dir, репозитория или allowed_roots, сервер отказывает (409).
   - Чекер не импортирует генератор. В квитанции нет ожидаемых значений, только имена несошедшихся полей.
   - Тест пересчитывает правду третьим, независимым способом из CSV.
   - Нет платежей, рассылок и кошельков. Сетевых вызовов модуль не делает.
4. **`tools/codex_learning_readiness.py`** — read-only проба работающего backend.
   - Отправляет только GET: `ReadOnlyClient` бросает исключение на любой другой метод.
   - Выдаёт PASS/WARN/FAIL по 12 возможностям.
5. **`live_e2e_temp_backend.py`** — живой сквозной прогон приёма уроков. Он пишет данные, поэтому отказывается работать с портами 8800 и 8801.

## Что НЕ доказано

- **Обучение у Codex не доказано.** Записанный урок ≠ выученный урок. Даже `verified_by_test` значит лишь, что связанное упражнение решено верно. Это не доказывает, что решение пришло из урока и что поведение Bossman изменилось.
- **Связь урока с упражнением объявляет сам писатель.** Сервер проверяет, что упражнение решено, но не проверяет, что оно относится к уроку.
- **`author` объявляется самим писателем.** Под токеном владельца Codex может назваться owner. Защита: приватные категории требуют loopback-адрес и отсутствия заголовка cloud. Codex через Computer Use на этом ПК — тоже loopback. Отдельного удостоверения агента нет.
- **Лимит частоты живёт в памяти процесса** и сбрасывается при рестарте.
- **Проверка свежести против реального интернета не запускалась**, в тестах работает фейковый fetcher. Путь `safe_fetch_text` (SSRF + pinned IP) живьём не прогонялся.
- **Проба на :8801 не запускалась** по правилу задачи. Состояние владельческого backend этой работой не проверено.
- **На ПК владельца через пульт/чат не проверено.** По правилу AGENTS.md «feature is PROVEN, not wrapped» это ещё не «добавленная возможность», а кандидат.
- **Полный набор тестов не прогонялся**, только перечисленные соседние наборы.
