# QLoRA tournament: результат отозван

`receipt.json` сохранён как историческое доказательство, а не сертификат. Его `PASS`, численные показатели и заявленные выводы **недействительны**: скрипт сопоставлял заранее записанные `base_response` и `qlora_response`, не выполняя ни базовую модель, ни QLoRA-адаптер.

Машиночитаемый отзыв и хеши двух связанных неизменённых квитанций: [revocation.json](revocation.json). Реальный турнир и выигрыш модели — **NOT_RUN / NOT_PROVEN**. Самостоятельный читатель старой квитанции без проверки отзыва всё ещё может ошибочно увидеть PASS; потребителям нужно учитывать revocation, прежде чем использовать её как доказательство.

Текущий скрипт по умолчанию не создаёт и не перезаписывает отчёт, не вызывает модель и завершается с ненулевым кодом. Для настоящего сравнения нужны проверенные модель и адаптер, замороженный holdout, фактические ответы и независимая оценка.
