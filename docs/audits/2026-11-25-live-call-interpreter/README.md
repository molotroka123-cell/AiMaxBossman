## Почему не «поставить Cicada»

Cicada (`github.com/wquguru/cicada`, Apache-2.0) — приложение для строки меню macOS: только macOS 26+ на Apple silicon,
Swift. Распознаёт речь Apple SpeechAnalyzer, переводит облачными Ling/Google, без API и без CLI. Боссман работает на
Windows, поэтому перенесена архитектура, а не код. Код Cicada не копировался.

| Cicada (macOS) | Боссман (Windows, локально) |
|---|---|
| Системный звук macOS | WASAPI loopback (`PyAudioWPatch`), `live_interp/capture.py` |
| Apple SpeechAnalyzer + определение языка | faster-whisper через `bcc.pit.speech` (тот же кэш модели), `language="auto"` |
| Ling / Google Translate | закреплённая Marian en→ru (`BOSSMAN_VIDEO_TRANSLATION_MODEL`, та же проверка SHA, что в видеостудии) |
| — | любой язык → en: собственный Whisper `task="translate"`; любой → ru: две ступени, помечено `two_hop` |
| Субтитры, расшифровка, экспорт SRT/MD | события `live_interp.subtitle`, `/api/live-interp/events`, `export?fmt=srt\|md` |
| Конец встречи после 10 мин тишины | `idle_end_s=600` |

## Правила

- Запускает и останавливает **только владелец** через пульт. Инструмента агента нет (как в `telegram_calls`), это проверено тестом.
- STOP владельца: `start` отказывает (409), идущая сессия заканчивается на следующей фразе (`owner_stop`, fail-closed).
- Аудио на диск не пишется никогда. Текст расшифровки пишется на диск только при `keep_transcript=true`, по умолчанию он в памяти.
- Перевод никогда не выдумывается. Для неподдерживаемой пары показывается оригинал с меткой `unsupported`,
  сломанная модель даёт `failed` с оригиналом. Ошибка распознавания пропускает одну фразу, звонок продолжается.
- Важно: у собеседников согласия на запись никто не спрашивает. Перед записью расшифровки чужого голоса предупреди собеседника.

## Этап 2 (26.11): перевод голоса владельца в звонок + экран пульта

Как «держи ⌥ и говори» у Cicada: кнопка «Удерживайте и говорите» в пульте (`/api/live-interp/speak/start|feed|stop`).
Микрофон → локальный Whisper → перевод → голос Piper → виртуальный микрофон VB-Cable («CABLE Input»), который звонок
(Zoom/Telegram/Meet) берёт как микрофон «CABLE Output».
- ru (и любой язык) → en: Whisper `task="translate"`, голос `BOSSMAN_PIT_TTS_MODEL_PATH_EN`.
- en → ru: закреплённая Marian, голос `BOSSMAN_PIT_TTS_MODEL_PATH`.
- Другое → `UNSUPPORTED_PAIR`: ничего не озвучивается и не выдумывается.
- Перед озвучкой текст проходит тот же фильтр утечек, что голос Джеффа в звонках (fail-closed): фраза, похожая на
  секрет, в звонок не уходит. STOP: отказ на старте и обрыв посреди фразы. Максимум 30 с на одно нажатие.
  В события и статус слова владельца не пишутся, только длина и вердикт.
- `bcc.oss.piper.synthesize_pcm(..., allowed_languages=)`: по умолчанию по-прежнему только `ru_RU`.
  Английский голос включается только явно (тест-негатив: без явного разрешения — `VOICE_LANGUAGE_UNSUPPORTED`).
- Экран «Переводчик звонков» (`ui/pages/live_interp.js`): готовность, старт/стоп субтитров, лента субтитров с честными
  пометками качества, экспорт SRT/MD, кнопка удержания. Чистые функции проверены в Node.

**Найдено попутно, не исправлено (вне этой задачи):** английский голос Джеффа в Telegram-звонках
(`jeff_engines.JeffTTS` + `pick_model`) на настоящем Piper никогда не звучит: `synthesize_pcm` отклонял всё, кроме
`ru_RU`, а в тестах Piper подменён. Теперь это чинится одной строкой (`allowed_languages`), но решение за владельцем.

Проверка этапа 2 на ПК: установить VB-Cable; в звонке микрофон «CABLE Output»; в пульте удерживать кнопку, сказать фразу по-русски.
Собеседник должен услышать английский. Замерить `latency_ms`.
