# Платные резервы не округляются в ноль — 01.11.2026

Задание владельца (мастер-промпт 01.11, пункт 2 «ЗАКРОЙ РАСХОДЫ»). Ветка `fix/paid-reservation-complete-20261101`,
база `origin/main` `c0f6d2e4`. Только синтетические данные: ни одного настоящего платного вызова, `:8801` не трогали,
чаты, ключи и данные владельца не читали.

**Что такое резерв.** Резерв — это ЛОКАЛЬНАЯ запись Bossman в его журнале расходов против потолка владельца: по ней
Bossman решает, отправлять ли вызов. Это не предел счёта провайдера. Провайдер списывает по своему учёту; фактическое
списание видно только на странице использования провайдера.

## 1. Воспроизведение (до правки)

Находка Кодекса подтверждена на чистом `c0f6d2e4`:

```
20 резервов по $0.0000001 при бюджете $0.000001 -> прошли все 20 (ожидалось: 1)
estimate_cost(цена 0.01/0.01 за 1M, 1+1 токен) -> 0.0
reserve(quoted_usd=0.0) -> резерв принят, quoted_cost_usd = 0.0
```

Причина: `round(x, 6)` превращал любую сумму меньше $0.0000005 в 0 — и в оценке, и в записи резерва. Поэтому журнал
держал 0, и сколько угодно мелких платных вызовов проходили потолок.

Новые тесты `test_paid_reservation_complete_20261101.py` на чистом main: **19 FAIL / 10 PASS**. После одного
cherry-pick Кодекса `e24c14f2` (`4491dcf0` в ветке, авторство сохранено): **12 FAIL / 17 PASS**. Кандидат Кодекса
закрывал оценку и сам резерв в `cloud.ask`, но не остаток, фактическую стоимость, сверку владельцем, платную модель с
ценой 0/0 и другие платные маршруты.

## 2. Правило (одно на все пути) — `command-center/bcc/paid_money.py`

- положительная оценка, резерв или известная фактическая стоимость округляются ВВЕРХ до микродоллара (минимум
  $0.000001). Шум float обрезается на 1e-12, поэтому точные суммы вроде 0.6 или 0.3 не раздуваются;
- платный вызов никогда не резервирует 0: `paid_quote` отказывает на 0, отрицательные суммы, NaN/inf, bool, None
  и строки;
- остаток потолка округляется ВНИЗ (`floor_micro`). `round()` мог поднять остаток $0.0000015 до $0.000002 и
  пропустить резерв на $0.000002;
- неизвестная цена и неизвестная итоговая стоимость — это не деньги: остаётся None/null, вызовы блокируются.

`bossman_shared/fable_budget.py` не импортирует `bcc`, поэтому там то же правило продублировано локально
(`_ceil_micro`, `_floor_micro`).

## 4. Тесты

Новые: `command-center/tests/test_paid_reservation_complete_20261101.py` (29) и
`command-center/tests/test_paid_rounding_all_paths_20261101.py` (24). Тест Кодекса
`test_paid_quote_rounding.py` (2) сохранён.

Положительные и отрицательные случаи:
- 20 резервов меньше микродоллара при бюджете $0.000001 → проходит ровно 1; в журнале `quoted_cost_usd` = $0.000001;
- `asyncio.gather` из 20 мелких платных `cloud.ask` при потолке $0.000005 → 5 вызовов провайдера (было 20);
  16 потоков при потолке $0.000004 → ровно 4 резерва; 2 процесса по 5 попыток при потолке $0.000003 → ровно 3
  (путь через threading и файловую блокировку);
- GovernedAdapter + long_run: 12 мелких вызовов GLM при потолке 5e-6 → 5 (было 12); 12 потоков → 5;
- цена 0 и неизвестная цена: неизвестная → `цена модели неизвестна` (отказ); платная 0/0 → отказ «нулевая цена»;
  бесплатная 0/0 → маршрут проходит, оценка 0 (положительный контроль); в Студии платная модель с ценой 0 при
  `free_only=False` → отказ, цена 1e-7 → резерв $0.000001;
- смена суток UTC: резерв в 23:59:59, расчёт в 00:00:01 → удержание живёт через полночь, известный расход
  засчитывается новому дню как $0.000001; неизвестный итог (`billing_unknown`) прошлого дня блокирует новый резерв
  и через сутки;
- провайдер не вернул usage → `billing_unknown`, `cost_usd = null`, следующий платный вызов → `CLOUD_ASK_NO_BUDGET`,
  провайдер вызван 1 раз; мелкий usage → $0.000001, не 0;
- сверка владельцем на 2e-7 → $0.000001; явный 0 от владельца («провайдер вернул») остаётся 0.

Прогоны на финальном коде ветки — см. `receipt.json`, поле `test_runs`.

**Отрицательный контроль.** Продуктовые файлы вернули к `c0f6d2e4` (кроме нового `paid_money.py`, иначе модуль не
импортируется), три новых файла тестов: **35 FAIL / 20 PASS**. Проходят положительные контроли, проверки
неизвестной цены (они работали и раньше) и юнит-тесты `paid_money`. С правкой — все PASS.

## 5. Что НЕ доказано и что осталось

- **Настоящий счёт провайдера** — NOT_RUN. Платные вызовы не запускались. Резерв ограничивает только то, что
  отправляет Bossman; сумму, которую спишет провайдер, он не ограничивает и не гарантирует.
- Живой путь на ПК владельца (pult/chat → cloud.ask → журнал) на этом SHA — NOT_RUN; CI на SHA ветки — NOT_RUN на
  момент записи.
- Вне класса округления, не исправлено (находки обхода):
  - `features/coding_tasks.py`: платные OpenRouter-исполнители идут через sidecar без резерва в USD;
    `estimate_coding_task_cost` только совещательный;
  - `features/agent_opencode.py`: платные ярусы блокируются только при остатке ≤ 0, оценка с остатком не
    сравнивается;
  - `engine._cost`: неизвестная цена (None) считается как 0. Для облачных моделей это перекрывает отказ
    GovernedAdapter на модель без цены; для локальных 0 — законная цена;
  - `usage.cost == 0` от провайдера на платном вызове принимается как известный 0 (`long_run.actual_eur`,
    `_actual_cost` cloud.ask);
  - `spend_meter` before_run без блокировки — совещательная проверка до старта; `autonomy/budget.exhausted`
    проверяет вне файловой блокировки (USD туда сейчас не передаётся);
  - `organization._cost_meter`: None → 0.0, только показ.
- long_run хранит журнал по суткам: если резерв сделан до полуночи, а commit после, строка commit попадает в файл
  нового дня. Худший случай остаётся в учёте прошлого дня (консервативно). Это прочитано в коде, отдельного теста нет.
