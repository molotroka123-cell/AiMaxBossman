## Настоящий пользовательский путь

Использовались официальный Chromium Playwright, настоящий BCC в отдельном процессе, временные БД и профиль, реальный FFmpeg. Авторизация выполнена через видимую форму входа. Изменения создавались кликами, вводом, файловым диалогом и клавиатурными командами; API использовался только для независимого чтения результата. Сервер перезапускался с новым PID и прежним тестовым хранилищем.

**Video Studio:** новый проект → импорт MP4 с аудио → добавление на timeline → изменение source-out с 2 до 1 секунды → Undo до 2 секунд → Redo до 1 секунды → создание preview → воспроизведение кнопкой ▶ до конца → Export через диалог → скачивание реального файла → проверка ffprobe/full decode → перезапуск сервера → повторное открытие проекта, результатов и воспроизведение preview.

Полученный экспорт: 1.000000 секунды, H.264 + AAC, 1280×720, 25 fps, 48 kHz stereo. Встроенный verifier проверил decode и три кадра; скачанный файл дополнительно декодирован независимо. SHA-256: `253b01ec6d3521fb367f93abbb8b26893039ae8869a3df55d362dd958a684549`.
В обоих проверенных воспроизведениях preview: currentTime=1, duration=1, ended=true, readyState=4, кадр 320×180. Ни play(), ни currentTime не подставлялись тестом: состояние меняли реальные кнопки транспорта, DOM только читался.

**Web Designer:** новый проект → ввод HTML в редакторе → автосохранение → выбор H1 кликом в iframe → изменение текста через инспектор → изменение кегля → mobile viewport 390px → скачивание HTML → перезапуск сервера → сохранность текста, стиля и кода → создание второго независимого проекта без изменения первого.
Проверена сохранность DOCTYPE, комментария, вложенного strong и JSON-LD. Дополнительные браузерные проверки подтвердили picker, изоляцию iframe и фактическую геометрию viewport. Sandbox остаётся `allow-scripts`, без `allow-same-origin`. Page errors: 0 для обоих сквозных сценариев.

## Постоянная проверка и граница приёмки

`.github/workflows/editors-user-safety.yml` запускает тот же обязательный набор на точном checkout SHA, устанавливает Chromium и FFmpeg, отказывает при отсутствии/пропуске любого сценария и сохраняет artifacts. У workflow только contents:read, нет автоматического изменения кода или push. Настройки защиты веток не менялись.

Текущий вердикт: **EDITOR_BASELINE_PASS_ON_LINUX_CHROMIUM** для перечисленных сценариев.
Это не полная сертификация всех профессиональных функций, всех форматов, многочасового/многодорожечного монтажа, мобильной верстки всего приложения или производительности на AMD владельца.

OWNER_WINDOWS_UI=NOT_RUN.
BOSSMAN_LOCAL_MODEL_EDITOR_USE=NOT_RUN.
HUMAN_SPEED=NOT_MEASURED.
FULL_MAIN_CI=SEPARATE_CURRENT_SHA_RESULT_REQUIRED.

До нового функционала сохраняется приоритет стабильности этой базы. Прогон владельца должен отдельно подтвердить ту же установленную версию, открытие через Bossman, управление локальной моделью и реальные задачи. Уже идущий прогон не перезапускался и его файлы не обновлялись; результаты разных SHA не смешиваются.
