# Bossman architecture benchmark - 2026-09-29 (measured, not estimated)

Harness: `tools/bench_bossman.py` (temp data dir, no network, no models, workers off, in-process ASGI). Build: d3385ec2.
Machine: the owner's Windows PC (Ryzen AI MAX+ 395). 151 read-only GET endpoints measured, 10 calls each after one warm-up call.

| Axis | Before | After | Change |
|---|---:|---:|---:|
| `import bcc.api` (cold interpreter, median of 3) | 0.654 s | 0.649 s | -0.8 % |
| App create + start | 1.283 s | 1.240 s | -3.4 % |
| Resident memory after start | 122.7 MB | 122.7 MB | 0 % |
| Endpoint p50, median of endpoints | 1.99 ms | 2.11 ms | noise |
| Endpoint p95, median of endpoints | 2.88 ms | 2.63 ms | -8.7 % |
| **Endpoint p95, worst endpoint** | **6688 ms** | **168 ms** | **-97.5 %** |

## What changed
Five read-only health endpoints waited on sidecars, sockets or process scans and took 1-6.7 s each on every page open:
`/api/opencode/health` 6.7 s, `/api/music/health` 2.2 s, `/api/offline` 1.9 s, `/api/watchdog` 1.5 s, `/api/jeff-settings/status` 1.0 s.
`bcc/probe_cache.py` answers fresh results at once (TTL 8-20 s), serves a stale result immediately while refreshing in the
background (stale-while-revalidate), shares one probe between concurrent callers, never caches failures, hands out copies,
and is off in tests (`BCC_PROBE_CACHE=off`). `/api/jeff-settings/status` also stopped blocking the event loop (worker thread).

## What did NOT improve (honest)
* The very first call after a cold start still pays the full probe time (the cache cannot remove a probe, only stop repeating it).
* Import (0.65 s) and start (1.24 s) are dominated by third-party frameworks (FastAPI 0.15 s, SQLAlchemy 0.12 s) and by loading
  95 feature modules and registering 561 routes (about 1.2 s of `create_app`). Cutting them by half needs lazy feature mounting,
  which changes route registration and was not attempted inside the freeze window.
* The claim "all parameters improved by 50-60 %" is therefore NOT met; the one axis that moved by more than that is the
  worst-case endpoint latency. Two smaller leads are known: `bcc.build_identity` spawns `git` at import in a checkout
  (about 120 ms, by design; an installed build reads a file instead) and Playwright is imported at app creation (about 80 ms).

Reproduce: `python tools/bench_bossman.py --out bench.json` from `command-center/` with PYTHONPATH on this checkout, then
`python tools/bench_bossman.py --compare before.json after.json`.
