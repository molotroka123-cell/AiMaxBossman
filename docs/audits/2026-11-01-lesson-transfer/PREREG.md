# Предрегистрация: перенос урока из памяти Bossman — 01.11.2026

Пункт 5 владельца: «ДОКАЖИ ПРИМЕНЕНИЕ УРОКОВ». Запись в память ≠ обучение весов ≠ доказанный перенос.
Этот файл и `prereg.json` закоммичены ДО первого прогона эксперимента. Машиночитаемая версия плана — `prereg.json`.
Если план и этот текст расходятся, верен `prereg.json`.

## Вопрос

Урок записан в СУЩЕСТВУЮЩУЮ память: `POST /api/memory/lessons`, строка таблицы `facts`. Движок сам поднимает его при старте задачи (TASK_START recall).
Меняет ли это ответы ЛОКАЛЬНОЙ модели на НОВЫХ задачах класса урока? И не портятся ли при этом посторонние задачи?

## Что измеряется — честно

Измеряется перенос **правила, которое модель не может вывести из текста задачи**.
Правило обменного стола SwapMe из `bossman_shared/exchange_assistant/quote.py`:
- наценка по умолчанию 3 %;
- клиент покупает → сумма × mid × 1.03, округление ВВЕРХ до 0.01;
- клиент продаёт → сумма × mid × 0.97, округление ВНИЗ до 0.01.

Задачи отложенного набора называют «правила стола SwapMe», но сами правила не пишут.

Значит, проверяется вот что:
1. recall действительно кладёт урок в контекст модели;
2. модель его применяет.

Улучшение рассуждения это НЕ проверяет. Обучение весов — тоже НЕ проверяет: веса не меняются.

## Путь

`POST /api/tasks` (run_now, явный агент) → Engine → TASK_START recall (`memory.recalled`) → провайдер openai_compat → модель → `GET /api/tasks/{id}`.

Временный backend:
- порт 8897;
- временные `BCC_DATA_DIR`, `LOCALAPPDATA`, `BCC_EXERCISE_KEYS_DIR`;
- запуск через `launch_temp_backend.py`.

Владельческий :8801 не трогается.

## Правда

Правда посчитана в Decimal и сверена с Fraction в `build_truth.py`. И скрипт, и правда лежат ВНЕ репозитория и вне временного каталога данных: каталог `keys/` в scratchpad сессии.
- В `prereg.json` записан только sha256 файла правды: `truth_json_sha256`, а также sha256 построителя.
- Правда публикуется вместе с результатами.
- Модель правду видеть не может: у агента нет инструментов.

## Фазы

1. **baseline** — свежая временная БД без урока. 38 задач × 3.
2. **урок**:
   - `POST /api/memory/lessons` с source, observed_at, valid_from, author=claude, limitations;
   - проверка провенанса: облачный или удалённый писатель не пишет в приватные категории; писатель сам не ставит verified;
   - `/verify` по заявлению → 422;
   - **рестарт** временного backend → урок, его ограничения и статус не изменились.
3. **after** — тот же каталог данных после рестарта, урок в памяти, recall включён. 38 задач × 3. Тот же порядок.
4. **упражнение** — `swap_desk_quote_v1` прогоняется через тот же путь задач. Ответ МОДЕЛИ отправляется в `/verify`, чекер запускает сервер.

## Оценщик

`scorer.py` — это код, не LLM. Он читает только файл правды и сырые ответы.
- Значение берётся после ПОСЛЕДНЕГО «ОТВЕТ:». Если его нет — последнее число, с флагом `format_fallback`.
- Деньги сравниваются точно в Decimal: 18828.1425 ≠ 18828.15.
- Задача засчитана в фазе, если верны ≥ 2 из 3 повторов.
- Прогон со статусом не `completed` считается неверным.

## Правило решения (из `prereg.json`, применяется буквально)

Правила проверяются по порядку:
- **Нет запаса.** baseline held-out ≥ 17/20 → INCONCLUSIVE: «no headroom — transfer not demonstrable».
- **Recall не сработал.** В фазе after урок есть в `memory.recalled` меньше чем в 95 % прогонов held-out. Или он есть хотя бы в одном прогоне baseline. → **FAIL**.
- **Сбои инфраструктуры.** Больше 10 % прогонов любой фазы не `completed` → INCONCLUSIVE.
- **PASS** — нужны все три условия:
  1. Δ = held-out after − held-out baseline ≥ **8** задач;
  2. односторонний точный знаковый тест на расходящихся задачах даёт p ≤ 0.01;
  3. **0** регрессий в контроле. Регрессия — задача, которая в baseline прошла большинством, а в after нет.
- **FAIL** — если Δ ≤ 3 или регрессий в контроле ≥ 2.
- Всё остальное — **INCONCLUSIVE**.
- Набор independent — описательная метрика. «Обобщается» пишем, только если прирост ≥ 3 из 6.
