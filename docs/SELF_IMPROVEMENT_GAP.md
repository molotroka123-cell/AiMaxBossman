# SELF_IMPROVEMENT_GAP — что не хватает до самоулучшающегося Bossman

Состояние на 2026-10-02. Это анализ по коду и документам репозитория, не новая
улика: ни один пункт ниже не закрыт, пока нет теста, лога или отчёта с SHA.

## Что уже есть

- Гейт решения: `bossman_shared/objective_improvement.py::may_promote`.
  Промотируемы только `route`, `context`, `skill`; ядро доверия и расширение прав
  отклоняются; нужно >= 20 выборок и удержание интеллекта >= 0.98 с привязкой к
  парному замеру.
- Learning Guard: candidate -> shadow -> verified -> owner, A/B, секретный holdout
  (`bossman-core/bossman/learning_guard/`), shadow-тренер `autonomy_trainer.py`.
- Оценка по Парето: `bossman-core/bossman_v3/self_improvement/lab.py`.
- Источники сигналов: failure memory и `failure_patterns.py` (только advisory).
- Процедуры: `.agents/skills/{skill-evaluator,failure-retrospective,skill-forge}`.

## Чего не хватает

1. **Нет подключения к рантайму.** `may_promote` вызывается только из тестов;
   `bossman_v3/self_improvement` — `INTENTIONAL_FROZEN`, 0 продакшн-импортов;
   тренер только shadow за выключенным флагом; V5 не завершён.
2. **Нет генератора гипотез.** Ничто не превращает отказы и паттерны в
   `CandidateImprovement` / `AutonomyCandidate` автоматически.
3. **Нет исполнителя стадий.** `PIPELINE_STAGES` — данные. Ничто не запускает
   sandbox, A/B, red-team и замер удержания и не записывает завершённые стадии;
   `completed_stages` заявляет вызывающий код.
4. **Нет canary / monitor / rollback в рантайме.** После `True` из `may_promote`
   нет механизма малой доли трафика, наблюдения и автоматического отката.
5. **Нет оценочного набора.** `LiveCapabilityScore` и `PureCodingIQ` —
   `INSUFFICIENT_EVIDENCE`; в release-уровне 2 REAL_SANDBOX-кейса; стоимость и
   трёхкратная производительность не измерены.
6. **Нет единого реестра версий** роутов, контекстов и скиллов с закреплением
   версии и ревокацией (M4 плана V4, NOT STARTED).
7. **Нет замкнутой обратной связи по стоимости.** Телеметрия наблюдательная и не
   доказывает правильность выполнения.
8. **Нет приёмки на реальном железе:** Windows, живой браузерный агент, Fleet на
   нескольких узлах.
9. **Нет владельца в петле.** Нет интерфейса, где владелец видит кандидата и
   доказательства и решает «canary» или «откат» (M9).
10. **Нет защиты от Goodhart-эффекта:** ротации holdout и контроля переобучения
    под фиксированный набор.

## Предлагаемый порядок

1. Честные метрики: больше REAL_SANDBOX-кейсов, замер стоимости.
2. Реестр версий с откатом (M4).
3. Исполнитель стадий + canary/monitor/rollback — за флагом, в shadow.
4. Генератор гипотез из `failure_patterns`.
5. UI владельца и включение на реальном железе.

Ядро доверия (policy kernel, подписи, финализатор, treasury, objective store)
остаётся вне автоповышения.

## Критерии приёмки по пунктам

| # | Пункт | Закрыт, когда есть улика |
|---|---|---|
| 1 | Подключение к рантайму | Выключенный флаг => поведение прежнее (тест); включённый => путь через `runtime_bridge`; запись в матрице связности |
| 2 | Генератор гипотез | Кандидат рождается только из >=3 свежих эпизодов; признаки доверия/прав определены структурно |
| 3 | Исполнитель стадий | `completed_stages` пишет исполнитель; подделка отклоняется (атакующий тест) |
| 4 | Canary/monitor/rollback | Авто-откат при security-регрессии; рестарт-тест |
| 5 | Оценочный набор | REAL_SANDBOX-кейсы для verifier и universal_computer_apprentice; честный `INSUFFICIENT_EVIDENCE` до набора выборки |
| 6 | Реестр версий | pin/revoke/rollback, состояние переживает рестарт |
| 7 | Стоимость | Поле стоимости есть только при провайдерской улике |
| 8 | Реальное железо | Улика с машины владельца; до тех пор `PENDING_OWNER_MACHINE` |
| 9 | Владелец в петле | UI со списком кандидатов и журналом решений; одобрения модели отклоняются |
| 10 | Goodhart | Ротация holdout и пометка подозрительных кандидатов |

## Риски и откат

- Любой этап откатывается `git revert` своих коммитов; флаги по умолчанию OFF,
  поэтому слияние этапа не меняет поведение продукта.
- Главный риск — ослабить гейт ради зелёных метрик. Защита: запрет менять
  `may_promote`, пороги и существующие тесты в рамках этой работы.
- Деградация интеллекта ловится парным замером удержания (>= 0.98) и откатом
  на canary.

## Как запускать работу

См. раздел «Запуск и заливка в GitHub» в
`MASTER_PROMPT_SELF_IMPROVEMENT_CODEX.md`: этапы 1–7, одна ветка и один draft PR
на этап, merge решает владелец.
