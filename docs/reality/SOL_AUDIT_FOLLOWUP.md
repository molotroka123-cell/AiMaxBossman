новых async/identity/fence-сценариев падали до shared-исправления. Терминальная
проверка до исправления давала два новых падения и три существующих падения

и результаты находятся в [final-engine-tests.json](evidence/final-engine-tests.json)

## Модели и распространение метода

Общий версионированный протокол подключён к фактическим system messages Core/BCC,
включая восстановление checkpoint. Он требует цель, ограничения, короткий план,
проверяемые действия, независимые доказательства и честный статус. Документы,
tool output и retrieved memory остаются данными; скрытые внутренние рассуждения
не записываются и не копируются. Это настройка runtime, не обучение весов.

Одна живая локальная проверка `qwen2.5:7b` заняла 10.735 секунды. Модель отказалась
считать отсутствующий файл выполненной задачей, но нарушила JSON-формат и дала
двусмысленное пояснение о README. Строгий итог — `FAILED_NARROW_CRITERION`, общий
результат `MIXED`. [Полный артефакт](evidence/local-model-eval.json).

[Десять предложений V4/V5](../TOP_10_IMPROVEMENTS.md) доступны по ссылке из общего
протокола. Внедрён общий метод работы; остальные предложения не выдаются за десять
уже запущенных функций. Публикация в Git не означает, что запущенный старый процесс
автоматически перечитал код: для него требуется штатное обновление и перезапуск.

Над работой параллельно работали три агента: engine_security (Popper),
model_protocol (Galileo), reality_security (Harvey). Root выполнял интеграцию,
контролируемую git-миссию, проверку исходного архива и публикацию чекпоинтов.
