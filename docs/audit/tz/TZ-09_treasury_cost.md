### 2.2 Оценка токенов, зависящая от скрипта
Текущая `_CHARS_PER_TOKEN_UPPER_BOUND = 3.0` не является верхней границей токенов для нелатиницы. Требование:
```
tokens_upper(text) = Σ_{script s} chars_s(text) / r_s
r = { latin: 3.0, cyrillic: 1.8, cjk: 0.7, other: 1.0 }        # НИЖНИЕ границы chars/token ⇒ верхняя граница токенов
```
Значения выбраны с запасом относительно наблюдаемых средних (латиница ≈ 3.5–4.0, кириллица ≈ 2.0–2.6, CJK ≈ 0.8–1.2). Классификация символов — по `unicodedata` диапазонам (без внешних зависимостей). Плюс константа +8 токенов на сообщение (служебные токены ролей).
Если провайдер даёт `count_tokens` — использовать его как точное значение **только для понижения** оценки, никогда для повышения потолка.

### 2.3 Более точная, но по-прежнему верхняя оценка стоимости
`worst = tokens_in · max(p_in, p_cache_write) + max_output_tokens · p_out` вместо `(tokens_in + out) · max(rates)`. Это остаётся верхней границей (кэш-чтение дешевле входа; худший вход — запись кэша) и снижает перерезерв в ≈ 3–5 раз для промптов, где вход ≫ выход, т.е. в типичном случае. При $3 потолке это разница между «можно 30 запросов» и «можно 6».

2. INV-3: `set_limit(child)` отклоняет `limit(child) > limit(parent)`; при `set_limit(parent)` проверяется `Σ siblings ≤ parent`.
3. Резерв — атомарно по всему пути `organization → department → mission` (одна транзакция store; при отказе любого уровня — откат всех). Сейчас `reserve()` сначала `preflight` по всем, затем запись — гонки нет только потому, что однопоточно; зафиксировать это транзакцией.
4. `restore()` восстанавливает `reserved` из store (новая колонка), незавершённая работа НЕ перерезервирует повторно (иначе двойной резерв).

## 4. Локальные вычисления как стоимость (TR-05) — SHOULD
Локальный запуск не бесплатен — он расходует энергию и время GPU, и без учёта казначейство не может сравнивать «локально vs облако».
```
cost_local_usd = (P_gpu_W · util + P_cpu_W · cpu_util + P_idle_W) · t_s / 3.6e6 · price_kWh
```
`P_gpu_W` — из `nvidia-smi --query-gpu=power.draw` при доступности, иначе TDP карты из таблицы; `price_kWh` — настройка владельца (дефолт 0.15 USD). Пишется в `tool_calls.duration_ms`-совместимый receipt `compute_seconds`, суммируется в конверт `compute_seconds` и в `cost_local_usd` (информационно, не против $-потолка). Отчёт «облако vs локально» в control-plane.

## 5. Прогноз и алерты (TR-06) — SHOULD
- Burn-rate EWMA: `b_t = α·spend_t + (1−α)·b_{t−1}`, `α = 0.3`, шаг 1 час; `ETA_exhaustion = remaining / b_t`.
- События `treasury.forecast{eta_h}` при `eta < 24 h` и `treasury.threshold{pct}` на 50/80/95 %.
- Атрибуция: каждая запись ledger несёт `mission_id/department_id/run_id` (сейчас `purpose` — строка); отчёт `cost per verified action = spent / |verified receipts|` по отделу — метрика эффективности организации.

## 6. Математика (проверка требований)
- Верхняя граница токенов: если `r_s ≤ min_actual_chars_per_token(s)`, то `chars/r_s ≥ tokens_actual` — по построению. Для кириллицы наблюдаемый минимум ≈ 2.0 ⇒ `r=1.8` даёт запас 10 %.
- Пример недорезерва сейчас: русский промпт 30 000 символов → оценка `10 000` токенов; фактически ≈ 12 500–15 000 ⇒ резерв занижен на 25–50 %; при цене входа $15/M (opus-класс) недосчёт до $0.075 на запрос — за 40 запросов потолок $3 «протекает» на $3 (100 %).
- Пример перерезерва сейчас: тот же промпт, `max_output=1 000`: `(10 000+1 000)·75/1e6 = $0.825` вместо `10 000·18.75/1e6 + 1 000·75/1e6 = $0.26` (opus-4-1) — ×3.2.
- INV-3 гарантирует, что сумма трат детей никогда не превысит родителя без явного повышения родителя владельцем.
