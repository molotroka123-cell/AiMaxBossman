# Как владельцу написать свою конституцию

Конституция Bossman - файл, который меняете только вы. Шлюз автономии читает ее из файла, SHA-256 которого
равен вашему pin (`%LOCALAPPDATA%\Bossman\autonomy\constitution.sha256`). Менять код под новый текст не нужно:
шлюз понимает либо machine-readable блок `bossman-policy`, либо старые формулировки правила 4.

## 1. Что писать

Пишите конституцию обычным текстом (цели, список «всегда решение пользователя», уровни, release tiers,
Enforcement - как в `BOSSMAN_CONSTITUTION_v2_DRAFT.md`) и добавьте ОДИН блок в формате JSON:

````
```bossman-policy
{
  "schema_version": 1,
  "approvers": {"mode": "independent", "min_independent": 2, "require_external": true},
  "writer_may_verify": false,
  "auto_tier_requires": ["tests", "verifiers"],
  "max_autonomy_level": "L2"
}
```
````

Поля:

| Поле | Значения | Смысл |
|---|---|---|
| `schema_version` | `1` | только эта версия |
| `approvers.mode` | `independent` или `named` | `independent`: тесты + не менее 2 верификаторов разных семейств моделей; `named`: как раньше, Claude и Codex |
| `approvers.named` | `["claude","codex"]` | только для `named`; другие имена эта сборка не поддерживает |
| `approvers.min_independent` | `2` | сколько семейств должно одобрить (эта сборка запускает ровно 2 стадии; меньше 2 или больше 2 - блок отвергается) |
| `approvers.require_external` | `true` | хотя бы один верификатор - облачная модель; `false` отвергается |
| `writer_may_verify` | `false` | автор изменения никогда не верифицирует себя и свое семейство; `true` отвергается |
| `auto_tier_requires` | `["tests","verifiers"]` | для автоматического уровня нужны и тесты, и верификаторы; убрать нельзя |
| `max_autonomy_level` | `L0`..`L4` | потолок уровня; старт не выше L2 в любом случае, выше L2 - только после 25 чистых циклов и вашего подтверждения |

## 2. Пример: оставить Claude + Codex

```bossman-policy
{"schema_version": 1, "approvers": {"mode": "named", "named": ["claude", "codex"]}, "max_autonomy_level": "L1"}
```

## 3. Чего блок НЕ может изменить (проверяется кодом, не текстом)

- список «всегда решение пользователя»: деньги, публикации, ключи, удаление данных, отключение защит, изменение
  конституции и шлюза;
- STOP (общий и автономии);
- protected path globs и release tiers (кнопку Release нажимаете вы);
- pin вне репозитория и проверку SHA-256;
- старт не выше L2 и правило «25 чистых циклов + ваше подтверждение»;
- автор изменения никогда не верифицирует сам себя.

Если в блоке упомянуто что-то из этого (ключи вроде `owner_decisions`, `stop`, `protected_globs`, `pin`) или
любой неизвестный ключ, блок целиком отвергается и шлюз работает как v1 (Claude + Codex). Нет блока - работает
старое распознавание правила 4 (предложение про independent verification -> independent, иначе Claude + Codex).
Два блока, незакрытый блок, невалидный JSON, неизвестный `mode`, противоречие между блоком и правилом 4 -
тоже v1 и причина в `warnings`.

## 4. Посмотреть смысл ДО pin

```
bossman autonomy constitution explain --path C:\путь\к\новой_конституции.md
```

Команда ничего не пинит и не пишет: показывает эффективный режим (v1/v2), минимум верификаторов,
требование внешнего, уровень старта, предупреждения и какое правило сработало. `tools\adopt_constitution_v2.ps1`
печатает тот же вывод перед запросом `ADOPT-V2`. Только после этого вы пинните файл
(`bossman autonomy constitution pin`, 12 символов SHA вводите сами). Блок читается только из файла, чей SHA-256
равен вашему pin.
