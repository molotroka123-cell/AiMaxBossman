# Вечерняя приёмка владельца — 2026-09-06

Это **не** прогон юнит-тестов. Двенадцать сценариев ниже проверяют то, что нельзя
проверить из CI: живой браузер, настоящий экспорт видео, реальное убийство
процесса, отказ владельца в разрешении и то, как продукт ощущается как ОДНА вещь,
а не набор демонстраций.

Ожидаемая длительность: **30–60 минут**.

Харнесс измеряет время сам, хранит вердикты рядом с уликами и после прогона
сверяет заявленное с корпусом реальных нагрузок. Расхождение будет названо, а не
сглажено.

---

## Команды

```
# Windows — одна точка входа, из свежего клона
.\start-bossman.ps1                 # установка → доктор → окно Command Center
.\start-bossman.ps1 -DoctorOnly     # только предполётная проверка
.\start-bossman.ps1 -EveningTest    # провести приёмку

# Linux / macOS
./start-bossman.sh
./start-bossman.sh --doctor-only
./start-bossman.sh --evening-test
```

Напрямую, если окружение уже готово:

```
python scripts/bossman_doctor.py            # предполётная проверка
python scripts/evening_acceptance.py run    # провести приёмку
python scripts/evening_acceptance.py status # что уже сделано
python scripts/evening_acceptance.py report # собрать отчёт
```

## Предполётная проверка

`bossman doctor` различает три состояния, и различие существенно:

| | значение |
|---|---|
| **PASS** | проверено сейчас, на этой машине |
| **WARN** | работать можно, часть возможностей отключится — сказано, какая |
| **BLOCKED** | начинать нельзя, это точно сломается |

Запуск при любом BLOCKED останавливается намеренно. `WARN` про `ffmpeg`,
`browser` или `model-endpoint` означает, что соответствующий сценарий честно
получит вердикт **BLOCKED**, а не FAIL: невозможность проверить — не провал
продукта, и записывать её как провал так же нечестно, как записывать как успех.

## Как выносить вердикт

| вердикт | когда |
|---|---|
| **PASS** | сделал по шагам, получил обещанное, улика есть |
| **FAIL** | продукт сделал не то, соврал об успехе, сломался или потерял состояние |
| **BLOCKED** | проверить нельзя: нет ffmpeg, нет браузера, нет модели |
| **SKIPPED** | сознательно пропустил |

Ничего не «подтягивайте». Один честный FAIL сегодня дешевле одной ложной
галочки, дожившей до продакшена.

## Корпус

Идентификаторы совпадают со сценариями в `scripts/evening_acceptance.py` —
`evening_acceptance.py verify` падает, если документ и харнесс разошлись.

### TEST 1 (T01) — Чат и рассуждение
Многошаговая задача, где второй шаг зависит от первого. Проверить: потоковый
вывод идёт по мере генерации; состояние задачи меняется видимо; финальный ответ
связан со всеми шагами. **Улика:** id задачи + скриншот финального состояния.

### TEST 2 (T02) — Веб-исследование
Тема, изменившаяся недавно, — так ответ по памяти модели не пройдёт. Требовать
ссылки, открыть две руками, убедиться, что взаимодействие было реальным (запросы
в трассе, а не только текст модели). **Улика:** ссылки + трасса браузера.

### TEST 3 (T03) — Управление компьютером
Открыть, нажать, напечатать, прочитать состояние. Запрос разрешения обязан
появиться ДО действия, меняющего состояние. **Прервать один раз** и возобновить;
сделанное не должно переигрываться. **Улика:** id задачи + скриншоты до/после.

### TEST 4 (T04) — Задача по коду
Небольшой контролируемый баг: воспроизведение → патч → тест. Тест обязан падать
на старом коде. Патч обязан быть минимальным. **Улика:** diff + вывод теста.

### TEST 5 (T05) — Web Studio
Создать, отредактировать, проверить два вьюпорта, сохранить, переоткрыть,
экспортировать, открыть в браузере. Ни одна кнопка не должна обещать
**публикацию**, если есть только предпросмотр и экспорт. **Улика:** файл + два
скриншота.

### TEST 6 (T06) — Video Studio
Импорт настоящего клипа → обрезка → изменение таймлайна → экспорт. Открыть
результат **независимым** плеером, проверить `ffprobe` (длительность,
разрешение, звук). Отменить один экспорт на середине. **Улика:** путь + вывод
`ffprobe`. *Требует ffmpeg.*

### TEST 7 (T07) — Файл или артефакт
Создать документ, найти на диске, открыть сторонним приложением, сверить с
обещанным. **Улика:** путь + скриншот.

### TEST 8 (T08) — Восстановление
Убить процесс на середине **безопасной** (только чтение или идемпотентной)
задачи, перезапустить, возобновить. Дублирующего эффекта быть не должно,
закрытые шаги не переигрываются. **Улика:** журнал до и после.

### TEST 9 (T09) — Запрещённый эффект
Отказать в разрешении. Финальное состояние задачи **не должно** быть
«завершено»: отказ — это failed или blocked. Текст ответа может сохраниться —
это нормально, истина задачи важнее текста. **Улика:** скриншот состояния.

### TEST 10 (T10) — Телеметрия
`python scripts/evening_acceptance.py report` сам вызовет
`scripts/real_workload_audit.py` по накопленному корпусу. Сверить число записей с
числом реально данных задач. Убедиться, что **провалы и отказы тоже в корпусе**.
При малом числе задач вердикт про железо обязан быть `INSUFFICIENT_EVIDENCE` —
это правильный ответ, а не недоработка. **Улика:** `real_workload_audit.md`.

### TEST 11 (T11) — Параллельность
3–5 безопасных задач одновременно. Смотреть на поведение, а не на факт запуска:
растёт ли задержка плавно, что с памятью, ограничивает ли admission нагрузку,
все ли задачи дошли до терминального состояния. *Не блокирует релиз.*

### TEST 12 (T12) — Обход интерфейса
Открыть каждое приложение. Video Studio — **один**, Web Studio — **один**. Нет
мёртвых ссылок и кнопок без действия. Нет кнопок, показывающих успех, ничего не
сделав. Вёрстка держит длинное сообщение и большой кусок кода. Русский ввод не
искажается. Fleet помечен **ЭКСПЕРИМЕНТАЛЬНЫЙ**. **Улика:** скриншоты.

## Что этот прогон НЕ доказывает

Прямо и заранее, чтобы результат не превратился в маркетинг:

- Один вечер на одной машине — **не** сертификация железа и **не**
  доказательство трёхкратной производительности. Вердикт про железо считается
  по корпусу реальных задач и при малом числе выборок обязан быть
  `INSUFFICIENT_EVIDENCE`.
- Успешный проход Fleet-сценария на одном узле **не** сертифицирует
  распределённый продакшен. Fleet остаётся экспериментальным.
- Отсутствие ffmpeg/браузера даёт **BLOCKED**, а не PASS: непроверенное не
  становится проверенным оттого, что его нельзя было проверить.
- Дескрипторная проверка файлов закрывает подмену файла по имени. Она **не**
  защищает от привилегированной записи в тот же inode на ходу — это ограничение
  ОС, а не недосмотр реализации.

## После прогона

`scripts/evening_acceptance.py report` пишет `EVENING_ACCEPTANCE_RESULT.md`,
`real_workload_audit.md` и `real_workload_audit.json`. Состояние прогона живёт в
`.bossman-state/acceptance/evening_acceptance.json` и не коммитится: это
наблюдения конкретной машины, а не исходники.

`ACCEPTANCE_VERDICT=PASS` возможен только когда записаны все 12 сценариев и ни
один блокирующий не FAIL.
