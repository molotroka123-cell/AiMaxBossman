## 3. Сначала закрой пользовательские дефекты

### Видео

Проверь актуальный результат Editors user safety. Исторический проверенный
run `34078123046`: 1 failed / 4 passed, timeout в play_preview_to_end.
Сними MediaError, currentSrc/stream, MIME/Range, readyState, actual codec
capabilities и трассу рендера. Не объявляй заранее, что причина именно кодеки.

Отдельно исправь разрыв fallback: на рассмотренном коде WebM выбирал ТЕСТ через
API, а настоящая кнопка по-прежнему шла в MP4. Выбор поддерживаемого формата или
понятный fallback должен находиться в продукте. Сервисный тест оставь отдельно.
Приёмочный тест проходит через обычную кнопку и реальный Play: время движется,
ролик заканчивается, затем тот же путь работает после перезапуска процесса.
В evidence назови фактический формат. Нельзя менять assertion на наличие тега
video, делать skip, подавлять ошибку или просто увеличивать timeout.

### OpenRouter

Проверь путь: база не пустая, но OpenRouter отсутствует — есть лишь Ollama или
другой провайдер. Не должно быть fallback на первую чужую строку с последующей
записью в неё ключа OpenRouter. Привяжи UI и backend к канонической identity
провайдера; чужие ключи и endpoint должны оставаться побайтово неизменными.
Тесты: пустая база, только Ollama, другой cloud, смешанная база, двойной Connect,
невалидный ключ, policy deny, сеть, поиск за первой страницей и честные counts.
Используй фиктивные credentials и разрешённые mock transports, не живые ключи.

## 4. Не подменяй сохранение интеллекта prompt-smoke

Текущий рассмотренный runner FULL лишь дописывал названия инструментов и
обращался прямо в Ollama. Прямо пометь этот режим как smoke либо подключи
настоящий production loop с наблюдаемыми вызовами инструментов/контекстного
механизма. Тест должен проваливаться, если FULL снова заменили короткой
строкой tools. Одна модель, одна конфигурация, тот же held-out dataset и
поэлементные парные результаты обязательны.

Сначала исправь метод измерения, затем оцени число вызовов, время и бюджет.
Не запускай многочасовой локальный или платный прогон без действующего
разрешения. Не выдумывай PASS, не копируй фиктивные показатели, не понижай
пороги gate. При нехватке измерений — INSUFFICIENT_EVIDENCE.
Сам факт фиксированного seed не обещает полную детерминированность среды.

Отдельно сверь N4: repo-local rank() не равно работающему scheduler.
Не включай standing autonomy ради демонстрации. Windows owner acceptance,
PRIVATE egress и soak должны оставаться отдельными строками до их реального
выполнения. Данные обучения: только проверенные очищенные трассы через
существующий learning loop; не превращай upstream-инструкции в полномочия.

## 5. Доказательства, интеграция и финал

Каждый фикс: воспроизводимый негативный случай → узкое изменение → позитивный
контроль → соседние regression. Отчёт об «environment-only» сбое требует
сопоставимого прогона чистой базы. Не приписывай checker-тестам пакета свойства
живого приложения, Windows или модели.

Публикуй небольшие проверенные коммиты в своей согласованной рабочей ветке и PR.
После изменения head перечитай фактический checkout CI. Не сертификатируй
новый commit по предыдущему run. Не подставляй head SHA в отчёт после проверки
merge tree. Для benchmark evidence используй artifact, связанный с tested SHA,
чтобы коммит самого отчёта не создавал цикл самоотсылки.

Финальный ответ владельцу — по-русски, без маркетинговых баллов:

```text

ACTUAL_TESTED_SHA_AND_TREE=
REMOTE_REF_VERIFIED=
SKILLS_ADDED=8
SKILL_DISCOVERY=
SKILL_ROUTING_RU=
PACK_INTEGRITY=

OPENROUTER_PROVIDER_ISOLATION=
ROOT_CORE_COMMAND_CENTER=

```

Называй NOT_RUN и ограничения прямо. Не заканчивай одним планом: выполняй
доступные локальные исправления и тесты сейчас. Для заблокированного доступа
укажи ровно требуемое разрешение/среду, не ослабляя критерии результата.
