# Bossman выбирает модель сам: бесплатная локальная / бесплатная Claude / платная Claude — и учится на своих же решениях

**Статус:** проектная спецификация по запросу владельца (2026-09-07). Не реализовано в живых ветках. Ничего здесь не является измеренным результатом.
**Связанные ветки:** `v6/teacher-traces-local-model-learning` (`bcc/v2/teacher_trace.py`, `docs/v6/TEACHER_TRACE_LEARNING.md`) — существующая, но не подключённая к живым веткам реализация журнала «учитель → ученик».

## 1. Что просил владелец (дословно, сжато)

1. Bossman сам понимает, какую модель подключить: бесплатную локальную, бесплатную Claude (подписка/локальный `claude`), или платную Claude (API-кредиты).
2. С этого момента каждая решённая проблема сопровождается записью: сколько контекста и сколько кредитов ушло. Локальная LLM учится на этом и вызывает «правильную» модель.
3. Настроить и проаудировать базу, куда складываются «ум и подсказки» будущих локальных LLM: серьёзный фильтр; писать ход мыслей и Claude, и локальных моделей, чтобы учились в тандеме.
4. Ожидание: «улучшить ум модели минимум на 30 % в среднем».

## 2. Что из этого можно обещать, а что — только измерить

| Пункт | Статус | Почему |
|---|---|---|
| Самовыбор модели | ПРОЕКТИРУЕТСЯ | Роутер `bcc/v2/model_router.py` уже умеет shortlist/route по возможностям и стоимости; не хватает **фактов о стоимости и исходе прошлых решений** как входа. |
| Журнал «контекст + кредиты на проблему» | НАЧАТ (см. `DECISION_COST_LEDGER.md`) | Токены контекста измеримы из счётчика; **кредиты (деньги) агенту не видны** — поле `credits` остаётся `UNAVAILABLE`, пока провайдер не отдаёт цену за запрос (OpenRouter отдаёт `usage`/`cost`; Claude Code — нет). |

## 3. Роутер стоимости: как Bossman будет выбирать модель

Входы для каждого запроса:

- **класс задачи** (`task_class`): chat / code / plan / computer-use / vision / research;
- **обязательный уровень проверки** (есть ли side-effect, нужен ли верификатор);
- **приватность** (`contains_private_data`): документы, чаты, расписки, фото владельца — **никогда не покидают машину** (правило предложено ранее и ждёт подтверждения владельца);
- **история**: для похожих задач (по `task_class` + сигнатуре) — какая модель решила, с каким `verified_outcome`, за сколько токенов/кредитов/секунд;
- **бюджет**: дневной лимит кредитов и текущее потребление (`bossman_shared/fable_budget.py` уже ограничивает платный контур).

Порядок выбора (детерминированный, объяснимый в логе):

1. если `contains_private_data` → только локальные модели; платный/облачный маршрут запрещён политикой, а не «не рекомендован»;
2. если у класса задачи есть ≥ N (предлагается 20) записей, где локальная модель давала `verified_outcome=ok` с долей ≥ 0.8 → локальная;
3. иначе, если задача без side-effect и бесплатная Claude доступна → бесплатная Claude;
4. иначе платная Claude — только в пределах бюджета и только с записью стоимости;
5. любой отказ (лимит, недоступность) → следующий уровень **с записью причины**; «молча упасть» запрещено.

Эскалация «локальная тупит»: таймаут первого полезного токена или два подряд `verified_outcome=fail` от локальной → следующий уровень в той же задаче; запись в журнал с `escalated_from`.

## 4. Схема записи решения (одна строка JSONL на проблему)

```json
{"schema":"bossman.decision_cost.v1","ts":"…","problem_id":"…","task_class":"code",
 "model":{"provider":"claude-code|openrouter|local","name":"…","tier":"free_local|free_claude|paid_claude"},
 "context_tokens_in":0,"tokens_out":0,"credits":null,"credits_status":"MEASURED|UNAVAILABLE",
 "wall_s":0,"verified_outcome":"ok|fail|unverified","escalated_from":null,
 "contains_private_data":false,"source_sha":"…","trace_id":"<teacher_trace id or null>"}
```

Правила честности: отсутствующее значение — `null` + статус, никогда `0`; `verified_outcome=ok` ставится только верификатором/тестом, не самой моделью.

## 5. Тандемное обучение: что пишем, что не пишем

- Пишем: краткое **резюме решения** (что выбрано и почему), события инструментов, наблюдаемый исход, проверку, теги сложности, стоимость. Это уже формат `TeacherTrace` (`decision_summary`, `tool_events`, `outcome`, `verification`).
- **Не пишем скрытую цепочку рассуждений** дословно — так решено в `teacher_trace.py` («compact decision summaries … not hidden chain-of-thought»), и это правильно: дословный поток мыслей несёт секреты и приватные данные, а для обучения нужны решения и проверенные исходы.
- Обе стороны пишут в один журнал: Claude как учитель (`teacher_provider=claude`), локальная модель как ученик (`teacher_provider=local`) — сравнение на одной задаче даёт пары «учитель/ученик», из которых считается разрыв.

## 6. Как измерить «+30 %», а не заявить

1. Зафиксировать набор задач (тот же, что для intelligence-preservation) и `source_sha`.
2. Прогнать локальную модель **до** дообучения: доля `verified_outcome=ok`, токены, время. ≥189 парных выборок на метрику.
3. Дообучить только на экспортированных `reusable=true, contains_private_data=false` записях (`export_training_candidates`).
4. Прогнать **после** на тех же задачах. Прирост — разность долей с доверительным интервалом; отчёт с `evaluated_sha` из прогона.
5. Любой результат ниже порога — честный `NOT_REACHED`, без пересчёта порога.
