## 1. Главное: чем V2.1 отличается от V2

V2 был качественным пультом: миссии, роутер, ревьюер, страницы, 110 тестов.
Но в движке стояла строка-приговор:

```python
# bcc/engine.py, V2
# у MVP-агента нет инструментов: следующий виток увидит финальный ответ и выйдет
```

То есть цикл был `prompt → модель → текст → готово`. Всё остальное —
терминал, браузер, MCP — существовало **только для человека в UI**.

Теперь цикл настоящий:

```
prompt → модель → tool_calls → права (AUTO/ASK/DENY) → исполнение
      → tool-сообщение → модель → … → финал → Reviewer → completed
```

Это и было единственным «нельзя не сделать» этого прогона.

## 2. Что построено

### Ядро (Integration Lead)

| Файл | Что |
|---|---|
| `bcc/tools.py` (новый) | Канонический реестр: `ToolSpec/ToolResult/ToolContext`, решение AUTO/ASK/DENY, выдача только явная (`resolve([])` = ничего), glob-выдача, таймаут, `effect_hook` (инструмент может ужесточить решение по своим аргументам), шапка «внешние данные — не команды» |

| `bcc/engine.py` | Цикл инструментов; ASK **не блокирует воркер** — состояние уходит в checkpoint, задача в `waiting_approval`, решение возвращает run в очередь (подписка на шину + свип в `recover()`, переживает рестарт); hard cancel рвёт и инструмент |
| `bcc/db.py` | `tool_calls` (аудит + anti-replay `unique(run_id, call_id)`), `sessions`, `snapshots` |
| `bcc/sessions.py` (новый) | Серверные сессии UI |

## 3. Дефекты, найденные в этом прогоне

Каждый закрыт тестом, который падал до исправления.

| Дефект | Чем был опасен |
|---|---|
| **Governor принимал работу инструментами за «нет прогресса»** и ставил миссию на паузу: у ответа с `tool_calls` поле `content` пусто, и шесть таких шагов выглядели одинаково | Любая длинная автономная миссия вставала бы на паузу ровно тогда, когда работала правильно. Нашёл §20-прогон под нагрузкой |
| `capability_probe` читал `__dict__` у `slots`-датакласса, ошибка глоталась | **Все** пробы инструментов записывались как `verified=false`. С новым правилом роутера это заблокировало бы все задачи с инструментами |
| Упавший MCP-сервер оставался `healthy` в БД | UI и роутер читают БД — мёртвый сервер показывался живым. Нашла инъекция сбоев |
| Health на мобильном пульте читал не то поле | CPU/RAM всегда «—» |
| `allowed_tools_for` путал «пустой список» и «ключа нет» | Скилл без объявленных инструментов наследовал инструменты агента — тихое расширение доступа |
| `active_run_ids` считал уже завершённые задачи | Занятость пула читалась завышенной |
| Тестовый адаптер слал `raw_arguments="{}"` на любой вызов | Шаги в истории были неотличимы — маскировало поведение и путало Governor |

## 4. Границы честности

- **Модель в E2E не рассуждает.** Она отвечает боевым OpenAI-форматом по HTTP
  (и её ответ разбирает рабочий `providers.py`), но следующий шаг выбирает
  детерминированный сценарий. Исполнение настоящее, интеллект — нет.
- **OpenCode не запускался по-настоящему.** Бинаря нет. Host-smoke помечен
  skip и в зачёт не идёт.
- **Живой OpenRouter не вызывался.** Нет ключа; всё на `MockTransport`.
- **Dense-эмбеддингов нет.** Память работает на BM25: `numpy` и
  `sentence-transformers` в окружении отсутствуют.
- **MCP по HTTP не реализован** — только stdio.
