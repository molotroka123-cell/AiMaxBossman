Вывод: аудио и «картинка с ведущим» генерируются **быстрее реального времени**. Говорящие лица — в ~350 раз медленнее, поэтому часы эфира с полной анимацией на этом ПК невозможны. Лица анимируются выборочно (интро, ключевые моменты), остальное — портреты с лёгкой анимацией.

## Конвейер эпизода (episode)
1. **План** — тема → сегменты (кто говорит, сколько секунд; смена ведущего 7/5/3 с или по репликам).
2. **Сценарий** — модель пишет блоками по 2–3 минуты с памятью предыдущего блока (краткое содержание + последние реплики), чтобы разговор не повторялся.
3. **Проверка текста** — без ссылок и выдуманных фактов о реальных людях; длина под слот.
4. **Голос** — Kokoro, подгонка темпа под слот (до 1,25×, слова не режутся).
5. **Картинка** — сегмент mp4 (фон по очереди, ведущий, титры).
6. **Апгрейд** — когда видеокарта свободна, отдельные сегменты пересобираются с говорящим лицом (S2V) и подменяются в спуле.

## «Бесконечный live» — фундамент
- **Производитель** пишет сегменты в спул `out/live/seg_000001.mp4 …` с запасом ≥ 10 минут вперёд.
- **Вещатель** отдаёт скользящий HLS-плейлист (`live.m3u8`, окно 5 минут): его можно пустить в OBS/RTMP или открыть в браузере.
- **Запас**: если производитель отстаёт (лимит бесплатной модели, сбой), в эфир идёт заставка, эфир не прерывается; отставание пишется в журнал.
- **Каскад моделей** при 429/таймауте переключается на следующую бесплатную, затем на локальную Qwen — текст есть всегда.
- **STOP** — файл `out/live/STOP` или команда из пульта; текущий сегмент доигрывает.
- **Отчёт в пульт** раз в час: сколько минут сгенерировано, запас вперёд, какая модель писала, ошибки.

Ёмкость (по замерам выше): без анимации лиц ПК делает эфир быстрее, чем он звучит; узкое место — лимиты бесплатных моделей. Пара часов подкаста заранее → дальше live держит запас.

## Правила
- Только бесплатные модели; платных в каскаде нет.
- Лица и голоса реальных людей — только с согласия (подтверждено владельцем 16.10 для текущих ведущих); голоса сейчас синтетические Kokoro, не клоны.
- Публикация наружу (YouTube/Twitch) — только по отдельному слову владельца.

## Live: замер (16.10)
`python tools/podcast/podcast.py live --topic "..." [--minutes 0] [--ahead 600]` — производитель (поток) держит
`--ahead` секунд готовых сегментов; вещатель публикует их в скользящий `live/live.m3u8` (HLS, окно `--window`) в темпе
реального времени; пустой запас → заставка «BACK IN A MOMENT», эфир не прерывается; файл `live/STOP` завершает эфир
после текущего сегмента и закрывает плейлист `#EXT-X-ENDLIST`.
Тест 4 мин (`out/live_test2`): 14 сегментов, 122 с эфира, заставка 0 с, ошибок 0, запас на конец 66 с; блоки писали
deepseek-v4.1-flash и nemotron-3.5-super-vl:free (8 реплик ≈ 46–120 с на блок). Первый блок — ожидание до 2 минут
перед эфиром (`--first-wait`).
Стыки: у AAC разгонный кадр −21,3 мс, а видео на ~7 мс длиннее контейнера — без поправки звук и видео шли назад на
каждом стыке (13 предупреждений на 110 с); сдвиг = реальная длина .ts + кадр AAC → 1 предупреждение (8 мс, демуксер HLS
на первом стыке; сами сегменты чистые).
Найдено тестом: новый портрет ведущей 820×970 ломал кадр (scale→899 < crop 900) — теперь масштаб с покрытием;
обрезанный посреди строки JSON бесплатной модели — целые реплики спасаются регуляркой.
