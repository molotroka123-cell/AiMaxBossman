# Bossman 1.8: 14 направлений × 2 open source кандидата

Дата проверки первичных GitHub README и метаданных: 2026-09-26. Статус: **справочник для будущей реализации**, не доказательство готовности 1.8. Основной дизайн: [BOSSMAN_18_EVOLUTION_ENGINE.md](./BOSSMAN_18_EVOLUTION_ENGINE.md). Внедрение разрешено только после реального freeze 1.5–1.7 и `READY_FOR_1_8=YES`.

**Как читать оценки.** `П/С` означает предполагаемую полезность для Bossman / совместимость с **существующей архитектурой как ограниченного адаптера или образца**. `9` означает сильный кандидат на сравнительный прототип, `10` — особенно прямое попадание. Это экспертный отбор по README, интерфейсам и устройству Bossman; **ни одна оценка не утверждает, что проект уже запущен на Windows AI Max+ 395**. Установка, лицензия, реальный расход памяти, точность, безопасность и экономия подтверждаются отдельным owner-machine тестом. У каждой идеи есть две альтернативы; не устанавливать их обе ради галочки.

## Прямые страницы документации: читай только нужную тему

1. Граф/restart: [LangGraph durable execution](https://docs.langchain.com/oss/python/langgraph/durable-execution), [DBOS docs](https://docs.dbos.dev/). Для Bossman нужен контракт существующего task engine, не новый обязательный сервер.
2. Роутер: [LiteLLM proxy docs](https://docs.litellm.ai/docs/simple_proxy) и README RouteLLM выше. Цена и качество подтверждаются текущим Bossman catalog и verifier.
3. Память: [Mem0 open source overview](https://docs.mem0.ai/open-source/overview) и README Graphiti выше. Внешнюю БД считать дополнительной стоимостью, сохранять текущую owner/participant изоляцию.
4. Оптимизация: [GEPA quickstart](https://gepa-ai.github.io/gepa/guides/quickstart/), [DSPy docs](https://dspy.ai/). Ответы holdout не передавать оптимизатору.
5. Computer Use: [UFO docs](https://microsoft.github.io/UFO/), [Browser Use docs](https://docs.browser-use.com/). Не расширять участнику Jeff доступ к PC/browser/tools.
6. Локальные модели: [llama.cpp docs](https://github.com/ggml-org/llama.cpp/tree/master/docs), [Ollama docs](https://docs.ollama.com/). На Windows проверять подписанный/разрешённый executable, память и реальный backend.
7. Видео: README Kadr выше и [MLT docs](https://www.mltframework.org/docs/). Изучать только timeline/экспорт/состояния; не переносить unrestricted eval/file/PTY в Jeff.
8. Общество агентов: [Agents SDK docs](https://openai.github.io/openai-agents-python/), [CAMEL society docs](https://docs.camel-ai.org/key_modules/society). Выбирай из них контракт узких ролей, без второго центра власти.
9. Телеметрия: [GenAI conventions docs](https://github.com/open-telemetry/semantic-conventions/blob/main/docs/README.md), [OpenTelemetry Python instrumentation](https://opentelemetry.io/docs/languages/python/instrumentation/). Сырые личные сообщения не отправлять в общий telemetry sink.
10. Поиск: README Crawl4AI выше, [Crawlee Python introduction](https://crawlee.dev/python/docs/introduction). Читать extraction/лимиты; обход авторизации запрещён.
11. MCP: [Registry docs](https://github.com/modelcontextprotocol/registry/tree/main/docs) и README reference servers выше. Reference servers прямо предупреждают, что примеры не являются готовым production решением.
12. Replay: [pytest docs](https://docs.pytest.org/en/stable/), [VCR.py docs](https://vcrpy.readthedocs.io/en/latest/). Кассеты очищать от токенов и личных данных.
13. Эксперименты: [Ax docs](https://ax.dev/), [Optuna docs](https://optuna.readthedocs.io/en/stable/). Не подменять воронку бизнес-показателем из модели.
14. UI: оба GitHub README выше; связывать анимации только с уже существующими backend events.

## Договор для Claude-кодера: экономия токенов и рабочий результат

1. Сначала прочитай [owner workbench](../owner/WORKBENCH_20260926.md), основной документ 1.8 и **только строку выбранной идеи** здесь. Получи актуальный remote SHA: workbench и оценки привязаны к прошлому состоянию. Пока нет `READY_FOR_1_8=YES`, выполняй только документационный/read-only анализ.
2. На одну задачу прочитай два указанных README и по одному нужному разделу docs на кандидат. Не загружай оба репозитория целиком в модель. Локально найди место в Bossman через `rg`; передавай кодеру только интерфейс, ~50–100 релевантных строк, тест и конкретный failure. Оставь краткий decision record: SHA upstream, license, API/формат, тест для Bossman, отклонённый кандидат и причина.
3. Выбери **одного** кандидата через микробенчмарк в отдельной ветке. Два кандидата в таблице означают конкуренцию, а не две установки. Модель для массового написания кода: проверенный local/free маршрут через Bossman; платный Claude только для точного блокера с общим budget ledger. Не заменяй существующие Bossman task engine, memory, Jev, Studio, authority или telemetry вторым стеком.
4. Каждый реальный патч: исходный сбой → минимальная правка → адресный тест → independent effect check → owner Windows smoke → стоимость/память/latency до и после → rollback. Сохраняй exact-SHA evidence. Новая технология получает оценку `OWNER_HARDWARE=PASS` только после запуска на Ryzen AI Max+ 395/Windows.
5. Для проектов с GitHub license `NOASSERTION` (в частности LiteLLM и MCP Registry/reference servers) обязательно прочитай LICENSE конкретного commit/пакета. До проверки лицензии и условий не копируй исходники. Kadr — GPL-3.0; держи его внешним процессом/адаптером и проверь условия распространения до любого включения в продукт.
6. Для любых новых инструментов: default-deny, разрешённые data roots, budgets, одноразовые owner approvals и STOP. Нельзя выдавать PASS по mock, preview или README. Нельзя обещать 9/10 runtime совместимости только потому, что таблица оценила архитектурный fit.

### Почему некоторые идеи базового документа здесь пока без пары 9/10

Streaming Giant (`FareedKhan-dev/kimi-k3-in-c`), NPU (`ROCm/FastFlowLM`), Qwen Windows/MTP (`olliehm/qwen-flash-next-windows`), External Gym (`harbor-framework/harbor`) и Distillation Foundry остаются в основном дизайне. Для них не подтверждены **две** взаимозаменяемые реализации с измеренной совместимостью на Windows AI Max. Считать их исследовательскими; после 1.5–1.7 freeze проводить отдельный owner-machine benchmark и только тогда дополнять эту матрицу. Не выдумывать второй проект или оценку 9/10 ради заполнения таблицы.
