# Bossman Chat UX — файл обучения для агента (Фаза 5 мастер-промта)

Кто читает: агент P5a из `docs/owner/MASTER_PROMPT_FINAL_ACCEPTANCE_AND_UX_20260927.md`.
Когда: только в ветке `feat/bossman-1.8-jeff-voice-chat-ux`, после `FREEZE_1_5_1_7=PASS`.
Задача: перенести утверждённый прототип в настоящий Command Center, подключив его к
**существующему** backend, и доказать тестами, что ничего не сломано.

Эталон: `docs/ux/prototype/bossman-chat.html` (открыть в браузере; опубликован владельцу как
Artifact «Bossman Chat»). Прототип — это образец вида и поведения, **не** код для копирования
в продукт: данные в нём выдуманы, backend не подключён.

---

## 1. Что меняется и что нет

Меняется: представление — главный экран становится одним разговором.
Не меняется: API, права, approvals, STOP, роутинг моделей, приватность памяти, Telegram, Jeff-изоляция.
Если для экрана не хватает данных из API — это вопрос владельцу, а не повод расширить backend
«заодно». Новые эндпоинты — только отдельным согласованным пунктом.

## 2. Информационная архитектура

**Сайдбар (постоянно):** «Новый чат», поиск, история разговоров по группам (Сегодня / Вчера / Раньше),
внизу «Инструменты», «Настройки», карточка компьютера (чип, «локально/облако», свободная память).
Больше ничего постоянного в сайдбаре нет.

**Каталог «Инструменты»** (лист поверх экрана, группы). Текущие страницы `command-center/ui/pages/`:

| Группа | Страницы (id) |
|---|---|
| Создание | `images` (Студия), `video-studio`, `music_studio`, `web_designer` |
| Работа | `coding`, `terminal`, `browser`, `web_research`, `file-intelligence`, `apps`, `missions`, `builder`, `objectives` |
| Bossman | approvals («Ждут решения»), `skills`, `openrouter`, `router`, `resources`, Telegram-настройки, `agentmap`, `orchestras` |

## 3. Экран разговора

**Шапка:** название разговора; пилюля маршрута «● Локально · <модель> · 0 ₽» (зелёная точка — локально,
жёлтая — облако). Клик → выбор: Локально / Облако (бесплатно) / Авто. Источник — `/api/models`,
`/api/providers`, `/api/free-providers`, предпросмотр маршрута — `POST /api/tasks/preflight`
(ничего не пишет). Подпись под облачным вариантом: «личная память не отправляется» — это правда,
только если `memory_to_cloud` для задачи выключен; иначе писать фактическое состояние.

**Лента** (ширина текста ≤ 740px). Типы сообщений и откуда данные:

| Тип | Вид | Данные |
|---|---|---|
| Сообщение владельца | пузырь справа, вложения над текстом | создание задачи `POST /api/tasks` |
| Ответ Bossman | текст слева с аватаром «B» | результат задачи/рана |
| Ход работы | сворачиваемый блок «Bossman работает…» → «Готово за N с», шаги с галочками и временем | `GET /api/runs/{id}/events`, живые события `WS /api/events` |
| Одобрение | карточка: заголовок, чип риска, «Где / Что изменится / Инструмент», кнопки [Разрешить] [Отклонить] | `GET /api/approvals`, решение `POST /api/approvals/{id}` `{approve, by:'ui'}` |
| Решённое одобрение | «Разрешено» / «Отклонено» + фактический результат | то же, после события |
| Голосовое Jeff | плеер (кнопка, волна, длительность), чип фона, «Показать текст» | голосовой пайплайн 1.8 |
| Профиль голоса | полоса выбранных фрагментов, модель, «где хранится», [Послушать] [Удалить] | голосовой пайплайн 1.8 |
| Остановка | красная строка «■ Остановлено по вашей команде…» | событие STOP |
| Ошибка | человеческий текст + одно действие («Повторить» / «Что сделать») | ошибка задачи |

Правило карточки одобрения: одна карточка = одно approval = одно действие. Кнопки блокируются сразу
после клика до ответа сервера (без двойной отправки). Карточка показывает то, что backend реально
выполнит, а не пересказ модели.

**Ход работы** показывает только реальные шаги из событий. Никакой декоративной «думающей» анимации
без данных. По умолчанию свёрнут после завершения, развёрнут во время работы.

## 4. Composer

Поле ввода (Enter — отправить, Shift+Enter — новая строка), 📎 вложения, 🎤 голосовое, выбор агента
(Bossman — действия на компьютере / Jeff — общение, без доступа к компьютеру), кнопка отправки.
**Пока идёт работа, кнопка отправки становится красной «Стоп»** и вызывает существующий
owner STOP: `POST /api/tasks/{id}/<stop-action>` для текущей задачи и `POST /api/control-plane/stop-all`
для «остановить всё» (точное имя действия взять из `api.taskAction` / backend, не придумывать).

Меню вложений: «Файл», «Голос для обучения (MP3, WAV или видео — звук извлечём сами)», «Фото».
Загрузка MP3/MP4 для голоса ведёт в поток профиля голоса из `docs/v1.5/VOICE_AND_PHONE.md` §2a.

тёмные — в `@media (prefers-color-scheme: dark)` с `:root:not([data-theme="light"])` и в `:root[data-theme="dark"]`.

## 6. Как не выглядеть «AI-generated»

Запрещено: неон, градиенты, свечения, «космос», стекло, слова «2030», «AI Core», «Neural»;
эмодзи вместо иконок; сетки больших цифр на главном экране; одинаковые скруглённые карточки
на всём подряд; всё по центру.
Нужно: одна колонка текста, спокойная типографика, один акцент, семантические цвета только
для смысла (ок / внимание / стоп), иконки тонкой линией одного веса, живой русский текст.

Тексты: говорить как человек, от лица владельца. «Разрешить», а не «Approve». «Ждут решения»,
а не «Pending approvals». Статусы — через существующий `statusText` из `pages/_ui.js`.
Ошибка = что случилось + что сделать, без извинений.

## 7. Мобильная версия (390px)

Тот же чат на весь экран; сайдбар — выезжающая панель по кнопке ☰ с затемнением; пилюля маршрута
укорачивается; composer прижат к низу с учётом safe-area; зоны нажатия ≥ 44px.

## 8. План реализации

1. Новый модуль `command-center/ui/chat/` (разметка, стили на токенах, рендер сообщений) и
   маршрут по умолчанию → чат. Старые страницы — через каталог.
2. Подключить: создание задачи, события рана по WebSocket, approvals, STOP, выбор агента/модели.
3. Каталог «Инструменты» и «Настройки» как листы; ссылки на существующие страницы.
4. Голосовые элементы (плеер, профиль) — когда готов пайплайн 1.8; до этого не показывать.
5. Удаление старой главной и лишних стилей (`console2030.css` и т. п.) — только в самом конце,
   отдельным коммитом, после зелёных тестов.

Файлы, которыми владеет агент UX: `command-center/ui/**` и `command-center/tests/test_chat_ui*.py`.
Backend (`command-center/bcc/**`) не трогать без отдельного согласования.

## 9. Тесты (обязательно, в настоящем Chromium, 1440px и 390px)

Новые, в `command-center/tests/test_chat_ui_*.py`:
- чат — экран по умолчанию; 0 ошибок в консоли;
- отправка сообщения создаёт задачу; ход работы показывает реальные события;
- карточка одобрения: «Разрешить» выполняет действие ровно один раз; «Отклонить» — ни разу;
  повторный клик ничего не отправляет;
- во время работы видна «Стоп»; нажатие реально останавливает (задача остановлена, дальнейшие
  действия отклоняются) — **негативный контроль**: без нажатия задача доходит до конца;
- Jeff выбран → действия на компьютере недоступны (запрос отклоняется backend'ом, UI это показывает);
- каталог открывает каждую страницу из таблицы §2 без ошибок;
- светлая, тёмная и системная тема читаемы; мобильная ширина без горизонтальной прокрутки.

Существующие UI-тесты (`test_ux2_*`, `test_editors_user_acceptance.py`, `test_*_ui.py` и др.) должны
остаться зелёными **без ослабления**. Если тест проверяет старую главную, его заменяет эквивалентный
тест на чат — с той же силой проверки, и это указывается в коммите.

## 10. Библиотека UX-промтов

Это те самые «промт-библиотеки» для генерации вариантов интерфейса. Пользоваться так: сгенерировать
2–3 варианта отдельного экрана, показать владельцу, взять выбранный, перенести на токены §5.

**Базовый стиль (добавлять к любому):**
> Интерфейс в духе ChatGPT и Claude: одна колонка разговора до 740px, сайдбар с историей чатов,
> composer снизу со скрепкой, микрофоном, выбором агента и кнопкой отправки, которая становится
> красной «Стоп» во время работы. Нейтральная графитовая палитра, один стальной синий акцент,
> шрифт Onest, моноширинный IBM Plex Mono для технических деталей. Без градиентов, неона, стекла
> и эмодзи. Русский язык, живые формулировки.

**Варианты экранов:**
1. «Пустой новый чат»: > Экран нового чата Bossman: крупный вопрос «Чем займёмся?», под ним 3–4
   подсказки-действия из реальных задач владельца (сохранить отчёт, собрать игру, ответить голосом,
   разобрать голосовое). Composer по центру по вертикали до первого сообщения.
2. «Одобрение»: > Карточка одобрения действия на компьютере внутри ленты чата: что будет сделано,
   где, что изменится, чип риска, две кнопки. Три состояния: ждёт / разрешено с фактическим
   результатом / отклонено.
3. «Ход работы»: > Сворачиваемый блок хода выполнения задачи как «Thinking» у Claude: во время
   работы — спиннер и список шагов с галочками и временем, после — одна строка «Готово за 12 с».
4. «Голосовое Jeff»: > Голосовое сообщение в чате: круглая кнопка воспроизведения, волна,
   длительность, чип фонового эффекта, ссылка «Показать текст». Вариант для входящего голосового
   собеседника с расшифровкой и пометкой «распознано на этом компьютере».
5. «Профиль голоса»: > Карточка готового профиля голоса: полоса 15-минутной записи с выделенными
   выбранными фрагментами, модель, где хранится, кнопки «Послушать пример» и «Удалить профиль».
   Плюс экран прогресса загрузки MP3/MP4 по стадиям.
6. «Каталог инструментов»: > Лист «Инструменты» поверх чата: группы Создание / Работа / Bossman /
   Лаборатория, карточки с названием и одной строкой описания, поиск сверху.
7. «Мобильная версия»: > Тот же чат на 390px: ☰ открывает историю, пилюля маршрута укорочена,
   composer прижат к низу с safe-area.

**Аудит варианта (для P5b):**
> Посмотри на экран глазами владельца-непрограммиста. Перечисли всё, что выглядит как типовой
> AI-сгенерированный дизайн (градиенты, неон, лишние бейджи, жаргон, декоративная анимация без данных),
> и всё, где непонятно, что нажать дальше. Для каждого — конкретная правка.
