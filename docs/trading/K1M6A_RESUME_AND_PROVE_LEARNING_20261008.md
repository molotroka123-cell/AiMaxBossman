## 4. Контроль качества данных

Сохранять raw extraction отдельно от corrections. У каждой записи: video_id, timestamp, source_kind (ASR/VTT/pixels), confidence, quote/reference span, наблюдение/интерпретация/условное правило/датированный прогноз, версия и статус.
Не путать OHLC open с current marker; проверить тикер, таймфрейм, часовой пояс, единицы CVD/OI, момент и источник измерения.
Нечитаемые цифры = UNKNOWN. Не реконструировать значения из ожиданий модели. Проверять ASR-термины SFP, CVD, OI, value, single prints и ошибочные фразы вроде «Bugatti money».
Убирать дубли, приветствия, рекламные вставки; личные взгляды автора и прогнозы событий не превращать в универсальные правила. Спорные тезисы сверять с соседними кадрами и аудио.
Проверить ВСЕ числовые поля выбранных учебных/экзаменационных кадров, а не только удобную выборку. Зафиксировать misread/unknown rates. Перед обучением критические поля размеченных примеров должны совпасть с независимой разметкой; неоднозначные примеры исключить с причиной.

На размеченных скриншотах оценивать:

- соответствие будущему комментарию автора, с допустимыми альтернативами;
- отсутствие выдуманных цифр, цитат и уверенности;

Не требовать дословного угадывания или гарантированного направления цены.

## 6. Эксперимент до/после без утечки

ДО обучения закрепить модель, quantization, prompt, runtime, seed где поддержан, retrieval policy и версии. Снять baseline без новых уроков.
Десять видео распределить заранее по целым роликам: 6 train / 2 validation / 2 locked test. Разделение хронологическое при доступности дат; соседние кадры одной ситуации остаются в одном split. Аудитор проверяет все десять, но ответы locked test никогда не попадают ученику.
Объяснения будущего фрагмента, субтитры после контрольного момента, последующие цены и reference answers скрыты до оценки. Не допускать future leakage в memory/search.
Если ролики/ответы уже были в памяти, это contaminated split: заменить примеры; если невозможно — честно ограничить вывод.

Фиксировать минимум 30 разных ситуаций, из них минимум 10 в locked test; если материал этого не даёт, EXAM_INSUFFICIENT. Рубрика 0–2 по пяти измерениям из раздела 5, итог 0–10; независимая оценка с обоснованием. Не менять рубрику после результатов.

Три режима на одинаковом frozen test:
1. BASELINE — без новых уроков;
2. LESSONS — проверенные уроки доступны через штатный retrieval;
3. RESTART_TRANSFER — после перезапуска, новые невиденные ситуации, без подсказок Claude.
Режим без retrieval — отдельная проверка; улучшение только с памятью означает workflow/retrieval learning, не изменение весов.
Fine-tune не обязателен. Сначала доказать качество данных и пользу памяти; тренинг весов/новые зависимости/RunPod требуют отдельного плана ресурсов и разрешения.

## 7. Учим, корректируем, удерживаем опыт

На train: Bossman отвечает → аудитор отмечает ошибки → ученик сам формулирует исправленный условный урок → проверка на другом train-примере → запись в существующее хранилище с provenance.
Урок содержит WHEN / OBSERVE / CONFIRM / INVALIDATE / UNKNOWN / COUNTEREXAMPLE, не голую команду «покупать».
Validation разрешает корректировки; locked test используется только для итоговой оценки. При провале не править ответ и не пересдавать тот же test как независимый.
Датированные уровни держать в архиве кейсов, не в активных торговых правилах. Не раздувать контекст: дедупликация, компактные уроки, retrieval top-k, сохранять ссылку на полную запись.

## 8. Критерии доказательства и границы автономности

Рабочие пороги эксперимента закрепить ДО baseline:
- matched-fields accuracy >=95% по читаемым полям; coverage/UNKNOWN публиковать отдельно;
- средняя locked-test оценка >=8/10;
- улучшение минимум +1 балл из 10 против baseline; показать каждую пару, разброс и размер выборки;
- ноль критических выдуманных цен/будущих данных/ложных цитат;
- после restart средняя оценка не ниже 8/10, падение не более 0.5 балла.
Это продуктовые критерии пилота, не статистическое доказательство прибыльности. При малой выборке — preliminary gain, не универсальная способность.
Если baseline уже высокий, не выдумывать улучшение; сообщить NO_MEASURED_GAIN.

Для «без надзирателя» отдельно выполнить двухчасовой batch на новых материалах без teacher hints: автономное завершение, timeout/retry/STOP, сохранение и проверка результатов, корректный UNKNOWN. Статус UNSUPERVISED_WORKFLOW_PASS относится только к ограниченному обработчику и оценённым задачам, не к автономной торговле.
Полный день оставить журнал ошибок/ресурсов; DAY_RUN_PASS только по реально отработанному времени. Модель должна уметь признать недостаток данных, а не обязательно отвечать.
