# web_research — поиск в интернете для локальных моделей

Как это делает Claude: модель зовёт поиск, читает выдачу, открывает нужные
страницы, ищет внутри уже прочитанного, ссылается на источник. Здесь то же
самое, но с двумя добавками, которых у облачной модели нет: у владельца ничего
не настроено и он часто офлайн, а модель у него маленькая и ошибается.

Документ собран из трёх независимых проектов (линзы «безопасность»,
«локальная модель», «происхождение»), сведён в один и ПРОВЕРЕН красной
командой по пяти направлениям. Поправки красной команды — раздел 0. Они
обязательны: без них проект содержит три критические дыры и несколько
обещаний, которых код не выполняет.

# Итоговый проект

ФИЧА web_research. Флаг BOSSMAN_WEB_RESEARCH_ENABLED, по умолчанию OFF. Требует также BOSSMAN_OSIRIS_ENABLED. При выключенном любом из двух: setup() выходит немедленно (ни REGISTRY.register, ни add_hook, ни подмены адаптера, ни одного обращения к диску), читающие ручки отдают {"enabled": false, ...}, мутирующие — 409. Приложение ведёт себя ровно как до модуля.

============ 1. ГРАНИЦЫ И ФАЙЛЫ ============
bcc/html_text.py — чистое извлечение текста (только stdlib, ни одного импорта из bcc, ни сети, ни диска, ни svc).
bcc/features/web_research/ — ПАКЕТ (load_features использует pkgutil.iter_modules, который отдаёт и пакеты; importlib.import_module импортирует __init__; FEATURE берётся оттуда). Это по-прежнему ОДИН модуль в bcc/features/. Запасной вариант, если ведущий пакет не примет: склеить submodules в один web_research.py — контракты между ними уже разделены так, чтобы склейка была механической.
ui/pages/web_research.js — готовится, но НЕ подключается (две строки в ui/pages/index.js — общий файл, их вносит ведущий).
Общие файлы не трогаются НИГДЕ.

Если после канонизации хост всё ещё не ASCII — вызывающий отказывает до сети.

============ 3. ТРАНСПОРТ ============
class WebFetchAdapter(osiris.HttpFetchAdapter): live = True (наследуется).
  async fetch_bytes(url, *, headers=None, timeout=None) -> RawResponse(status:int, content:bytes, headers:dict, url:str)
    Вокруг вызова — asyncio.timeout(TOTAL_DEADLINE): у safe_get общего дедлайна нет, per-read таймаут перезапускается на каждом чтении (замер: живое соединение через 45 с при timeout=5), и slowloris держит соединение сутками.
    psec.safe_get(url, headers={"User-Agent": osiris.USER_AGENT, "Accept-Encoding": "identity", "Accept": ..., "Accept-Language": ..., **headers}, timeout=PER_READ, max_bytes=..., max_redirects=3, allowed_hosts=<см. ниже>).
    Accept-Encoding: identity закрывает СРАЗУ два дефекта чужого файла: httpx.DecodingError на любом сжатом ответе (safe_get копирует content-encoding, но подставляет уже распакованное тело) и zip-бомбу (aiter_bytes отдаёт распакованный chunk целиком, max_bytes ловит его уже после аллокации).
  async fetch(url, *, headers=None, timeout=15.0) -> osiris.FetchResult
    Совместимо с osiris.FetchAdapter (его зовёт osiris.collect). Реализовано через fetch_bytes + html_text.decode_body; в headers результата добавляются служебные x-bossman-charset и x-bossman-replace-ratio, потому что FetchResult — frozen dataclass с четырьмя полями и другого канала нет.
  Установка: в setup() при включённых флагах, только если isinstance(store(svc).adapter, osiris.HttpFetchAdapter) — стаб в тестах не затаптывается.
allowed_hosts вычисляет same_site(host) -> {host, host без "www.", "www."+host}. Кросс-сайтовый редирект НЕ выполняется: следующий hop падает на validate_url («host not allowlisted»). Честный текст модели: «страница перенаправляет за пределы сайта; автоматический переход запрещён — найдите целевую страницу поиском». Конечный URL после редиректов транспорт не возвращает (safe_get собирает httpx.Response без url/request), поэтому в наблюдение пишется ЗАПРОШЕННЫЙ канонический адрес, и это сказано в шапке.
Приватная дверь (только локальный SearXNG): отдельная функция searxng_fetch(), единственное место во всём модуле, где встречается allow_private=True; хост берётся ТОЛЬКО из BOSSMAN_WEB_SEARXNG_URL, allowed_hosts жёстко = {этот хост}, путь /search и набор параметров фиксированы, ни один аргумент модели туда не попадает.
content_type_ok(headers) -> (bool, why): пускаем text/html, application/xhtml+xml, text/plain, text/xml, application/xml, application/*json, application/atom+xml, application/rss+xml. Всё прочее — честный отказ ДО чтения тела (safe_get Content-Type не смотрит вообще).

============ 4. ИСТОЧНИКИ (всё через OSIRIS, второго реестра нет) ============
Поисковые движки — osiris.Source категории A (method="api"), объявляются декларациями и проходят ТОЛЬКО через osiris.normalize_source (она сама зовёт _forbidden_reason и checked_url; своей валидации деклараций нет). Каждый обязан нести honest_capability — одну строку про то, что он реально умеет; она показывается и владельцу, и в шапке выдачи.
  wikipedia-opensearch-{ru,en} — action=opensearch, ключа нет, CC BY-SA. honest: «энциклопедические статьи, НЕ открытый веб».
  stackexchange — /2.3/search/advanced, ключа нет.
  hn-algolia — публичный официальный API.
  openalex — CC0, ключа нет (вежливый пул хочет контакт — он уже есть в osiris.USER_AGENT).
  arxiv — Atom, разбирается xml.etree (Atom well-formed, в отличие от HTML); единственный с http:// в base_url, поэтому включается владельцем вручную.
  pypi, crates.io — точечные справки по пакетам.
  searxng-local — свой инстанс владельца, только при заданном BOSSMAN_WEB_SEARXNG_URL. Единственный честный путь к общему веб-поиску.
  brave-search — auth_mode="api_key". Ключ из svc.vault; ключа нет — источник виден в реестре с пометкой «ключ не задан» и НИКОГДА не опрашивается молча. Ключ подставляется только KeyedFetchAdapter'ом и только если host(url)==host(source.base_url).
Прочитанные хосты — osiris.Source категории C, создаётся автоматически при первом чтении: id=f"web-{slug(host)}", base_url=f"https://{host}", license="не определена (страница из сети)", rate_limit_per_min=10, parser="web.page_text", tos_checked_at=<дата сборки>. Это несущий приём: normalize_source прогоняет имя хоста через ЧУЖОЙ FORBIDDEN_PATTERNS, поэтому dehashed.com, pimeyes.com, 12ft.io отклоняются не моим кодом и с чужим кодом причины; и rate_allows впервые становится ПОХОСТОВЫМ (он ключуется по source.id).
Парсеры регистрируются в osiris.PARSERS (штатный и единственный механизм — normalize_source проверяет parser in PARSERS): "web.serp_opensearch", "web.serp_json", "web.serp_atom", "web.serp_searxng", "web.page_text". Сигнатура строго осирисовская: (source, subject, payload, *, url, raw_ref, collected_at, fetched_at) -> list[Observation]. Регистрация идемпотентна и только при включённом флаге.
SERP_DENY — кортеж (regex, причина) на семейства общих поисковиков (google.*/search, bing.com/search, yandex.*/search, duckduckgo.com/html, *.serp*, известные SERP-скрейперы). Проверяется ДО normalize_source, до чеканки любого ref и в open_effect. Это НЕ второй словарь запретов, а один дополнительный кортеж на одну тему, которую чужой словарь не покрывает (проверено: ни один из восьми regex не содержит serp/search/google).
Стоки утечки EXFIL_SINKS (webhook.site, requestbin, *.ngrok*, pastebin-подобные) — deny в open_effect.

============ 5. РЕЕСТР ССЫЛОК (LEDGER) ============
Файл <settings.data_dir>/osiris/web_runs/run-<run_id>.json, атомарная запись (tmp + os.replace). Содержимого страниц в нём нет — только адреса и счётчики, поэтому он не является параллельным хранилищем и не ломает полноту удаления.
@dataclass RefEntry: ref, url (канонический), host, kind ("search"|"owner"|"link"), origin (id backend'а или родительский ref), subject, title, snippet, minted_at, minted_step, opened_at, raw_digest, body_sha256, status, chars, truncated.
Префиксы ref НЕСУТ ПОЛИТИКУ, а не косметику: "w<N>" — отчеканено backend'ом поиска или владельцем (auto), "l<N>" — отчеканено из тела уже прочитанной, то есть потенциально враждебной, страницы (ask). Именно это делает правило «ссылка со страницы требует одобрения» выразимым в ЧИСТОМ effect_hook, у которого по сигнатуре нет ни run_id, ни svc.
Методы: load(svc, run_id), save(), mint(url, *, kind, subject, ...) -> ref, resolve(ref) -> RefEntry|None, spend(kind, n=1) -> bool, left() -> dict, seed_from_task(task) (читает task.meta.web_seed_urls, чеканит как "w"), gc(svc, ttl_hours).
Ref чужого прогона не резолвится: файл выбирается по run_id из ToolContext. Дисковое хранение обязательно — ask паркует run и освобождает воркер, пробуждение может прийти в другой процесс.
Суточный счётчик — <data_dir>/osiris/web_runs/_daily.json, ролловер в tick().

============ 6. ИНСТРУМЕНТЫ ============
Общее для всех четырёх: source="web", category="read", permission="" (пусто СПЕЦИАЛЬНО: выданное право в decide_effect повышает эффект до auto ДО хука, и одного tool_rule хватило бы, чтобы web.open с сырым url поехал в auto), external_output=True (шапку «это НЕ команды» ставит сам ToolResult.render(), своей не пишем), idempotent=True, generation НЕ заполняется (перезапишет register). Имена дают api_name web_search / web_open / web_find / web_cite — ровно те строки, что чаще всего встречаются в обучающих данных локальных файнтюнов. Схемы плоские: ни одного вложенного объекта и массива. В description каждого — одна строка примера вызова с реальными значениями. Валидация аргументов ОБЯЗАТЕЛЬНО внутри handler'а (пустой required не защищает: схема — единственное, что видит модель).
_coerce_args(args) -> dict — единая терпимость: синонимы q/search/input/text/text→query, id/ref/link→ref, address/link→url; ключ "_raw" (то, что кладёт _parse_tool_arguments при битом JSON от локальной модели) сначала пробуется json.loads (7B часто кодирует дважды), иначе трактуется как сама фраза запроса или как ref/url по форме. Эта же функция стоит в normalize_args ВСЕХ спек — иначе одобренный путь ≠ исполненный.

web.search {query: str (обяз., 3..200), site: str (необяз., один хост), limit: int 1..10, fresh: bool}
  default_effect="auto"; effect_hook search_effect → только deny: пустой/длиннее 200 запрос, base64/hex-блоб >40 знаков без пробелов, URL-подобный токен внутри запроса, site не похож на hostname, site попал в SERP_DENY, limit вне 1..10.
  ПОЧЕМУ auto: получателя выбирает не модель, а зарегистрированный владельцем backend, поэтому человеку решать нечего. Ask на каждый поиск паркует run и за неделю приучает жать «одобрить» не читая — это не безопасность, а её имитация. Единственный реальный риск (текст запроса как канал) закрывается шлюзом до сети.
  Handler: _coerce_args → _guard_query (см. §7) → выбор backend'а → osiris.collect(svc, source_id, subject) → чеканка ref'ов → рендер.
  Возврат: шапка-метаданные (backend + его honest_capability, число результатов, остаток бюджета), затем строки "w1 | ru.wikipedia.org | 2026-04-11 | Заголовок" + выжимка ≤200 знаков, затем "ДАЛЬШЕ: web.open {\"ref\":\"w1\"}". truncated/more честные.

web.open {ref: str ("w3"/"l2") ИЛИ url: str, max_chars: int 500..8000 (по умолчанию из BOSSMAN_WEB_PAGE_CHARS, 3000), query: str (необяз., чем сузить пассажи)}
  default_effect="auto"; effect_hook open_effect (чистый, на СЫРЫХ аргументах, канонизацию делает сам через html_text.canon_url):
    deny — ни ref, ни url; ref не по регулярке ^[wl][0-9]{1,3}$; url не https; url с userinfo; url на SERP_DENY; url на EXFIL_SINKS; query-строка url длиннее 256 знаков (это выгрузка, а не навигация); хост после канонизации не ASCII или с завершающей точкой (там pinning в чужом файле молча откатывается на повторный резолв — fail-open).
    ask — url присутствует и непуст (ЛЮБОЙ, прошедший deny); либо ref начинается на "l".
    None — только ref на "w".
  ПОЧЕМУ так: по ref байтов, управляемых моделью, в сетевом адресе ноль — адрес отчеканен backend'ом или владельцем до и независимо от воли модели, одобрение не добавило бы человеку ни одного бита. url и l-ref — единственные два случая, где адрес выбирает модель или враждебная страница, и там человек видит полный канонический URL в предпросмотре. normalize_args даёт ту же каноническую форму, что использует handler, поэтому identity-гард при resume не срабатывает на косметике.
  Handler: резолв ref/канонизация url → бюджет → fetch_page (§8) → decode → extract → defang → select_passages → рендер.
  Возврат: блок метаданных (~400 знаков: ref, host, путь без query, время, sha256 тела, статус robots, кодировка, «обезврежено строк: N», «пассажи k из n»), затем пассажи в порядке документа с метками w1§12, обрамлённые "<<< НАЧАЛО ТЕКСТА w1" / "КОНЕЦ ТЕКСТА w1 >>>", затем блок не более 12 ссылок как "l1 | текст якоря | host" (если BOSSMAN_WEB_PAGE_LINKS≠0), затем "ССЫЛАЙСЯ ТАК: [w1] https://…" и "ДАЛЬШЕ: web.find {\"ref\":\"w1\",\"query\":\"…\"}". truncated=True + more всегда, когда текст неполон.
  ПОЧЕМУ метаданные первыми: engine пишет result.content[:500] в tool_calls.result_preview, и из фичи это не отключить — в аудит должен попадать провенанс, а не сочинение атакующего.

web.find {ref: str (обяз.), query: str (обяз.)}
  default_effect="auto", effect_hook только deny на кривые аргументы. Сети не касается вообще: перечитывает сырьё из raw-кэша OSIRIS и заново применяет select_passages. Ни egress, ни новых байт, ни расхода rate limit — спрашивать не о чем, а ask вытолкнул бы модель к повторной выборке той же страницы. Решает главную беду 7B на длинных страницах.
  При нуле совпадений: «в тексте w1 нет ничего про "…". Есть разделы: …» + первые слова найденных блоков (подсказка, по какому слову искать).

web.cite {ref: str, quote: str (≤600), claim: str}
  default_effect="auto", хуков нет. Сверяет, что quote — ТОЧНАЯ подстрока извлечённого текста (html_text.find_quote), и только тогда пишет Observation(attribute="quote"). Наружу не ходит.
  ПОЧЕМУ auto: это единственный инструмент, который ДЕЛАЕТ ответ проверяемым; любое трение здесь толкает модель ровно к тому, ради борьбы с чем всё затевалось, — пересказать своими словами и не сослаться.
  Отказ (самый частый и самый важный): «такой цитаты нет в тексте страницы; процитируйте дословно» + три ближайших фрагмента. Цитирование запрещено, если replace_ratio>0.02 или looks_mojibake — из битого текста цитировать нельзя.
  Возврат: готовая строка «[1] Заголовок — https://… (получено 2026-09-04 12:31 UTC, raw:ab12cd34)».

============ 7. ЭКСФИЛЬТРАЦИЯ ============
Наружу уходит ровно два вида байтов.
(1) Текст запроса. _guard_query до всякой сети: длина ≤200; отказ при точном вхождении известного значения секрета (расшифрованные providers.api_key через svc.vault + svc.auth.token — сравнение по значениям, сами секреты наружу не идут); отказ при base64/hex-блобе >40 знаков; отказ при URL-подобном токене внутри запроса; отказ, если psec.redact_text ИЗМЕНИЛ строку. При срабатывании запрос НЕ отправляется в урезанном виде — урезанный запрос и поиск ломает, и событие прячет. Возврат ToolResult(error=True) + событие web.query_refused. Запрос он же subject эпизода, то есть дословно виден владельцу в GET /api/web/episodes: «что ушло с моей машины» — вопрос с ответом.
(2) URL в web.open. По ref — адрес выбрала не модель. По url — ask, человек видит полный канонический адрес. Приписать ?leak=<секрет> к ref-адресу невозможно: у ref нет поля, куда это дописать.
Транспорт модель не настраивает: max_bytes, дедлайны, UA, заголовки, число редиректов, allowed_hosts — константы модуля, ни один не выведен в input_schema. Cookie не отправляются никогда и Set-Cookie не сохраняется. Только GET, никаких тел запроса. Прокси не используется (PinnedTransport создаётся без proxy). Ключ API уходит только на хост своего источника.

============ 8. КОНВЕЙЕР ЧТЕНИЯ СТРАНИЦЫ (порядок обязателен) ============
canon_url → precheck (ASCII-хост, не SERP_DENY, не EXFIL_SINKS) → osiris.checked_url (psec.validate_url) → ensure_host_source (osiris.normalize_source ⇒ чужой словарь запретов) → robots_ok → кэш (st.read_raw + st.raw_is_fresh) → st.rate_allows → пауза вежливости 1 с на хост → adapter.fetch_bytes → status → content_type_ok → decode_body → looks_mojibake → extract → минимум 200 знаков текста → st.write_raw → Observation(attribute="page.text") → st.save_observations → osiris._mark_live. Любая перестановка ослабляет fail-closed. Единственное отличие от osiris.collect и оно в безопасную сторону: сырьё пишется ПОСЛЕ успешного извлечения, чтобы на диске не появлялось файла, на который не ссылается ни одно наблюдение.
robots_ok(st, source, url) — тонкая мемоизация ВЕРДИКТА по (host, path) на 1800 с поверх st.robots_allows; свой RobotFileParser не поднимается, fail-closed наследуется (недоступный или не-200 robots = отказ). Ужесточение против OSIRIS: проверяется для ВСЕХ категорий, а не только C.

============ 9. ПРОИСХОЖДЕНИЕ ============
Один эпизод = один субъект OSIRIS. Субъект поиска = f"web:{канонический запрос}"[:200] (в субъекте запрещён "/", поэтому URL субъектом быть не может); страницы, открытые в рамках эпизода, ложатся под ТОТ ЖЕ субъект; страница по адресу владельца без запроса — субъект f"web:url:{sha1(url)[:16]}".
Пять типов наблюдений, различаемых attribute, связанных value["of"] = id родителя, с общим строго возрастающим st.next_collected_at():
  search.query — сам факт запроса; source_url = точный адрес запроса к API; raw_ref = сырьё выдачи.
  search.result — каждая позиция отдельной записью (rank, title, url, snippet, engine); тот же raw_ref (одна страница выдачи = один файл, а не N).
  page.text — прочитанная страница; source_id = автосозданный источник хоста; source_url = ЗАПРОШЕННЫЙ канонический адрес (конечный после редиректов транспорт не отдаёт — это сказано прямо, а не скрыто); value несёт chars, text_sha256, extractor=EXTRACTOR_VERSION, encoding, replace_ratio, title, truncated.
  quote — текст ≤600, offset и length В ИЗВЛЕЧЁННОМ ТЕКСТЕ, claim, тот же raw_ref, что у страницы.
  citation.check — результат перепроверки: intact | moved | changed | gone | unreachable | blocked | superseded. Старая запись НИКОГДА не переписывается.
Паспорт нигде не собирается вручную: конструктор Observation отказывает без source_id, source_url, method, license, observed_at и — для api/fetch — без raw_ref. confidence ≤0.5. live_status пишет только osiris._mark_live через транспорт с live=True.
Удаление: delete_episode() СНАЧАЛА считает, какие raw-дайджесты эпизода делятся с другими субъектами (raw_key = sha256(source_id|url), один URL из двух запросов = ОДИН файл, подписанный первым субъектом), и при пересечении отвечает 409 со списком пострадавших эпизодов; с orphan_ok=1 удаляет через osiris delete_subject. Ledger удаляется вместе с эпизодом и GC-ится через 24 часа.
prune_raw() — единственный уборщик: удаляет только файлы источников с id, начинающимся на "web-", на которые НЕ ссылается ни одно наблюдение. Референсное сырьё не удаляется никогда, даже при переполнении бюджета: при переполнении система ОТКАЗЫВАЕТСЯ собирать новое.

============ 10. ЗАЩИТА ОТ ИНЪЕКЦИЙ ============
(1) external_output=True — шапку ставит движок. (2) Структурное удаление невидимого: script/style/noscript/template/svg/iframe/form, комментарии, hidden/aria-hidden/display:none, zero-width и bidi. (3) defang — помечает "⚠" и экранирует управляющие токены чат-шаблона, но НЕ удаляет: удаление лжёт владельцу о содержимом и заодно даёт цензуру легитимного текста («ignore previous instructions» бывает цитатой в статье про инъекции). (4) Число обезвреженных строк печатается в подвале и уходит событием web.injection_suspected (только счётчик, host и ref — без текста). (5) Разовый сторожевой маркер + пометка каждого пассажа w1§N; все внешние значения перед подстановкой чистятся от "]" и от последовательностей маркера, чтобы страница не подделала границу. (6) ГЛАВНОЕ — лишение полномочий, а не уговоры: из текста страницы модель может сделать ровно три вещи — web.find (локально), web.cite (локально) и попросить открыть l-ref или url, что стоит одобрения владельца с показом полного адреса. Ни записи, ни исполнения, ни отправки у web.* нет.
Честный предел, названный вслух: ничто из этого не останавливает убедительную инъекцию обычной прозой без ключевых слов. Регулярки ловят форму, а не намерение.

============ 11. БЮДЖЕТ ============
В движке бюджета вызовов НЕТ (max_steps ограничивает обращения к модели, engine.py:569/593; список calls внутри шага исполняется целиком, engine.py:797; governor ловит только ОДИНАКОВЫЕ отпечатки шага, а 200 запросов по разным адресам для него «прогресс»). Поэтому бюджет свой, в ledger'е на диске.
На прогон: 5 поисков, 12 открытий (перелистывание из кэша и web.find не считаются), 3 МБ принятых байт, 90 с суммарного сетевого времени. На вызов: PAGE_MAX_BYTES=400_000 (вчетверо строже osiris.MAX_BYTES; при identity байты на проводе = байты после), TOTAL_DEADLINE 25 с для open и 20 с для search; ToolSpec.timeout_seconds ставится ЧУТЬ ВЫШЕ (30/25/10/10), чтобы владелец видел осмысленный текст отказа, а не общий таймаут движка. На хост: osiris rate_allows (10/мин, ключ = source.id = хост) + пауза вежливости 1 с. Глобально: BOSSMAN_WEB_DAILY_FETCHES (500). На диск: BOSSMAN_WEB_RAW_BUDGET_MB (200).
Исчерпание — с error=False и явным сценарием: «ЛИМИТ ПОИСКА ИСЧЕРПАН (5 из 5). Уже найдено: w1, w3. Отвечай по тому, что есть. Если данных не хватает — так и скажи владельцу. ДАЛЬШЕ: ничего. Заверши ответ.» error=True здесь провоцирует маленькую модель повторить вызов, и лимит превращается в цикл до max_steps.

============ 12. ЛОКАЛЬНАЯ МОДЕЛЬ ============
Главный разрыв вне моих файлов: OpenAICompatAdapter читает только choices[0].message.tool_calls (providers.py:198-204); текстового парсера вызовов в проекте нет ни одного; текст с <tool_call> движок принимает за финальный ответ (engine.py:662-663) — прогон «успешно» завершается вызовом вместо результата, без ошибки и без ретрая.
Что делает модуль, оставаясь в границах: (а) POST /api/web/preflight — существующий bcc/v2/capability_probe.probe_tools против модели владельца, вердикт «ваш раннер отдаёт нативные tool_calls: да/нет/не проверялось», результат в свой файл (строку в model_capability_checks не пишем — таблица принадлежит фиче openrouter); (б) хук gate_completion (§13); (в) вся эргономика: _coerce_args, строка ДАЛЬШЕ везде, четыре плоских схемы, пассажи вместо страницы, метки w1§N, PAGE_CHARS по умолчанию 3000 и рекомендация 1500 для окна 4k, «страница k из n» в шапке.
Чего модуль НЕ делает: не исполняет разобранный из текста вызов. Такой вызов миновал бы decide_effect, парковку, approval_digest, args_hash и anti-replay — модель, пишущая вызов текстом, получила бы БОЛЬШЕ прав, чем вызывающая штатно. Правильное лечение — три строки в providers.py, и это работа ведущего.

============ 13. ХУК gate_completion ============
Ставится svc.engine.add_hook("gate_completion", ...) только при включённых флагах. Возвращает dict строго по контракту (проверено по engine.py:118-128: verdict обязателен и обязан нормализоваться в PASS|FAIL|NOT_APPLICABLE; молчаливый None и dict без verdict считаются сбоем).
Правила, каждое даёт РОВНО ОДНУ корректирующую попытку на прогон (счётчик в ledger):
  (а) в финальном ответе есть текстовый вызов web.* (<tool_call>…, <|python_tag|>, ```json{"name":"web.…"}, «Action: web.search»), а строки tool_calls для него нет → FAIL + requeue с инструкцией; движок сам добавит её сообщением пользователя.
  (б) в прогоне исполнялись web.open, а в ответе нет ни одного маркера [wN] → FAIL + requeue со списком «w1 = https://…» и требованием проставить ссылки.
После одной попытки — PASS плюс событие web.text_call_detected / web.uncited_answer. Если веб-инструменты в прогоне не использовались — NOT_APPLICABLE.
ВЕСЬ хук в try/except Exception с возвратом {"verdict": "PASS"}: gate_completion входит в CRITICAL_HOOK_NAMES, и исключение = CriticalHookFailure = эскалация человеку по ЧУЖОМУ прогону. Это сознательный fail-open ровно в одном месте — в отличие от fail-closed на всём пути egress.

============ 14. ОТВЕТ ПРИ НУЛЕВОЙ НАСТРОЙКЕ ============
Флаг OFF (по умолчанию): инструментов не существует, модель их не видит, файлов нет, GET /api/web = {"enabled": false, "flag": "BOSSMAN_WEB_RESEARCH_ENABLED"}.
Флаг ON, OSIRIS OFF: отдельный явный отказ — «нужен BOSSMAN_OSIRIS_ENABLED=1: без слоя происхождения результат нельзя ни проверить, ни стереть».
Оба ON, ничего не настроено: 6 источников без ключа работают сразу (Википедия, StackExchange, HN, OpenAlex, PyPI, crates.io). Владельцу и модели идёт ОДИН И ТОТ ЖЕ текст из ОДНОЙ функции readiness(), поэтому разойтись они не могут: «Ключи не нужны: работают 6 источников без ключа — справки, документация, пакеты, научные работы, но НЕ общий веб-поиск. # Конфликты и решения

- КОНФЛИКТ 1 — есть ли у модели поле url вообще. П1: нет, только непрозрачные ref (канал убран конструкцией). П2/П3: есть, с ask/deny по хуку. РЕШЕНИЕ: web.open принимает ref XOR url, и это разные ветки эффекта. ref → auto (адрес отчеканен backend'ом или владельцем, байтов от модели в сетевом адресе ноль). url → НИКОГДА не auto: effect_hook отдаёт ask на любой непустой url и deny на структурно негодный. ОБОСНОВАНИЕ: П1 прав, что allowlist — это политика, которую расширяют, а отсутствие поля — свойство; но П1 не заметил, что его собственный вариант отнимает две настоящие возможности. Первая: владелец не может дать правило по хосту, потому что tool_rules матчатся через _resource_of (tools.py:299-305), и ключ там называется именно url. Вторая: пройти по ссылке, которую владелец сам вписал или которая напечатана в тексте статьи, становится невозможно вовсе. Развилка ref/url отдаёт всю дешёвую работу ветке auto и оставляет человеку ровно один вопрос — «пустить ли на этот новый адрес», причём с полным каноническим URL в предпросмотре. Побочный выигрыш: run-скоуп больше не нужен как защита (auto достижим только по ref), поэтому чтение tool_calls.approval_id из П3 выбрасывается целиком вместе со своей хрупкостью.

- КОНФЛИКТ 2 — ссылки со страницы. П1: отдельный инструмент web.links, чеканит l-ref, открытие через ask. П2: не показывать ссылки вообще (главный разворот инъекции и бесполезный шум для 7B). П3: seen-set наполняется ТОЛЬКО выдачей, ссылки из тела не попадают туда никогда. РЕШЕНИЕ: отдельного инструмента нет; в конец результата web.open добавляется блок не более 12 ссылок как l1..l12 (текст якоря + хост, БЕЗ полного URL); открытие любого l-ref → ask через тот же чистый хук по префиксу. ОБОСНОВАНИЕ: П2 прав насчёт разворота инъекции, но его запрет ломает исследование по цитатам и документации — ровно то, ради чего фича существует. П1 прав, что l-ref строго лучше показа сырого URL (7B искажает 120-символьный адрес при копировании, а искажённый адрес — это новый, никем не одобренный адрес назначения; и человек всё равно видит настоящий URL в предпросмотре одобрения). Отдельный инструмент при этом не нужен: он повышает tool_count, а весь его смысл — чеканка, которая бесплатна и делается на месте. Цена названа прямо в honest_failures и в weakest_point: это остаточный оракул на единицы бит за прогон, и он полностью снимается переменной BOSSMAN_WEB_PAGE_LINKS=0, которая просто убирает блок.

- КОНФЛИКТ 3 — эффект web.search. П1: auto, но ask при заданном site. П2/П3: auto всегда. РЕШЕНИЕ: auto всегда; site — только deny при негодном значении. ОБОСНОВАНИЕ: собственный же аргумент П1 против усталости от одобрений применим здесь сильнее, чем его аргумент за ask: сужение по домену не добавляет человеку НИ ОДНОГО нового бита (получателя всё равно выбирает не модель, а зарегистрированный backend), зато делает обычный исследовательский цикл диалоговым. Утечка через текст запроса закрывается шлюзом до сети, а не вопросом, который прочитают один раз из десяти.

- КОНФЛИКТ 4 — переиспользовать osiris.collect() или писать свой конвейер. П3: звать collect. П1/П2: свой. РЕШЕНИЕ: расщепить. ПОИСК идёт через osiris.collect() без единой строчки повторения его порядка проверок (мои парсеры регистрируются в osiris.PARSERS — штатный и единственный механизм, его же требует normalize_source). ЧТЕНИЕ СТРАНИЦЫ идёт своим конвейером, потому что collect жёстко делает json.loads(body) (проверено, строка ~934) и HTML через него не проходит принципиально. Свой конвейер повторяет порядок collect один в один и отличается ровно в одном месте и в безопасную сторону: сырьё пишется ПОСЛЕ успешного извлечения, чтобы на диске не появлялось файла, на который не ссылается ни одно наблюдение.

- КОНФЛИКТ 5 — где живёт реестр ссылок. П1: файл на диске. П2: LRU в памяти процесса. П3: реестра нет, run-скоуп из tool_calls. РЕШЕНИЕ: файл на диске, П1. ОБОСНОВАНИЕ: механическое, не вкусовое. Ask паркует run и освобождает воркер (engine.py:966-982), пробуждение может прийти в другой процесс.
