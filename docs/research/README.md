## Шаблон ТЗ

Каждый документ строится по одинаковой структуре — иначе их нельзя сравнить:

1. **Паспорт** — что это, лицензия (из файла LICENSE, не из README), реальные
   звёзды/активность на дату проверки, язык, зависимости, как ставится.
2. **Что делает на самом деле** — по исходникам: архитектура, ключевые модули,
   формат данных, где хранит состояние.
3. **Проверка утверждений** — что из консультации подтвердилось, что нет.
4. **Сопоставление с нашим кодом** — что у нас уже есть, что дублируется,
   что реально добавляет.
5. **Что берём** — конкретно: библиотека целиком / отдельный подход / только идея.
6. **Что НЕ берём и почему.**
7. **Точки интеграции** — наши файлы и функции поимённо, наши контракты
   (`ToolSpec`, `MemoryBackend`, `Feature`), какие таблицы понадобятся.
8. **Цена** — RAM/VRAM/диск/CPU, время индексации, внешние сервисы (Docker,
   WSL2, Milvus, Postgres), офлайн-работа.
9. **Риски** — лицензия, телеметрия, отправка данных наружу, зрелость, привязка
   к вендору, объём кода на сопровождение.
10. **Приватность** — уходит ли хоть что-то в облако по умолчанию; как выключить.
11. **План внедрения** — этапы, оценка объёма, что можно сделать за один заход.
12. **Критерии приёмки** — проверяемые утверждения, будущие тесты.
13. **Что не проверено** — честно.

Оценка в конце каждого ТЗ — одна из четырёх:
**ВНЕДРЯТЬ** / **ВНЕДРЯТЬ ПОЗЖЕ** / **ВЗЯТЬ ИДЕЮ** / **НЕ ВНЕДРЯТЬ**.
