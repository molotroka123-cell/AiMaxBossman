## 2. Что делает на самом деле (по исходникам)

### 2.1 Ядро — два публичных класса

`mem0.Memory` и `mem0.AsyncMemory` (`mem0/memory/main.py`, 3868 строк). Обе реализуют
один и тот же конвейер, различий в логике извлечения нет (`ADDITIVE_EXTRACTION_PROMPT`
используется в обоих: строки 942 и 2604).

API: `add / search / get / get_all / update / delete / delete_all / history / reset`.
`chat()` — заглушка `NotImplementedError` (строка 2168).

### 2.2 `add()` — «V3 PHASED BATCH PIPELINE»

`_add_to_vector_store()` (строка 879). Если `infer=True` (по умолчанию):

1. **Фаза 0.** Достать последние 10 сообщений сессии из локальной SQLite
   (`~/.mem0/history.db`, таблица `messages`).
2. **Фаза 1.** Эмбеддинг всего склеенного диалога → векторный поиск `top_k=10`
   существующих воспоминаний по фильтрам `user_id/agent_id/run_id`.
   UUID'ы найденных подменяются на целые «0», «1», … — явный
   **анти-галлюцинационный приём** (`uuid_mapping`), чтобы LLM не выдумывала id.
3. **Фаза 2.** **Один вызов LLM.** System = `ADDITIVE_EXTRACTION_PROMPT`,
   user = собранная секционная простыня (Summary / Last k Messages / Recently
   Extracted / Existing Memories / New Messages / Observation Date / Current Date).
   Ответ — JSON `{"memory": [{"id": "0", "text": "...", "linked_memory_ids": [...]}]}`.
   Ошибка LLM больше не глотается — поднимается `LLMError`.
4. **Фаза 3.** Батч-эмбеддинг текстов новых фактов.
5. **Фазы 4–5.** Дедупликация **только по `md5(text)`** — точное совпадение строки
   против хэшей найденных на фазе 1 и внутри текущей пачки. Семантического
   слияния нет.
6. **Фаза 6.** Батч-`insert` в векторную БД + батч-запись в SQLite-историю
   (`event="ADD"`).
7. **Фаза 7.** Извлечение сущностей (spaCy, не LLM) из каждого факта, глобальная
   дедупликация, батч-эмбеддинг сущностей, поиск в отдельной «entity store»
   коллекции, слияние при точном совпадении текста или косинусе ≥ 0.95;
   у сущности хранится `linked_memory_ids`.
8. **Фаза 8.** Сохранить сообщения в SQLite, отправить телеметрию, вернуть список.

**Критично:** операции `UPDATE` и `DELETE` в конвейере **больше нет**. Промпт
называется `ADDITIVE_EXTRACTION_PROMPT` и прямо говорит: «Your sole operation is
ADD». Старый `DEFAULT_UPDATE_MEMORY_PROMPT` и `get_update_memory_messages()`
остались в `mem0/configs/prompts.py`, но **из `main.py` не вызываются** —
это мёртвый код (проверено grep'ом). Противоречия не разрешаются: новый факт
просто добавляется рядом со старым, максимум — получает `linked_memory_ids`
на конфликтующий.

`infer=False` — режим без LLM: каждое сообщение кладётся как есть (только
эмбеддинг). Это, по сути, обычный векторный индекс.

### 2.3 `search()` — LLM не вызывается вообще

`_search_vector_store()` (строка 1628):
1. лемматизация запроса (spaCy) + извлечение сущностей (spaCy);
2. эмбеддинг запроса;
3. плотный поиск с переизбытком: `internal_limit = max(limit*4, 60)`;
4. keyword-поиск (`vector_store.keyword_search`) — только если стор умеет BM25;
5. нормализация BM25 логистической сигмоидой с параметрами, зависящими от длины
   запроса (`mem0/utils/scoring.py`);
6. entity boost: по каждой сущности запроса — эмбеддинг + поиск в entity store,
   буст связанным воспоминаниям (вес 0.5);
7. **аддитивное** объединение: `combined = (semantic + bm25 + entity) / max_possible`,
   где делитель адаптивен (1.0 / 2.0 / 1.5 / 2.5). Порог `threshold` режет
   **до** сложения — только по семантике.

Опциональный `reranker` (`mem0/reranker/`): cohere, huggingface, sentence-transformers,
zero-entropy и **llm_reranker** (ещё один вызов LLM, по умолчанию выключен).

### 2.4 Где хранит состояние

| Что | Куда | По умолчанию |
|---|---|---|
| Векторы фактов | vector store, провайдер на выбор (25 шт.) | `qdrant`, локальный embedded-режим, путь `/tmp/qdrant` |
| Векторы сущностей | отдельная коллекция того же стора | `<collection>_entities` |
| История правок + сообщения сессий | **SQLite** | `~/.mem0/history.db` |
| Анонимный `user_id` для телеметрии | JSON | `~/.mem0/config.json` |
| Каталог | `MEM0_DIR` | `~/.mem0` |

Дефолтные LLM и эмбеддер — **`openai`** (`mem0/llms/configs.py`,
`mem0/embeddings/configs.py`). Локальные варианты есть: LLM — `ollama`, `lmstudio`,
`vllm`, `litellm`; эмбеддер — `ollama`, `huggingface`, `lmstudio`, `fastembed`.

### 2.5 Что живёт только в облаке (важно)

Из `docs/platform/platform-vs-oss.mdx` (файл в репозитории, прочитан целиком):

* **Graph Memory — удалён из OSS.** Цитата: «Removed. OSS previously connected
  external graph stores (Neo4j, Memgraph, Kuzu, Apache AGE); that integration was
  dropped when the v3 pipeline landed». Каталога `mem0/graphs/` в дереве нет —
  проверено.
* **Dream (фоновая консолидация: слияние дублей, вытеснение устаревших фактов)** —
  только платформа. Это и есть настоящее «разрешение противоречий».
* **Memory Decay** (затухание), **Temporal Reasoning** (`timestamp`,
  `reference_date`) — в OSS кидают явную ошибку «not supported by the OSS Memory SDK».
* Также только платформа: `app_id`, организации/проекты, custom categories,
  webhooks, memory export, `batch_update`/`batch_delete`, `feedback()`,
  `get_summary()`, event-feed проекта, дашборд.

Отдельно: `server/` — самохостимый REST-API на FastAPI, но он тянет
**Postgres + pgvector** через `docker-compose.yaml`. Библиотека `mem0.Memory`
Postgres не требует.

## 5. Что берём

**Не библиотеку.** Берём три приёма и переносим их на наш `ObsidianMemoryService`.

**И-1. Двухуровневая память: «документы» + «факты».**
Сейчас `memory.write` пишет заметку целиком. Добавить второй, более мелкий
уровень — **факт**: самодостаточное утверждение в 15–80 слов, с датой наблюдения,
без местоимений. Именно эта форма и есть настоящий вклад mem0, а не код.
Требования к формулировке взять прямо из их промпта (§ «Memory Quality Standards»):
самодостаточность, привязка относительных дат к «дате наблюдения» (не к «сегодня»),
запрет обобщать имена собственные и числа, обязательное сохранение перехода
(«перешёл с X на Y», а не просто «использует Y»).

**И-2. Additive + hash-дедуп + связи, без разрушающего UPDATE/DELETE.**
Модель никогда не переписывает и не удаляет чужой факт. Новый факт добавляется,
конфликтующий помечается ссылкой. Разрешение — отдельная **редкая** офлайн-задача
(наш аналог Dream), запускаемая по расписанию/вручную, а не на каждом шаге агента.
Это ровно то, к чему mem0 пришёл сам, отказавшись от UPDATE-конвейера.

**И-3. Анти-галлюцинационная подмена id.**
Когда список существующих фактов подаётся в LLM — подменять UUID на «0», «1», …
и мапить обратно на выходе. Дешёвый приём, у нас пригодится всюду, где модель
ссылается на строки БД.

**И-4 (опционально, дёшево). Entity boost в ранжировании.**
Наш `local_index.py` уже токенизирует и стеммит. Добавить извлечение «сущностей»
без spaCy — заглавные многословные последовательности, текст в кавычках,
идентификаторы (`bcc/db.py`, `v2.1-phase-E`) — и давать бонус к BM25-скору за
совпадение сущности. Формула аддитивного скоринга из `mem0/utils/scoring.py`
воспроизводится в 30 строк.

**И-5. Экстракция — ОДИН раз на run, а не на шаг.**
mem0 вызывает LLM на каждый `add()`. У нас `add` должен происходить один раз —
в конце run'а, по итоговым сообщениям, отдельным инструментом `memory.harvest`.

## 6. Что НЕ берём и почему

1. **Пакет `mem0ai` как зависимость.** 127 МБ базово / 755 МБ с экстрами против
   нашего stdlib-индекса. Тянет `posthog` в обязательных зависимостях, `openai`,
   `protobuf`, `qdrant-client`. На машине, где память — ресурс для моделей, это
   плохая сделка (§8).
2. **`ADDITIVE_EXTRACTION_PROMPT` как есть.** 33 653 символа ≈ **8 413 токенов**
   системного промпта на каждое сохранение. Мы напишем свой на 600–900 токенов:
   90% их промпта — примеры и нравоучения для консьюмерского сценария
   («любимые фильмы», «фото с пикника»), нам не нужные.
3. **Их модель хранилища.** Факты в непрозрачном qdrant-payload + `~/.mem0/history.db`
   ломают наше правило «человек владеет своими заметками». Наши факты должны лежать
   в vault (или в нашей БД, схемой которой владеет `bcc/db.py`), а не в чужом сторе.
4. **Entity store как отдельная векторная коллекция.** Удваивает диск и добавляет
   2 embed-вызова на `add()` и 1 на каждую сущность запроса. При нашем BM25 буст
   считается по инвертированному индексу бесплатно.
5. **Телеметрию PostHog.** См. §10.
6. **`server/`** (FastAPI + Postgres + pgvector в docker-compose). У нас свой
   HTTP-слой и свой `db.py` — единственный владелец схемы.
7. **Платформенные функции** (Dream, decay, temporal, categories, webhooks,
   export). Их в OSS нет, и рассчитывать на них нельзя.
8. **spaCy `en_core_web_sm`.** Английская модель; BOSSMAN работает на русском.
   Лемматизация и NER на русском деградируют молча (`return text`, `return []`).

## 7. Точки интеграции

Ничего из mem0 не импортируется. Реализуем свой код в существующих файлах.

### 7.1 Контракты

* `bcc/v2/memory/service.py` → `MemoryBackend` (Protocol) — **не меняется**.
* `ObsidianMemoryService` — добавить методы:
  * `async def harvest(self, messages: list[dict], *, run_id: int, llm) -> list[Fact]`
    — извлечение фактов (И-1, И-3, И-5);
  * `async def facts_search(self, query: str, *, top_k: int) -> list[Fact]`;
  * `async def facts_link(self, fact_id: int, related_ids: list[int], kind: str)`.
* `bcc/v2/memory/local_index.py` — добавить `extract_entities(text)` (регулярки,
  stdlib) и учёт `entity_boost` в скоринге (И-4). `INDEX_VERSION` → 4.
* Новый файл `bcc/v2/memory/facts.py` — датакласс `Fact`, промпт экстракции,
  парсер JSON-ответа, подмена UUID↔int.

### 7.2 Инструменты (`bcc/features/tools_memory.py`, `SPECS`)

| Инструмент | `category` | `default_effect` | `permission` | Примечание |
|---|---|---|---|---|
| `memory.harvest` | `write` | **`ask`** | `filesystem.write` | извлечь факты из текущего run'а; показывает человеку список кандидатов в `preview` approval'а |
| `memory.facts` | `read` | `auto` | — | `external_output=True` — факт извлечён из внешнего текста, это данные, а не команда |
| `memory.forget` | `write` | **`ask`** | `filesystem.write` | `idempotent=False`; помечает факт `superseded_by`, физически не удаляет |

`memory.search/expand/write/index/stats` остаются как есть. Правило «память не
подмешивается в каждый вызов модели» (комментарий в шапке `tools_memory.py`)
**не нарушается**: `memory.facts` вызывает агент, а не хук.

### 7.3 Новые таблицы (`bcc/db.py` — единственный владелец схемы)

```
memory_facts
  id, run_id FK task_runs, task_id FK tasks,
  text TEXT NOT NULL,                 -- самодостаточное утверждение
  text_hash CHAR(64),                 -- sha256, дедуп (у mem0 md5 — берём sha256)
  scope VARCHAR(16),                  -- user | agent | run | project
  scope_key VARCHAR(120),             -- имя проекта / агента
  observed_at DATETIME,               -- «дата наблюдения», к ней привязаны «вчера»/«на той неделе»
  entities JSON,                      -- [[тип, текст], ...]
  status VARCHAR(16) DEFAULT 'active',-- active | superseded | rejected
  superseded_by INTEGER FK memory_facts,
  note_path VARCHAR(500),             -- зеркало в vault, если решим дублировать в markdown
  created_at DATETIME
  UNIQUE(text_hash, scope, scope_key)

memory_fact_links
  id, src_id FK memory_facts, dst_id FK memory_facts,
  kind VARCHAR(16),                   -- same_topic | update | continuation | contradiction
  created_at

memory_fact_history                   -- аудит, аналог их history.db
  id, fact_id FK memory_facts, event VARCHAR(8),  -- ADD | LINK | SUPERSEDE | REJECT
  old_text TEXT, new_text TEXT, decided_by VARCHAR(120), created_at
```

Колонки добавляются через существующий идемпотентный механизм
`V2_NEW_COLUMNS` / `Database.migrate()`; новые таблицы — через `metadata`.

### 7.4 Связь с существующими таблицами

* `task_runs.checkpoint` — после завершения run'а движок дёргает `memory.harvest`
  по `checkpoints.messages` последнего шага. Никакой новой машинерии не нужно.
* `tool_calls` — вызов `memory.harvest` логируется как обычный инструмент,
  с `args_hash` и anti-replay, поэтому повторный запуск того же run'а не породит
  дублей даже до `text_hash`-дедупа.
* `approvals.preview` — сюда кладём список фактов-кандидатов текстом, человек
  видит, что именно агент собрался запомнить.

## 8. Цена

### 8.1 Токены и задержка (измерено)

Прогон: фейковый OpenAI-совместимый сервер на `127.0.0.1`, локальный embedded
qdrant, эмбеддинги 8-мерные, скрипт `/tmp/research/exp/run2.py`.

| Операция | chat-вызовов | embed-вызовов | Промпт chat | ≈ токенов |
|---|---|---|---|---|
| `Memory.from_config()` | 0 | 0 | — | — |
| `add()` первый, без spaCy | 1 | 2 | 33 993 симв. | **≈ 8 498** |
| `add()` с spaCy (entity store) | 1 | **3** | 33 957 симв. | ≈ 8 489 |
| `add()` второй (память не пуста) | 1 | 3 | 34 214 симв. | ≈ 8 553 |
| `search()` | **0** | 1 (2 со spaCy) | — | 0 |

Разбор промпта: `ADDITIVE_EXTRACTION_PROMPT` = **33 653 символа ≈ 8 413 токенов**
константы; скелет user-промпта — 189 символов; остальное растёт линейно от числа
существующих фактов (top-10) и последних 10 сообщений.

**Что это значит для нас.** На каждый шаг агента такой `add()` вешать нельзя.
Даже один вызов на run: 8.5k токенов prefill. На Ryzen AI MAX+ 395 без dGPU
prefill плотной модели ~8B идёт грубо в диапазоне сотен токенов/с →
**оценочно 10–40 с** только на разбор промпта (это оценка, не замер — см. §13).
Облачной модели по цене входа $0.25/M это ~$0.002 за сохранение — терпимо, но
данные при этом уходят наружу (§10).

Наш собственный промпт на 600–900 токенов даёт **≈10× экономии** при том же
результате: 90% их текста — примеры про кофе, собак и Netflix.

Плюс: константный system-промпт хорошо ложится на prompt caching (облако) и
prefix caching (llama.cpp/vLLM). Но полагаться на это в ТЗ нельзя.

### 8.3 Офлайн-работа

Запущено **полностью офлайн** (LLM и эмбеддер — локальный HTTP-стенд):
`add()` и `search()` отработали, факты записались, поиск вернул их со скором.
Docker, Postgres, Milvus **не нужны**: qdrant в embedded-режиме — просто
`storage.sqlite` в каталоге.

Оговорки, найденные экспериментально:

1. **`fastembed` качает модель BM25 с HuggingFace при первом обращении.**
   В нашей среде: `Failed to load BM25 encoder: 403 Forbidden` → `keyword_search`
   вернул `None` → **гибрид молча деградировал до чистой семантики**. Ошибка
   уходит в `logger.debug`/`warning`, вызывающий код о ней не узнаёт.
2. **spaCy-модель качается автоматически при первом использовании.**
   `mem0/utils/spacy_models.py::_ensure_model_available()` вызывает
   `spacy.cli.download('en_core_web_sm')`, который **шеллится в установщик пакетов**
   и тянет 12.2 МБ с `github.com`. Наблюдалось вживую. В нашем прогоне установщик
   поставил модель **в чужой venv** (`./.venv` рядом со скриптом), и `spacy.load()`
   в этом же процессе её не увидел — то есть приём ещё и ненадёжен.
3. Без spaCy: `extract_entities` → `[]`, `lemmatize_for_bm25` → возвращает исходный
   текст. Тихая деградация обеих фич.
4. Локальный qdrant не поддерживает payload-индексы:
   `UserWarning: Payload indexes have no effect in the local Qdrant`. То есть
   фильтрация по `user_id` — линейный проход.

**Вывод по офлайну:** ядро офлайн работает, но полный набор фич требует двух
предзагруженных моделей, и обе деградируют молча.

## 10. Приватность

**Уходит ли что-то наружу по умолчанию: ДА.**

`mem0/memory/telemetry.py`:
* `MEM0_TELEMETRY = os.environ.get("MEM0_TELEMETRY", "True")` — **включено**;
* PostHog, хост `https://us.i.posthog.com`, ключ проекта зашит в код;
* при инициализации — блокирующий (таймаут 0.5 с) запрос **feature flags**
  `POST /flags/?v=2`, чтобы решить, показывать ли «нотисы» с рекламой платформы;
* события `mem0.init`, `mem0.add`, `mem0.search`, `mem0.reset`, `mem0.notice_displayed`;
  «горячие» сэмплируются на 10% (`_DEFAULT_SAMPLE_RATE = 0.1`), lifecycle — 100%;
* `posthog` — в **обязательных** зависимостях, не в extras.

**Что именно уходит** (`capture_event`): имя коллекции, размерность вектора,
классы vector store / LLM / эмбеддера, версия mem0, версия Python, `sys.platform`,
`platform.version/release/processor/machine`, анонимный UUID из
`~/.mem0/config.json`, список ключей фильтра и **md5 от `user_id`/`agent_id`/`run_id`**
(`process_telemetry_filters`). **Текст воспоминаний и содержимое диалога не
отправляются** — это проверено чтением кода.

Замечание: md5 короткого `user_id` («timur», «bossman») подбирается перебором за
секунды. Это не анонимизация.

**Проверено экспериментально.** Прогон с настройками по умолчанию дал:
```
ProxyError: HTTPSConnectionPool(host='us.i.posthog.com', port=443)
  ... url: /flags/?v=2
[PostHog] error uploading: ... url: /batch/
```
То есть исходящие попытки на `us.i.posthog.com` реальны и происходят и при init,
и при add/search.

**Как выключить:** `MEM0_TELEMETRY=False` в окружении **до `import mem0`**
(значение читается на импорте модуля). Повторный прогон с этой переменной:
**ни одной попытки исходящего соединения**. Заодно отключаются и «нотисы»
(`display_first_run_notice` первым делом проверяет `telemetry_module.MEM0_TELEMETRY`),
и запрос feature flags.

**Чего `MEM0_TELEMETRY=False` НЕ отключает:** автозагрузку spaCy-модели с
`github.com` и модели BM25 с HuggingFace (§8.3). Для BOSSMAN это означало бы
белый список хостов на фаерволе или предустановку моделей — то есть ещё один
пункт в эксплуатации.

**Итог для BOSSMAN:** приемлемо только с `MEM0_TELEMETRY=False`, зафиксированным
в коде запуска, и с локальными LLM/эмбеддером. Дефолт (OpenAI + PostHog) для
приватного домашнего сервера неприемлем. Это ещё один довод не тащить пакет:
своя реализация не создаёт этой поверхности вообще.

## 11. План внедрения

Реализуем И-1…И-5 своими силами. Кода mem0 в репозитории не появляется.

**Этап 2 (~1 день). Экстракция.**

  исходных сообщений» — то, чего нет у mem0.
* `ObsidianMemoryService.harvest()` — один вызов LLM по сообщениям завершённого
  run'а, с top-10 существующих фактов в контексте.
* Инструмент `memory.harvest` (write, **ask**, `filesystem.write`), список
  кандидатов — в `approvals.preview`.
* Приёмка: русский диалог даёт русские факты; повторный harvest того же run'а

**Этап 3 (~0.5 дня). Ранжирование.**
* `local_index.py`: `extract_entities` на регулярках + аддитивный скоринг
  `bm25 + 0.5*entity` с нормировкой (порт `mem0/utils/scoring.py`, ~30 строк).
* `INDEX_VERSION` → 4, полная переиндексация при апгрейде.

**Этап 4 (~0.5 дня). Разрешение противоречий как отдельная задача.**
* Наш «Dream»: `schedules`-задача, раз в сутки/по кнопке, берёт кластер связанных

(разрешение противоречий) в OSS отсутствует.

## 12. Критерии приёмки

Проверяемые утверждения для будущих тестов:

1. `memory.harvest` делает **ровно один** вызов LLM на run; при повторном вызове
   с тем же `args_hash` — ноль вызовов (anti-replay `tool_calls`).
2. Системный промпт экстракции ≤ **1000 токенов** (тест на `len(PROMPT)//4`).
3. Русский вход → русские факты: тест с зафиксированным ответом мок-LLM проверяет,
   что в промпте присутствует инструкция о языке.
4. Дедуп: два `harvest` с одинаковым текстом факта → одна строка в `memory_facts`
   (`UNIQUE(text_hash, scope, scope_key)`).
5. `memory.facts` возвращает результат с `external_output=True`, то есть с шапкой
   `EXTERNAL_DATA_HEADER`.
6. `memory.harvest` и `memory.forget` имеют `default_effect="ask"` и требуют права
   `filesystem.write`; `memory.forget` — `idempotent=False`.
7. `memory.forget` никогда не удаляет строку: после вызова
   `status='superseded'`, `superseded_by IS NOT NULL`, запись читается.
8. Ноль исходящих сетевых соединений при полном цикле harvest → search
   (тест с патчем `socket.socket.connect`, как в `/tmp/research/exp/net_watch.py`).
9. Entity boost: документ с точным совпадением имени собственного ранжируется
   выше документа с той же BM25-массой, но без совпадения сущности.
10. Дельта RSS процесса после включения фактов < 20 МБ.

## 14. Оценка

# ВЗЯТЬ ИДЕЮ

**Почему не «ВНЕДРЯТЬ».** Единственное, чего у нас принципиально нет и что mem0
действительно даёт, — автоматическая экстракция долговременных фактов из диалога.
Это **промпт и дисциплина формулировок**, а не код: сам конвейер вокруг него
(векторный стор, entity store, SQLite-история) мы либо уже имеем, либо не хотим.
Цена доставки этой идеи в виде библиотеки — 755 МБ зависимостей, 328 МБ RSS,
8.5k токенов на каждое сохранение, включённая по умолчанию телеметрия в PostHog,
две модели, качаемые из интернета в рантайме, английская NLP-обвязка и второй,
непрозрачный для человека источник правды рядом с Obsidian.

**Почему не «НЕ ВНЕДРЯТЬ».** Идеи в mem0 честные и выстраданные: ADD-only вместо
разрушающего UPDATE, привязка относительных дат к дате наблюдения, подмена UUID
на целые против галлюцинаций, аддитивный скоринг с адаптивным делителем, аудит
каждой правки. Это стоит воспроизвести — примерно за три дня и без единой новой
зависимости.

**Отдельно, для протокола.** Ключевое обещание из консультации — «автоматически
разрешает противоречия и забывает устаревшее» — в OSS-версии **не выполняется**:
конвейер только добавляет, дедуп только по точному хэшу, а промпт сам велит
«при сомнении — извлекай», ссылаясь на несуществующую в OSS систему дедупликации.
Разрешение противоречий (Dream) и граф памяти живут только в облаке, причём граф
из OSS был **удалён**. Если бы мы взяли mem0 ради этого — мы бы получили ровно
то, чего опасались в постановке задачи: слой, который тихо копит мусор.
