# Tasks/Agents: дополнить понравившийся интерфейс

Автор: Кодекс, проект UX, 22.10.2026. Сохранить существующие страницы, карточки и navigation. Дизайн не является evidence работающего backend.

## Главные пользовательские действия

1. На Agents владелец видит вкладки «Локальные», «Бесплатные облачные», «Платные», «Не подключены».
2. Нажимает карточку существующего агента → inspector с ролью, exact model/provider, инструментами, границами данных, бюджетом, последним результатом и кнопкой «Дать работу».
3. Нажимает «Создать агента» → existing form с выбором role template, модели и разрешённых tools. «Сгенерировать описание» открывает отдельную bounded задачу; черновик не активируется автоматически.
4. В чате Gemma предлагает помощника только когда он полезен. Карточка показывает конкретный brief, ожидаемый результат, данные для передачи, free/paid, цену/её свежесть, предел расходов и срок.
5. Подтверждение связывается сервером с execution snapshot. Само открытие формы, карточки или ссылки не запускает модель.
6. В Tasks появляется child task под общей миссией. Клик открывает историю событий, проверку, артефакты и receipt. Существующий чат продолжает показывать общий прогресс без второй копии задачи.

## Состояния карточки

| Ситуация | Текст | Допустимое действие |
|---|---|---|
| Definition enabled, health неизвестен | «Включён · связь не проверена» | Открыть настройки/проверку |
| Есть credentials, live run не был | «Ключ подключён · успешных запусков нет» | Preflight |
| Цена/latency/tokens не измерены | «N/A» | Показать причину и источник |
| Нет quota/модели | «Недоступен: …» | Выбрать разрешённый маршрут |
| Ожидание owner approval | «Нужно подтвердить передачу/расход» | Preview, подтвердить, отказаться |
| Run идёт | «Работает: текущий этап» | Details, STOP |
| Связь потеряна | «Связь потеряна; задача может продолжаться» | Проверить статус; не повторять POST |
| Cancel отправлен | «Останавливаем…» | Ждать подтверждения; показать remote uncertainty |
| Есть модельный ответ | «Проверяем результат» | Проверка; ещё не зелёный успех |
| Проверка не пройдена | «Не выполнено: …» | Evidence, bounded retry |
| Независимая проверка прошла | «Готово · результат проверен» | Открыть результат/receipt |

Стоимость показывать раздельно: лимит, зарезервировано, подтверждённо потрачено, неизвестный остаток. Недостающий cost не отображать как `$0.0000 FREE`. Бюджет поступает из server-side effective policy, а не строкой, зашитой в JS.

## Телефон

Использовать существующие mobile proxies и тот же backend. Не раскрывать cloud catalog через native `/m/api/agents`, который сейчас намеренно фильтрует local agents: согласованный scoped каталог предоставлять через уже разрешённые router/coding catalog APIs или их тонкое extension. Это расширение UI не меняет privacy автоматически.

Минимальные состояния проверить на ширине 390 px и desktop: карточка, конфигурация, approval preview, running, ошибка, результат. Кнопки доступны с клавиатуры и touch, минимум 44 px touch target, без горизонтального scroll. Состояния имеют текст и иконку; цвет не единственный признак. При updates фокус не теряется.

Повторный tap, переход background → foreground, reload и переключение Wi-Fi/мобильной сети сохраняют один operation key. Сначала загрузить durable task snapshot; затем события с epoch/cursor. Не перезапускать run при remount компонента. Телефон и desktop показывают одинаковые IDs, final state и расходы.

STOP одинаков по смыслу во всех интерфейсах. Кнопка вызывает canonical cancellation. Событие `agent.stopped` или смена цвета не заменяет проверку отсутствия новых действий.

## Что сделать в существующих экранах

- `command-center/ui/pages.js`: extend Agent cards/inspector и existing agent modal; оставить привычный Tasks board.
- `command-center/ui/pages/coding.js`: использовать уже существующие worker chips и task modal, исправить misleading FREE/лимиты.
- `apps/bossman-mobile/bossmobile/ui/app.js`: stable operation key, shared task detail, reconnect/resync; не дублировать workflow.
- `apps/bossman-mobile/bossmobile/api.py`: единый scope-aware proxy и те же backend task/receipt IDs.

Сначала один read-only помощник, потом остальные роли. Выбор модели не означает, что у неё есть tools/vision/context нужного размера: совместимость показывает backend.
