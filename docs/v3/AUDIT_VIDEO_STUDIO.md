# Аудит видеостудии (`codex/video-studio`, dfce725)

База сравнения `a14515d`. Проверено запуском там, где это возможно; помечено,
что установлено чтением кода.

## Безопасность: в полосе P0/P1 чисто

Проверено предметно, а не предположено: пользовательский контент не рендерится
на origin панели (`h()` строит DOM через `createTextNode`, `innerHTML` в
студии нет); инъекции в команду нет — все вызовы `create_subprocess_exec` со
списком аргументов, имена файлов адресуются содержимым (`<sha256>.<ext>`),
поэтому аргумент не может начаться с `-`, а фильтрграф уходит через
`-filter_complex_script`; обхода путей нет (`is_relative_to` ПОСЛЕ `resolve()`
плюс сверка полного хеша); авторизация на всех ручках; SSRF нет — единственный
исходящий HTTP жёстко прибит к `127.0.0.1/v1`; загрузки ограничены 8 ГиБ, ZIP
только пишется, никогда не распаковывается.

Две P2-щели на будущее: `media_file` берёт Content-Type из имени файла, которое
задаёт загружающий, и `nosniff` в приложении нет нигде — сегодня не
эксплуатируется только потому, что Starlette по умолчанию отдаёт вложением;
и проверка имени при загрузке пропускает `..` и переводы строк, читаясь при
этом как защита от путей, которой не является.

## P1 — экспорт проверен, лежит на диске и не может быть скачан никогда

`render_gate` не укладывается в фиксированные 60 с таймаута критичного хука
(`engine.py:48`, поднимать его негде — константа нигде не меняется). Внутри
этих 60 с гейт делает полный `digest_file` результата, затем `verify_output` с
ПОЛНЫМ декодированием файла `ffmpeg -f null -`, три выборки кадров и ВТОРОЙ
полный `digest_file`. На десятиминутном 1080p это заведомо больше минуты:
рендер прошёл, проверка внутри исполнителя прошла, `output.mp4` на месте — и
задача уходит в `waiting_approval`, `output_url` остаётся null, а `GET
/exports/{id}/file` навсегда отвечает 409 «экспорт не подтверждён». Одобрение
не спасает: повторный вход упирается в «export path already exists».
Механизм подтверждён исполнением; величина нагрузки — чтением. Та же форма у
`package_gate` (пересчитывает SHA-256 каждого файла внутри архива) и
`analysis_gate` (полный хеш исходника до 8 ГиБ).

## P1 — причина любого отказа уничтожается

`engine.py:700-702` записывает `f"executor failed: {type(exc).__name__}"`.
Подтверждено исполнением: исключение с текстом «export failed independent
verification: duration mismatch, audio/video stream start mismatch»
сохраняется как `executor failed: ValueError`. Для системы, построенной на
квитанциях и проверках, неудачный экспорт становится чёрным ящиком и для
владельца, и для агента.

## P1 — ресурсы

Один `GET .../thumbnail` запускает полное перекодирование исходника
(`scale=640:-2,fps=25 -c:v libx264 -crf 28` по всему клипу) с таймаутом в час,
мимо учёта ресурсов и без ограничения параллельности: открытие проекта с 30
источниками выдаёт 30 перекодирований разом. Отдельно: `resolve()` считает
SHA-256 всего файла при КАЖДОМ вызове, на общем пуле потоков всего Command
Center — большая медиатека подвешивает всё остальное.

## P1 — расхождение модели и рендерера

Длительность клипа-корректировки: модель по умолчанию даёт 1 с, рендерер — 0,
JS не знает такого типа вовсе. Подтверждено исполнением: `clip.add` с
`{"adjustment": true}` проходит с 200, дальше `render.sequence_duration` = 0.0,
в JS `endTime` = `NaN`. Итог: либо экспорт падает с неверным объяснением «длина
должна быть положительной», либо слой корректировки молча не действует —
`enable='gte(t,X)*lt(t,X)'` никогда не истинно.

## P2 (кратко)

Ничего никогда не удаляется — ни экспорты, ни прокси, ни исходники, команды
удаления медиа нет вовсе. Загрузка 8 ГиБ пишется на диск дважды, второй раз без
проверки свободного места. Отложенные задачи повторяются бесконечно без
предела попыток. `GET /capabilities` блокирует цикл событий синхронным
`subprocess.run`. Полоса прогресса рендера не отображается никогда (сервер
пишет словарь, UI ждёт число). Опрос задачи не считает `waiting_approval`
конечным состоянием, поэтому при P1 выше каждая длинная выгрузка крутит опрос
вечно, а восстановление вкладки поднимает до сотни таких циклов. Схема ручки
аренды объявляет пределы шире, чем принимает хранилище. `caption_export` с
неизвестным форматом даёт 500 вместо 422. Конфликт ревизии экспорта теряет
структурный ответ.

## Главное про проверки

**35 тестов рендера пропускаются всегда**: они требуют настоящих бинарников
FFmpeg, а CI их не ставит (`grep ffmpeg .github/workflows/` — пусто). Значит
компилятор фильтрграфа, проверка результата, копирование потоков и упаковка
в CI не исполняются ни разу. Пропуск — не прохождение: это первое, что нужно
закрыть, иначе все находки выше будут возвращаться незамеченными.

## Порядок починки

Сначала P1 про недостижимый экспорт и уничтоженную причину отказа — вместе они
дают худшее сочетание: работа сделана, а владелец видит молчащую кнопку и не
может узнать почему. Затем ресурсы (перекодирование по HTTP мимо учёта), затем
расхождение длительности. Установка FFmpeg в CI — до всего остального, иначе
чинить придётся вслепую.
