# Organization Layer — инварианты безопасности

1. **Текст ≠ исполнение.** `WorkResult.claims` не читаются валидацией контракта. `success` ставит только
   `DelegationContract.validate`, и только по уликам.
2. **Доверие — свойство слоя.** `Evidence.verified=True` принимается только из источников
   `journal:*` (TaskJournal V3: чек + подтверждение), `bcc.v2.verification`, `bossman_v3.verifier`.
   Улика с `verified=True` от `model:*`/`agent:*` считается неподтверждённой и даёт ошибку контракта.
3. **Организация не одобряет.** ASK нижнего слоя → `WAITING_APPROVAL`, запрос в `HumanReviewPort`,
   исполнение продолжается только после решения владельца в очереди V2 (`svc.approvals`), которую
   организация не трогает. `RecordingHumanReview` по умолчанию ничего не одобряет.
4. **Организация не расширяет права.** Ни один модуль не вызывает инструменты, не меняет
   `permissions`, `allowed_tools`, не создаёт `ToolSpec`. Единственный путь вниз — `ExecutionBridge`
   → `UniversalComputerAgent` → V2 `decide_effect` (AUTO/ASK/DENY решает V2).
5. **Ревью — только вето.** `ReviewVerdict.approved=False` роняет результат; `approved=True` не делает
   неподтверждённое подтверждённым. Ревьюер не может быть производителем или той же моделью под
   другим именем (`route_reviewer`).
6. **Скоупы — граница, не соглашение.** `ScopedKnowledge.read(scope)` возвращает только факты этого
   скоупа; перенос — только `export()` по allowlist видов отдела-источника, с сохранением
   происхождения. `FailureMemory` — отдельный корень на отдел.
7. **Секреты не пишутся.** Все публикуемые факты и provenance проходят `bossman_v3.memory.redact`
   до записи в store. Store хранит метаданные и ссылки на улики; транскриптов и рассуждений моделей нет.
8. **События — не побочные эффекты.** Событие может создать только контракт по заранее объявленной
   `Reaction`; дальше он идёт общим циклом (казначейство, маршрутизация, V2-политика, владелец).
   Неизвестный вид события отклоняется и записывается как отклонённый.
9. **Бюджет честен.** Казначейство считает то, что сообщили нижние слои и измерители. Оно НЕ
   утверждает жёсткого провайдерского enforcement; перерасход записывается и эскалируется владельцу.
10. **Рестарт не дублирует.** COMPLETED-контракт не делегируется повторно даже при потере журнала;
    незавершённый продолжается с первого незакрытого шага журнала V3.

Проверки: `bossman-core/tests/test_v3_organization_core.py`, `test_v3_organization_e2e.py`,
`test_v3_organization_command_center.py` (живой стек через замороженный V2).
