# Аудит веб-дизайнера (`feat/web-designer-live-panel`, 54947dc)

Все находки ниже **проверены исполнением**, а не чтением: парсер и ручки
запускались на состязательных входах. Пять ранее исправленных пунктов
перепроверены и действительно закрыты (числовая сортировка снимков,
`MAX_HTML_CHARS` в `_save_code`, предел проектов при создании, песочница
превью), существующий набор — 20 passed.

Общий корень большинства находок: **любая правка переписывает весь документ**
(`parse_document → serialize`), поэтому неточность парсера — это не артефакт
превью, а необратимая порча сайта владельца.

## P1

1. **Инструкции обработки и CDATA молча удаляются.** `web_designer_dom.py:49-107`
   — нет `handle_pi` и `handle_unknown_decl`. `<?php … ?>`, `<?xml … ?>`,
   `<![CDATA[…]]>` исчезают при первой же правке кегля.
2. **Инлайновый SVG/MathML ломается приведением к нижнему регистру.**
   `:75-76`. `viewBox → viewbox`, `linearGradient → lineargradient`,
   `clipPath → clippath`. Содержимое чувствительно к регистру, браузер
   перестаёт его понимать: логотип «умирает» после смены цвета заголовка.
3. **Незакрытая разметка в конце файла отбрасывается.**
4. **Неограниченная рекурсия: глубокий документ роняет панель.** `serialize`
   (`:134,143`) и `walk_elements` (`:149-155`) рекурсивны; порог ~350 вложений
   ≈ 4 КБ при пределе 2 000 000 символов. Обработчики ловят только
   `ValueError`/`LookupError`, `RecursionError` уходит наружу — 500, после
   чего проект нельзя ни показать, ни править.
5. **Устаревший `bd_id` правит ЧУЖОЙ элемент.** `assign_bd_ids` нумерует по
   порядку документа, `resolve_element` (`:226-233`) сначала пробует `bd_id` и
   до `path` не доходит, потому что сдвинутый id всё ещё существует. В UI
   `sendEdit` не сбрасывает `state.selected`, поэтому после удаления одного
   элемента инспектор целится в другой — и подсвечивает его как подтверждение.
6. **«Текст» схлопывает всё поддерево.** `op_set_text` (`:254-255`) заменяет
   всех детей одним текстовым узлом, а инспектор подставляет `textContent`
   всего поддерева. Выбор `<section>` и «Применить» без изменений уничтожает
   всех потомков: документ на 500 элементов сжался до 38 символов.
7. **Инъекция ИМЕНИ атрибута при сериализации.** `:136-140` экранирует
   значения, но не имена. `{"attrs":{"x\" onmouseover=\"alert(1)":"y"}}`
   сохраняется как живой обработчик события; вариант с `>` разрывает тег и
   вставляет элемент. Песочница превью не даёт добраться до панели, но
   документ испорчен навсегда и скрипт уезжает в экспортированный сайт.

## P2

- `op_replace`: фрагмент, закрывающий обёртку, теряет всё после неё — при
  ответе «Элемент заменён». Тот же путь у AI-правки.
- Собственные `data-bd-id` владельца удаляются безусловно.
- Запасной путь по `path` не работает там, где нужен: браузер добавляет
  `<tbody>`, которого нет в серверном дереве; короткий путь игнорирует `nth`.
- Генератор вставляет имя/запрос в HTML без экранирования (`<title>`, логотип,
  `<h1>`).
- `ai-edit` теряет чужую запись: чтение до `await`, запись после, без блокировки;
  `current.html` пишется не атомарно.
- `meta.id` — строка, а в UI сравнивается `===` с числом: «последний проект» и
  ссылка `?project=N` не работают никогда.
- Несохранённый текст в редакторе затирается `reloadState`.

## Чисто (проверено)

Идемпотентность сериализации, квадратичный рост (16 000 элементов за 63 мс),
комментарии и `<script>`/`<style>` с разметкой внутри, `>` внутри кавычек,
сущности, экранирование ЗНАЧЕНИЙ атрибутов, обход путей по `pid`/`version`,
предел размера генерации.

## Порядок починки

Сначала 5 и 6 — они уничтожают работу владельца при обычных действиях. Затем
7 и 4. Пункты 1–3 требуют либо отказа от полной пересборки документа при
точечной правке, либо честного отказа обслуживать вход, который парсер не
умеет сохранить без потерь: молча терять содержимое хуже, чем сказать «не могу».
