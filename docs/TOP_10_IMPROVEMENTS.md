# Десять предложений Astra для Bossman V4/V5

2026-09-05. Ниже — предложения по развитию на основе текущих исходников и явно названных архитектурных пробелов, а не список уже реализованных функций. В этой интеграции создаётся общий рабочий протокол из `bossman_shared/reasoning_protocol.py`; остальные пункты требуют отдельных проверяемых изменений. Документ доступен моделям по ссылке в протоколе. Он не запускает фоновые задачи и не выдаёт новых полномочий.

| № / этап | Предложение и основание в репозитории | Критерий приёмки | Зависимости |
|---|---|---|---|
| 1 / V4 | **Одинаковый рабочий метод во всех agent loops.** Core собирает `_system_prompt` и обрезает его через `ContextBuilder`; BCC восстанавливает `checkpoint.messages`. Разные пути легко теряют одни и те же правила. Общий компактный протокол создан в этой поставке; качество ответов на живых моделях ещё нужно измерить. | Протокол присутствует в фактическом payload обоих движков после обрезки и resume; старые защиты проходят regression suite; нет ложного DONE на контрольной задаче. | `bossman_shared/reasoning_protocol.py`, `bossman/runner.py`, `bcc/engine.py`, интеграционные тесты. |
| 2 / V4 | **Показывать причину каждого DONE и блокировки.** `bossman_shared/reality_guard.py` и `reality/` дают барьер завершения; владельцу нужен короткий путь от статуса к obligation, receipt и наблюдаемому эффекту. Предлагается единое отображение существующих доказательств, а не ещё один ledger. | По каждой завершённой action-задаче можно открыть проверенное доказательство; отсутствующий/устаревший receipt виден как незавершённость; приватные данные редактируются. | Reality contracts, существующие API задач, UI, политика доступа к артефактам. |
| 3 / V4 | **Общая таблица проверенных исходов для Router.** `bcc/v2/model_router.py` принимает `role_scores`, а `docs/intelligence/BOSSMAN_INTELLIGENCE_IMPLEMENTATION_PLAN.md` отдельно называет сбор outcome table следующим шагом. Сначала связать события с независимым verdict, затем менять маршрутизацию. | Для каждой записи есть model/runtime, класс задачи, стоимость, помощь, версия и внешний verdict; до ≥20 задач на класс и ≥2 кандидатов поведение роутера не меняется. | EventBus, Model Intelligence, `learning/trace.py`, независимые проверяющие. |
| 4 / V4 | **Резерв проверки в едином бюджете задачи.** `bossman_shared/fable_budget.py` уже резервирует расходы до вызова; `bossman/context.py` имеет резерв контекста. Развить их до общего правила сохранения ресурсов на финальную проверку, не создавая альтернативный платёжный лимит. | При малом остатке задача сохраняет checkpoint с незавершёнными obligations; проверка не финансируется за счёт превышения лимита; неизвестная стоимость остаётся отказом. | Общий ledger, Governor/Resource Brain, task checkpoints, тесты исчерпания бюджета. |
| 5 / V4 | **Проверять сохранность контекста на малых локальных окнах.** `bossman/context.py` выделяет system 5% и применяет `_fit`; ссылки на правила не гарантируют, что они дошли до модели. Измерять доставку критичных ограничений, свежего failing test и provenance. | Матрица окон подтверждает сохранение защищённых инструкций и ближайшей цели; вместимость не превышена; недоверенные данные не становятся system authority. | ContextBuilder, оценка токенов/usage, фиксированные контекстные fixtures, protocol version. |
| 6 / V4 | **Единая регрессионная матрица границ Core/BCC/Fleet.** `docs/intelligence/BOSSMAN_INTELLIGENCE_IMPLEMENTATION_PLAN.md` описывает SECREM mutator substrate. Расширить существующие mutators на Reality, resume, budget и approval с обязательным запретом небезопасных вариантов. | Одна и та же мутация args, actor, target, plan, receipt, DNS/пути проверяется у каждого применимого адаптера; отклонение не совершает побочный эффект. | Существующие SECREM tests, Reality tests, CI, отдельные временные каталоги. |
| 7 / V4 | **Библиотека восстановления после неопределённого эффекта.** В `fable_budget.py` неопределённость удерживается как RECONCILING; в Fleet `LocalNodeTransport.cancel()` честно возвращает False. Расширить такой подход на задачи записи, публикации и внешних API: inspect → reconcile → retry только при доказанной безопасности. | Сбой после выполнения эффекта, но до ответа, и последующий restart дают один эффект; «cancelled» не утверждается, если действие реально продолжается. | Идентификаторы операций, task journal, receipts, поддержка идемпотентности конкретным инструментом. |
| 8 / V5 | **Распространять проверенные уроки без распространения ложных инструкций.** `learning/trace.py` уже разделяет VERIFIED и failed, запрещает hidden reasoning и требует внешнего verifier. Дополнить передачу уроков версией, сроком актуальности и отметкой superseded, используя существующее хранилище. | Урок извлекается другим агентом с provenance; устаревший урок не рекомендуется; секрет и утверждение «разрешено» из retrieval не обходят runtime gate. | Learning trace/store, ContextBuilder retrieved boundary, Learning Guard promotion. |
| 9 / V5 | **Локальная лаборатория сравнения протоколов.** `bcc/features/benchlab.py`, Model Intelligence и `bossman/learning_guard/` дают основу. Сравнивать протоколы на одинаковых задачах, включая отказ политики, а не по красноречию модели. | Отчёт содержит hardware/runtime/quant, holdout hashes, токены, время, реальные проверки и must-deny verdict; неизвестное остаётся UNKNOWN; есть откат версии. | Пункты 1, 3 и 6, доступная локальная модель, независимая контрольная выборка. |
| 10 / V5 | **Довести Remote Fleet до защищённого исполнения.** `bossman_v3/fleet/node_agent.py:RemoteNodeTransport.dispatch` сейчас явно поднимает `RemoteTransportUnavailable`. Это корректный отказ, не скрытая готовность. Следующий этап — проверенная идентичность узла, подписанный запрос, replay window, шифрование и ротация ключей. | Два реальных узла проходят execution/restart/reconcile; подмена actor и replay отклоняются до действия; компрометация одного узла не раскрывает полный контекст. | Стабильные пункты 2, 6 и 7, node identity, транспорт, минимизированные контракты, отдельный security review. |

Порядок внедрения: V4 закрепляет наблюдаемую корректность, восстановление и измерения на текущем компьютере. V5 использует эти доказательства для передачи опыта и расширения на несколько узлов. Любое улучшение оценивается по доле проверенных результатов, стоимости результата и сохранности защит; число агентов или длина рассуждения не являются метрикой качества.

Исторические архитектурные документы здесь служат источником предложений. Утверждение о готовности конкретного пункта требует свежего запуска тестов и проверки его фактического пути исполнения. Десять строк таблицы не являются десятью автоматически включёнными функциями.
