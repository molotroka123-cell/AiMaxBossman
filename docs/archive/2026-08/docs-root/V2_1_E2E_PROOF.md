# V2.1 — E2E Proof

Два сквозных прогона, которые нельзя пройти «рапортом»: оба проверяют
последствия в файловой системе, во внешних процессах и в БД, а не то,
что агент о себе написал.

## 1. §20 — автономная миссия с 10+ вызовами инструментов

**Тест:** `command-center/tests/test_v21_e2e_mission.py::test_autonomous_mission_with_ten_plus_tool_calls`
**Запуск:** `cd command-center && timeout 400 python -u -m pytest tests/test_v21_e2e_mission.py -q` → `2 passed`

### Что в этом прогоне настоящее

| Компонент | Настоящий? | Как именно |
|---|:---:|---|
| Модель | да, как HTTP-сервис | Отдельный процесс `tests/fixtures/scripted_llm_server.py` отвечает боевым OpenAI-форматом (`choices[0].message.tool_calls`, `finish_reason: tool_calls`). Разбирает ответ рабочий `bcc/providers.py` — не подменённый адаптер |
| Рассуждение модели | **нет** | Следующий шаг выбирается детерминированным сценарием. Это единственная подмена, и она названа прямо |
| Терминал | да | `asyncio.create_subprocess_shell` в разрешённом корне; pytest запускается по-настоящему |
| Память | да | Реальный индекс по реальному Obsidian-хранилищу на диске |
| MCP | да | Сервер на официальном SDK, отдельный процесс, stdio |
| Браузер | да | Предустановленный Chromium через Playwright, локальная страница по http |
| Approvals, tool_calls, checkpoints, миссии | да | Боевые таблицы и боевой движок |

### Цепочка прогона

```
Миссия «Починить проект и отчитаться»
 → memory.search   «соглашения проекта тесты»   → находит notes/conventions.md
 → terminal.run    cat calc.py                  → видит return a - b
 → terminal.run    python -m pytest -q          → 1 failed
 → mcp:echo:echo   «план: заменить минус на плюс»
 → terminal.run    правка calc.py               → exit_code=0
 → terminal.run    python -m pytest -q          → 1 passed
 → browser.open    локальная страница           → DOM-снимок
 → browser.read_dom                             → «2 + 2 = 4»
 → terminal.run    git diff --stat
 → memory.write    урок в BOSSMAN Memory/       → ASK → подтверждение человека
 → финальный отчёт
```

### Что проверяет тест (а не принимает на слово)

- `calc.py` на диске действительно заканчивается на `return a + b`;
- строк в `tool_calls` **≥ 10**, все со статусом `executed`/`error`;
- задействованы все источники: `memory`, `terminal`, `browser`, `mcp`;
- MCP-вызов дошёл до серверного процесса — счётчик пишет **сам сервер**,
  не наш код;
- в каждом запросе к модели предлагались **ровно** выданные инструменты
  (проверка по логу самого «модельного» процесса) — ни одного лишнего;
- `memory.search` вернул именно соглашение, а не пустоту;
- подтверждение человека потребовалось **ровно одно** — `memory.write`, потому
  что право `filesystem.write` агенту намеренно не выдано;
- миссия закрыта, прогресс 100 %.

### Честная граница

Это доказывает, что **исполнение** — настоящее: права, approvals, реальные
процессы, реальный браузер, реальный MCP, anti-replay. Это **не** доказывает
качество рассуждения модели: без локальной GPU-модели в этом окружении такой
прогон невозможен. Для боевой машины сценарий заменяется реальной coding-моделью
без изменений в коде — меняется только `base_url` провайдера.

## 2. §21 — инъекция сбоев

**Тест:** `command-center/tests/test_v21_failure_injection.py` → `11 passed`

| Сбой | Ожидание | Проверено |
|---|---|---|
| Провайдер недоступен | конечные ретраи, честный `failed` | попыток ≤ `max_retries`, провайдер дёрнут ≤ 3 раз, статус `failed`, не «успех» |
| Провайдер моргнул один раз | ретрай срабатывает | задача доходит до `completed`, есть событие `run.retry` |
| Инструмент завис | ограничен таймаутом | вызов оборван, модель получает текст об этом, строка `tool_calls` = `error`, run жив |
| Процесс MCP умер | ошибка данными + сервер нездоров | run `completed`, статус сервера в БД ≠ `healthy` |
| Браузер недоступен | ошибка данными, не падение | run `completed`, `tool_calls.status = error` |
| Ревьюер валит подряд | конечные итерации → человек | `waiting_approval` + approval `review_escalation`, итераций ≤ 3 |
| Процесс умер на середине | состояние переживает | протухшая аренда → `queued` (attempt+1) → задача доходит до конца |
| Модель зациклилась | нет бесконечной петли | `max_steps` обрывает; Governor ставит паузу на 6 одинаковых шагов |
| Активная работа инструментами | Governor НЕ вмешивается | 8 разных вызовов подряд — ни одной паузы (регресс на ложный сработ) |
| Неидемпотентная отправка | не переигрывается | после подтверждения ровно одна отправка, вторая строки `tool_calls` нет |
