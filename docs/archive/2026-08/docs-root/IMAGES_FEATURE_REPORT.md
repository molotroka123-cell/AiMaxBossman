## Правки, внесённые в поставленные файлы пака

Три штуки, все — «иначе не работает», не косметика:

1. **`loadProtectedImage()` — авторизация превью.** Пак слал `X-BCC-Token: getToken()`.
   Сегодня UI живёт на серверной сессии (HttpOnly-cookie `bcc_session` + CSRF на
   мутациях), а `getToken()` в `ui/api.js` — заглушка, возвращающая пустую строку.
   Заголовок убран, добавлен явный `credentials: 'same-origin'`; импорт `getToken`
   удалён. Мутации в странице и так шли через `api.raw(...)`, который подставляет
   `X-BCC-CSRF` сам, — там правок не потребовалось.
2. **Начальные значения `<select>`.** Фабрика `h()` из `components.js` присваивает
   `el.value` до добавления детей, поэтому `h('select', {value:'16:9'}, options)`
   терял значение и показывал первый пункт. В живом браузере это выглядело так:
   «Соотношение» показывает `1:1`, а состояние и подпись под кнопкой — `1280×720`.
   Добавлен локальный хелпер `withValue(node, value)`, ставящий `.value` после сборки.
3. **Пункт приёмки 12/13 «привязать изображение к коллекции».** В поставленной
   странице такого управления не было вообще: коллекцию можно было выбрать только
   *перед* генерацией. В инспектор добавлен `<select>` «Коллекция» и обработчик
   `assignCollection()` поверх уже существующего `PATCH /api/images/assets/{id}`.
   Бэкенд не менялся.

Плюс одна правка под правило проекта (не под пак): в `ensureStyles()` добавлен блок
`@media(max-width:900px)` с `min-height:44px` для табов, строк коллекций, кнопок и
инпутов страницы — до него тач-таргеты были 31–38 px.

## Ограничения

- Единственный работающий провайдер — `MockImageProvider`. Любой другой alias
  задача честно проваливает с текстом «реальный image provider для «…» ещё не
  подключён» (проверено тестом `test_real_unwired_model_fails_honestly`).
- Поиск по библиотеке: поле ввода в шапке панели есть, но не подключено к
  `?search=` — бэкенд фильтр поддерживает, UI его не вызывает.
- Вкладка «Шаблоны» — заглушка. API `/api/images/templates` (GET/POST) работает,
  UI создания шаблонов нет.
- Клики по строкам коллекций в сайдбаре не фильтруют библиотеку (обработчики пустые);
  фильтрация доступна только через API-параметры.
- Отмена задачи между кадрами реализована, но кнопки «Стоп» на mock-провайдере
  практически не поймать: генерация занимает миллисекунды.
- Отдельный ассет нельзя удалить: доступен только `status: deleted` через PATCH,
  файл с диска не убирается; сборщика мусора нет.
- Превью грузятся `fetch` + objectURL и кешируются в `PREVIEW_CACHE` навсегда
  (до перезагрузки страницы). С cookie-сессией `<img src="/api/images/...">`
  работал бы напрямую — упрощение возможно, но схему пака решено не переписывать.
- Импорт ограничен 15 MB и списком PNG/JPG/WEBP/GIF/SVG; валидации содержимого нет
  (Pillow сознательно не добавляли), проверяется только расширение.

## Точный следующий шаг для реального провайдера

Контракт уже задан протоколом `ImageProvider` в
`command-center/bcc/v2/images_runtime.py`:

```python
async def render(self, spec: dict[str, Any], index: int) -> tuple[bytes, str, dict[str, Any]]:
    """Return bytes, mime_type, provider metadata."""
```

Порядок работ:

1. **Добавить класс провайдера** рядом с `MockImageProvider` в `images_runtime.py`,
   например `OpenAIImageProvider` / `OpenRouterImageProvider`. `render()` берёт из
   `spec` поля `prompt`, `negative_prompt`, `width`, `height`, `steps`, `seed`,
   `model_alias`, ходит в HTTP через уже имеющийся в репозитории `httpx`
   (новых пакетов не нужно) и возвращает `(bytes, mime_type, meta)`, где в `meta`
   обязательно `provider`, фактический `seed` и `mock: False`.
2. **Ключ брать из `svc.vault`**, а не из окружения: провайдеры BOSSMAN уже хранят
   `api_key_enc` (Fernet) в таблице `providers`. Значит `render()` должна получать
   ключ аргументом, а не читать его сама — сигнатуру расширить как
   `render(spec, index, *, credentials)` и обновить `MockImageProvider` тем же
   ключевым аргументом (он его игнорирует).
3. **Заменить жёсткую заглушку в `features/images.py`.** Сейчас там:
   ```python
   if job.get("model_alias") != "mock-image":
       await _fail_job(svc, job_id, f"реальный image provider для «…» ещё не подключён")
   ```
   Вместо этого — реестр `PROVIDERS: dict[str, ImageProvider]` и выбор по
   `model_alias` через уже существующий `GET /api/images/models`, который отдаёт
   модели с caps `image_generation | image | images | text_to_image`. Ветка «алиас
   неизвестен → `_fail_job`» должна остаться: молча подменять реальную модель
   моком нельзя.
4. **Тайм-ауты и ретраи** — на уровне `process_one()`: обёрнуть `render()` в
   `asyncio.wait_for` и отправлять задачу в `failed` с текстом ошибки провайдера,
   а не в бесконечный `running`.
5. **Тест по образцу `test_real_unwired_model_fails_honestly`**, но с
   `httpx.MockTransport` (в `tests/conftest.py` этот приём уже используется):
   проверить, что байты провайдера попадают в файл, `meta.mock is False`,
   а сетевая ошибка даёт `status="failed"` с внятным сообщением.
6. **Только после реального прогона против живого API** статус «Реальные
   провайдеры» можно двигать с PARTIAL. До этого — PARTIAL.
