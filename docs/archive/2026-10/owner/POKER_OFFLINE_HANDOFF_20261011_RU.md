# Poker: офлайн-подготовка без трансляции — 11.10.2026

Ветка: `feat/bossman-genjutsu-jeff-unified-20261010`. Один существующий Poker
Vision backend; здесь нет другого ядра, облачной отправки или управления игрой.

## Сделано

- Исправлен X-Frame-Seq для legacy replay/window: MJPEG получает новые кадры.
- MSS создаётся в capture worker и закрывается там же, а не в API-потоке.
- Локальный OCR сохраняет только числовые черновики, проверяет хеши/число кадров,
  не перезаписывает результаты и не выдаёт частичный вывод за завершённый.
- Калибровка существующего GlyphBook выбирает два разных видео по явным SHA256;
  новый --output сохраняет старые результаты. Кандидат всегда непроверенный.
- Сборщики видео и OCR с лимитами: private output, временные метки, остановка при
  потере окна/сессии; MP4 автоматически превращается в неразмеченный датасет.
  Видео 4 FPS без аудио; реальные интервалы отдельно в JSONL, возможна окклюзия.

## Фактические проверки

```text
python -m pytest tests/test_offline_training_tools.py tests/test_window_capture_thread.py tests/test_service_api.py tests/test_recording_dataset.py -q
35 passed
```

В новом synthetic-тесте создан и декодирован настоящий MP4, подготовлены кадры
и annotations.jsonl с reviewed=false/truth=null. Сети/телефона тест не использует.

На прежних приватных записях повторён CPU-прогон нового инструмента: 262 числовых
токена для калибровки, 141 экземпляр цифр, все 10 классов; на втором видео 3304
токена: 2991 совпадение с OCR, 64 расхождения, 249 UNKNOWN. OCR-согласие 90.53%
не является независимой точностью. Новый private candidate SHA256:
`b3e2c76713ad48c11674668a38faa1dc4eb8813e5130676f5da0d74b58475a1d`.

Запись текущей игры НЕ состоялась: предыдущий live recorder завершился по
duration_limit с 0 кадрами. Это не мешает офлайн-калибровке прежних видео.

## Следующий шаг Fable

1. Не повторять импорт прежних двух видео и не считать эти кадры blind holdout.
2. По `OWNER_IPHONE_RECORDINGS_RU.md` подготовить human-reviewed truth для карт,
   банка, стеков, улицы и позиции. Неподтверждённые значения оставить UNKNOWN.
3. Использовать существующие export-reviewed, calibrate/verify и ProfileRegistry;
   проверить отдельную сессию и ошибки до активации. Не превращать OCR в truth.
4. Не объявлять LoRA, GTO-обучение, full hand history или production freeze:
   этот шаг доказал офлайн-подготовку и числовой кандидат, не всю Poker-функцию.

Медиа, метки, веса кандидата и персональные данные остаются вне Git. Живой owner
run, CI точного коммита и установленная поставка не сертифицированы этим шагом.
