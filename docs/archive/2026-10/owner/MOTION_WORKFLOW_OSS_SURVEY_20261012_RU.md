### 1.2 Правила оценки (зафиксированы до первого прогона соответствующего теста)

- Границы: жёсткая склейка засчитана при |t − t_gt| ≤ 0.10 с; плавный переход — при попадании времени/интервала детекции в
  [t0 − 0.10, t1 + 0.10] с эталонного интервала; одна детекция гасит один эталон, остальные — ложные (дубликаты тоже).
- Камера: ошибка на кадрах вне переходов, в пикселях исходного кадра; метка плана выбирается одним правилом для всех методов
  (порог зума 0.10/с по логарифму масштаба, панорамы 40 пикс/с на кадр шириной 1280, «ручная» — разброс > 1.2 пикс/кадр).
- OCR: кадры по 2 к/с; эталонная строка «ожидается», если она на экране и кадр дальше 0.4 с от её t_in/t_out; попадание =
  ≥ 85% символов покрыто текстом кадра (difflib, регистр и пунктуация не учитываются); «лишняя строка» = строка OCR, не совпавшая
  с любым ожидаемым текстом на 50%.
- Речь: WER по нормализованным токенам; слова ASR сопоставляются с эталонными по difflib; ошибка начала слова = est − gt, мс;
  время — стенное, включая загрузку модели (холодный старт), CPU 32 потока.
- Бит: F-мера с окном ±70 мс (как в mir_eval), один-к-одному; ошибка темпа в BPM (октавные ошибки считаются ошибками); фаза —
  медианная разность до ближайшего эталонного бита.

Одно решение принято ПОСЛЕ просмотра результата и помечено как таковое: слияние детекций TransNetV2, ближе 0.5 с друг к другу, в
один переход (дубликаты «одиночный кадр + many-hot» на одном плавном переходе). Приведены оба числа — «сырое» и «со слиянием».

### 3.9 Субтитры в кадр (libass) — NOT NEEDED

Недостающее — не burn-in, а генератор ASS из слов: заголовок, стиль, `\k`-теги, перенос строк (`WrapStyle: 0`, иначе строка

## 6. Ранжированная рекомендация

1. TransNetV2 (ONNX) — границы и переходы. Замена `analyze_edit.detect_cuts`/`scdet` как первого прохода не нужна: оставить их
   как дешёвый запасной путь, а в «анализе референса» использовать TransNetV2. Форма: sidecar-процесс/функция, вход — путь к
   видео, выход — JSON `{boundaries:[{t, type_hint, interval}]}`. Усилие (оценка): 0.5–1 день.
2. faster-whisper `word_timestamps=True` + замена ffmpeg-фильтра в `transcribe`. Усилие (оценка): 0.5 дня; нужна
   модель в `BOSSMAN_WHISPER_MODEL_PATH` (на ПК есть small и large-v3-turbo).
3. RapidOCR (eslav, PP-OCRv5 mobile) — текст на экране по 1–2 к/с с интервалами появления. Усилие (оценка): 1 день вместе со
   слиянием строк по времени. Маски текста — вход для п. 5.
4. Камера на OpenCV LK + маска текста (≈ 100 строк, без нового компонента). Усилие (оценка): 0.5–1 день.
5. Beat This! — для темпа/долей, c проверкой на 3–5 размеченных треках владельца до включения в резку по ритму.
6. Выравнивание wav2vec2 — только когда понадобятся караоке-слова с точностью < 100 мс (иначе faster-whisper достаточно).
7. Подключить уже имеющееся: `pysilero-vad`, libass, u2net_cloth как коммерчески чистая маска одежды.

Единый разбор референса (`analyze_reference`) из пунктов 1–4 и 7 даёт весь список брифа: сцены/длительности/склейки/переходы,
движение камеры, текст, тайминг речи. «Оставить/заменить выбранные элементы» опирается на уже существующие гейты
(лица/одежда/фон) и в этот обзор не входит.
