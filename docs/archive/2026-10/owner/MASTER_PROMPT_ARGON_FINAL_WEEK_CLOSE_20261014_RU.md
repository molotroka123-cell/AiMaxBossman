## ПРОМПТ ДЛЯ ARGON

Ты — единственный интегратор Bossman на этот прогон. Владелец прямо разрешил
довести текущую работу до `main`. Работай с фактическим состоянием репозитория,
runtime и evidence; старые SHA, отчёты и слова `VERIFIED` не считай доказательством.

### Результат прогона

К концу прогона должен существовать один пригодный для ежедневной работы Bossman:

1. один точный source SHA в `main`;
2. один собранный из него пакет с SHA-256 и обратной сверкой состава;
3. установленный runtime с совпадающими source/build/runtime identity;
4. один owner-only Telegram-пульт для PC agent, генерации, Reports и STOP;
5. один коммерчески применимый Reports-процесс для Telegram-экспорта;
6. единый честный acceptance-документ с PASS/FAIL/BLOCKED/NOT_RUN и ссылками на
   воспроизводимые evidence.

Это интеграционный и приёмочный прогон. Не добавляй новые модели, команды,
направления заработка, приложения, экраны или архитектурные ядра.

### Порядок закрытия

#### 1. Зафиксировать и перепроверить текущий код

- Проверь, что новые `pc_agent_policy_paths.py` и `reports_runner.py` входят в
  коммит и действительно импортируются рабочим путём.
- Удали ложные и исторические `VERIFIED`: результат считается проверенным только
  после фактического действия и независимой постпроверки в текущем запуске.
- Проверь защиту от обходов: исполняемые файлы по полному пути, opaque browser
  refs, shell/git options, protected paths, queue overflow, recovery/STOP и
  процессы, запущенные в середине задачи.
- Проверь testing-period: публикация только текущей сессии, строгий whitelist,
  отсутствие prompt/model output/личных путей/имён медиа, честный full state,
  rotate и preview.
- Проверь пресеты генерации: один immutable snapshot на enqueue; ограничения не
  обрезаются хвостом; конфликтующие `/poseonly`, `/outfitonly`,
  `/identitylock`, `/studioquality`, `/cleanup` разрешаются явно. Обычные
  Qwen-Image-Edit и Wan5B не называй uncensored.
- Запусти целевые тесты изменённых контуров, затем применимый полный набор.
  Сохрани команды, версии, длительность и полный итог. Существующие baseline
  failures отделяй от новых regressions; новые обязательные failures блокируют
  продвижение.

#### 2. Собрать и установить один кандидат

- Собери пакет только из чистого точного SHA `main`.
- Запиши source SHA, archive SHA-256, manifest и результат обратной сверки файлов.
- Установи кандидата штатным способом с резервной копией и проверенным откатом.
- После запуска докажи совпадение source/build/runtime SHA. `SOURCE_IDENTITY_STALE`,
  старый backend или запуск из checkout блокируют freeze.
- Не запускай второй пульт и не завершай неизвестный poller. Секреты остаются
  только в существующем защищённом конфиге.

#### 3. Провести короткую живую приёмку владельца

На установленном кандидате выполни и сохрани наблюдаемые результаты:

1. Telegram → PC agent: открыть Блокнот, ввести уникальную строку, сохранить файл,
   вернуть скриншот; проверить содержимое файла и окно независимо.
2. Вторая безопасная задача → `/stop` посреди выполнения: задача `stopped`,
   дочерние процессы завершены, после STOP нет новых шагов этой задачи.
3. `/refs`, `/edit` и `/create`: один короткий нейтральный smoke без личных фото;
   записать реальные модели, время, выходной файл и ограничения. Не выдавать unit
   test за генерацию.
4. Пресеты: доказать snapshot и отсутствие конфликтов на фактической очереди.
5. Reports: импортировать разрешённый владельцем локальный Telegram JSON/HTML,
   посчитать период 21–20 Europe/Prague, сформировать `report.md` и
   `disputed.csv`, повторить расчёт и сравнить нормализованные результаты. Бонусы,
   отменённые выводы и неполные строки должны быть видимо исключены/оспорены, а не
   потеряны. Синтетика должна иметь крупную маркировку и не считается пилотом.
6. Проверить recovery после штатного перезапуска backend и пульта. Перезагрузку
   Windows выполняй только если она заранее разрешена и можно безопасно вернуться
   в этот прогон; иначе `OWNER_REQUIRED`.

Не используй реальные сделки, кошельки, платежи, Telegram Stars, внешние
публикации или платные модели. Не отправляй личные данные в облако.

#### 4. Свести дерево и документацию

- Восстанови публичное дерево из канонического source с 15 зонами и исключи гонку
  издателей, которая ранее возвращала 13 зон. После публикации проверь реальный
  HTTP `meta.json`/`tree.json`, source SHA и число зон.
- Обнови `READY_FOR_PULT_20261014_RU.md`, current state, bug ledger и acceptance
  только наблюдаемыми фактами текущего SHA.
- Не перекрашивай 24h/48h/week ladder в PASS. Если время не прошло, поставь
  `NOT_RUN` с точной командой продолжения и требуемой длительностью.

#### 5. Freeze gate

`FINAL_FREEZE=PASS` разрешён только если одновременно доказаны чистый source SHA,
принятый архив, установленная identity, обязательные тесты, Telegram PC+STOP,
короткая генерация, реальный Reports E2E и recovery. При любом обязательном FAIL
оставь кандидат без freeze, исправь доступное в этом же прогоне и повтори только
затронутые стадии.

Финальный ответ владельцу должен содержать:

- точный SHA `main`, SHA-256 архива и установленный runtime SHA;
- таблицу обязательных gates с PASS/FAIL/BLOCKED/NOT_RUN и evidence paths;
- что реально выполнено через Telegram и Windows;
- что доказано для Reports на реальном экспорте;
- один следующий шаг владельца, только если без него действительно нельзя
  продолжить.

Не заканчивай прогон созданием ещё одного плана. Заканчивай проверяемым кандидатом
или честным перечнем конкретных блокеров с сохранёнными evidence.
