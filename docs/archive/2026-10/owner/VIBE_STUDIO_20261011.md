# Vibe Studio и профиль long_run — 11.10.2026

Ветка `feat/vibe-studio-20261011` (от `feat/bossman-genjutsu-jeff-unified-20261010`). В `main` не вливалась, ждёт приёмки владельцем.
Источник идеи: vibeOS (аудит — `VIBE_OS_AUDIT_20261011.md`).

## 1. Что это

Страница **Vibe Studio** (меню «Ещё» → Студия): пишете словами «счётчик подходов с кнопками» — Bossman ставит задачу в очередь, модель пишет маленькое **статическое** приложение (HTML/JS/CSS, без CDN и сети), статический скан его проверяет, и оно открывается в изолированной песочнице. Дальше можно просить изменения («сделай заголовок красным») — получаются версии v1, v2, … с diff и откатом. В список приложений Bossman приложение попадает **только после вашего явного подтверждения**.

## 2. Как запустить

1. Запустить Command Center как обычно (`start-bossman.ps1`). Модуль включается сам (`bcc/features/vibe.py`), отдельного флага нет.
2. Открыть страницу «Vibe Studio». Вверху — состояние: сколько моделей на каждой ступени (локальные / бесплатные / платные) и STOP.
3. Ввести запрос, при необходимости поставить «Только локальные модели», нажать «Собрать».
4. Смотреть «Ход работы»: план → лестница моделей → генерация → файлы → проверка. По готовности — «Открыть превью».
5. Изменение существующего приложения: в поле «Приложение» выбрать его, написать, что поменять.
6. «В список приложений…» создаёт подтверждение владельца №N. Решить его на странице «Подтверждения», затем «Завершить продвижение» — карточка `vibe-<slug>` появится на «Приложения» со статусом LIVE.

API (под `/api`, только владелец): `POST /vibe/jobs`, `GET /vibe/jobs/{id}/events?after=N`, `POST /vibe/jobs/{id}/cancel|retry`, `GET /vibe/apps`, `GET /vibe/apps/{slug}/versions/{n}/preview`, `GET /vibe/apps/{slug}/diff?from=&to=`, `POST /vibe/apps/{slug}/rollback|promote|promote/finish`, `GET /vibe/long-run`, `POST /vibe/stop|resume`.

## 3. Лестница моделей

`local → бесплатное облако → платное (GLM 5.3 Flash → Haiku 5.5 → Mistral Large 4)`.

- Список берётся из реестра моделей Bossman через `Registry.adapter_for`, то есть каждый вызов уже обёрнут free-only-гейтом, проверкой цены и приватности (`GovernedAdapter`).
- Платные ступени **существуют, только пока включён профиль long_run** (раздел 6). Без него они не предлагаются и всё равно были бы отказаны гейтом.
- До платной ступени дело доходит, только если локальные и бесплатные не смогли (ошибка модели, таймаут, скан отклонил после одного ремонтного раунда).
- Haiku/Mistral/GLM распознаются по имени модели **и** хосту (`openrouter.ai`, `api.mistral.ai`): модель-двойник на чужом хосте не проходит. Прямой `api.anthropic.com` под long_run не попадает — он по-прежнему под жёстким потолком Fable (3 USD).

## 4. Правила приватности

Из ПК уходит **только**: константный системный промпт + название приложения + тексты ваших запросов к этому приложению (исходный и последующие правки). Это проверяется перед каждым облачным вызовом (`assert_cloud_payload`).

Никогда не уходит: исходный код репозитория, чаты, фото, логи, память, ключи, предыдущий сгенерированный код (его видят **только локальные** модели при правке; облако получает накопленный список запросов и пересобирает приложение заново).

Дополнительно:
- Флаг задачи **«только локально»** (`privacy: local_only`) исключает все облачные ступени и дополнительно включает `execution_privacy("local_only")`: даже если бы какая-то ступень проскочила, граница провайдера выбросит отказ.
- Если в тексте запроса есть что-то похожее на секрет или локальный путь (ключи `sk-…`, `AKIA…`, токены, `C:\Users\…`, слова vault/DPAPI/`.env`/`bcc.db`), облако для этой задачи отключается автоматически, и это видно в журнале шагов. Нет локальной модели — задача падает с `no_model`, а не уходит наружу.
- Вывод модели пишется на диск ТОЛЬКО в `<data>/vibe/apps/<slug>/vN/` (имя файла проходит `safe_rel_path`: без `..`, абсолютных путей, обратных слэшей, скрытых и зарезервированных имён, не более одного уровня подпапки, расширения из белого списка; проверка содержания пути после resolve; версия никогда не перезаписывается).

## 5. Безопасность превью

Три независимых слоя:
1. **Статический скан** до первого показа и **при каждой отдаче**: нет сетевых URL/`fetch`/`XMLHttpRequest`/`WebSocket`/`EventSource`/`sendBeacon`/`import()`/Worker к хостам не из белого списка (по умолчанию пустой); нет `eval`, `new Function`, строковых таймеров, `document.write`, динамических обращений `window[...]`, `parent`/`top`; нет `<iframe>/<object>/<embed>/<base>`, `meta refresh`, форм с action, `javascript:`; секретоподобные ключи в `localStorage`, `document.cookie`, зашитые ключи; лимиты 20 файлов / 256 КБ файл / 1 МБ всего. Скан **эвристический**: он отсекает очевидное и случайное, но не заменяет слои 2 и 3.
2. **Песочница**: `<iframe sandbox="allow-scripts">` БЕЗ `allow-same-origin` — документ получает непрозрачный origin, не видит cookie сессии, хранилище и DOM Command Center.
3. **CSP-заголовок ответа** `default-src 'none'; script-src 'unsafe-inline'; connect-src 'none'; form-action 'none'; base-uri 'none'; frame-src 'none'; frame-ancestors 'self'` (без `unsafe-eval`). `connect-src` совпадает с белым списком скана.

Превью отдаётся одним самодостаточным документом (локальные `<link>`/`<script src>` встраиваются) по отдельному пути `/api/vibe/apps/<slug>/versions/<n>/preview` с авторизацией владельца. Отдельный TCP-порт не заводился: изоляцию даёт непрозрачный origin песочницы, а не путь.

Проверено в реальном Chromium (`tests/test_vibe_sandbox_browser.py`): враждебная страница с `fetch`, `WebSocket`, `<img>`, `form.submit()`, чтением `parent.document`, `localStorage`, `document.cookie` — слушатель «атакующего» получил **0 запросов**, чужие данные недоступны; негативный контроль без sandbox/CSP — утечка есть (значит тест измеряет именно защиту).

## 6. Профиль long_run (бюджет для длинных прогонов)

Идея владельца: «сними лимиты для long run» — снято **ограниченно**.

| Что | По умолчанию (без профиля) | Профиль long_run |
| --- | --- | --- |
| Платные облачные модели | запрещены free-only-гейтом | разрешены ровно: Mistral Large 4, GLM 5.3 Flash, Haiku 5.5 (по имени и хосту) |
| Суточный потолок на провайдера | — | по умолчанию и **жёсткий максимум 10 EUR** на каждого (файл может только уменьшить) |
| Потолок одной миссии (`mission_budget`) | 400 000 токенов, 2.00 USD, 6 одинаковых вызовов | 3 000 000 токенов, 12.00 USD, 12 одинаковых вызовов — только для задач с `meta.budget_profile = "long_run"`; явные значения в meta по-прежнему главнее |
| Бюджет одного прогона GLM (`economy_orchestrator`) | 0.25 USD (или `BOSSMAN_15_GLM_BUDGET_USD`) | суточный потолок GLM, сумму всех прогонов всё равно режет суточный журнал |
| Глобальная кнопка | `<data>\computer\STOP` | + `<data>\autonomy\STOP` читается перед **каждым** платным вызовом и каждым шагом Vibe Studio |

Как включить (только владелец, создаёт файл `<data>\autonomy\long_run.json`; сам продукт его не пишет):

```powershell
cd command-center
python -m bcc.long_run enable --glm 10 --haiku 10 --mistral 10   # потолки EUR/сутки, максимум 10
python -m bcc.long_run status        # профиль, STOP, расход за сегодня
python -m bcc.long_run report        # то же + история 7 дней и последний отказ
python -m bcc.long_run stop --reason "ночь кончилась"   # глобальный kill
python -m bcc.long_run resume        # снять STOP
python -m bcc.long_run disable       # вернуться к профилю по умолчанию
```

Как считается: перед сетевым вызовом бронируется **худший случай** (1 токен на символ запроса + весь `max_tokens` по цене выхода), после ответа — фактическая цена (поле `usage.cost` провайдера или токены × цена). Вызов без свидетельства расхода (обрыв, таймаут, отмена) остаётся в журнале по худшему случаю — провайдер мог списать деньги. Курс: 1 USD записывается как 1 EUR (в запас). Журнал: `<data>\autonomy\long_run\ledger-YYYY-MM-DD.jsonl` (append-only, с межпроцессной блокировкой).

**Громкий отказ**: при превышении потолка вызов **не совершается**, бросается `ProviderError(kind="budget")` с текстом `LONG-RUN CAP HIT: … The call was NOT made.`, пишется строка `refusal` в журнал и ERROR в лог; на странице Vibe Studio счётчик отказов и причина показываются красным. При активном STOP — отказ `LONG-RUN REFUSED: owner STOP …`.

Единицы цен: в таблице `models` цены — USD за 1M токенов; синтетические модели экономического оркестратора — USD за токен и помечены `price_unit: per_token`. Это было найдено и исправлено тестом реального реестра (первая версия оценщика ошиблась в 10⁶ раз и громко отказала бы всё).

## 7. Что сделано и что нет

Сделано и проверено тестами (см. `docs/owner/runs/VIBE_STUDIO_CHECKS_20261011.md`): очередь с возобновлением после рестарта, отмена, STOP, лестница моделей на реальном реестре, privacy-флаг и канареечная проверка payload, скан с 22 негативными контролями, защита путей, версии/diff/откат, превью с CSP, продвижение через подтверждение, long_run (потолки, STOP, единицы, CLI), страница UI (статические инварианты + загрузка в Chromium через ленивый реестр), песочница в Chromium.

Не сделано / честные ограничения:
- Не запускалась **реальная** генерация живой моделью (ни локальной, ни облачной): GPU занят очередью, облачные ключи в этой сессии не использовались и тратить деньги не требовалось. Все тесты — на поддельных моделях. Качество приложений от конкретных моделей не измерено.
- Журнал шагов «стримится» опросом с курсором раз в ~1.2 с (не SSE и не WebSocket).
- Скан эвристический; полагаться надо на слои 2–3.
- Имена моделей Haiku/GLM/Mistral определяются по подстроке (`bcc/long_run.py: FAMILIES`); если OpenRouter назовёт Haiku 5.5 иначе — поправить список токенов.
- Профиль читает каталог данных из `BCC_DATA_DIR`/стандартного места (как автономность); если сервер запущен с другим `data_dir` через `Settings`, STOP и журнал всё равно лежат в стандартном каталоге данных.
- Продвинутое приложение показывается страницей `GET /api/vibe/promoted/<slug>/` (нужна сессия владельца), а не отдельным процессом.
- Отдельного UI для включения long_run нет — сознательно: включает только владелец файлом/CLI.
