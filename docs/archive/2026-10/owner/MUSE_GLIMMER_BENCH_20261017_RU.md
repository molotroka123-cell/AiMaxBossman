# Muse Glimmer 30B против Qwen3.8-27B: локальный замер (17.10.2026)

Стенд: Ollama (дедикированный экземпляр :11435), обе модели на GPU (`ollama ps`: 100% GPU), ПК простаивал
(самый тяжёлый python < 0,3 ГБ), контекст 8192, температура 0,1, `think=false`, по одной модели за раз.
Модели: `muse-glimmer-30b-q4` (bartowski Q4_K_M, 17,3 ГБ, SHA256 сверен) и `Qwen3.8-27B-pi` Q4_K_M (17 ГБ).

| Задача | Glimmer: ток/с, выход | верно | Qwen: ток/с, выход | верно |
|--------|----------------------|-------|--------------------|-------|
| логика (яблоки) | 11,6; 319 ток. | да | 12,0; 74 ток. | да |
| арифметика 17*23 | 11,6; 251 ток. | да | 12,4; 21 ток. | да |
| JSON (Алматы) | 11,6; 270 ток. | да | 12,5; 17 ток. | да |

## Выводы (только то, что измерено)

- Скорость генерации сопоставима: ~11,6 против ~12,2 ток/с. Glimmer не быстрее.
- Glimmer выдаёт в 3–15 раз больше токенов на ту же задачу при `think=false` (250–320 против 17–74), поэтому время ответа
  22–38 с против 2–32 с (32 с у Qwen на первой задаче включают загрузку модели).
- Качество на этих трёх задачах одинаково (3/3). Выборка из трёх простых задач ничего не говорит о коде, длинном контексте
  и русском тексте: сравнения качества НЕТ.

## Причина прежних 0,7–2,5 ток/с (16.10)

Не доказана одним экспериментом. Что известно: тогда параллельно шёл рендер ComfyUI (~43 ГБ) и работали другие модели;
первый запуск шёл встроенным `llama-server` без GPU-бэкенда (CPU); Ollama по умолчанию просил контекст 262144 (лог:
`default_num_ctx=262144`, урезан до 131072 по обучению модели). На простаивающем ПК с контекстом 8192 те же файлы дают
~11,6 ток/с. Вероятная причина — конкуренция за память/GPU плюс огромный контекст, но вклад каждого фактора отдельно не измерялся.

## Решение по модели

Оснований заменять Qwen3.8-27B на Glimmer нет: скорость та же, ответы многословнее. Glimmer оставлен как скачанный кандидат
для проверки на задачах с кодом и длинным контекстом (отдельный замер, если владелец подтвердит).
