# Этап 2.2b: гейт одобрений v2 (независимые проверяющие вместо Claude + Codex)

Дата: 2026-10-13. Ветка-предложение: `feat/stage22b-v2-approver-gate-20261013` (не смержена, не запушена).
Живая конституция v1 **не изменена**, пин **не создан**. Пока вы сами не примете v2 и не запинуете её, поведение
прежнее: петля автономии в `BLOCKED`.

## 1. Что меняется

Правило 4 конституции v1 требует одобрения Claude **и** Codex для одного SHA. У вас нет квоты Codex и вы хотите
уйти от обоих. Код теперь выбирает требуемых одобряющих **по тексту закреплённой (запиненной) конституции**:

| Закреплённый текст | Что требует гейт |
|---|---|
| v1 (или файл нечитаем, нет пина, пин не совпал) | как раньше: Claude **и** Codex |
| v2: в правиле 4 есть фраза «independent verification of the same immutable SHA» | все тесты зелёные **и** одобрения >= 2 проверяющих моделей **разных семейств**, минимум одна внешняя (облачная, не local-only) |

Правила v2, проверяемые кодом (`command-center/bcc/autonomy/approver_policy.py`):

- одобрение привязано к паре (SHA, хэш диффа) так же, как раньше; любой новый ход писателя (другой SHA или дифф)
  обнуляет все одобрения;
- писатель никогда не проверяет сам себя: проверяющий не может быть самим писателем **и** не может быть из его
  семейства (Qwen-писатель не проверяется другой Qwen);
- одно семейство дважды (например две модели Google) считается один раз;
- неизвестный провайдер, неизвестное семейство модели или неизвестный автор кандидата: не считается (закрыто по
  умолчанию), цикл уходит в `BLOCKED`;
- проверяющий видит только промпт с диффом и тестовыми доказательствами, инструментов и записи у него нет;
  вердикт принимается только как один строгий JSON с эхом SHA и хэша диффа.

Состояния `CLAUDE_REVIEW` / `CODEX_REVIEW` сохранены (совместимость хранимых целей, журнала, контракта); в v2 это
просто «проверяющий 1» и «проверяющий 2». Добавлены псевдонимы `VERIFY_1` / `VERIFY_2`.

Проверяющие по умолчанию (только `:free` через OpenRouter, меняется переменной `BOSSMAN_AUTONOMY_VERIFIERS`):
`openrouter:nvidia/nemotron-3-ultra-550b-a55b:free`, `openrouter:google/gemma-3-27b-it:free`,
`openrouter:z-ai/glm-4.5-air:free`. Идентификаторы моделей **в живую не проверялись** (NOT_RUN): если какой-то
больше не существует, цикл честно блокируется, ничего не одобряется молча.

## 2. Что НЕ меняется

Весь список «Всегда решение пользователя», пин владельца вне репозитория (`pin()` отказывает без TTY и в сессии
агента), защищённые маски (конституция, гейт, бюджеты, vault, охранники: новый модуль тоже внутри
`command-center/bcc/autonomy/*`), ярусы релиза (всё выше автоматического яруса docs/tests выпускаете вы кнопкой
Release), STOP, правило 25 чистых циклов плюс ваше подтверждение для повышения уровня, уровни L0..L4 (старт не выше
L2), правило качества (метрика цели улучшилась, защищённые не просели). Навыки (`skills.py`) по-прежнему требуют
Claude и Codex: это отдельный ворота, в этот этап не входило.

## 3. Три шага владельца

1. **Прочитать diff.** Живая v1 против v2: `git diff --no-index docs/constitution/BOSSMAN_CONSTITUTION.md
   docs/constitution/proposals/BOSSMAN_CONSTITUTION_v2_DRAFT.md`. Значимое отличие только правило 4 и формулировки
   «оба одобрения» -> «верификаторы». Заголовок уже чистый («Version 2 - 2026-10-13»), слово DRAFT убрано; скрипт пинит ровно этот файл из
   `docs/constitution/proposals/`, байт-в-байт.
2. **Запустить скрипт в СВОЁМ окне PowerShell** (не через агента):
   `powershell -File tools\adopt_constitution_v2.ps1 -Build <корень сборки>`.
   Корень сборки: установленный бандл `C:\Users\asd\Bossman\app\BOSSMAN-Windows-x64-94e40cd17822` **или** чекаут с
   кодом (по умолчанию чекаут, где лежит скрипт). Скрипт сам спрашивает у Python этой сборки, какой файл она
   хэширует, показывает diff, требует ввести `ADOPT-V2`, делает бэкап `<файл>.bak-<время>`, подменяет **только**
   этот файл, проверяет хэш и запускает штатный `bossman autonomy constitution pin`: там вы вводите первые 12
   символов SHA-256. Сам скрипт пин не пишет и сам подтверждение не вводит.
   Важно: в установленном бандле 94e40cd1 путь по умолчанию указывает на `runtime\Lib\docs\constitution\...`
   (такого файла нет, поэтому пин там невозможен и сейчас). Скрипт создаст файл именно по этому пути; новый код
   (`constitution.default_constitution_path`) дополнительно умеет искать `<бандл>\docs\constitution\...`.
3. **Проверить статус:** `bossman autonomy constitution status` (ожидается `OK ... pinned by the user`) и
   `bossman autonomy status`. Дальше цикл сам применит политику v2; ничего вручную перезапускать не нужно.

## 4. Риск (честно)

Кто проверяет теперь: тесты Bossman (в изолированной копии, как раньше) плюс две бесплатные облачные модели разных
семейств, которые не писали изменение. Claude остаётся необязательным аудитором по вашему вызову.

- **Слабее по уровню одного проверяющего.** Бесплатные модели, как правило, слабее Claude и Codex в поиске тонких
  ошибок. Две именованные подписочные CLI были сильнее «двух бесплатных».
- **Сильнее в одном: структура независимости.** v2 кодом требует разных семейств и запрещает писателю и его
  семейству проверять себя; в v1 допускалось, что один из двух (автор) одобряет, лишь бы второй одобрил.
- **Остаются коррелированные ошибки** (обе модели могут пропустить одно и то же), возможны отказ лимитов и
  недоступность бесплатных провайдеров: в этом случае система блокируется, а не слабеет.
- **Что реально страхует:** тесты, метрика цели и защищённые метрики на стейдже, защищённые маски, ваш Release для
  всего выше docs/tests, откат, STOP. Автоматический выпуск без вас возможен только в ярусе docs/tests и только
  с уровня L3, а уровень L3 требует 25 чистых циклов и вашего подтверждения; пока уровень L2, каждый кандидат
  ждёт вас.

Не запускалось (NOT_RUN): живой вызов OpenRouter за вердиктом, NVIDIA NIM как транспорт проверяющего (нет
клиента в цикле; id `nvidia:...` распознаются, но без транспорта цикл блокируется), сам скрипт `adopt` (только
разбор парсером PowerShell и тест отказа при перенаправленном вводе/выводе).
