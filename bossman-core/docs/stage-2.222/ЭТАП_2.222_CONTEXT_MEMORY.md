# ЭТАП 2.222 — Context & Memory Engine

**Статус:** implementation-ready handoff для Claude Code.  
**Цель:** повысить полезность контекста локальных LLM без скрытой потери смысла, уменьшить шум и повторное чтение, добавить долговременную память с происхождением каждого факта.

## Главный принцип

Этап 2.222 не пытается «сжать всё любой ценой». Он разделяет контекст на сырой источник, индекс, структурированную память и финальный context pack. Сжатие должно быть проверяемым и обратимым по источникам: любой важный тезис в памяти или compact-handoff обязан вести к исходному документу/сообщению.

## Что встроено кодом

`bossman/context_engine/` содержит готовый каркас: SQLite/WAL store, FTS5 lexical search с portable fallback, гибридный retrieval, pluggable embeddings/reranker, семантический chunking, memory manager, conflict marker, knowledge distiller, adaptive context compiler и новый Compact Skill.

Пакет работает без обязательных тяжёлых зависимостей. `HashEmbedder` существует как deterministic fallback для тестов и первой установки. На целевой машине Claude обязан подключить нормальную локальную multilingual embedding-модель через интерфейс `Embedder`, а затем локальный cross-encoder через `Reranker`, не переписывая остальную архитектуру.

## Что заимствуем концептуально

Не копировать чужие репозитории целиком. Перехватить архитектурные идеи: deterministic pre-compression, AST/code graph, context compiler, sliding hot window, conversation/decision graph, structured handoff, tool pruning, provenance, token telemetry. Любая внешняя библиотека проходит benchmark и license/security review до production.

## Ключевые запреты качества

1. Не заменять сырой источник summary и затем удалять источник.
2. Не считать LLM-summary «без потерь».
3. Не перезаписывать конфликтующие факты молча.
4. Не загружать всю память во все prompts.
5. Не использовать embedding similarity как единственный retrieval signal.
6. Не продвигать memory candidate автоматически в durable `ACTIVE`, если это решение/ограничение/секреточувствительный факт.
7. Недостаток контекста лучше обозначить явно, чем заполнить окно слабым материалом.
8. Recent transcript в Compact Skill сохраняется verbatim прежде, чем урезаются старые extractive сигналы.

## Дополнительные идеи, добавленные сверх исходного плана

### Context checksum anchors
Перед compact/distill извлекать критические anchors: пути файлов, commit SHA, IDs, числа, версии, имена функций, explicit constraints. После compaction проверять, что обязательные anchors не исчезли. Для высокорисковых задач fail closed: если anchor потерян — использовать более длинный pack.

### Dual-channel context
Держать отдельно `evidence` и `interpretation`. Evidence — verbatim/near-verbatim chunks с provenance. Interpretation — память и distillation. Модель всегда понимает, где первичный источник, а где производная запись.

### Negative memory
Хранить не только успехи, но и подтверждённые неудачные подходы с причиной и тестом, который подтвердил исправление. Coder-агент сначала ищет failure memory перед повторным экспериментом.

### Context shadow benchmark
При важных задачах можно в фоне (опционально) сравнивать два context pack: новый оптимизированный и baseline. Сравнивать ответ judge-тестом/детерминированными assertions. Это позволяет менять retrieval без деградации «на глаз».

### Retrieval diversity floor
Финальный pack не должен состоять из 15 почти одинаковых chunks одного файла. Вводится diversity cap по document/source и минимальное число независимых источников, если запрос исследовательский.

### Freshness hierarchy
`active decision > current branch code > latest audit > old spec > historical chat`. Релевантность не должна позволять устаревшему spec победить текущий код только из-за совпадения слов.

### Query decomposition
Сложный запрос разбивается на 2–6 subqueries, retrieval идёт отдельно, потом объединяется. Это особенно важно для «сравни X, вспомни решение и найди код».

### Retrieval retry
Если top hits слабые, система не заполняет окно мусором, а делает второй проход: query expansion, aliases, русский/английский вариант, code symbols.

### Tool schema pruning
Агенту передаются только tools, релевантные текущей задаче. Это уменьшает system/tool context без сжатия пользовательских данных.

### Context TTL
Working/episodic memory получает TTL. Stable facts TTL не имеют, но имеют `last_verified_at`. Stale information не удаляется — понижается в ranking.

### Sensitivity-aware retrieval
Chunks маркируются `sensitivity`. Агент без соответствующего permission не должен получать sensitive chunk даже если он релевантнее.

### Model-specific packer
Для coder/vision/research/browser агентов разные веса и формат pack. Один универсальный prompt считается anti-pattern.

## Acceptance gate

Этап не считается завершённым пока: unit tests зелёные; benchmark показывает отсутствие деградации на golden tasks; provenance присутствует; conflict state тестируется; compact сохраняет recent transcript и memory IDs; индекс можно rebuild; store переживает restart; raw sources не удаляются; telemetry показывает raw/final token count.
