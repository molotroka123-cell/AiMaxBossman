# Регламент использования локального прокси LiteLLM

## 1. Архитектура интеграции
Использование локального сервиса LiteLLM Proxy в качестве единого шлюза для стандартизации вызовов к разнородным провайдерам моделей (OpenAI, Anthropic, Ollama, OpenRouter).

## 2. Контроль расходов и квот
1. Единый формат запросов: преобразование форматов сообщений и вызовов функций к стандарту OpenAI-compatible.
2. Локальное ограничение частоты: контроль RPM (requests per minute) и TPM (tokens per minute) на уровне прокси.
3. Учёт бюджета: отслеживание фактических затрат по каждому ключу и агенту с немедленным отсечением при достижении лимита.

## 3. Безопасность шлюза
- Привязка прокси строго к адресу 127.0.0.1.
- Запрет передачи приватных заголовков во внешние журналы отладки.
