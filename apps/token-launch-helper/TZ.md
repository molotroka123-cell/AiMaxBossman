# ТЗ: помощник запуска одного токена на pump.fun (прототип, 09.10.2026)

## Цель
Владелец запускает ОДИН токен с ОДНОЙ прозрачной покупкой разработчика с ОДНОГО кошелька и подписывает транзакцию сам, на своём ПК. Покупка разработчика — гарантированно ПЕРВАЯ на кривой (защита от снайперов).

## Как обеспечивается «первая покупка»
Создание токена (`create_v2`) и покупка разработчика собираются в ОДНУ транзакцию (`createV2AndBuyInstructions`): она исполняется атомарно, ни одна чужая покупка не может встать между созданием и покупкой разработчика. Для быстрого попадания в блок — опциональная приоритетная комиссия (`ComputeBudgetProgram.setComputeUnitPrice`). Никакого роя транзакций, высокочастотной торговли и бандлов не требуется и не делается.

## Что входит
1. Ввод: название, тикер, описание, картинка (файл), сумма покупки разработчика в SOL (0 = без покупки), публичный адрес кошелька владельца, приоритетная комиссия (микролампорты за CU, по умолчанию 0).
2. Сборка транзакции локально официальным SDK `@pump-fun/pump-sdk` (MIT, версия закреплена); количество токенов — `getBuyTokenAmountFromSolAmount`; явный лимит вычислений; ключ минта генерируется локально.
3. Раскрытие: в описание автоматически дописывается «Dev buy: X SOL from <адрес>» (если X > 0).
4. Проверка без денег: `simulateTransaction` на mainnet RPC (sigVerify=false, свежий blockhash) — обязательный шаг перед отправкой.
5. Отправка только по явной команде `--send` + файл ключа владельца + фраза подтверждения; подпись локально; вывод подписи и ссылки на обозреватель.

## Чего НЕТ (в коде, с тестом на каждое)
Покупки с нескольких кошельков, автоторговля, продажи, автодеплой и деплой по трендам, повторные запуски в цикле; отправка без симуляции/подтверждения; передача приватного ключа куда-либо; загрузка метаданных без отдельной команды (в проверке — заглушка `uri`).

## Приёмка (рабочий протестированный прототип)
- `node --test`: транзакция = (лимит CU [+ цена CU]) + create_v2 + ровно одна покупка одного кошелька, покупка идёт сразу после create в той же транзакции; сумма покупки = введённой; раскрытие в описании; отказы: 2+ кошелька, сумма ≤ 0 при покупке/выше лимита, отправка без симуляции/подтверждения.
- Интеграция: реальная `simulateTransaction` против mainnet RPC с `err: null`; журнал сохраняется в `evidence/`.
- Реальная отправка — только владельцем.
