# Bossman Shorts Factory

Изолированное приложение (по образцу `apps/war-terminal`), которым Bossman управляет через API `/api/v1`
(loopback, порт **8860**, токены ролей `viewer < editor < owner` в `~/.shorts-factory/tokens.json`).
Цель владельца — заработок на YouTube Shorts: Bossman находит сильные моменты, режет вертикальные ролики,
пишет заголовки/хэштеги и ставит в очередь. **Публикация — только после «да» владельца на каждый ролик.**

Запуск: `cd apps/shorts-factory && python -m shortsfactory --port 8860` → UI: `http://127.0.0.1:8860/ui/`
(вставьте токен `owner` из `tokens.json`). Тесты: `python -m pytest -q` (офлайн, ffmpeg нужен).

## Как это работает

1. **Источник + права.** `POST /sources` (editor) регистрирует файл: `kind` = `own` (запись владельца) |
   `generated` (сделано на ПК) | `licensed` (чужое, только с `licence_url`/`licence_doc`), `rights_note`,
   `ai_generated`. При регистрации `approved_by_owner=false` всегда. Подтвердить права может только владелец:
   `POST /sources/{id}/rights {approve:true, confirm:"ДА", note}`. Одобрение привязано к отпечатку файла
   (размер + sha256 первых/последних МиБ): подмена или перекодирование файла, смена пути/вида/основания
   прав — одобрение аннулируется. Без одобрения конвейер **отказывает** (403 `RIGHTS_NOT_APPROVED`) до любой
   работы; проверка повторяется перед каждой резкой и при каждой постановке в очередь (`pipeline.enqueue`).
2. **Расшифровка** — faster-whisper локально (CPU int8, модель `small` из `Bossman\models\voice\whisper`,
   word timestamps, кэш по отпечатку файла).
3. **Сигналы** — громкость (RMS по 0,5 с, z-оценка), смены сцен (ffmpeg `scdet` на 5 к/с и 160 px;
   запасной вариант — детектор разностей кадров из `tools/trend_edit/analyze_edit.py`).
4. **Хайлайты** — окна 15–60 с по границам фраз; прозрачная эвристика (громкость, плотность речи,
   «крючок» в первой фразе, смены планов, чистый конец) + локальная Qwen через Ollama (уже загруженная
   модель предпочтительна, `think:false`, JSON) ставит `hook_score` 0–10 с причиной. Итог =
   0,6·LLM + 0,4·эвристика; выбираются непересекающиеся моменты. Если LLM недоступна — ранжирование по
   сигналам, статус честно `NOT_CONNECTED/ERROR`. **Это ранжирование внутри источника, не прогноз просмотров.**
5. **Рендер 9:16** (ffmpeg, libx264 CRF 20, AAC 192k, `-threads 4`):
   * `cover` — источник можно уменьшить до заполнения 1080×1920 → масштаб ≤ 1 + кроп вокруг лица;
   * `inset` — источник ≥ 1080 по ширине, но мал для 9:16 (например 1920×1080) → нативное окно 1080 px
     вокруг лица 1:1 поверх размытой затемнённой подложки (подложка — декор, контент не увеличивается);
   * `native` — источник уже 1080 → нативное разрешение, кроп 9:16, выход меньше 1080×1920 и это
     пишется в `framing.note` (правило владельца: никаких мягких апскейлов);
   * лицо: OpenCV Haar, а если в этой сборке cv2 его нет (OpenCV 5) — `yoloface_8n.onnx` из FaceFusion на
     CPU (2 потока); не найдено — центр;
   * субтитры из слов расшифровки (2–5 слов, ASS, жирный белый с обводкой), позиция настраивается
     у источника (`caption_margin_v`), чтобы не перекрывать уже вшитый текст;
   * громкость: `loudnorm I=-14 LUFS, TP -1.5`; оригинальный звук, музыка не добавляется; максимум 60 с.
6. **Проверка ffprobe** каждого выхода: разрешение = обещанному, вертикаль, длительность ±0,35 с и ≤ 60 с,
   есть аудио, H.264, нет апскейла выше источника. Не прошёл — элемент остаётся `draft` и одобрить его нельзя.
7. **Метаданные** — локальная Qwen: заголовок (≤ 100 символов, без `<>`, кликбейт-слова вычищаются),
   описание, хэштеги (`#shorts` + 3–5 тематических). Источник `ai_generated` или элемент
   `realistic_synthetic` → `contains_synthetic_media=true` и строка раскрытия в описании. Правкой
   метаданных флаг раскрытия выключить нельзя.
8. **Очередь**: `draft → ready → approved_by_owner → scheduled|published`, `rejected` — конечное.
   Одобряет/отклоняет/публикует только `owner`. `youtube.upload(...)` вызывается **только** для
   `approved_by_owner`, по умолчанию `privacy="private"`; при `publish_at`/`use_slot` — всегда private +
   `publishAt` (так требует YouTube). Правка метаданных после одобрения возвращает элемент в `ready`.
   Слоты: по умолчанию 3/день (10:00, 15:00, 19:30, Europe/Prague), `PUT /schedule` — только владелец.
9. **Аудит** — хэш-цепочка как в war-terminal (`/audit/verify`), любое изменение строки ломает проверку.

### Новостная линия (оригинальные ролики)

`POST /jobs/news {source_id, query, max_images≤2}`:
GDELT DOC API (`mode=artlist`, ключ не нужен; ≥ 5,5 с между запросами, кэш 30 мин, на 429 — пауза и
повтор, потом честная ошибка; GDELT ищет по машинному переводу на английский, поэтому ключевые слова —
английские + `sourcelang:russian`). Если GDELT отвечает 429/пусто и задан `rss_keywords` (regex), берутся
открытые RSS изданий (`SHORTS_NEWS_RSS`, по умолчанию lenta.ru, meduza.io, ria.ru: заголовок + подзаголовок
+ ссылка), источник и причина фолбэка пишутся в элемент (`story.feed`, `story.fallback_reason`) → группировка заголовков об одном событии (больше изданий — выше) →
локальная Qwen пишет 70–110 слов по-русски **только из заголовков** → **исполняемая проверка фактов**:
каждое число должно быть в заголовках, издания — из полученных доменов, никаких цитат, которых нет в
заголовках, объём 30–50 с; модель, которая продолжает выдумывать, получает отказ (`FactCheckError`) →
озвучка **Piper** `ru_RU-denis-medium` (локально; у Kokoro v1.0 нет русского голоса) → до 2 иллюстраций
через Bossman direct-gen (`z-image-turbo` 864×1536, кладутся в кадр в нативном размере на размытую
подложку) или текстовые карточки → 1080×1920, заголовок сверху, «Источник: <издание>» всё время на экране,
субтитры → `ready`. В описании — ссылки на статьи и атрибуция GDELT. Чужие видео не используются.

## Люди в кадре: согласие (обязательно)

* У источника есть `people_in_frame` и `consent_recorded`. Флаг людей ставится при регистрации или
  **автоматически**, если детектор лица нашёл лица при нарезке; редактор снять его не может.
* Согласие записывает только владелец: `POST /sources/{id}/consent {consent:true, confirm:"ДА", persons:[...], note}`.
  Смена файла источника аннулирует согласие.
* Пока согласия нет, элемент очереди помечен `blocked_consent=true`; **одобрение и публикация отказываются**
  (403 `CONSENT_REQUIRED`), отзыв согласия после одобрения тоже блокирует загрузку.

## Субтитры: одна фраза — один раз

Если в источнике уже есть текст речи на экране (`has_burned_captions=true`), второй слой субтитров не
накладывается (`captions.burned=false` + причина). Иначе субтитры ставятся ниже лица (по умолчанию 22 % от
низа кадра, `caption_margin_v`). Неодобренную нарезку можно перерендерить с текущими настройками источника:
`POST /queue/{id}/rerender` (старый элемент снимается с пометкой `superseded_by`); неодобренный элемент
редактор может снять `POST /queue/{id}/withdraw`. Автоматического распознавания текста в кадре (OCR) пока нет.

## Политика прав (обязательна)

* `own` — записи владельца; `generated` — сгенерировано на ПК; `licensed` — сторонние фильмы/видео
  **только** после того, как владелец записал разрешение на этот конкретный источник (ссылка/документ).
* Любой другой материал (скачанные чужие подкасты, ролики с YouTube, стоки без проверки лицензии) в
  очередь не попадает. Пример: `podcast-studio/footage/yt/src.mp4` («Сделано Круто!») и
  `podcast-studio/digest/audio.m4a` (David Packouz) — **чужие**, их не регистрировать как `own`.

## Политики YouTube, которые учтены

* **Повторно используемый контент (reused content)** — нарезки чужих видео без существенного вклада не
  монетизируются; поэтому чужое — только по лицензии, а новости — оригинальный текст/голос/визуал.
* **Неаутентичный / массовый контент** (шаблонный, повторяющийся «конвейер») — в YPP запрещён; поэтому
  каждая публикация проходит «да» владельца, есть лимит слотов в день, заголовки не штампуются.
* **Раскрытие ИИ** — реалистичный изменённый или синтетический контент (ИИ-голос, сгенерированные лица/сцены)
  отмечается `status.containsSyntheticMedia=true`; мы ставим флаг консервативно для любого ИИ-источника.
* **Никакой накрутки** — покупка просмотров/подписчиков, sub4sub, автокомментарии/лайки не реализованы
  (`POST /actions/*` → 403) и нарушают правила о фейковой активности.
* **Новости** — нейтрально, без обвинений, с указанием издания; без выдуманных фактов (проверка выше).
* Загрузка через API от непроверенного проекта Google может принудительно стать `private` — модуль
  `youtube` возвращает предупреждение.

## Цель монетизации (это цели, не обещание)

YouTube Partner Program: **1 000 подписчиков** и **10 млн просмотров Shorts за 90 дней**, или 4 000 часов
просмотра длинных видео за 12 месяцев. UI показывает только числа из `youtube.channel_stats`; просмотры
Shorts за 90 дней — нижняя оценка по последним загрузкам (Data API не отдаёт точную сумму), часы просмотра —
«нет данных». Пороги могут меняться; доход не гарантирован.

* `tools/motion_studio/make_video.py`, `tools/promo_video/voice.py` — локальный TTS (Kokoro): по образцу
  вызова, но для русского выбран Piper (`media-runtime/voice-venv`, модели `models/voice/piper/ru`).

* FaceFusion `yoloface_8n.onnx` (уже на ПК) — детектор лица для кадрирования.
* `tools/motion_workflow`, `tools/video_studio`, `bcc/features/video_studio.py`, `motion_workflow_api.py`,
  `tools/seedance_shorts.py` — прочитаны: это редактор/планировщик проектов и облачная генерация Seedance;
  для нарезки по транскрипту подходящих чистых функций там нет, поэтому не подключались.
* `shortsfactory/trends.py`, `shortsfactory/youtube.py` — пишет параллельный агент; здесь только импорт
  и обработка `NOT_CONNECTED`.

## Открытые вопросы

* Текст в кадре источника не распознаётся автоматически (флаг `has_burned_captions` ставит человек).
* Режим текстовых карточек статичен (без анимации); при недоступной GPU-генерации ролик визуально простой.
* GDELT часто отвечает 429 с этого IP; есть RSS-фолбэк, но группировка заголовков разных изданий грубая.
* Просмотры Shorts за 90 дней — только нижняя оценка (Data API), точные — YouTube Analytics API (не подключён).

## Нагрузка

Одна тяжёлая задача за раз (lock), ffmpeg `-threads 4`, whisper CPU 4 потока, детектор лица 2 потока,
LLM — уже загруженная модель Ollama (без загрузки второй).
