# OSIRIS — порядок сбора данных

Локальная панель. Источники только открытые и только разрешённым источником способом. Факт без паспорта происхождения не сохраняется.

## 1. Паспорт факта

У каждого факта: источник, ссылка, время наблюдения, метод получения, лицензия, уверенность. Нет поля — нет записи.

## 2. Категории источников

A, B, D и C с разрешающим `robots.txt` — свободно по умолчанию (уровень 2).

## 2.1 Чьё согласие требуется

То, что касается вас и ваших систем, вы можете разрешить сами. То, вред от чего падает на третье лицо, которое вас об этом не просило, вы разрешить не можете — не потому что модель так решила, а потому что согласия этого человека у вас нет.

### Уровень 0 — закрыто наглухо, не открывается ничем

1. Купленные «слитые базы», комбо-листы, дампы персональных данных. Данные уже украдены у людей; покупка — соучастие, а не сбор.
2. Вход под чужими учётными записями, чужие cookie, сессии, токены. Это доступ к чужой системе без разрешения владельца системы.
3. Обход капчи, paywall, anti-bot защиты. Источник прямо сказал «нельзя»; обход — это отказ услышать.
4. Распознавание лиц и биометрия по фото людей для установления личности.
5. Слежка за конкретным частным лицом: перемещения, режим дня, окружение, деанонимизация под псевдонимом.
6. Сбор из закрытых профилей и групп, куда доступ дан лично конкретному человеку.

Почему эти шесть неоткрываемы: каждый либо преступление независимо от того, кто его совершает, либо его вред падает на человека, который не давал согласия — а ваше разрешение его согласия не заменяет. Вы вправе разрешать про себя и про свои системы.

Код: `osiris.policy.LEVEL0`. Именной грант на эти классы отклоняется. Локальная модель этот контур не снимает.

### Уровень 1 — открывается вашим явным письменным решением

По умолчанию выключено, но законные применения есть, и решение ваше:

1. Скрейпинг страницы, где `robots.txt` не запрещает прямо, но и не разрешает — серая зона, решение под конкретный домен.
2. Темп выше «вежливого» там, где источник лимит не публикует.
3. Данные публичных лиц по должности — директор, учредитель, официальный представитель. По должности, не по частной жизни.
4. Связанные лица из официальных реестров — учредители, директора: поля, публичные по закону.
5. Хранение сырья дольше стандартного TTL — когда нужно вернуться к материалу.
6. Платные API — уже подпадает под бюджетный гейт, отдельного механизма не нужно.
7. Экспорт собранного наружу — файл, отчёт, отправка кому-то.
8. Повышение гипотезы до факта по слабым признакам (имя + город) — только человек, с записью автора и времени.

Уровень 1 — это ваша ответственность за спорное решение внутри закона, а не способ закон обойти. Персональные данные остаются персональными данными.

### Уровень 2 — свободно по умолчанию

Категории A, B, D и C с разрешающим `robots.txt`.

### Что технически значит «явное решение»

Не глобальный тумблер «разрешить всё», а именной грант: запись с датой, сроком, конкретным источником или субъектом и причиной; в коде — ограниченное разрешение ровно на это; каждое действие под ним пишется в журнал; по истечении срока закрывается само. Просроченный грант не продлевается молча.

Механика: `POST /api/grants` → `osiris.grants.GrantBook`. Поля: `author`, `created_at`, `expires_at`, `source_or_subject`, `reason`, `clause`. Журнал: `grant.issued`, `grant.expired`, `grant.revoked`, плюс каждое действие с `grant_id`.

## 3. Порядок работ

1. Классифицировать запрос. Совпадение с уровнем 0 — отказ, без обхода.
2. Если уровень 1 — найти неистёкший именной грант на этот источник/субъект и эту оговорку. Нет гранта — отказ.
3. Прочитать `robots.txt`. `Disallow` = уровень 0 (обход защиты). Неопределённость = уровень 1.
4. Забрать данные разрешённым методом. User-Agent идентифицирует OSIRIS. Чужие cookie и сессии не используются.
5. Собрать паспорт. Без паспорта факт отбрасывается.
6. Записать в SQLite, обновить граф организаций, событие в шину и журнал.
7. Экспорт наружу только при гранте `export_outbound`.
8. Гранты: выдать / отозвать / дождаться истечения. Молчаливого продления нет.

## 4. Локальная модель

Облачный лимит сессии (800k) на локальный рантайм не вешается. Облачный safety-overlay не инжектится. Политика уровней живёт в коде инструментов, не в промпте провайдера.

Хук будущей локальной модели: реализовать `osiris.local_runtime.LocalModel` и подставить в `LocalRuntime`. Инструментов уровня 0 в этом интерфейсе нет и не будет.
