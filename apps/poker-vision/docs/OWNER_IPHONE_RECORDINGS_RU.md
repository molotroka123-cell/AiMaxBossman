# iPhone → Poker Vision: подключение и подготовка записей

## Текущее состояние

Код подготовки записей добавлен в существующий пакет Poker Vision.
Он не запускает fine-tune и не включает советы/действия в стороннем руме.
Cash и tournament — отдельные метаданные. Семплированные кадры не заменяют
полную историю действий. Распознавание обучается только после разметки и
проверки на отдельных сессиях; стратегия требует проверенных solver targets.

При первоначальном запуске portable процесс появился, но доступного окна

отклонила запуск MSI (`blocked by policy`). Установка требует ручного запуска
владельцем; её успех и входящий экран пока NOT_VERIFIED.

1. Владелец запускает `uxplaywindows-installer.msi` из этой папки и завершает
   установку, включая необходимый запрос администратора Windows.
2. Запускает установленный UxPlay. Управление обычно через значок в трее.
3. iPhone и ПК подключены к одной локальной сети, без изоляции клиентов Wi-Fi.
4. На iPhone: свайп вниз из правого верхнего угла → «Повтор экрана» →
   `uxplay-windows`. Если запрошен код, вводится показанный приёмником код.
5. Проверка: открыть безопасный экран часов/настроек и наблюдать изменение
   изображения на ПК. Затем перейти в разрешённый тренировочный интерфейс.
6. Отсоединение: «Повтор экрана» → «Остановить повтор».

VPN-туннель сам по себе не гарантирует AirPlay mDNS discovery. Firewall и UAC
нельзя считать настроенными, пока соединение не прошло. Не отключать firewall.
UxPlay передаёт экран; Poker Vision ещё требует калибровки именно этого layout.

## Подготовка присланных записей

Из `apps/poker-vision` в Python-окружении с зависимостями приложения:

```powershell
python -m pokervision.recording_dataset prepare "C:\Users\asd\Videos\cash.mp4" --output "C:\Users\asd\Videos\Bossman-Poker-Private" --game cash --split train --session-group cash_session_01
python -m pokervision.recording_dataset prepare "C:\Users\asd\Videos\tournament.mp4" --output "C:\Users\asd\Videos\Bossman-Poker-Private" --game tournament --split test --session-group tournament_session_02
```

Все части одной сессии имеют один session-group и один split. Не выдавать
другую запись той же раздачи за независимый тест. Для cash и tournament нужны
собственные train/dev/test сессии. Тестовую сессию не использовать при калибровке.
По умолчанию 1 кадр/с, максимум 1800 PNG; ограничение явно записывается в manifest.
Переменная частота кадров телефона может давать неточные nominal-FPS таймкоды;
перед точным сопоставлением действий нужна проверка PTS отдельным декодером.

## Разметка и экспорт

`annotations.jsonl`: каждому проверенному кадру присвоить `hand_idx` и truth,
затем `reviewed: true`. Неизвестные кадры оставить с truth=null/reviewed=false.
Пример truth (пример формата, не метка реального кадра):

```json
{"hero_cards":[{"card":"As"},{"card":"Kd"}],"board":[],"street":"preflop","pot":75,"hero_stack":1000}
```

```powershell
python -m pokervision.recording_dataset export-reviewed "C:\Users\asd\Videos\Bossman-Poker-Private\cash-<hash>"
```

Экспорт создаёт labels.jsonl для существующего `eval.dataset.load_session`.
Повторный экспорт не перезаписывает файл. Проверяются хеши кадров, дубли карт,
соответствие street/board, числовые значения и наличие human review.
Один объект разметки не является полной hand history или целью GTO-обучения.
ROIs/карточные примеры для существующего RoiAdapter требуют дополнительной разметки.
Калибровка/heldout verification идут через существующие `/api/v1/calibrate` и
`/api/v1/verify`, ProfileRegistry; новый профиль не активировать только по наличию.

PKO дополнительно требует стеков соперников, bounty/payouts и полного action log.
GTO Wizard — только разрешённый post-session доступ; скрейпинг решений и обучение
по его данным без соответствующего разрешения не включены.
Все медиа/лейблы лежат вне Git; опубликованы только код, synthetic tests и документация.

## Черновая разметка GLM по поручению владельца (11.10)

`tools/audit_owner_recordings_glm.py PRIVATE_OUTPUT VIDEO...` отправляет ровно
6 JPEG-кадров каждой записи модели `z-ai/glm-5.3-flash` через OpenRouter.
Это отдельная явно разрешённая владельцем отправка выбранных покерных кадров
облачному аудитору. Не применять к личным фото/другим видео без разрешения.
Ключ читается из существующего provider-keys.env, не выводится.
Нет повторов, подмены модели, автообучения, активации профиля или советов в игре.
При ошибке сети исход неизвестен: не повторять автоматически платный запрос.

В приватной папке сохраняются исходный SHA256, кадры, таймкоды по nominal FPS,
ответ модели и usage/cost. Проверять response_model, finish_reason и полноту
JSON перед использованием. Ответы GLM — предложения разметки, не проверенные
labels.jsonl: запрещено автоматически выставлять reviewed=true/verified=true.
Нужны раздельные сессии калибровки и независимой проверки, не случайные кадры
одной раздачи в train и test. Просмотр 6 кадров не доказывает полноту hand history.
# Локальный прогон OCR и кандидат цифр

`--game unknown` сохраняет отсутствие подтверждённого типа игры; режим не
угадывается. Две записи с неизвестной принадлежностью к сессии сохраняются
в одной группе train. Они не считаются независимым holdout автоматически.

Из `apps/poker-vision`, с рабочим окружением RapidOCR/OpenCV:

```powershell
python tools/local_recording_ocr.py PRIVATE_DATASET_ROOT
python tools/fit_numeric_candidate.py PRIVATE_DATASET_ROOT
```

Первая команда локально распознаёт числовые токены, сохраняя confidence и
координаты, но не назначает роли pot/stack. Вторая использует существующий
GlyphBook: строит экземпляры цифр по OCR-псевдометкам из IMG_0909 и измеряет
согласие с OCR на IMG_0910. Хеши источников закреплены в harness этого прогона.
Совпадающие кропы исключаются из проверки. Это калибровка k-NN, не LoRA.
OCR-согласие не является независимой точностью, распознаванием карт или GTO.
Кандидат всегда `verified=false`; никакой активации профиля или ставок.
Команды отказываются перезаписывать существующие результаты.
