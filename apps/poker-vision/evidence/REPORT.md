Стартовый SHA ветки: `2a69b34b` (до моих изменений). Канонический код не менялся. Чёрный ящик: **зелёного статуса нет** — не было прогона адаптера на точном SHA на Windows-ПК владельца (см. NOT_RUN).

## Что реализовано
- `apps/poker-vision` — один backend (`VisionService` → FastAPI на loopback, CLI — тонкий HTTP-клиент), приложение запускается манифестом `python -m pokervision.cli serve`.
- Конвейер: источник (папка кадров / видео / loopback-браузер своего тренажёра / окно через mss) → якорь по картам героя (масштаб в CSS-единицах, без фиксированных пикселей) → карты/цифры/кнопки (k-NN-эталоны с порогами отказа; UNKNOWN вместо догадки) → проверка (дубли карт, формат сумм, улицы) → временная сверка (голосование, границы раздач, устаревшие/замороженные кадры) → история (только наблюдённое, `complete=false` + список ненаблюдаемого, PHH-подобный вывод).
- Адаптеры: `poker_train` (калибруется по размеченным кадрам), `ton_poker`/`RoiAdapter` (профиль «непроверен»; калибровка + проверка на отложенных кадрах; только наблюдение/replay, действия и советы запрещены).
- Действия: только в собственном тренажёре на loopback; watchdog, STOP, проверка эффекта клика, остановка при неоднозначности/повторе.
- Стратегия получает тип `VisibleInfo` без скрытых полей. Реестр моделей (общий holdout, откат).
- Bossman: страница «Poker Vision» (выбор режима/окна, калибровка, overlay, поля с уверенностью/временем/источником, история, объяснение неопределённости, STOP), loopback-прокси, `tree-sync`, 7 узлов дерева (`pv`).
- Исправлена гонка в странице: таймер опроса гасился, если страница вставлялась в DOM позже 700 мс (из-за этого страница показывала «кадров 0»).

## Зрение: baseline → after (одни и те же кадры, один профиль)
Baseline — те же пиксели и те же эталоны, но **без отказа** (всегда выдаёт ответ). Train: 6 сессий A_tr1–6 (506 кадров); тест — сессии с другими раздачами (пересечение 0). Сумма по 11 полям, ячейки «неверно» / «UNKNOWN»:

| сплит | неверно baseline → after | UNKNOWN baseline → after | точное состояние (все ключевые поля) baseline → after | состояние без неверного ключевого поля baseline → after |
|---|---|---|---|---|
| test_in (тот же тренажёр) | 660 → 2 | 258 → 531 | 0.298 → 0.271 | 0.555 → 1.000 |
| test_theme (другие темы/форматы) | 682 → 4 | 570 → 1047 | 0.206 → 0.099 | 0.603 → 0.998 |
| test_layout (другие экраны/DPR) | 694 → 0 | 1079 → 1645 | 0.212 → 0.136 | 0.487 → 1.000 |
| test_theme_layout | 164 → 0 | 574 → 830 | 0.156 → 0.012 | 0.713 → 1.000 |

Латентность CPU на кадр: p50 61 мс / p95 87 мс (520×900), p50 157 мс / p95 302 мс (большие раскладки); пик RSS процесса оценки 2.5 ГБ; GPU не использовался.

**Честный вердикт по цели ×2:**
- Ошибки (молча неверные значения) — сокращены с сотен до 0–4 на сплит: цель «в 2 раза и больше» выполнена с большим запасом.
- Но это достигнуто ценой покрытия: доля UNKNOWN выросла, а **доля точного совпадения всего состояния не улучшилась, на новых темах/раскладках упала** (0.206→0.099, 0.156→0.012). Критическая метрика «точное состояние» ухудшилась ⇒ условие «без ухудшения других критических метрик» **не выполнено** для точного совпадения; выполнено для «нет неверных ключевых полей».
- Время обработки ×2 не измерялось как цель.
- Карты героя и банк читаются надёжно на своём тренажёре (0 ошибок); на новых раскладках карты героя UNKNOWN в 17 % кадров.
- Дилер (UNKNOWN в 20–23 кадрах из 65–103), места/ставки, доступные действия на новых темах — слабые места. Метрика событий слабая (test_in: сопоставлено 7/36, 2/39, 6/42; пропущено большинство, 7–12 ложных/дублей на сессию).
- Раздач: 12 истинных, найдено 11 (1 смешана) на каждой сессии.

Раскрытие: мои исправления делались, глядя на сплиты test_*, поэтому holdout частично загрязнён процессом (не данными). Независимого holdout на свежесобранных кадрах после последней правки профиля не было.

## Живые действия в собственном тренажёре (через страницу Bossman)
Работает, но **пропускная способность низкая**: в прогоне — 4 решения, из них 3 подтверждены сменой состояния; после неподтверждённого клика/нечитаемых кнопок (To-call закрыт картами флопа → действия UNKNOWN) актуатор останавливается сам («hero's turn for 12s but the state is not actionable»). Это безопасное поведение, а не покрытие. Тест E2E утверждает: любое неподтверждённое решение ⇒ актуатор остановлен.
