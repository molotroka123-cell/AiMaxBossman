# Bossman Mobile — Bossman на iPhone

Приложение для iPhone (PWA, ставится на экран «Домой»), которое показывает **тот же самый Bossman**, что работает
на ПК. Это не второе ядро: нет своего агента, своих моделей, своей очереди задач или памяти. Всё, что вы делаете
с телефона, выполняет ваш Bossman (сейчас `127.0.0.1:8801`, сборка 586345db) со всеми его правами, проверками и
подтверждениями.

Вкладки:

| Вкладка | Что делает | Через что в Bossman |
|---|---|---|
| **Чат** | Пишете задачу обычным языком, Qwen сам вызывает инструменты Bossman. Ответ идёт потоком, каждый вызов инструмента — карточка (имя, аргументы, результат), запрос на подтверждение — карточка «Разрешить / Отклонить». | `POST /api/chat/threads/{id}/send` (= задача Bossman), поток `GET /api/events/stream?task_id=`, `POST /api/approvals/{id}` только по вашему нажатию |
| **Фото** | Генерация картинок на ПК локальными моделями «Прямого генератора»: выбор модели (названия и пометки «uncensored» — как их пишет Bossman), промпт, формат, размер, шаги, seed, фото-референс из «Фото» для моделей «по фото» (I2I), прогресс (очередь, %, шаг, осталось ≈), галерея, просмотр, «Сохранить в Фото». | `/api/direct-gen/models`, `/jobs`, `/jobs/{id}`, `/jobs/{id}/cancel`, `/jobs/{id}/file` |
| **Панель** | Полная админ-панель Bossman 1:1 (все страницы, все действия, живые обновления). Значок на вкладке — сколько действий ждут вашего решения. | обратный прокси на весь Bossman |
| **Статус** | Bossman (сборка), локальные модели Ollama (какие загружены), генератор (очередь, ОЗУ), War Terminal, выход. | `/health/live`, Ollama `/api/tags` `/api/ps`, `/api/direct-gen/status`, War Terminal `/api/v1/health` |

«Сгенерируй фото …» в чате: мобильный чат сам отправляет такую фразу в «Прямой генератор» (самая быстрая
доступная модель, Z-Image Turbo) и показывает картинку прямо в переписке. У агентов чата нет инструмента
генерации картинок (`direct_gen` в списке их tools нет), поэтому выбран этот путь; модельные правила генератора
не меняются.

## Установка на iPhone

1. **На ПК** (один раз): запустите `scripts\Start-BossmanMobile.ps1 -Tailscale -ShowPairing`.
   Скрипт поднимает сервер на `127.0.0.1:8840` и публикует его **только внутри вашей сети Tailscale**
   (`tailscale serve`, никогда не `funnel` — из интернета приложение не видно). В конце печатается
   ссылка сопряжения `https://win-iqprhtsajl9.tail0f845b.ts.net/m/#pair=…`.
2. **HTTPS-сертификаты Tailscale сейчас выключены** (`tailscale status --json` → `CertDomains: null`),
   поэтому `tailscale serve --https` пока не выдаст сертификат. Включите один раз:
   админка Tailscale → **DNS** → **HTTPS Certificates → Enable**. До этого есть запасной вариант:
   `scripts\Start-BossmanMobile.ps1 -Tailscale -Http` → адрес `http://win-iqprhtsajl9.tail0f845b.ts.net/m/`.
   Внутри tailnet трафик всё равно шифрует WireGuard, но без HTTPS iPhone не включит service worker
   (оболочка не будет открываться без связи) и cookie будет без флага `Secure`. Рекомендуется HTTPS.
3. **На iPhone**: поставьте приложение **Tailscale** из App Store и войдите в **тот же** аккаунт/tailnet, что на ПК.
4. Откройте в **Safari** ссылку сопряжения из шага 1 (или `https://win-iqprhtsajl9.tail0f845b.ts.net/m/` и введите
   код сопряжения вручную — он лежит в `%USERPROFILE%\.bossman-mobile\tokens.json`).
5. Safari → **Поделиться** → **На экран «Домой»** → «Добавить». Иконка «Bossman» открывается как обычное
   приложение (без адресной строки), вход сохраняется на 30 дней.

Остановить публикацию: `tailscale serve reset`. Новый код сопряжения (все телефоны выйдут):
`python -m bossmobile rotate` из `apps\bossman-mobile`, затем перезапуск сервера.

## Модель безопасности

* **Сервер слушает только `127.0.0.1:8840`.** Иной адрес CLI отклоняет. До телефона он доходит только через
  `tailscale serve` внутри tailnet; `funnel` не используется нигде.
* **Код сопряжения ≠ токен Bossman.** Телефон знает только свой код. Вход `POST /m/api/login` выдаёт cookie
  `bm_session`: HttpOnly, SameSite=Strict, Secure при HTTPS (`X-Forwarded-Proto: https`). Сессии хранятся на ПК
  только как SHA-256.
* **Перебор ограничен**: 5 неверных попыток в минуту на клиента и 20 в минуту всего; лимит проверяется ДО
  сравнения кода (ответ 429 + Retry-After).
* **CSRF**: каждый POST приложения требует заголовок `X-BM-CSRF` своей сессии. В Панели изменяющий запрос
  требует значение `X-BCC-CSRF`, которое прокси выдаёт этой сессии телефона, и тот же Origin; на входе прокси
  меняет его на настоящий CSRF Bossman.
* **Токен Bossman не покидает ПК.** Сервер читает его из `%LOCALAPPDATA%\Bossman\CommandCenter\token`
  (или `BOSSMAN_TOKEN_FILE`) только для входа в Bossman (`POST /api/login`) и держит сессию Bossman у себя.
  Cookie телефона в Bossman не передаётся, `Set-Cookie` Bossman телефону не отдаётся, токен, id сессии и CSRF
  Bossman вырезаются из всех ответов, потоков и WebSocket-сообщений (`[hidden]`). Экран входа панели
  (`/api/login-hint`) путь к токену не показывает; `/api/logout` из Панели завершает и сессию телефона.
* **Вызовы приложения — фиксированный список** `/m/api/*`; неизвестный путь — 404. Панель (полные права
  владельца) открыта только при действующей сессии телефона; без неё — 401 на всё.
* **Никаких авто-одобрений.** Каждое «Разрешить/Отклонить» — нажатие владельца; приложение не меняет
  настройки, политики и gates Bossman и не обходит их.
* **Картинки** остаются на ПК (`Прямой генератор`), на телефон идут только в его сессию; сторонних загрузок нет.
* Интерфейс: весь текст сервера выводится через `textContent` (без `innerHTML`), CSP `default-src 'self'`,
  нет CDN и внешних шрифтов. Service worker кэширует только оболочку (`/m/`, css, js, иконки), ответы API,
  фото и Панель — никогда.

## Что значит «только локально»

Сообщение чата выполняет ОДИН агент Bossman. Телефон может назвать только агента, у которого:

1. модель по оценке самого Bossman (`/api/chat/options`, provider_governance) — `locality_detail = local`,
   `billing = local` (провайдер на 127.0.0.1; не LAN, не локальный прокси к облаку);
2. запасная модель (`fallback_model_id`) отсутствует или тоже локальная — иначе при сбое ход ушёл бы в облако;
3. нет `permissions.cloud_allowed = true`.

«Auto» запрещён (может выбрать облачного агента). Любой другой выбор — **403 `BM_LOCAL_ONLY`** на сервере,
до Bossman запрос не доходит. Поэтому «Пилот» и «Решатель» (запасная модель — облачный Nemotron) в мобильном
чате скрыты; по умолчанию выбран «Qwen Оператор (компьютер)» (`bossman-fast-qwen36-35b-a3b-q5`, инструменты
`computer.observe`/`computer.act`). Правила роутера Bossman (`/api/router/rules`: `prefer_local`, облако только
при явном разрешении) не меняются.

Почему не `/api/qwen-operator`: это L1-Lab оператор правки кода в отдельном worktree, а его роль verifier по
умолчанию — облачный Nemotron. Для разговорного управления ПК он не подходит и нарушил бы «без облака».

## Ограничения

* Нужен включённый ПК, запущенный Bossman и Tailscale на обоих устройствах.
* Без HTTPS-сертификатов Tailscale — нет офлайн-оболочки (service worker) и Secure-cookie.
* Панель — это десктопный интерфейс Bossman как есть; на узком экране часть страниц плотная.
* Вложения файлов в чат пока не отправляются (Bossman их поддерживает, в мобильный чат не добавлены).
* Поток ответа: если модель отвечает без потоковых дельт, текст появляется целиком по завершении задачи.
* Выбор локального агента проверяется в момент отправки; если владелец позже сменит агенту модель на облачную,
  следующая отправка будет отклонена, но уже идущий ход Bossman доведёт сам.
* Запуск: `python -m bossmobile` (из `apps\bossman-mobile`), логи — `%USERPROFILE%\.bossman-mobile\server.*.log`.
