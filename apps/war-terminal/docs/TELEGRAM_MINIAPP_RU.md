# War Terminal — мини-приложение «Оборонка» в пульте Telegram

Только владелец, только мониторинг. Мини-приложение открывается кнопкой меню **«Оборонка»** в чате с пультом
(companion-бот) и показывает открытые чешские тендеры категории `security_defence`. Подача заявок, контакты с
заказчиками и любые записи из мини-приложения невозможны.

## Что внутри

| Файл | Назначение |
|---|---|
| `warterminal/tgapp.py` | проверка initData, сессия, прокси `/tg/api/*`, раздача `/tg/` |
| `warterminal/ui/tg/` | `index.html`, `app.js`, `style.css` — интерфейс (русский, mobile-first) |
| `warterminal/api.py` | одна строка `tg_mount(app, store)` в конце `create_app` |
| `tools/set_pult_menu_button.py` | кнопка меню пульта только для чата владельца (по умолчанию dry-run) |
| `tests/test_tgapp.py` | 34 теста: подпись, негативные контроли, прокси, dry-run, утечки, инструмент |
| `docs/screenshots/tg_*.png` | скриншоты 390×844 на тестовых данных |

## Как работает вход

1. Telegram открывает `https://<хост>/tg/` и передаёт странице `Telegram.WebApp.initData`.
2. Страница отправляет её на `POST /tg/api/auth`. Сервер проверяет её по официальному алгоритму:
   `secret_key = HMAC_SHA256(key="WebAppData", msg=bot_token)`,
   `hash = HMAC_SHA256(key=secret_key, msg=data_check_string)`. В `data_check_string` входят все поля, кроме `hash`,
   отсортированные по имени, в виде `k=v` через `\n`. Сравнение идёт за постоянное время. Повтор ключа отклоняется.
   Если `auth_date` старше 1 часа или больше чем на 60 с опережает часы сервера, вход отклоняется.
3. `user.id` должен совпасть с id владельца из
   `%LOCALAPPDATA%\Bossman\telegram-companion\config.json` (`people[0].user_id`, запасной вариант `chat_id`; при
   `role` ≠ `owner` вход закрыт). Токен бота читается из `companion.env` (`TG_COMPANION_BOT_TOKEN`). Оба файла
   читаются при каждом входе, поэтому после смены токена перезапуск не нужен. Ни токен, ни id не логируются и не
   возвращаются; в аудит пишутся только события `tg.auth.ok / tg.auth.denied` с причиной без идентификаторов.
4. При успехе сервер выдаёт cookie `wt_tg` (HttpOnly; Secure; SameSite=None; Path=/tg/; 30 минут) и CSRF-токен.
   Страница передаёт CSRF-токен в заголовке `X-TG-CSRF`. Одной cookie недостаточно, поэтому чужой сайт не сможет
   сделать запрос от имени владельца.
5. Если вход не удался (чужая подпись, просрочка, другой пользователь, нет initData), сервер всегда отвечает
   **403** с одним и тем же текстом и без данных. Если пульт не настроен, ответ — 503. После 30 ошибок за минуту
   включается тормоз: 429.

## Что может сессия (белый список)

| Запрос мини-приложения | Внутри | Роль |
|---|---|---|
| `GET /tg/api/tenders?...` | `GET /api/v1/tenders` | viewer |
| `GET /tg/api/tenders/{key}` | `GET /api/v1/tenders/{key}` | viewer |
| `GET /tg/api/tenders/{key}/checklist` | `GET /api/v1/tenders/{key}/checklist` | viewer |
| `POST /tg/api/assessments` | `POST /api/v1/assessments`, принудительно `dry_run=true`, `use_ai=false` | analyst, только чтение |

Всё остальное под `/tg/api/` отвечает 403: одобрения, аудит, профиль, ingest, `/actions/*` и т. д. Тело с
`dry_run≠true`, с `use_ai` или с лишними полями тоже получает 403. Сессия не открывает `/api/v1` напрямую.
Токены ролей подставляются внутри процесса и наружу не выходят.

## Интерфейс

- Подключён `telegram-web-app.js` с telegram.org — это единственный внешний скрипт. CSP разрешает только его и
  собственные файлы. Вызываются `ready()` и `expand()`. Цвета берутся из `themeParams`, событие `themeChanged`
  тоже обрабатывается.
- Вверху баннер: «Только мониторинг. Подача заявок и контакты с заказчиками — только после юридической проверки и
  вашего решения.»
- Под баннером KPI: сколько тендеров открыто, у скольких есть флаг «лицензия» (`open_gates` содержит
  `controlled_goods`) и у скольких срок истекает в ближайшие 14 дней.
- Фильтр: «Все» / «Военные (лицензия)» / «Гражданская безопасность».
- Карточка тендера: сумма и валюта, срок и сколько дней осталось, заказчик, бейдж DEMO.
- Шторка с подробностями: проверки (gates) с причинами, fit и уверенность, черновик чек-листа, ссылка на
  официальный источник (`Telegram.WebApp.openLink`, только http/https). Кнопка «Оценить (dry-run)» в Telegram —
  это MainButton, вне Telegram — кнопка на странице. Закрывается шторка через BackButton.
- Все строки выводятся текстовыми узлами, HTML-строк нет. Тест с `<script>` в названии показывает его как
  обычный текст.

## Условие: HTTPS, доступный с телефона

Telegram открывает Mini App только по **HTTPS**. Здесь адрес идёт через tailnet:
**https://win-iqprhtsajl9.tail0f845b.ts.net/tg/**

- На iPhone должен быть установлен и включён Tailscale с тем же аккаунтом (tailnet). Без него страница не откроется.
  Так и задумано: снаружи она недоступна.
- В админке Tailscale (login.tailscale.com → DNS) должны быть включены MagicDNS и **HTTPS Certificates**.
- **Никогда не используйте `tailscale funnel`** и не открывайте доступ публично. Только `tailscale serve`
  (tailnet only).

Сейчас (17.10) `tailscale serve status` показывает только http: `:80 → 127.0.0.1:8840` и `:8830 → 127.0.0.1:8830`.
HTTPS на 443 не настроен.

## Команды владельца (PowerShell)

1. Перезапустите War Terminal на :8830 из этой ветки, чтобы появился код `/tg/`. Уже запущенный процесс его не
   содержит. Агент процесс не перезапускал.

2. Опубликуйте в tailnet только мини-приложение (рекомендуется):

   ```powershell
   tailscale serve --bg --https=443 --set-path=/tg http://127.0.0.1:8830/tg
   tailscale serve status
   ```

   Вариант, если нужно опубликовать всё приложение (главный UI тоже защищён токенами ролей):

   ```powershell
   tailscale serve --bg --https=443 http://127.0.0.1:8830
   ```

   Отключить: `tailscale serve --https=443 --set-path=/tg off` (или `tailscale serve --https=443 off`).

3. Проверьте с телефона, где включён Tailscale. Откройте `https://win-iqprhtsajl9.tail0f845b.ts.net/tg/` в
   Safari: должна появиться фраза «Откройте через кнопку «Оборонка» в пульте…». Значит, HTTPS работает, а данные
   без Telegram не отдаются.

4. Поставьте кнопку меню, только для вашего чата:

   ```powershell
   cd C:\Users\asd\Bossman\wt-checkpoint-20261015\apps\war-terminal
   python tools\set_pult_menu_button.py --url https://win-iqprhtsajl9.tail0f845b.ts.net          # dry-run: показать запрос
   python tools\set_pult_menu_button.py --url https://win-iqprhtsajl9.tail0f845b.ts.net --apply  # отправить в Bot API
   ```

   Инструмент отклоняет не-https адреса и печатает запрос без токена и без id. Он вызывает
   `setChatMenuButton` только с `chat_id` владельца, поэтому у остальных пользователей бота кнопка не меняется.

5. В Telegram откройте чат с пультом и нажмите кнопку меню «Оборонка» слева от поля ввода.

## Известные ограничения

- Сессии хранятся в памяти процесса: после перезапуска War Terminal страница сама войдёт заново, если initData
  ещё не старше часа. Если старше, Mini App нужно открыть заново.
- `pyproject.toml` включает в пакет только `ui/*`. При установке через `pip install` (не из исходников) папка
  `ui/tg/` не попадёт в пакет, пока не добавить `ui/tg/*` в package-data. Это файл вне зоны этой задачи.
- Флаг «лицензия» ставится по тексту и CPV (`controlled_goods`, сюда же признаки двойного назначения). Это не
  юридическая классификация.
