# War Terminal: обзор OSS API, MCP и готовых компонентов

Проверено 18.10.2026 по официальной документации и состоянию GitHub-репозиториев. Это исследование и план отбора; новые пакеты, MCP-серверы и источники данных в продукт не подключались.

## Уже есть в Bossman

- War Terminal уже имеет коннекторы TED, NEN через браузер, UCDP, GDELT, USAspending, World Bank, SAM и Czech data, общий API и отдельные статусы источников.
- `command-center/bcc/features/war_terminal.py` предоставляет Bossman read-only инструменты и проксирует их в тот же сервис War Terminal с ролью `analyst`. `POST /war-terminal/refresh` требует `confirm_live=true`; анализ тендера — dry-run. Права owner остаются у человека.
- Поэтому новые проекты должны дополнять этот сервис и существующий API. Не добавлять вторую базу, второй агентный цикл или самостоятельный набор permissions.

## Не копировать без лицензии

`[fbuchner/ted-mcp](https://github.com/fbuchner/ted-mcp)` выглядит как готовый MCP для поиска TED и использует публичный TED Search API; README описывает три инструмента и Python/Streamable HTTP варианты. Но GitHub API на 18.10.2026 не обнаружил для репозитория SPDX-лицензию (`NOASSERTION`), а в документации проект предупреждает, что код в основном создан ИИ. Не переносить его код или зависимости до появления и проверки явной лицензии и ревью исходников. Поскольку Bossman уже имеет TED-коннектор и общий analyst API, повторный TED-MCP сейчас не нужен.

OCDS — полезный формат данных, а не e-procurement сервер. Перед использованием схем, codelists или кода из репозитория Open Contracting проверить лицензию именно конкретного файла/пакета; не считать лицензию данных лицензией на ПО или наоборот.

## Рекомендованная последовательность

1. **Сначала Docling на локальных синтетических файлах.** Тендерное вложение → локальный текст/таблицы с номером страницы, source hash и статусом качества → детерминированные проверки → только затем черновая AI-классификация. Внешняя отправка файлов отключена.
2. **Затем каталог OCDS-источников.** Выбрать один открытый dataset для коммерческой категории (например, логистика или продукты), проверить publisher/license/period/retrieval date и только после этого добавить read-only адаптер с provenance.
3. **OCDS Kit — как валидатор до записи.** Сохранить исходный package/hash, подтвердить версию схемы, затем нормализовать в существующую модель War Terminal.
4. **Playwright MCP — только если API/HTML-коннектора недостаточно.** Сначала сравнить запуск MCP с существующим `browser_nen.py`; предпочтителен узкий вызов из того же backend с allowlist и STOP, а не новый «полный браузерный агент».
5. **Prozorro — позже и read-only.** Только при отдельном подтверждённом украинском бизнес-кейсе; не открывать создание/изменение заявок, подачу bid или действия владельца через Bossman.

## Контракт данных и MCP для будущей интеграции

Каждый результат, в том числе извлечённый vision/OCR или браузером, должен содержать `source`, `source_url`, `source_version`, `dataset_period`, `retrieved_at`, `content_hash`, `license`, `mode` (`DEMO`/`LIVE`) и `verification`. Неизвестные поля остаются `N/A`; ошибочный или просроченный источник не маркируется `VERIFIED`.

Внешние MCP-инструменты должны быть тонкими read-only методами над существующим API War Terminal и существующими analyst permissions. Разрешённые кандидаты: статус источников, поиск публичных тендеров, чтение записи, сводка по агрегированным индикаторам, dry-run оценка. Не давать tools для подачи заявки, контакта с контрагентом, изменения профиля, подтверждения ворот, использования owner token или импорта результата без проверки владельцем.

Для конфликтного контекста использовать только лицензированные агрегаты по стране и периоду. Сырые геокодированные события, точные координаты, адреса, перемещения, уязвимости и рекомендации действий в vision prompt, MCP-ответы и обучающий корпус не включать.

## Состояние evidence и свежесть записи

Строка `mode=DEMO`, `live_enabled=false`, `ai_configured=false` была наблюдением
предыдущего прогона, а не live-проверкой этого commit. После исходного обзора в main
добавлены commits `36f5278a` (источники только с provenance, demo-коннекторы удалены,
live по умолчанию) и `ceee487e` (ограничения генерации/ресурсов FX tracker). Поэтому
старый статус нельзя считать текущим. В рамках этого документа свежий endpoint и
установленный Windows runtime не проверялись; их статус — `NOT_RUN`. Этот обзор
фиксирует кандидатов и план PoC, а не подключение MCP или обучение модели.
