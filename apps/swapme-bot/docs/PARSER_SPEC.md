# PARSER_SPEC — парсер сделок из Telegram-канала/чата SwapMe

Назначение: импорт сделок и расходов из Telegram-экспорта (или live-сообщений) в swapme.db.
Проверен на реальных данных: импорты от 03.06 (125 сделок) и 12.06.2026 (29 сделок, сверка 65/65).
Готовый код: `import_deals_v3.py` (исторический импорт), `ux_patch.py::parse_quick_deal` (live-парсер, 22 теста).

## 1. Источник
- Telegram Desktop → Export chat history → `messages.html` (+папки photos/css/js — игнорировать).
- Разбор: BeautifulSoup(lxml), сообщения `div.message.default`, дата — атрибут `title` у `.date`
  (формат `DD.MM.YYYY HH:MM:SS UTC+01:00`), текст — `.text`.
- Windows: запускать `python -X utf8` (иначе UnicodeEncodeError на кириллице/эмодзи).

## 2. Конвенция данных (КРИТИЧНО)
- `from_*` = что клиент ОТДАЁТ нам («Принял» = мы приняли = from).
- `to_*` = что клиент ПОЛУЧАЕТ («Выдал» = мы выдали = to).
- Курс пары "A/B" = 1 A = rate × B. deal_rate = to_amt / from_amt.
- deal_type: from=фиат,to=USDT → BUY; from=USDT,to=фиат → SELL; фиат↔фиат → SWAP_FF; крипто↔крипто → SWAP_CC.

## 3. Форматы сообщений-сделок
| Паттерн | Пример | Разбор |
|---|---|---|
| Прямой | `Принял 500 USDT Выдал 10400 CZK` | from=500 USDT, to=10400 CZK |
| Обратный порядок | `Выдал 15000 USDT Принял 314700 CZK` | from=314700 CZK, to=15000 USDT |
| Синонимы from | принял/получил/взял/зашло/пришло | |
| Синонимы to | выдал/отдал/дал/отправил/ушло | |
| Без слов | `500 usdt 10400 czk` | первая пара = from |
| Стрелки | `500 USDT -> 10400 CZK`, `=` | первая = from |

## 4. Нормализация чисел и валют
- Пробел (и nbsp) = разделитель тысяч ТОЛЬКО перед группой ровно из 3 цифр: `20 800`, `316 200`.
- Запятая = десятичная: `534,88`. Если есть и точка и запятая — точка тысячная, запятая десятичная.
- Суффикс к/k/К/K = ×1000: `10к czk` = 10000 CZK.
- Валюты в любом регистре: czk, USDt, UsDt. Алиасы: € → EUR, $ → USD, тезер/юсдт → USDT,
  евро → EUR, крон/кроны/крона → CZK, доллар/бакс → USD. Слитно: `500usdt`, `15000czk`.
- Только CURRENCIES = [USDT, EUR, USD, CZK]; прочие валюты (рубли, гривны) → сообщение НЕ сделка.

## 5. Расходы (не сделки)
Паттерны: `Расход 16$ прописка`, `Расходы 258$`, `-9650 офис`, `-400 крон taxi`, `500 на кофе`,
`-2к на шмотки, 3к аванс` (два расхода в одном сообщении!), `-9к позор реклама`.
- `к` в расходах = тысячи CZK (валюта по умолчанию для расходов — CZK; `$` → USD).
- Писать в таблицу `expenses` (ccy, amount>0, note, created_at=дата сообщения).
  Ledger-запись НЕ создавать (историческая конвенция; capital_pnl.py читает expenses напрямую).

## 6. Особые случаи (все встречались)
- **Комплексная выдача**: `Принял 2990 USDT Выдал 2500€ и 900 CZK ...` → разложить на 2 ордера
  пропорционально (см. import_complex.py) или 1 ордер по основной ноге + note.
- **Возврат долга**: `... (Odtat dolg)` / упоминание долга → НЕ сделка. Решение пользователя
  (12.06.2026): долг РЕАЛЬНО выдан → записывать как корректировку баланса, не как торговлю:
  ledger -23000 USDT и +1104 CZK с entry_type='adjustment' (не inflow/outflow, чтобы не попасть
  в торговый P&L). См. CLAUDE_REVIEW_TODO.md.
- **Дубль-сообщения**: одинаковая сделка дважды за минуты (репост фото) → импортировать одну.
- **Болтовня и одиночные числа** (`61800`, `22500` перед сделкой) → игнорировать.
- **Префикс даты в тексте** переопределяет дату сообщения (формат «25.03 ...»).
- **Зеркальные пары** (`Принял X Выдал Y` + следом `Выдал X Получил Y`) = ДВЕ разные сделки.

## 7. Дедупликация против БД
Сделка уже есть, если в `orders` существует запись:
- `date(created_at)` в окне ±1 день от даты сообщения, И
- суммы совпадают с точностью 0.01 в ЛЮБОЙ ориентации:
  (from_amt≈A AND to_amt≈B) OR (from_amt≈B AND to_amt≈A).
Уже импортированные часы могут отличаться (прошлый импорт ставил округлённое время).

## 8. Запись в БД
На каждый ордер — атомарно (BEGIN IMMEDIATE):
1. INSERT в `orders`: state='completed', completed_at=created_at=дата сообщения,
   manager='import_<тег>', deal_rate=to/from, market_rate из rate_history на дату (если есть).
2. Две ноги в `ledger_entries`: (+from_amt, 'inflow', ref_id=order_id) и (−to_amt, 'outflow', ref_id).
ПЕРЕД импортом: `cp swapme.db swapme_backup_before_<тег>.db`.

## 9. Протокол верификации (ОБЯЗАТЕЛЕН)
1. COUNT(*) orders до/после = +N импортированных.
2. Кросс-чек: каждое сообщение-сделка экспорта находится в orders (скрипт из сессии 12.06 —
   regex по «Принял|Выдал», первые 2 числа, окно ±1 день). Цель: 0 MISS.
3. ledger: на каждый новый ордер ровно 2 ноги.
4. Отчёт суб-агента ≠ истина — проверять SELECT'ами.
