# SwapMe Bot — UX Redesign для менеджеров (мобильный, десятки сделок/день)

Версия бота: v6.4 · `bot.py` ~4120 строк · python-telegram-bot 20.7
Весь код решений — в `ux_patch.py` (модуль для переноса в `bot.py`, без правок репозитория).

Конвенция данных (важно, не менять):
`from_ccy/from_amt` = что клиент **ОТДАЁТ** нам (мы приняли).
`to_ccy/to_amt` = что клиент **ПОЛУЧАЕТ** (мы выдали).
«Принял X» → from. «Выдал Y» → to.

---

## 1. Боль: создание сделки = 9 шагов

### Сейчас
`new_deal → тип → источник → имя → from-ccy → from-amt → to-ccy → to-amt → дата → XE → TX → подтверждение`.
Для типовой «принял 500 USDT, выдал 10400 CZK сейчас» — 9 экранов, ~9 тапов + 2 ввода. На телефоне в потоке сделок это главный тормоз.

### Анализ доп. проблем
- Шаги **дата / XE / TX** в быстром потоке почти всегда «2» (пропустить) — три лишних экрана ввода текста ради пропуска.
- Источник клиента (organic/ads) и имя — нужны не для каждой сделки, по умолчанию `organic`/пусто.
- `deal_type` (BUY/SELL/SWAP) **выводится однозначно из пары валют** — спрашивать его не нужно:
  - from=USDT, to=фиат → SELL (клиент отдал крипту? нет — клиент отдаёт USDT и получает фиат = мы продаём фиат / клиент продаёт нам USDT). По текущему `format_receipt`: `BUY` = клиент даёт фиат→крипто, `SELL` = клиент даёт крипто→фиат. Значит from=USDT,to=фиат → **SELL**; from=фиат,to=USDT → **BUY**; крипто↔крипто → SWAP_CC; фиат↔фиат → SWAP_FF.

### Решение: быстрый ввод одним сообщением (главная фича)
Менеджер пишет так же, как пишет в рабочий чат:
```
500 usdt 10400 czk
принял 500 usdt выдал 10400 czk
выдал 10400 czk принял 500 usdt
500 USDT → 10400 CZK
20 800 czk 800 eur
€500 = 13000 czk
```
Парсер `parse_quick_deal()` (см. ux_patch.py) извлекает две пары `(amount, ccy)`, определяет какая from / какая to по ключевым словам «принял/получил/from» vs «выдал/отдал/to», иначе по порядку (первая = принял = from). Затем:
1. Один экран-подтверждение с маржой/курсом/предупреждением о ликвидности и кнопками **✅ Записать / 🟢→🔴 источник / 📅 дата / ❌**.
2. Тап «✅ Записать» — сделка в БД. Итого: **1 сообщение + 1 тап** вместо 9 экранов.

Полный пошаговый мастер остаётся как fallback (кнопка «🧙 По шагам» в подтверждении и пункт меню) — для нестандартных кейсов.

Парсер обрабатывает (см. unit-блок в ux_patch.py):
- суммы с пробелами `20 800`, запятая-десятичная `1 250,5`;
- регистр валют любой; `€`→EUR, `$`→USD;
- `к`/`k` после числа в CZK-контексте = тысячи (`10к czk` = 10000);
- стрелки `→ -> =`, слова «принял/выдал/отдал/получил/дал»;
- обратный порядок «выдал … принял …».

## 2. Боль: reply-клавиатура через костыль (двойное нажатие)

### Сейчас
`reply_kb_router` на тап кнопки отвечает **промежуточным сообщением** с inline-кнопкой «Нажми чтобы…». Пользователь жмёт дважды.

### Решение
`reply_kb_router_v2()` вызывает целевой обработчик **напрямую**, синтезируя «фейковый» `callback_query` через лёгкий объект-обёртку `_FakeCallback`, который рендерит результат как новое сообщение (`reply_text`) вместо `edit_message_text`. Один тап = действие. Маршруты те же (`REPLY_BTN_TO_CB`).
Для «Сделка» reply-кнопка теперь подсказывает быстрый ввод (а не открывает мастер).

## 3. Боль: cb_pnl_show — стена ~50 строк

### Сейчас
6 блоков (VWAP CZK/EUR, Капитал, Маржа, Simple CZK/EUR) = ~50 строк. На телефоне — простыня, скролл.

### Решение
`cb_pnl_show_v2()` — краткая сводка (8–10 строк): период, итог CZK+EUR, equity+DD, маржа+сделки, 1 строка AI-инсайта. Кнопки: **🔍 Детали** (полный текущий вывод), **↩ Периоды**, **Меню**. Детали (`pnl_full_*`) показывают старую развёрнутую версию по запросу.

## 4. Боль: меню 11 рядов — перегруз

### Сейчас
11 рядов кнопок в одном экране (Сделка, Баланс, Статистика, Курсы, Ввод курса, Цены, Себестоимость, Тренды, P&L, Ликвидность, Менеджеры, Аналитика, Cashflow, Excel, Конвертер, Чеки, Заметки, Клиенты, Реклама, Админ).

### Решение
`main_menu_keyboard_v2()` — 2-уровневое, сгруппировано:
- Верх (всегда): **➕ Сделка** (широкая).
- 4 раздела: **💱 Сделки** · **💰 Деньги** · **📈 Аналитика** · **⚙️ Ещё**.
- Быстрый ряд частого: **📊 Баланс · 💱 Курсы · 💰 P&L**.
Подменю (`menu_deals` / `menu_money` / `menu_analytics` / `menu_more`) раскрывают по 4–6 кнопок с «↩ Меню». Cognitive load с 20 кнопок → 8 на главном экране. Все существующие callback_data сохранены — подменю просто их группируют.

## 5. Боль: шаги дата/XE/TX — почти всегда «2»

### Решение
В быстром пути этих шагов **нет вовсе** — дата=сейчас, XE=курс бота, TX=нет. Изменить можно тапом на подтверждении (📅 дата → инлайн-выбор «Сейчас / Вчера / Ввести»). В полном мастере шаги ввода текста «или 2» заменяются на кнопки **«Сейчас» / «Пропустить» / «Курс бота»** (`deal_*_kb` — готовые клавиатуры в патче), чтобы не печатать «2».

---

## 6. Боль: нет /undo

### Решение
Команда `/undo` (и кнопка «↩ Отменить» в чеке сделки) → `cmd_undo()`:
находит **последнюю completed-сделку этого менеджера за 10 минут**, показывает её и кнопку подтверждения; по подтверждению зовёт существующий `cancel_order(order_id, tg_id)` (он уже делает реверс ledger + reconcile). Защита: только свои сделки, окно 10 мин, требует подтверждения (двухшаговое, чтобы не отменить случайно).

## Требует решения пользователя

1. **Быстрый ввод как глобальный перехват текста**: любое сообщение «число валюта число валюта» от авторизованного менеджера вне диалога будет трактоваться как сделка-черновик (с подтверждением, без авто-записи). Согласовать: не конфликтует ли с другими свободными текстовыми вводами (заметки и т.п. идут внутри ConversationHandler-диалога, так что глобальный handler сработает только вне диалога — безопасно, но подтвердить).
2. **`к`/`k` = тысячи**: применять только когда валюта CZK (как в расходах) или всегда? В патче — только при явном `к/k` суффиксе, для любой валюты, т.к. «10к eur» тоже валидно. Подтвердить.
3. **deal_type SWAP USDT↔USDT** невозможен (одна валюта), но USDT↔другая крипта в проекте нет (только USDT крипта). Поэтому SWAP_CC практически не встретится; from=USDT,to=USDT отсекается валидатором. ОК.
4. **Окно /undo = 10 минут** — подтвердить значение (можно вынести в константу `UNDO_WINDOW_MIN`).
5. **Меню v2**: сохранить ли старую плоскую раскладку как опцию для админа? В патче — единая новая.
6. Заменять ли text-prompt в полном мастере на кнопки (п.5) — опционально, требует мелкой правки 2 handler'ов в bot.py (их правит другой агент). Клавиатуры готовы.
