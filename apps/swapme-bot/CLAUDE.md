## Капитал — основной метод (якорный)
`Капитал = СТАРТ_USDT(якорь) + торговый P&L по ledger после якоря − расходы после якоря`.
- Якорь в таблице `capital_anchor` (id=1, `anchor_ts`, `start_usdt`); задан 03.06.2026, якорь `2026-05-20 14:01:24`.
- P&L = сумма движений `ledger_entries` после якоря, только типы inflow/outflow/reversal/fee_income, каждая нога
  в USDT по курсу её дня: CZK → `rate_history` pair `XE:USD/CZK`, EUR → `USDT/EUR`, USD ≈ USDT.
- Расходы — таблица `expenses` (CZK по XE-курсу дня). Исторические expenses id 3–10 без ledger-пары → WARN в
  full_audit это норма; новые через бота пишут обе записи.
- В боте: `/capital`, `/set_anchor`, кнопка 💼, `capital_history` (ночные снимки). CLI `capital_pnl.py` даёт те же числа.

## Конвенции импорта сделок из Telegram-экспорта (подтверждены владельцем)
- «Принял» = from (клиент отдаёт), «Выдал» = to (клиент получает); бывает обратный порядок слов.
- USDT→фиат = SELL, фиат→USDT = BUY, фиат→фиат = SWAP_FF.
- Зеркальные пары (одна сумма с двух сторон) = 2 сделки. Сложные сделки — сплит на отдельные ордера,
  пропорционально USD-стоимости.
- Дедуп против БД: exact + near (дата ±1 день и суммы); против репостов — одно фото + те же суммы.
- Префикс даты в тексте («29.04 Принял…») переопределяет дату сообщения.
- Запятая = десятичный разделитель, пробелы в числах, € = EUR, $ = USD.
- Курсы: скриншоты xe.com в экспорте = mid-market USD/CZK ≈ USDT/CZK → `rate_history` `XE:USD/CZK`.
  Опечатки в суммах сверять по XE-скриншоту той же сделки.
- Перед любым импортом — бэкап БД (`swapme_backup_before_<что>.db`), сначала dry-run.
- Не-сделки (подбивка ликвидности, расходы, подсчёты прибыли, долги, болтовня) ордерами не заводить —
  это кандидаты в `expenses`/справку, спросить владельца.
- Подробно — `docs/PARSER_SPEC.md`.
