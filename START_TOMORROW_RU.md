# Завтрашний прогон Bossman 1.0-RC — что делает владелец

Статус кандидата на момент передачи: **READY_FOR_OWNER_RUN / BOSSMAN_1.0_RC**.
Ничего из списка ниже сегодня НЕ выполнено на машине владельца; OWNER_HARDWARE_CERTIFIED
объявляется только после этого прогона на новом архиве. Все упомянутые команды —
реальные файлы архива (`*.cmd` в корне, скрипты в `app-support\`).

Общее правило для каждого шага: вход → ожидаемый эффект → таймаут → улика → куда
идти при отказе. Улика — это файл/скриншот/строка журнала, а не сообщение модели.
Если результат внешнего действия неизвестен, сначала сверка, потом решение о повторе.
При утечке секретов, обходе подтверждения, оплате или разрушительном действии —
остановить прогон (`Стоп` на Пульте, затем закрыть окно).

## 0. Подготовка (10 мин)

| | |
|---|---|
| Вход | ZIP из прогона `One-download Windows application` на CANDIDATE_SHA из handoff; `Get-FileHash .\BOSSMAN-Windows-x64-<SHA>.zip -Algorithm SHA256` |
| Ожидание | хэш совпадает с `INNER_ZIP_SHA256` из handoff; распаковка в новую папку рядом со старой (например `C:\Bossman-Test\`), старая папка не трогается |
| Таймаут | — |
| Улика | строка с хэшем в отчёте |
| Отказ | хэш не совпал → СТОП, сообщить интегратору; не запускать |

Сделать копию папки данных по `docs\owner\ROLLBACK_RU.md` (шаг 2).

## 1. Baseline машины и установка (15 мин)

| | |
|---|---|
| Вход | `Owner-Run.cmd --stage doctor --stage models --stage media --stage diagnostics --coaching-backend mock --stage coaching` (или просто `Owner-Run.cmd` — тогда coaching идёт по живому endpoint) |
| Ожидание | `doctor` PASS/WARN без BLOCKED; `models` PASS с двумя endpoint (MAIN :8081, FAST :8082 — llama-server должен быть запущен заранее); `media` OWNER_REQUIRED, пока не выполнен шаг 6.0; отчёт `report.md` в `%LOCALAPPDATA%\Bossman\CommandCenter\owner-run\<время>\` |
| Таймаут | 5 мин (без coaching), до 3 ч с coaching по живой модели |
| Улика | `report.json`, `doctor.json`, `models.json` |
| Отказ | `doctor` FAIL → дефект упаковки, приложить `diagnostics.zip`; `models` OWNER_REQUIRED → поднять llama-server и повторить |

Затем `Start-Bossman.cmd`, вход в панель, `Evening-Test.cmd` (без `--full`): базовая
проверка установленного продукта. Ожидание — вердикт PASS/PARTIAL с названными причинами.

## 4. Рабочий стол: фокус, набор, Стоп/Продолжить (20 мин)

| | |
|---|---|
| Вход | агенту с правом `computer.control`: «открой Блокнот, напиши три строки текста с путём `C:\Bossman-Test\README.md`, сохрани как `%USERPROFILE%\Documents\bossman-test\notes.txt`»; во время длинного набора нажать **Стоп** на Пульте (панель «Рабочий стол»), затем **Продолжить** |
| Ожидание | окно Блокнота получает фокус само; текст (включая слово Bossman) набирается; после Стоп набор прерывается между порциями и новые действия отклоняются; после Продолжить агент ОБЯЗАН заново прочитать экран (старое наблюдение не исполняется); сохранённый файл проверяется на диске (`file_exists`), а не по заголовку окна; клик по кнопке с последствием (Удалить/Оплатить) требует подтверждения, и `semantic` от модели его не заменяет |
| Таймаут | 15 мин |
| Улика | `notes.txt`, скриншоты `CommandCenter\computer\screens\`, события `computer.stop`/`computer.resume`, файл `CommandCenter\computer\STOP` во время паузы |
| Отказ | ввод ушёл в чужое окно → FAIL (CU-TARGET); действие после Стоп → СТОП прогона; отказ политики на Bossman-путь в тексте → FAIL (CU-PATH) |

Дополнительно: перезапустить backend, пока нажат Стоп — после старта состояние
`Стоп` сохраняется (панель показывает СТОП) до нажатия Продолжить.

## 6. Image → T2V/I2V → playback/export → cancel/restart (60–90 мин)

6.0 Настройка движка (один раз): `Media-Setup.cmd validate <папка моделей>` → при
нехватке файлов `Media-Setup.cmd plan-download <папка>` и, если разрешено,
`Media-Setup.cmd download <папка> --allow-download`; затем
`Media-Setup.cmd configure --sdcpp-bin <путь к sd-cli.exe> --models-dir <папка>`.
Проверка: `Owner-Run.cmd --stage media` → PASS (sha256 всех файлов сверен;
одинаковый размер с другим содержимым обязан дать BAD_HASH).

| | |
|---|---|
| Вход | Studio → `sdcpp:z-image-turbo` 1024×1024, seed 7 → PNG; затем `sdcpp:wan2.2-ti2v-5b` 832×480, 49 кадров, 16 fps (≈3 с), 20 шагов, seed 7 — T2V; затем I2V от полученного PNG (роль `start`); во время второй генерации — Отмена; затем перезапуск backend во время генерации |
| Ожидание | PNG открывается; клип ≥3 с, ffprobe и полное декодирование проходят; в provenance: engine_trace с наблюдаемым backend (не константа), ожидаемый и наблюдаемый sha256 моделей, generation/transcode разделены; отмена оставляет 0 runs и не оставляет процесса `sd-cli.exe`; после перезапуска задание в состоянии `interrupted_unknown` / OWNER_REQUIRED, сирота-процесс убит, не тихий повтор |
| Таймаут | 5 мин на картинку, 15 мин на клип (варианта A из handoff хватило 293 с) |
| Улика | файлы в медиатеке, `provenance`, `tasklist /fi "imagename eq sd-cli.exe"` после отмены |
| Отказ | шум вместо клипа → НЕ объявлять пресет рабочим; запустить A/B: `app-support\media_ab_preset.py plan --seed 7 --out <папка>` затем `--run` (одна переменная на пару: разрешение / шаги / vae-tiling / diffusion-fa), результаты — только ffprobe-статистика и sha256, без оценок качества; 17 кадров при 16 fps — это ≈1 с, не «полноценный клип» |
