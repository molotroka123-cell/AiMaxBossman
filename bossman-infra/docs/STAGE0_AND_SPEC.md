Версия 0.1 · 27.08.2026 · Железо: ACEMAGIC M1A PRO+ (Ryzen AI MAX+ 395, 128 ГБ LPDDR5X, 2 ТБ NVMe)

## Короткий ответ

Да, инфраструктуру пишем до приезда. Всё, кроме параметров ядра и бенчмарков, — это git-репозиторий с docker-compose и конфигами (стартер `bossman-infra` приложен). Он тестируется на любом ноутбуке через облачные модели или крошечную CPU-модель. День приезда: ~2,5 часа на ОС и настройку + одна команда `docker compose up` + загрузка моделей.

## Часть 1. Этап 0 — чек-лист

### 1.0 До приезда (делаем сейчас)

- [ ] Репозиторий `bossman-infra` на GitHub (приватный), стартер залит, `.env` заполнен локально
- [ ] Прогон на ноутбуке: `COMPOSE_PROFILES=` (только облако) — чат через Claude работает; `CPU_TEST=1` — цепочка llama-swap работает
- [ ] Аккаунт Tailscale: включить Tailscale SSH и MagicDNS; приложение на телефон
- [ ] Флешка: Fedora Server 43 (или Ubuntu 24.04 LTS + HWE-ядро). Нужно ядро ≥ 6.14
- [ ] Ключи: Anthropic, OpenRouter, токен Hugging Face
- [ ] Купить: ИБП 600–1000 ВА с USB-портом; кабель Ethernet до роутера (сервер — не по Wi-Fi)
- [ ] Проверить имена репозиториев моделей в `scripts/download-models.sh` (строки TODO)

### 1.1 Распаковка и BIOS (30 мин)

1. Ethernet-кабель, монитор, клавиатура. Первая загрузка — сразу в BIOS (Del/F2), не в Windows.
2. Обновить BIOS с сайта ACEMAGIC, если есть версия новее.
3. Настройки (названия зависят от BIOS):
   - **Restore on AC Power Loss → Power On** — сервер сам поднимается после отключения света
   - **Performance mode → Balanced** (или Performance; шум против скорости — решим после замера)
   - **UMA Frame Buffer / iGPU Memory → минимум (512 МБ–2 ГБ)**. Память отдадим GPU динамически из Linux (шаг 1.4). Запасной вариант, если 1.4 не заведётся: выставить здесь 96 ГБ
   - Secure Boot можно оставить (Fedora подписана); **fTPM — включён** (нужен для авторазблокировки диска)
4. Загрузка с флешки.

### 1.2 Установка ОС (30 мин)

- Удалить **все** существующие разделы. Заводской Windows не оставляем: у бренда была история с предустановленным ПО, да и место нужнее под модели
- Fedora Server 43, hostname `bossman`, **LUKS-шифрование всего диска**, пользователь с sudo
- После установки: `sudo dnf upgrade -y && sudo reboot`

### 1.3–1.7 Базовая настройка хоста (40 мин)

Скрипт `scripts/host-setup-fedora.sh` делает это по секциям; ниже — что именно и зачем.

**1.3 Пакеты и группы.** git, docker-зависимости, `rocminfo`, `mesa-vulkan-drivers`, `nvtop`, `nut`. Пользователь в группах `video`, `render`. Проверка: `vulkaninfo --summary` показывает Radeon 8060S; `rocminfo | grep gfx` → `gfx1151`.

**1.4 Память под GPU.** Параметры ядра:

```
amdgpu.gttsize=120000 ttm.pages_limit=30720000 ttm.page_pool_size=30720000
```

Это **потолок ~117 ГБ**, а не резерв: пока модели не загружены, память свободна для CPU. Ubuntu: то же в `GRUB_CMDLINE_LINUX_DEFAULT` + `update-grub`. Проверка после перезагрузки: `cat /sys/class/drm/card*/device/mem_info_gtt_total`.

**1.5 Docker** из репозитория docker-ce, `docker compose` v2, автозапуск.

**1.6 Tailscale и периметр.** `tailscale up --ssh --hostname bossman`. firewalld: `tailscale0` в зону trusted, зона public — DROP. Парольный SSH выключен. **Никакого проброса портов на роутере.** Проверка с телефона (мобильная сеть, не домашний Wi-Fi): `ssh bossman` работает.

**1.7 Авторазблокировка LUKS через TPM2.** Без этого каждая перезагрузка ждёт пароль у монитора — для сервера 24/7 неприемлемо. `systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=7`, `tpm2-device=auto` в crypttab, `dracut -f`. Компромисс: укравший сервер целиком сможет его загрузить, но без пароля пользователя данных не увидит. Пароль остаётся резервным способом.

### 1.8 Развёртывание bossman-infra (20 мин + загрузка моделей)

```bash
sudo mkdir -p /opt/bossman/models && sudo chown -R $USER /opt/bossman
git clone git@github.com:<you>/bossman-infra.git /opt/bossman/infra
cd /opt/bossman/infra
cp .env.example .env && nano .env        # секреты: openssl rand -hex 32; RENDER_GID/VIDEO_GID: getent group
./scripts/download-models.sh             # ~150 ГБ, ставим на ночь
nano llama-swap/config.yaml              # сверить имена .gguf-файлов
docker compose up -d
./scripts/smoke-test.sh
```

### 1.9 Доступ с телефона (5 мин)

```bash
sudo tailscale serve --bg --https=443  http://127.0.0.1:3000    # Open WebUI
sudo tailscale serve --bg --https=8443 http://127.0.0.1:3001    # Uptime Kuma
```

→ `https://bossman.<tailnet>.ts.net` в браузере телефона. Первый вход в Open WebUI создаёт администратора.

### 1.10 ИБП и живучесть (30 мин)

- NUT: ИБП по USB, `upsmon` → корректное выключение при 20 % батареи
- Uptime Kuma: мониторы на `litellm:4000/health/liveliness`, `llama-swap:8080/health`, Open WebUI; уведомления в Telegram
- **Тест 1:** `sudo reboot` — всё поднялось без участия (TPM2 + `restart: unless-stopped`)
- **Тест 2:** выдернуть шнур на 5 секунд — сервер включился сам, сервисы вернулись
- **Тест 3:** с телефона вне дома — чат отвечает

### 1.11 Фиксируем результат

`./scripts/bench.sh <алиас>` по каждой модели → таблица tok/s в README. Конфиги в git (`.env` — никогда).

**Итого день приезда: ~2,5 часа + загрузка моделей.**

## Часть 2. ТЗ: инфраструктура локальных LLM (bossman-infra v0.1)

### 2.1 Цель

Единая точка доступа к моделям — локальным и облачным — для чата сейчас и для агентов Bossman потом. Приватно по умолчанию, воспроизводимо из git, переживает перезагрузки без человека.

**Не входит в v0.1** (этапы 1–2): агенты, Studio (ComfyUI/Whisper), RAG-пайплайн, бэкапы 3-2-1, VLAN.

### 2.2 Требования

**Функциональные**

| # | Требование |
|---|---|
| F1 | OpenAI-совместимый API (`/v1/chat/completions`, `/v1/embeddings`, `/v1/models`) на одном адресе |
| F2 | Несколько локальных моделей, загрузка по требованию, выгрузка простаивающих |
| F3 | Облачные модели (Anthropic, OpenRouter) через тот же адрес; в коде агентов — алиасы, не адреса |
| F4 | Веб-чат с телефона и ПК с историей и выбором модели |
| F5 | Postgres + pgvector и Redis подняты и готовы для агентов и RAG |
| F6 | Мониторинг доступности с алертом в Telegram |
| F7 | Ключ доступа на каждого агента с белым списком моделей |

**Нефункциональные**

| # | Требование |
|---|---|
| N1 | Ни один порт не открыт в интернет; доступ только через Tailscale; сервисы слушают 127.0.0.1 |
| N2 | Диск зашифрован; секреты в `.env` (права 600), не в промптах и не в git |
| N3 | После перезагрузки или отключения питания всё поднимается без участия человека |
| N4 | Полное переразвёртывание из git ≤ 15 минут (без загрузки моделей) |
| N5 | Тот же compose работает на ноутбуке без GPU (облачные модели) — тестируем до приезда железа |

### 2.3 Архитектура

```
телефон / ноутбук
      │  Tailscale (WireGuard) · tailscale serve → HTTPS
      ▼
 Open WebUI :3000                    (позже: Bossman Control, агенты)
      │
      ▼
 LiteLLM :4000  ← единый API · алиасы · ключи per-агент · fallback · лимиты · логи
      │                         │
      ▼                         ▼
 llama-swap :8080          облако: Anthropic · OpenRouter
      │  загрузка по требованию, группы по памяти
      ▼
 llama-server (Vulkan / ROCm, gfx1151) ← GGUF из /opt/bossman/models

 Postgres 17 + pgvector · Redis 7 · Uptime Kuma      (внутренняя docker-сеть)
```

Ключевой приём: агенты и UI ходят в один OpenAI-совместимый адрес. «Локально или облако» — строка в конфиге шлюза, поэтому вся система собирается и тестируется до приезда железа.

### 2.4 Компоненты

| Компонент | Роль | Образ | Порт (только 127.0.0.1) |
|---|---|---|---|
| llama-swap + llama.cpp | загрузка моделей по требованию, инференс | `ghcr.io/mostlygeek/llama-swap:vulkan` | 8080 |
| LiteLLM | шлюз: алиасы, ключи, роутинг, fallback, логи | `ghcr.io/berriai/litellm:main-latest` | 4000 |
| Open WebUI | чат | `ghcr.io/open-webui/open-webui:main` | 3000 |
| Postgres 17 + pgvector | БД LiteLLM; БД `bossman` для агентов и RAG | `pgvector/pgvector:pg17` | внутр. |
| Redis 7 | очереди задач, кэш | `redis:7-alpine` | внутр. |
| Uptime Kuma | мониторинг, алерты в Telegram | `louislam/uptime-kuma:1` | 3001 |
| Tailscale | доступ, SSH, HTTPS | на хосте | — |

Если Vulkan-образ не увидит GPU — запасной образ, собранный под gfx1151: `kyuz0/amd-strix-halo-toolboxes` (варианты Vulkan и ROCm).

### 2.5 Реестр моделей и бюджет памяти

Потолок GPU: ~117 ГБ из 128. **Правило: одновременно загружено ≤ 95 ГБ**, остальное — KV-кэш и ОС.

| Алиас | Модель | Формат · размер | Скорость | Назначение |
|---|---|---|---|---|
| `bossman-fast` | Qwen3.6-35B-A3B | Q8_0 · ~37 ГБ | 50+ ток/с | агенты, чат, рутина |
| `bossman-smart` | gpt-oss-120b | MXFP4 · ~61 ГБ | ~30 ток/с | сложные задачи, анализ |
| `bossman-coder` | Qwen3-Coder 30B-A3B (актуальная версия) | Q8_0 · ~32 ГБ | 50+ ток/с | код, рутина |
| `bossman-writer` | Qwen3.8-27B | Q6_K · ~22 ГБ | 10–15 ток/с | тексты, зрение |
| `bossman-embed` | Qwen3-Embedding-0.6B | Q8_0 · ~1 ГБ | — | RAG, всегда загружена |
| `bossman-uncensored` | Qwen3.6-35B-A3B Uncensored | Q8_0 · ~37 ГБ | 50+ ток/с | личный чат, без инструментов |
| `claude-heavy` | claude-sonnet-5 (облако) | — | — | сложный кодинг, важные тексты |
| `claude-max` | claude-opus-4-8 (облако) | — | — | самое важное |
| `cloud-fallback` | gpt-oss-120b через OpenRouter | — | — | запасной вариант при недоступности локальной |

Группы llama-swap: `always` (embed — постоянно); `light` (fast + coder живут вместе, ~70 ГБ); `heavy` (smart / writer / uncensored — вытесняют всё, кроме always). Точные имена репозиториев на Hugging Face уточняем в день загрузки — они обновляются ежемесячно.

### 2.6 Контракт для будущих агентов

- Base URL: `http://litellm:4000/v1` внутри docker-сети, `http://127.0.0.1:4000/v1` с хоста
- Модель — **только алиас** (`bossman-fast`), никогда имя файла. Замена модели = одна строка в конфиге, код агентов не меняется
- Каждый агент — свой ключ LiteLLM с белым списком (`scripts/create-agent-key.sh`). Это и есть разделение «мозг / руки» на уровне шлюза: ключ личного чата видит только `bossman-uncensored` и не имеет инструментов; ключ Coder не видит `bossman-uncensored`
- Fallback в облако — только для ключей, которым облако разрешено. Ключам с приватными данными (почта клиники, сделки) облачные алиасы не выдаются; тогда при сбое локальной модели запрос падает, а не утекает
- Все вызовы логируются в Postgres LiteLLM: кто, какая модель, сколько токенов

### 2.7 Безопасность

- Периметр: только Tailscale; порты сервисов на 127.0.0.1; на роутере ничего не проброшено
- LUKS + TPM2, резервный пароль
- `.env` с правами 600, не в git; облачные ключи ротируются раз в квартал
- Docker: `restart: unless-stopped`, контейнерам отдаются только нужные устройства (`/dev/dri`, `/dev/kfd`)
- Этап 4: отдельный VLAN для сервера

### 2.8 Что делаем сейчас и что после приезда

**Сейчас, без железа:** репозиторий, compose, конфиги LiteLLM и llama-swap, скрипты, README; прогон на ноутбуке в двух режимах — только облако (Open WebUI → LiteLLM → Claude) и CPU-тест (llama-swap с Qwen3-0.6B) для проверки всей цепочки; создание ключей per-агент.

**После приезда:** шаги 1.1–1.11, загрузка моделей, сверка имён файлов, бенчмарк, подбор контекста и квантов под замеры, алерты в Telegram.

### 2.9 Критерии приёмки v0.1

1. С телефона вне дома открывается чат и отвечает `bossman-fast`
2. `curl /v1/models` через LiteLLM показывает все алиасы; вызов `claude-heavy` работает
3. Переключение `fast` → `smart` происходит само (llama-swap), без ручных действий; `embed` при этом не выгружается
4. Перезагрузка и отключение питания: сервисы вернулись сами; Uptime Kuma прислал ровно один алерт о простое
5. Замеры tok/s по каждой модели зафиксированы в README
6. Ключ агента с ограниченным списком получает отказ при обращении к запрещённой модели

### 2.10 Что пересмотреть при росте

- ≥ 2 агентов с постоянной параллельной нагрузкой → оценить vLLM (ROCm) вместо llama.cpp для батчинга запросов
- Моделей > 6 → реестр в отдельный файл, конфиги генерировать
- Данных > 100 ГБ → NAS + restic (этап 2)
- Память стала реальным ограничением → 192-ГБ вариант чипа или eGPU с NVIDIA для CUDA-задач (Studio, обучение)
