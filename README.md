<a id="why"></a>
## Why Bossman — для чего мы это строим

У работы с ИИ есть бытовая сторона: найти документ, объяснить задачу, перенести ответ в другой инструмент, дождаться генерации, проверить файл и на следующий день вспомнить, на чём остановился. Bossman собирает эти переходы в одно рабочее пространство.

Пользователь формулирует результат: **«собери материалы», «подготовь страницу», «разложи файлы», «сделай ролик», «покажи, что сейчас происходит на компьютере»**. Система должна выбрать подходящий путь, показать необходимые разрешения, сохранить ход работы и дать проверяемый результат.

Это направление продукта. Не каждое предложение из этого README уже доступно одним сообщением. Ниже у текущих модулей есть границы проверки, а у будущих идей — отдельная маркировка.

<a id="principles"></a>
## Principles — как устроена работа

**Результат важнее красивого ответа.** Созданный файл нужно открыть, видео — воспроизвести, правку проекта — увидеть после перезапуска. Ответ модели «я сделал» недостаточен.

**Одна политика для разных исполнителей.** Браузер, терминал, модель и внешний сервис не должны иметь запасной путь вокруг разрешений. Подключение библиотеки не даёт ей дополнительных прав.

**Память не должна смешивать людей.** Проект, пользователь и назначенный агент — реальные границы данных. Общий компьютер не означает общий доступ ко всем разговорам и файлам.

**Неизвестное остаётся неизвестным.** Нет измерения — нет числа. Нет провайдера — нет выдуманной генерации. Зелёный тест настройки не равен успешной живой задаче.

**Скорость измеряется на нужном устройстве.** Быстрый ответ функции в Linux не доказывает быстрый интерфейс Windows. Итог проверяется на установленном архиве и целевом компьютере.

## Interface — пространство для работы

<img src="docs/v8/readme-visuals/interface-concept.webp" alt="Нарисованный концепт панели Bossman. Не скриншот текущего интерфейса и не результат пользовательской приёмки." width="440">

*AI-концепт интерфейса. Настоящий UI нужно смотреть в запущенной сборке. Имена, цифры и готовность внутри рисунка не являются спецификацией продукта.*

Рабочий путь пользователя проходит через несколько связанных областей: **задача → исполнитель → ход выполнения → результат → проект**. Интерфейс должен сохранять введённый текст, объяснять блокировку кнопки, различать ожидание разрешения и работу, а после перезапуска возвращать проекты и историю.

Для оценки удобства недостаточно открыть страницы. В [владельческом протоколе](docs/v8/owner-final-run/OPENCODE_OWNER_RUN_RU.md) проверяются реальные нажатия, первый клик, двойная отправка, конфликт вкладок, отмена, смена страницы и повторный запуск.

<a id="workflows"></a>
## Workflows — что показывать и для чего использовать

Ниже — **пользовательские сценарии**, а не обещание универсального автономного режима. Перед демонстрацией каждый выбранный путь должен пройти локальную репетицию на том же архиве.

| Сценарий | Что видит человек | Что считается результатом |
|---|---|---|
| **Порядок в файлах** | Выбор тестовой папки → предложения → предпросмотр → Apply | Файлы на месте, содержимое сохранено, undo работает после рестарта |
| **Локальная страница** | Создание страницы → выбор заголовка → правка → сохранение | Изменился нужный узел; проект снова открывается без потери дизайна |
| **Короткий ролик** | Импорт клипа → trim → undo/redo → preview → export | Экспорт открывается в отдельном плеере и доходит до конца |
| **Работа с документами** | Загрузка документа → извлечение фактов → задача агенту | Ответ с проверяемыми фактами и существующий выходной файл |
| **Изображение для проекта** | Запрос → разрешённая модель → галерея → редактор | Настоящие байты генерации и сохранённая страница, не подмена готовой картинкой |
| **Помощь с телефона** | Сообщение Telegram → поручение → подтверждение → уведомление | Реальная задача Bossman и доступный результат именно этого пользователя |
| **Возвращение к работе** | Закрытие программы → повторный запуск | История и проекты сохранены, оборванная задача не выдана за выполненную |

### Примеры запросов

> «В разрешённой тестовой папке прочитай два документа. Сохрани summary.txt с источниками и суммой найденных чисел».

> «Подготовь локальную страницу записи на консультацию. Не публикуй её. Покажи результат и дай изменить заголовок».

> «Собери короткий ролик из этих моих файлов. Покажи preview, затем экспортируй и сохрани проект».

> «Найди варианты прогулки на завтра со ссылками. Ничего не бронируй и не оплачивай».

Часть запросов потребует перехода в соответствующий модуль или явной команды Telegram. Свободный текст ещё не означает, что все инструменты автоматически доступны.

<a id="studio"></a>
## Studio & Video — создавать, проверять, переиспользовать

**Studio V8** объединяет описания провайдеров, очередь и галерею. У результата должны быть локальный файл, происхождение, параметры и понятный статус. Галерея поддерживает работу с коллекциями и повторным использованием; готовые результаты передаются в существующие редакторы.

**Video Studio** остаётся отдельным инструментом монтажа. Его способность экспортировать MP4 не доказывает способность генерировать видео моделью. Так же импорт изображения в галерею не равен AI-генерации.

| Уровень | Что проверяем |
|---|---|
| Каталог | Схема модели, обязательные параметры, явная неизвестная цена |
| Отправка | Разрешение на конкретные данные, маршрут, бюджет до первого запроса |
| Выполнение | Реальный provider ID, корректные ошибки, отмена без ложного completion |
| Результат | Декодируемые байты, происхождение, отсутствие частичного «готового» файла |
| Повторное использование | Передача в редактор, сохранение и восстановление после рестарта |

**Higgsfield внутри Bossman:** это направление собственной творческой системы, а не просто подключение чужого сервиса. Последнее решение на `172d39e1…` исправляет прежнее полное отклонение PR #59: часть защитных механизмов уже лучше реализована в каноне, но `job_store`, `content_buffer`, `persona`, `segment_qa` и другие части требуют переноса. Адаптер/селекторы требуют отдельной живой проверки. Это **ещё не готовый форк или принятый live-провайдер**. Актуальна [матрица по подсистемам](CONVERGENCE_DECISIONS.md), а старое общее отклонение больше не является решением для всех файлов.

**Открытый риск Studio:** в проверенном snapshot матрица продолжает называть **BL-084** — локальная оценка цены `0` не должна разрешать первый запрос платной модели. До доказанного закрытия этого пути облачную генерацию нельзя объявлять безопасно готовой. Защита нового Telegram-маршрута сама по себе не чинит Studio.

<a id="telegram"></a>
## Telegram Companion — Bossman на телефоне

Companion работает отдельным явно запускаемым процессом. Это позволяет отделить канал беседы и диагностики от окна Command Center. Обычное сообщение идёт настроенной локальной модели; её ответ не является командой ОС.

| Команда | Назначение |
|---|---|
| Обычный текст | Беседа с локальной моделью и отдельной короткой памятью |
| `/task описание` | Подготовить поручение назначенному агенту |
| `/confirm код` | Однократно подтвердить показанное поручение |
| `/result ID` | Получить состояние и результат собственной задачи |
| `/search запрос` | Запросить настроенный локальный SearXNG и получить ссылки |
| `/status` | Проверить доступность Bossman; только владелец |
| `/watch on` / `/watch off` | Включить или выключить уведомления о доступности |
| `/cloud on` / `/cloud off` | Разрешить или отозвать резерв Claude для этого пользователя |
| `/lock` | Заблокировать новые поручения; это не отмена уже запущенных |
| `/forget` | Очистить локальную память беседы и выключить согласие на облако |

### Local first, cloud by consent

В штатном режиме отвечает уже установленная локальная OpenAI-compatible модель. При её отказе предусмотрен резерв **Claude через OpenRouter**: нужны точная модель, ключ, пределы расходов и согласие пользователя. Облачный ответ отмечается.

Передаётся только текущее человеческое сообщение после проверки секретов. Локальная история, файлы, статус компьютера и результаты задач автоматически в облачный контекст не подмешиваются. Списание учитывает консервативную оценку; неоднозначные запросы не повторяются вслепую.

### Owner and guest

Пользователи задаются числовыми идентификаторами личных чатов. У каждого — отдельная память и свой назначенный исполнитель. Гость не получает мониторинг владельца или результат чужой задачи. Само назначение агента не делает его права безопасными: разрешённые папки и инструменты задаёт владелец в Bossman.

### Что ограничивает доступность

`/status` не ждёт ответа разговорной модели, но ему всё ещё нужны живой процесс моста и сеть. **Выключенный ПК, сон Windows или потеря интернета не исправляются переключением LLM на облако.** Для этого понадобится отдельный always-on relay; такой сервер пока не поставлен.

При переполнении ограниченной очереди новое сообщение может не выполниться; отсутствие ответа нельзя считать выполнением. Голосовые сообщения, фото-вложения, календарные напоминания и неограниченный доступ ко всем данным не объявляются готовыми.

**Проверки:** 79 offline-контрактов; повторный набор 74/74 проверяет также изоляцию окружения. Эти числа нельзя складывать в «153 независимые возможности». **Live Telegram / local LLM / Claude / Windows: ещё требуют приёмки.** [Инструкция и доказательства](docs/v8/TELEGRAM_COMPANION_RU.md).

<a id="architecture"></a>
## Architecture — как связаны слои

<img src="docs/v8/readme-visuals/architecture.svg" alt="Схема: UI и Telegram передают задачи через права и очередь назначенным агентам; модели и инструменты дают проверяемый результат. Облако опционально." width="1000">

Это упрощённая карта, не изображение всех процессов. Главные границы: **пользователь → политика → задача → исполнитель → наблюдаемый эффект**. Разговорная модель, кодовый агент и оператор компьютера не обязаны быть одной моделью и не должны незаметно получать одинаковые полномочия.

Технологические области: `command-center/` — UI и сервисы; `bossman-core/` — исполнение и защиты; `apps/` — приложения; `bossman_shared/` — общие контракты. Внешние sidecar-сервисы остаются отдельными зависимостями с собственным статусом.

<a id="models"></a>
## Local AI — одна большая модель или несколько маленьких

Bossman допускает разные стратегии, но не назначает победителя по размеру весов. На целевой машине нужно сравнивать время до полезного результата, память, точность аргументов инструментов, устойчивость многошаговой задачи и необходимость вмешательства человека.

| Категория | Для чего нужна | Что измерять |
|---|---|---|
| **LLM / coding / agents** | Диалог, планирование, код и выполнение задач | Ответ, рабочий проект, успешный эффект, время и потребление памяти |
| **Image generation** | Иллюстрации и визуальные материалы | Реальная генерация, время, пик памяти, отмена и повтор |
| **Video generation** | Короткие генерируемые клипы | Поддержка конкретного backend, формат, длительность, память и воспроизведение |
| **Tool calling / structured outputs** | Выбор инструмента, JSON и цепочки действий | Верный инструмент, схема, аргументы, несколько вызовов, обработка ошибки |

Целевая конфигурация владельца — **Ryzen AI Max+ 395 / Radeon 8060S / 128 GB общей памяти**. Память CPU и shared GPU не складывается как два независимых банка. README не фиксирует непроверенный список «лучших» моделей и не обещает CUDA-совместимость AMD.

Практический старт: одна проверенная модель и один рабочий сценарий; затем добавление vision/media по измеренному запасу. Веса не входят автоматически в архив приложения, облачные ключи тоже.

## Performance — «летает» в измерениях

<img src="docs/v8/readme-visuals/event-loop.svg" alt="Контролируемый Linux-тест: задержка независимого события снизилась с 240.744 до 0.352 мс при чтении с искусственной задержкой 250 мс; само чтение занимает около 251 мс." width="1000">

**Что изменено:** блокирующее чтение системных показателей перенесено из основного asyncio-loop в поток; одновременные запросы разделяют только выполняющееся чтение, без нового долгого кэша. Отмена одного клиента не ломает остальных, а отменённый sampler не должен позднее писать результат в БД.

**Что измерено:** 20 чередующихся пар с искусственным ожиданием 250 мс. Медианная задержка независимого callback — **240.744 → 0.352 мс**. Само медленное чтение — **250.706 → 251.219 мс**. На быстром контроле накладные расходы порядка 0.15 мс. Это исправление блокировки, а не ускорение всего продукта в сотни раз.

## Security & privacy — управляемая автономность

**Режимы `never / ask / allowed`.** Отдельные операции запрещены, отдельные требуют подтверждения, безопасные разрешены в заданной области. Пользователь должен видеть, что именно будет изменено или отправлено.

**Локально не значит безусловно безопасно.** Модель может ошибиться, неправильно понять текст страницы или предложить действие вне задания. Внешние документы, сообщения, веб-страницы и ответы инструментов — данные, а не источник новых полномочий.

**Секреты и личные данные.** Токены не кладутся в Git, README, лог или скриншот. Шифрование с ключом на том же компьютере не защищает от компрометации учётной записи ОС. Telegram и облачные API — внешние каналы; локальная модель не делает их приватными по определению.

**Расходы и побочные эффекты.** Неизвестная цена не равна нулю. После потерянного ответа сначала выясняется, произошло ли действие; автоматический повтор может создать дубль или второй расход. Финансовые операции, публикации, бронирования и сообщения третьим лицам требуют отдельных разрешений.

**Ремонт и откат.** Исправление сначала проверяется на тестовых данных. Предыдущий архив и совместимая резервная копия сохраняются. Новая отметка поколения БД не добавляет защиту в старые уже выпущенные бинарники.

Наличие этих механизмов не является обещанием отсутствия уязвимостей. Известные проблемы, включая BL-084, остаются видимыми в [BUG_LEDGER](docs/final/BUG_LEDGER.md).

| Идея | Проверяемое преимущество |
|---|---|
| Выбор модели по задаче | Меньше времени и памяти при сохранении качества |
| Предварительный прогрев | Готовая модель перед ожидаемой задачей в пределах бюджета |
| Тихие часы | Не начинать тяжёлый рендер во время важного звонка |

| Планировщик энергии | Перенос необязательной работы в подходящее время |
| Сравнение стратегий | Одна большая модель против группы небольших на одинаковых задачах |

### 9. Evidence-first memory — память с происхождением

### 10. Everyday reliability — надёжность в быту

| Идея | Как ощущается пользователю |

<a id="quick-start"></a>
## Quick Start — как начать

### Windows: рекомендуемый путь для владельца

1. Найдите **проверенный application ZIP** и запись с его именем, source SHA, размером и SHA-256. Источники: [INSTALL.md](INSTALL.md), [реестр кандидатов](docs/final/KNOWN_GOOD_SHAS.json). Архив исходников GitHub и ZIP-обёртка Actions — не одно и то же, что приложение.
2. Сверьте хеш, распакуйте в отдельную папку и откройте **`Start-Bossman.cmd`**. Браузер, Python runtime и медиабинарники должны соответствовать манифесту выбранной поставки.
3. Через настройки подключите уже подготовленную локальную модель. Наличие имени в каталоге не доказывает загруженные веса или ускорение на GPU.
4. Начните с тестового проекта и безопасной задачи. Проверяйте вывод на диске, сохранение и повторный запуск.
5. Перед обновлением сохраните данные и предыдущую сборку по [инструкции отката](docs/final/ROLLBACK.md).

**Обязательная оговорка:** последний исходный commit не автоматически последний принятый ZIP. Если новой принятой поставки нет, состояние остаётся RC/непринято — README не заменяет её красивой кнопкой Download.

### Telegram: первая настройка

Используйте встроенный Python **новой поставки, действительно содержащей Companion**:

```powershell
.\runtime\python.exe -I -m bcc.telegram_companion --setup
.\runtime\python.exe -I -m bcc.telegram_companion --diagnose
.\runtime\python.exe -I -m bcc.telegram_companion
```

Первая команда открывает локальную форму. Нужны отдельный токен бота, свой числовой user ID, точный модельный endpoint и при необходимости назначенный исполнитель. Ключ вводится локально, не в сообщение ассистенту. `getMe` подтверждает авторизацию Bot API, но не всю цепочку. **Удобный проверенный ярлык Telegram в корне Windows-архива ещё требуется довести.**

Если legacy `X-BCC-Token` сознательно отключён, этот путь делегирования не должен включать его обратно автоматически: нужен предусмотренный безопасный способ аутентификации. [Полная инструкция](docs/v8/TELEGRAM_COMPANION_RU.md).

### Development: запуск из исходников

Python **3.11+**; зависимости и особенности ОС — в инструкции установки. Запуск из исходников может устанавливать пакеты и Chromium, поэтому не используйте его вместо демонстрации проверенного архива.

```powershell
.\start-bossman.ps1
.\start-bossman.ps1 -SkipInstall
```

```bash
bash start-bossman.sh
bash start-bossman.sh --skip-install
```

Панель по умолчанию: `http://127.0.0.1:8800`. Linux/macOS source-путь не означает, что для них выпущен и принят такой же готовый Windows-архив.

<a id="release"></a>
## Release readiness — что нужно для V8 Total

Три разных утверждения:

**CODE PRESENT:** механизм написан. **CANDIDATE ACCEPTED:** определённый архив прошёл определённый профиль. **READY FOR OWNER WORK:** выбранные реальные задачи прошли на машине владельца. Ни одно из них само по себе не означает весь V8 Total.

| Gate | Доказательство для закрытия |
|---|---|
| Repository | Нет воспроизводимых блокирующих дефектов в согласованном объёме; актуальный CI завершён |
| Package | Закреплённые входы, полный состав, один application ZIP, известные размер и хеш |
| Windows | Чистая установка и установленный профиль без скрытых обязательных пропусков |
| GUI | Владельческий путь через настоящие окна и проверенные эффекты |
| Local AI | Настоящая модель → агент → инструмент → результат → рестарт |
| Media | Для заявленной генерации — живой provider и настоящие декодируемые байты |
| Telegram | Реальный round-trip, изоляция owner/guest, отказ локальной модели и разрешённый резерв |
| Hardware | CPU/GPU/общая память, latency, безопасная нагрузка и возврат памяти |
| Recovery | Рестарт, отмена, update и совместимый rollback с данными |
| Intelligence | Сравнение той же модели напрямую и через систему на достаточном проверенном корпусе |
| Delivery | Публикуются те же байты, которые проверяли, а не rebuild после теста |

Хеш архива фиксируется **до тестирования**, сверяется при приёмке и ещё раз перед выдачей. Правильная последовательность: **build → hash → test these bytes → publish the same bytes**. Документы не могут сами переключить вердикт в `FROZEN`.

Открытые внешние требования не останавливают доступные исправления кода. Но отсутствие кода, например неподключённого провайдера или неудобного запуска, нельзя прятать за фразой «нужен ключ». Отсутствующие ранее согласованные функции нельзя молча исключать ради красивого релиза.
