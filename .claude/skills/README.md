# `.claude/skills` — рабочие методы, снятые с закрытия дефектов

Это не теория и не стайлгайд. Каждый файл здесь описывает приём, которым в этом
репозитории реально был закрыт дефект, и ссылается на конкретный коммит и
конкретный файл, где результат можно увидеть.

## Как этим пользоваться (в том числе локальной модели)

1. Прочитай только поля `description` в списке ниже.
2. Выбери один-два скила, чьи условия совпадают с твоей текущей задачей.
3. Открой их `SKILL.md` и выполняй шаги буквально.
4. Не читай все восемь подряд — они не связаны между собой и не образуют процесс.

Проверять цитаты можно прямо: `git show <sha>` и `ls <путь>`. Если ссылка не
открывается, скил устарел — почини ссылку, а не игнорируй её.

## Скилы

| скил | брать, когда |
|---|---|
| `reproduce-before-fixing` | есть строка аудита, баг-репорт или жалоба владельца, и хочется сразу править код |
| `negative-control` | правка меняет строгость проверки: допуск, новый отказ, ослабление валидации |
| `measure-do-not-assume` | в отчёте вот-вот появится оценка, «примерно» или «должно хватить» |
| `port-do-not-merge` | нужно свести разошедшуюся ветку (приёмка, аудит, чужой патч) с текущим HEAD |
| `atomicity-boundary` | запись в БД и вызов внешнего порта идут подряд без общей транзакции |
| `honest-verdict` | закрываешь задачу, пишешь отчёт/scorecard или проектируешь код, возвращающий вердикт |
| `tests-that-find-bugs` | пишешь тесты на планировщик, парсер, состояние во времени или логику внутри UI |
| `parallel-agent-file-ownership` | над одним checkout одновременно работает несколько агентов |

## Источник

Ветка `claude/v5-closure-at-reconcile-xdh12f`, диапазон `1bb39bf..HEAD`.
Сообщения коммитов в этой ветке — первоисточник: в каждом названы дефект,
воспроизведение, корневая причина и контроль, доказывающий фикс. Скилы — выжимка
из них, а не замена.

Соседний каталог `.agents/skills/` содержит более общие скилы агентов BOSSMAN
(`proof-before-done`, `safe-code-change`, `repo-audit` и другие) и не дублируется
здесь.
