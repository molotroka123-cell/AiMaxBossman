# Tests That Find Bugs

Тест, который повторяет то, что делает код, подтверждает код. Дефект находит тест,
который утверждает СВОЙСТВО и не знает про реализацию.

## Приём 1 — свойство на длинной оси вместо точки

Не «при t=100 порядок такой». А «на всём таймлайне число переворотов порядка
конечно, и к хвосту порядок ЗАМИРАЕТ».

`tests/test_v5_fairness.py::test_the_order_settles_instead_of_oscillating`
(`0d732c7`): 8 целей, 400 тиков по 15 секунд (таймлайн 6000 с), считаются
перевороты по каждой паре.

- утверждение: у каждой цели ровно три односторонние границы (стала подходящей,
  старение упёрлось в потолок, наступил крайний срок голодания), поэтому
  переворотов не больше шести на пару, а после трети таймлайна — ноль
  (`assert late_flips == 0`);
- **этот тест нашёл настоящий дефект**: ступенчатая (квантованная) надбавка
  старения переступала у разных целей в разных фазах, и пары менялись местами
  каждые полминуты — **двенадцать переворотов на одной паре**;
- фиксов было три: надбавка стала непрерывной, ещё не подошедшая цель не
  соревнуется с ожиданием, зажатым в ноль, и голодающая группа упорядочивается по
  ожиданию, а не по приоритету, чтобы продвижение не откатывалось.

Как применять: выбери величину, которая ОБЯЗАНА быть конечной или монотонной
(число переворотов, число вызовов порта, число наблюдений), и проверь её на всём
диапазоне, а не в одной точке.

## Приём 2 — вынести чистую функцию из UI

Логика, до которой можно добраться только кликом, не тестируется и потому не
проверена.

`command-center/ui/pages/objectives.js` (`c673bea`): построитель спецификации
мастера экспортирован как чистая функция и протестирован без DOM
(`command-center/ui/tests/objectives_wizard.test.mjs`, 7 тестов). Именно там
всплыл третий дефект: **`Number('')` равен 0 и проходит `isFinite`**, поэтому
очистка поля «лимит времени» молча давала бюджет в 0 секунд. Пустое поле теперь
означает документированный дефолт, а введённый вручную 0 сохраняется, чтобы сервер
отказал по имени, — это разные намерения, и клиент обязан их различать.

## Приём 3 — holdout и детерминированное разбиение

Улучшение, показанное на тех же задачах, на которых кандидата настраивали, — это
подгонка, а не улучшение.

`bossman_shared/objective_promotion.py` (`5abd4a6`):

- `split_tasks(...)` разбивает по `sha256(material + task_id)`, БЕЗ генератора
  случайных чисел: разбиение, которое нельзя повторить в другом процессе, делает
  отчёт непроверяемым;
- кандидат обязан выиграть на измеряемой части И не просесть на holdout;
- негативный контроль: переобученный кандидат отвергается `holdout_regression`;
- та же техника в `bossman_shared/objective_canary.py` — когорта выбирается
  `sha256` по цифре ревизии и идентификатору цели.

## Приём 4 — враждебная фикстура вместо удобной

- Кириллица под враждебной ASCII-локалью: регресс в
  `command-center/tests/test_apps_control_child_encoding.py` (`6cc9523`)
  воспроизводит падение дочернего процесса и проверяет, что настоящий exit code
  выживает.
- Отсутствующий модуль, а не мок: `OBSERVER-DEPS-001` в
  `bossman-core/tests/test_live_run_findings_20260906.py`.
- Настоящий durable-ledger, а не порт-заглушка:
  `bossman-core/tests/test_v5_promotion_durable_ledger.py` — отказ переживает
  перезапуск процесса, нечитаемый ledger отказывает, а не промоутит.

## Чек-лист перед коммитом теста

- [ ] тест утверждает свойство, а не последовательность вызовов;
- [ ] есть положительный И отрицательный контроль (skill `negative-control`);
- [ ] тест детерминирован: без `random`, без часов, без сети;
- [ ] docstring объясняет, ПОЧЕМУ так, и называет найденный дефект, если он был.
