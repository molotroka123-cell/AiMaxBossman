## ROOT CAUSE (found, not guessed)

1. Bossman bench sends ONE tiny request (~20 prompt tokens, ~2 output tokens) and reports
   gen_tps = output_tokens / TOTAL_WALL_TIME. For MAIN: 2 tokens / 3.91 s = 0.51 t/s.
   The metric is dominated by per-request fixed latency (TTFT ≈ 3.5-4.8 s on MAIN,
   ≈ 1.5 s on FAST), which in turn is dominated by Vulkan per-request prefill overhead
   on tiny prompts. It does NOT measure generation throughput.
2. Cross-check: Bossman latency_ms (3910) ≈ direct direct-measured TTFT for the same
   tiny prompt class (3.57-4.83 s). Bossman's proxy overhead is negligible;
   the bottleneck is the metric definition, not the runtime, not the GPU, not Bossman.
3. The earlier cold number (TG 3.5 t/s direct, TTFT 15.9 s) was first-generation
   mmap page-in of 19.8 GiB weights while a 64 GiB download was saturating disk —
   transient cold-start effect, disappears when weights are resident.
